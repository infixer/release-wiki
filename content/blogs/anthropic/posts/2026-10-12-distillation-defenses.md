## 要約

Anthropic は、Claude に対する蒸留攻撃（不正アカウント網などを使って、開発元の許可なくモデルの能力を別のモデルに写し取る大規模な活動）への新しい防御策を公表した。初期の評価では、蒸留者が収集できるデータ量を約 90〜99% 減らせたとしている。防御は主に、蒸留で最も価値が高い Claude の推論（thinking）へのアクセスを難しくすることに集中している。一方で、正規ユーザーにも統合の更新や誤検知（0.1% 未満）などの負担が生じていることも認めている。

## 新機能・主な変更

> [!info] 蒸留を懸念する理由
> - 蒸留されたモデルは、能力に見合う安全策なしに公開されがちで、生物学やサイバーセキュリティで悪用されうる。例として、Zhipu が GLM-5.3 の開発で米国モデルのサイバー能力を蒸留した（Claude Fable 5 も試みたが、安全策で攻撃が弱まったため古い Claude モデルなどに切り替えた）としている
> - 蒸留した能力が外国の軍事・情報・監視システムに組み込まれており、国家安全保障上のリスクになる

> [!info] 単純な防御では不十分だった
> 当初は推論を要約してから表示する対策を取った。Claude Opus 4.8 の全文の推論で学習したモデルは SWE-bench Verified で 80.4% だったが、要約だけでは 71.8% にとどまった。しかし攻撃者は「推論を一字一句出力せよ」といった能動的な抽出や、数十万の不正アカウントを操るプロキシ網に移行した。

> [!tip] 推論の行き先を制御する
> - Claude Fable 5.1 と Claude Opus 5.5 で **preserved thinking** を導入。2026-08-31 以降に作られた API アカウントは、Claude の過去のコンテキストを編集できない
> - これらのモデルの推論を、蒸留対策の弱い以前のモデルに読ませないようにした
> - Claude Sonnet 5.5 では、推論の記録をそのリクエストを出した組織だけが参照できるようにした

> [!tip] 抽出の試みをブロックする
> constitutional classifiers の研究と同じ 2 段階の分類器を導入し、社内外のレッドチーミングで見つかった穴を修正した。生物兵器の支援を防ぐ安全策とほぼ同等の堅牢さで、誤検知率は 0.1% 未満。現在 Claude Sonnet 5.5、Claude Opus 5 / 5.5、Claude Fable 5 / 5.1 で動いている。推論を別の言語に翻訳させる、回答と一緒にタグ内に書かせる、といった新しい手口にも素早く対応している。

> [!tip] 繰り返しの試みを難しくする
> 推論の抽出を繰り返すユーザーには厳しい利用制限をかけ、執拗な場合はアカウントを停止する。9 月 24 日からは、誤検知率 0.1% 未満の領域（蒸留を含む）で、応答前に安全策がブロックしたリクエストにも課金を再開した。

> [!success] 効果
> 分類器の導入後、自社プラットフォームで蒸留者が抽出できた推論トークンは以前の 10〜100 分の 1 以下になり、9 月の報告で紹介した手口はすべて検出できている。蒸留に関係する数万のアカウントを、多くは活動開始から 2 時間以内に停止した。ただし効果がどれだけ続くかは分からず、いたちごっこが続くと見ている。

蒸留者は Anthropic の API だけでなくサードパーティのクラウドや推論プロバイダーにもトラフィックを分散させるため、すべてのモデル開発者とプラットフォームが対策に加わる必要があると訴えている。

## 破壊的変更・移行手順

> [!warning] preserved thinking による統合の更新
> 2026-08-31 以降に作られた API アカウントでは、Claude Fable 5.1 / Claude Opus 5.5 の過去のコンテキストを編集できない。記事によると、一部の開発者は統合の更新が必要になった。また、安全策がブロックしたリクエスト（誤検知を含む、0.1% 未満）にも課金される。
