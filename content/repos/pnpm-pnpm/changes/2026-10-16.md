## 新機能

### `sideEffectsCache.exclude` 設定を追加（[#15651](https://github.com/pnpm/pnpm/pull/15651)）

> [!tip] 何ができるようになったか
> ビルド結果が実行環境に左右されるパッケージ（`JAVA_HOME` に対してコンパイルするネイティブアドオンなど）を、side-effects キャッシュの対象から外せるようになった。これまでは最初に成功したビルドがキャッシュされ、別の環境のプロジェクトにもそのバイナリが復元されていた（[#5271](https://github.com/pnpm/pnpm/issues/5271)）。
>
> - **使い方**: `pnpm-workspace.yaml` の `sideEffectsCache.exclude` にパッケージを並べる（`java`、`'@native/*'`、`'sharp@1.0.0 || 2.0.0'` のように `minimumReleaseAgeExclude` / `trustPolicyExclude` と同じ書式）
> - **挙動**: 対象のパッケージは毎回どのプロジェクトでもビルドし、ローカルでもリモート（`remoteCache`）でもキャッシュから復元・保存しない。グローバル仮想ストアではプロジェクトごとの置き場所を持つ
> - `exclude` だけを書けば `read`・`write`・`remote` は既定値のまま。`pnpm config delete sideEffectsCache` でまとめて消える。pnpm v12 のみ

⏳ 未リリース（v12.14.0 に記載）· トピック: [[repos/pnpm-pnpm/topics/インストール|インストール]]

### `pnpm login` の Web ログインで `npm-notice` ヘッダーを表示（[#16697](https://github.com/pnpm/pnpm/pull/16697)）

> [!tip] 何ができるようになったか
> Web ログインの最初の要求（`POST <registry>/-/v1/login`）の応答にある `npm-notice` ヘッダーを、ログイン URL と QR コードの前に表示する（npm CLI と同じ）。
>
> - **嬉しい場面**: Artifactory のように、ブラウザでの確認コードをこのヘッダーで返すレジストリでログインを完了できる
> - レジストリが決める文字列なので、制御文字・書式文字（bidi の上書きなど）を取り除いて表示する。応答が失敗・本文が不正・URL が安全でないときは何も表示しない
> - ユーザー名とパスワードによる従来のログインは変わらない

⏳ 未リリース（v12.14.0 に記載）· トピック: [[repos/pnpm-pnpm/topics/CLI-コマンド|CLI コマンド]]

### zstd で圧縮された応答を受け付け、pnpr からも配る（[#16585](https://github.com/pnpm/pnpm/pull/16585)）

> [!tip] 何ができるようになったか
> インストールのクライアントが `Accept-Encoding: zstd,gzip,deflate`（これまで `gzip,deflate`）を送り、zstd の本文を展開するようになった。pnpr も zstd で応答を返せる。
>
> - **嬉しい場面**: 完全な packument（`trustPolicy: no-downgrade`、`time` の無いレジストリでの `resolutionMode: time-based`、`minimumReleaseAge` で取得）。PR 本文の計測では `vite` の完全な packument が gzip -6 で 4.65 MB、zstd -3 で 603 KB
> - registry.npmjs.org・registry.yarnpkg.com・registry.npmmirror.com は現時点では zstd を返さない（PR 本文より）

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/インストール|インストール]]、[[repos/pnpm-pnpm/topics/pnpr|pnpr]]

### pnpr: SIGTERM での停止とレディネス・ライブネスの確認（[#16934](https://github.com/pnpm/pnpm/pull/16934)）

> [!tip] 何ができるようになったか
> コンテナでの運用向けに、停止とヘルスチェックを整えた（pnpm/tasks#131 の C1）。
>
> - **停止**: Ctrl-C（`SIGINT`）に加えて Unix の `SIGTERM` で、新しい接続の受け付けをやめ、処理中の要求を終えてから止まる（`docker stop`、Kubernetes の Pod の停止）
> - **`GET /-/ready`**: ストレージ（ファイルシステム、S3 は 5 秒のタイムアウト）と認証のバックエンドを確認し、`200` か `503`
> - **`GET /-/live`**: プロセスが動いていれば `200`
> - **`GET /-/ping`**: レディネスの確認を行い、使えないときは `503`（成功時は npm CLI 互換の `{}`）

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/pnpr|pnpr]]

### pnpr: 信頼するプロキシからクライアントの IP を求める（[#16939](https://github.com/pnpm/pnpm/pull/16939)）

> [!tip] 何ができるようになったか
> リバースプロキシの後ろで、本当のクライアントの IP をアクセスログなどに使えるようになった（C2）。
>
> - **設定**: `trustedProxies`（IP・CIDR・`"loopback"`）と `trustedProxyHeader`（`x-forwarded-for`（既定）・`forwarded`・`x-real-ip`）
> - 直接の接続相手が信頼するプロキシのときだけ、指定したヘッダーを右から読み、信頼するプロキシを飛ばして最初の信頼しない IP を使う。それ以外やヘッダーが無効なときは接続相手の IP を使う
> - 求めた IP はアクセスのトレースの `client_ip` に入る

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/pnpr|pnpr]]

### pnpr: レート制限・要求のタイムアウト・upstream 取得のまとめ（[#16943](https://github.com/pnpm/pnpm/pull/16943)）

> [!tip] 何ができるようになったか
> DoS・資源枯渇への対策（C3）。
>
> - **書き込み前の認可**: パッケージの書き込み（`PUT /{pkg}` など）は、本文（最大 100 MiB）を読む前に認証と書き込み権限を確認する
> - **upstream の取得のまとめ（singleflight）**: 同じパッケージの同時のキャッシュミスで upstream への取得を 1 回にする
> - **ログインのレート制限**: IP とユーザー名ごとに失敗を数え、`429 Too Many Requests` と `Retry-After` を返す。ログインと publish のバッファリングの同時実行数にも上限
> - **`requestTimeout`**（既定 60 秒）: 超えた要求に `504 Gateway Timeout`

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/pnpr|pnpr]]

### pnpr: Prometheus のメトリクス・要求 ID・アクセスログの拡充（[#16944](https://github.com/pnpm/pnpm/pull/16944)）

> [!tip] 何ができるようになったか
> 運用の観測のための機能（C4）。
>
> - **`GET /-/metrics`・`GET /metrics`**: Prometheus のテキスト形式で、処理中の要求数、メソッド・ステータスごとの要求数、所要時間のヒストグラム、応答のバイト数、プロキシのキャッシュのヒット・ミス、ログインのレート制限、ビルド情報を出す（`/metrics` は npm の Accept ヘッダーなら `metrics` パッケージの packument を返す）
> - **要求 ID**: 受け取った `x-request-id`（印字可能な ASCII、128 文字以下）を使うか UUID v4 を作り、応答ヘッダー・トレース・アクセスログに入れる
> - **アクセスログ**: ターゲット `pnpr::access` に `request_id`・`method`・`uri`・`client_ip`・`user`・`user_agent`・`status`・`latency_ms`・`bytes`

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/pnpr|pnpr]]

### pnpr: キャッシュの削除（LRU・TTL）と孤立した名前空間の掃除、`pnpr cache-gc`（[#16946](https://github.com/pnpm/pnpm/pull/16946)）

> [!tip] 何ができるようになったか
> キャッシュの大きさと古さに上限を設けられるようになった（C5）。
>
> - **設定**: `cache:` にパスの文字列か `{ path, maxSize, maxAge }`
> - **削除**: 期限切れ・容量超過の packument・tarball・放置された一時ファイルを消し、空になったパッケージ・スコープのディレクトリも消す
> - **孤立した名前空間**: 以前のプロセスごとの秘密値や設定の変更で残った `~upstreams/`・`~public/` の下の名前空間を起動時に消す。定期的な掃除もバックグラウンドで実行できる
> - **`pnpr cache-gc`**: `--dry-run`・`--max-size`・`--max-age-secs`・`--orphans-only`（`oci-gc` と同様）

### pnpr: トークンの作成・有効期限・読み取り専用トークンでの audit（[#16954](https://github.com/pnpm/pnpm/pull/16954)）

> [!tip] 何ができるようになったか
> `npm token create` に対応した（C7）。
>
> - **作成**: `POST /-/npm/v1/tokens`（`~{registry}` の接頭辞付きも）。読み取り専用・CIDR の許可リスト・有効期限（`expires`・`expires_in`）・名前を指定できる。bcrypt のパスワードがあるアカウントはパスワードを確認し、失敗はレート制限する

> [!quote] Before
> `files` の許可リストがあると、`pnpm pack` / `pnpm publish` はすべての `.npmignore` / `.gitignore` を無視していた（npm と pnpm 11 が無視するのはルートのものだけ）。

### 依存が peer に変わったら、lockfile で固定した子を解決し直す（[#16912](https://github.com/pnpm/pnpm/pull/16912)）

> [!quote] Before
> 依存と任意の peer の両方に同じパッケージを持つパッケージがあると、2 回に分けてインストールしたときに、一度にインストールしたときと違う lockfile が書かれることがあった（v12 が前の lockfile の子の固定をそのまま読んでいた）。

> [!success] After
> 新しく解決したパッケージが固定された子を読む前に、依存と peer の分け方が変わるものが無いかを確かめ、あれば子を解決し直す。メタデータを読むのは上の階層の有無が変わった固定パッケージだけ。1 回でも 2 回でも同じ lockfile になる（v11 と同じ）。

### Windows の Rust ツールチェーンを rustup の既定のホストに合わせる（[#16917](https://github.com/pnpm/pnpm/pull/16917)）

> [!quote] Before
> [#16868](https://github.com/pnpm/pnpm/pull/16868) で Windows のツールチェーンの ABI を pnpm のビルドターゲットに合わせたが、MSYS2 向けのビルドでも公式（MSVC 版）の pnpm を使うため 12.13.0 は `x86_64-pc-windows-msvc` を入れていた。

> [!success] After
> rustup と同じく、`$RUSTUP_HOME/settings.toml` の `default_host_triple`（対応する Windows のホストなら）を使い、無ければマシンのネイティブのアーキテクチャの MSVC ツールチェーンを入れる。`MSYSTEM` は（Git Bash も設定するため）使わない。

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/Rust-ツールチェーン|Rust ツールチェーン]]

### stderr が閉じたパイプでも異常終了しない（[#16916](https://github.com/pnpm/pnpm/pull/16916)）

> [!quote] Before
> stderr の読み手が先に終わると、次の書き込みでパニックし、リリースビルドの `panic = "abort"` により SIGABRT・終了コード 134・コアダンプで落ちていた（例: `pnpm start 2>&1 | head -1`）（[#16904](https://github.com/pnpm/pnpm/issues/16904)）。

> [!success] After
> stderr への書き込みの失敗を無視する `pnpm_diagnostics::eprintln!` / `eprint!` に置き換え、スクリプトの終了コードがそのまま返る。clippy の `print_stderr` で標準のマクロの再導入を防ぐ。stdout については [#16932](https://github.com/pnpm/pnpm/pull/16932) で同様の修正。

⏳ 未リリース（v12.14.0 に記載）· トピック: [[repos/pnpm-pnpm/topics/CLI-コマンド|CLI コマンド]]

### 読み取りだけのコマンドや拒否されたコマンドで `package.json` を作らない（[#16915](https://github.com/pnpm/pnpm/pull/16915)）

> [!quote] Before
> `pnpm why`・`pnpm outdated`・`pnpm fetch`・`pnpm sbom`・`pnpm dedupe --check` や、引数・前提の確認でエラーになるコマンド（`pnpm rt ls`、lockfile の無い `pnpm audit`、`pnpm link ./missing` など）が、無い `package.json` を作っていた（[#16907](https://github.com/pnpm/pnpm/issues/16907)）。

> [!success] After
> 無いマニフェストはメモリ上の `pnpm init` のひな形として持ち、`pnpm install` は成功後、`pnpm link` はすべての対象を解決した後、`pnpm add` は保存時に書く。`binding.gyp` だけのプロジェクトは `install` の段階の直前に書き、暗黙の `node-gyp rebuild` を保つ。

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/CLI-コマンド|CLI コマンド]]

### silent・ndjson のレポーターで `[ELIFECYCLE]` の行を正しく扱う（[#16891](https://github.com/pnpm/pnpm/pull/16891), [#16925](https://github.com/pnpm/pnpm/pull/16925)）

> [!quote] Before
> stdio を引き継いで実行したスクリプトが失敗すると、`pnpm run` はレポーターに関係なく `[ELIFECYCLE] Command failed with exit code N.` を stderr に書いていた。`--reporter=silent` でも出て、`--reporter=ndjson` では JSON の記録の間に素の行が混ざった。

> [!success] After
> 既定のレポーター以外ではレポーターを通す。silent は何も出さず（pnpm 11 と同じ）、ndjson は `-r --stream` と同じ `name: "pnpm"` のエラーの記録を書く。既定のレポーターと `--loglevel=error` では従来どおり stderr に出る。

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/タスク実行・並行処理|タスク実行・並行処理]]

### Windows で、切り離された孫プロセスに pnpm の標準ハンドルを渡さない（[#16940](https://github.com/pnpm/pnpm/pull/16940)）

> [!quote] Before
> Windows で出力をリダイレクト・パイプした `pnpm exec` / `pnpm run`（`pnpm nx ...` など）が、Nx のデーモンのような切り離された孫プロセスが動いている間、戻らなかった（[#16930](https://github.com/pnpm/pnpm/issues/16930)）。

> [!success] After
> 起動時に pnpm 自身の標準ハンドルを継承不可にする（Node.js と同じ）。子プロセスには Rust が作る複製で stdio を渡す。Unix では何もしない。v12 のみの修正。

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/タスク実行・並行処理|タスク実行・並行処理]]

### `pnpm pipeline --dry-run` で選択が空のとき実行レポートを書かない（[#16872](https://github.com/pnpm/pnpm/pull/16872)）

> [!quote] Before
> プロジェクトが 1 つも選ばれないと、`--dry-run` を確かめる前に実行を終え、実行レポートを書き、`--json` ではログの行を出していた。

> [!success] After
> `pnpm pipeline --dry-run --json` は `{"tasks": []}` を出し、`--dry-run` は「nothing to run」のメッセージだけを出して、どちらもレポートを書かない。通常の実行は変わらない。

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/タスク実行・並行処理|タスク実行・並行処理]]

### pnpr: 監査で見つかったセキュリティ・不変性・ストレージの問題を修正（[#16927](https://github.com/pnpm/pnpm/pull/16927)）

> [!quote] Before
> unpublish が pnpr 内部のキャッシュを消せる、S3 のパッケージ一覧の接頭辞の比較がずれる、クラッシュ後のジャーナルの再生で tarball を失われたと誤判定する、設定の `Debug` 表示に秘密値が出る、などの問題があった（pnpm/tasks#131 の D 節）。

> [!success] After
> 削除をホスト型のバックエンドに限る、`htpasswd`・`tokens.db` を `0600` で作り置き換え時に権限を保つ、ユーザーの有無で応答を変えない（ダミーの bcrypt 照合と `401`）、パスワードを 71 バイトまでに制限して bcrypt の切り詰めを防ぐ、などを修正した。

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/pnpr|pnpr]]
