## 新機能

### pnpr: 本番準備の Section A（形式バージョン・CLI の文法・厳密な設定・`v0` プロトコル）（[#17112](https://github.com/pnpm/pnpm/pull/17112)）

> [!tip] 何ができるようになったか
> pnpm/tasks#131 の Section A の要件をまとめて実装した。
>
> - **保存する文書の形式バージョン（A2）**: packument・OCI イメージの文書・crate の文書・ジャーナルの状態レコードに `formatVersion` を付け、新しすぎる形式は `DocumentFormatTooNew` で分かるように失敗させる
> - **CLI の文法（A4）**: `pnpr serve` サブコマンドに整理し、TTL と GC 間隔のフラグ（`--packument-ttl`・`--min-age`・`--max-age`）で `30s`・`5m`・`1h`・`1d` の単位と秒数だけの指定を受け付ける
> - **設定の厳密な検証（A6）**: YAML の設定で未知のフィールド・古いセクション名・非推奨のオプションを拒否し、設定項目と CLI 引数の名前をそろえた
> - **プロトコルのバージョン（A7）**: resolver のプロトコルを `v0` に（`/-/pnpr/v0/resolve`・`/-/pnpr/v0/verify-lockfile`・`/-/pnpr/v0/publish`）。`/-/pnpr` で対応するバージョン・エコシステム・機能を返すハンドシェイクを追加し、終端の `done` フレームで適用した解決・検証のポリシーを返して pnpm 側が要求した設定と照らす。エラーはエラーコード付きで返す

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/pnpr|pnpr]]

### pnpr: 秘密情報の検証とサブキーの導出、エコシステムごとの設定の検証（[#17126](https://github.com/pnpm/pnpm/pull/17126)）

> [!tip] 何ができるようになったか
> pnpm/tasks#131 の Section B（B4〜B7）を実装した。
>
> - **秘密情報（B5）**: 秘密情報を持つ項目（`secret`・`secrets.cache`・`secrets.oci`・`s3.secretAccessKey`・`auth.scim.token`・`clientSecret`・SQL/libsql の `authToken`・upstream の `token`）に解決されない `${VAR}` があれば、空文字やプロセスごとの乱数の鍵に落とさず起動時に失敗する。`secrets.cache`・`secrets.oci` を別に設定でき、互いを無効にせずに鍵を入れ替えられる。ルートの `secret` からは用途ごとに分けた HMAC-SHA256 のサブキーを導く
> - **エコシステムごとの検証（B4）**: npm 以外のレジストリでの `teamsManagedBy: api` と、Cargo・PyPI のレジストリでの `unpublish` ルールを拒否する
> - **その他（B6・B7）**: `pnpr` クレートに `publish = false` を付けて crates.io への誤公開を防ぎ、v1 の拡張モデル（`pnpr-auth` の `UserBackend`・`TokenBackend` をコンパイル時に実装する方式で、動的なプラグインは無い）を文書にした

### pnpr が tarball から確かめた `requiresBuild` を配り、pnpm v12 がインストールに使う（[#17164](https://github.com/pnpm/pnpm/pull/17164)）

> [!tip] 何ができるようになったか
> pnpr が tarball の中身からビルドが要るかどうか（`requiresBuild: bool`）を判定し、`versions[v].dist.pnpr.requiresBuild`（と `POST /-/pnpr/v0/resolve` の `package` フレーム）で返す。pnpm v12 はこれを使ってインストールを速くする（pnpm/tasks#177）。
>
> - **判定**: 復号した `.tar` を調べ、`package.json` の `scripts.{preinstall,install,postinstall}`、`binding.gyp`（`gypfile: false` でなければ）、`.hooks/*` があればビルドが要るとする（`pnpm-tarball` の展開と同じ規則）
> - **記録**: `<pkg>/tar-integrities.json` に `tar_integrity` と並べて保存（既存の文字列だけのエントリも読める）。`PUT /<pkg>` での公開時、最初の tar の復号時、upstream から `.tgz` を初めてキャッシュしたとき（バックグラウンド）に記録する
> - **配信**: upstream や公開者が書いた `dist.pnpr` は信用せずに取り除き、完全な packument・省略形の packument（`application/vnd.npm.install-v1+json`）・単一バージョンの manifest・resolve の NDJSON に載せる

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/pnpr|pnpr]]、[[repos/pnpm-pnpm/topics/インストール|インストール]]

## 変更・修正

### macOS で owner が読めないストアのディレクトリに group の権限を付ける（[#17104](https://github.com/pnpm/pnpm/pull/17104)）

> [!quote] Before
> macOS で、group が書き込めるストアに owner の読み取りを外す umask（`0o477` など）でディレクトリを作ると、`pnpm install` が `EISDIR` で失敗していた。Node の `fs.lchmodSync` が macOS ではディレクトリを `O_WRONLY` で開くため、この処理は必ず失敗していた。

> [!success] After
> ディレクトリを `O_SEARCH`（読み取り権限が要らない）と `O_NOFOLLOW` で開いて `fstat`・`fchmod` する。シンボリックリンクにすり替えたディレクトリは引き続き拒否する。pnpm v11 の修正で、v12 はもともと影響を受けない。

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/ストア|ストア]]

### 置き換えのロックを対象ごとではなくインストールごとに 1 つに（[#17113](https://github.com/pnpm/pnpm/pull/17113)）

> [!quote] Before
> [#17091](https://github.com/pnpm/pnpm/pull/17091) で入った importer の置き換えのロックは対象のディレクトリごとに取られ、既存のパッケージを強制的に置き換えるたびにロックを取り、ユーザーごとのロックのディレクトリにパッケージ×プロジェクトのパスごとのファイルを残していた。

> [!success] After
> modules ディレクトリをキーにしたロック（`ModulesSwapLock`）をインストールごとに 1 回だけ取り、リンクの段階が終わったところ（ライフサイクルスクリプトの前）で放す。何も強制しない isolated のインストールでは取らない。同じプロジェクトの強制インストール 2 つは置き換えの段階全体で順番を待つ（pnpm/tasks#156）。

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/インストール|インストール]]

### ローカルのディレクトリ依存の下で tarball の URL・git のコミットが変わったら frozen install を拒否（[#17143](https://github.com/pnpm/pnpm/pull/17143)）

> [!quote] Before
> injected のワークスペースのパッケージや `file:` のディレクトリの子の依存で、範囲でない指定子は名前しか確かめず、tarball の URL を別のものに変えても `--frozen-lockfile` が通って古い tarball を入れていた（pnpm/pnpm#17129）。

> [!success] After
> tarball の URL や 40 桁の git のコミットが lockfile と違う元を指せば拒否する（v11・v12）。ブランチ・タグ・`#semver:` のような動く指定子と URL が同じ場合は、これまでどおり frozen install では記録した解決を使う。git はコミットと `path:` を比べ、リポジトリは比べない。

⏳ 未リリース · トピック: [[repos/pnpm-pnpm/topics/ワークスペース|ワークスペース]]

### `sharedWorkspaceLockfile: false` のワークスペースでパッチを使える（[#17155](https://github.com/pnpm/pnpm/pull/17155)）
