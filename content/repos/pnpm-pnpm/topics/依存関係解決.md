## 概要

依存関係の解決・カタログ・更新まわり。解決中に見つかった互換なバージョンをまとめる自動重複排除（`autoDedupe`）、カタログエントリでの `file:`/`link:` プロトコル対応、`pnpm update --peer` による peerDependencies の更新に対応している。重複排除では `catalog:` が固定するバージョンも直接指定と同じく優先されるようになった。lockfile の再利用判定はプレリリースと安定版の範囲を厳密に区別し、npm エイリアスも保持する。`minimumReleaseAge` まわりでは、レジストリから消えたバージョンを `pnpm update <pkg>` で置き換えられるようになり、時間ベースの解決で成熟したバージョンが優先されるよう修正中（未リリース）。`pnpm dedupe` の収束性の修正が続き、ハッシュ化された peer 接尾辞の読み戻し（v12.8.1）と、変種の統合後のキーの付け直し（v12.8.2）で `pnpm dedupe --check` が通るようになった。`minimumReleaseAge` で `latest` が隠れたときは、同じメジャーのプレリリースを下位メジャーの安定版より優先する（v12.8.2・v11.28.3）。未リリースの修正として、`autoDedupe` でダウングレードしたバージョンに他のプロジェクトも揃うようになり、巻き上げた任意の peer のサブツリーでインストール直後の `pnpm dedupe --check` が通り、提供元が上がった任意の peer の古いロック済みバージョンを捨てるようになった。ワークスペースの無関係な編集で直接依存のロック済みバージョンが動く v12 の後退と、パッチ済み peer が循環にあると毎回解決し直す問題（v11.28.3 のリリースノートにも記載）も直った。v12 では、任意の依存の下で解決できない依存があると npm と同じくその任意の依存をサブツリーごと除外する。12.8.0 以降キャッシュ不可のメタデータを毎回丸ごと再取得していた問題は、`Cache-Control: no-cache` 付きの再検証で直った（v11・v12）。信頼性の格下げチェックは過去のバージョンの公開者・provenance だけを読んでキャッシュする。未リリースの修正として、`auto-install-peers` で巻き上げた必須の peer が提供元のバージョンに従う。未リリースの新機能として、`lockfile.includeResolutionSettings: true` で解決に関わる設定（`autoDedupe`・`dedupeInjectedDeps`・`dedupePeerDependents`・`linkWorkspacePackages`）を `pnpm-lock.yaml` に記録できるようになった（v12.10.0 のリリースノートにも記載）。Yarn の `patch:` のような未対応のプロトコルの指定は `ERR_PNPM_UNSUPPORTED_PROTOCOL` で失敗し、v12 では `pnpm install --fix-lockfile` がスナップショットの無い参照を直せるようになり、`name@version` のキーの `custom:*` 解決も lockfile の検証で受け付ける（いずれも未リリース）。未リリースの修正として、config 依存の解決にも `minimumReleaseAge` を適用し（違反は `ERR_PNPM_BAD_CONFIG_DEP`）、`catalogPrune` が lockfile に記録済みのカタログエントリを残し、`peerDependenciesMeta` だけに宣言された任意の peer にも削除の override（`"debug>supports-color": "-"` など）が効き、任意の peer の巻き上げでルートの `workspace:` 指定を保つようになった（いずれも v11・v12）。v12.12.0 で `addMissingPeerTypes` 設定が入った（peer `X` ごとに `@types/X` を任意の peer にし、グローバル仮想ストアでも TypeScript が peer の型を見つけられる。既定は無効で lockfile に記録）。`@pnpm/napi` の install オプションにもある（未リリース）。同じく v12.12.0 で、config 依存が `pnpm add --config` で通常の依存と同じ規則で範囲を保存し、`pnpm update`（`--latest`）で更新できるようになった。未リリースの変更として、v12 の lockfile はスコープのレジストリのパッケージの tarball URL をそのレジストリと比べて省き（v12.13.0 に記載）、git の ref の照会はインストールごとに 1 回になり、lockfile を再利用するサブツリーはメタデータのウォームアップから外れた。依存かつ任意の peer でもある依存（`ajv-formats` の `ajv` など）は浅い出現で決まる（v11・v12）。依存が peer に変わる場合は lockfile で固定した子を解決し直し、2 回に分けたインストールでも同じ lockfile になる。参照されないカタログの項目があっても lockfile を再利用する（いずれも v12.14.0）。2026-10-19 の回では、pnpm v12 の git の resolver が gist を認識するようになった（未リリース）。未リリースの修正として、lockfile を再利用するときの peer の判断を `BoundProviders` に集め、ハッシュした peer の接尾辞からも束縛された提供元を復元し、後の importer の直接依存の変更がワークスペース全体で見えるようになった（pnpm/tasks#143・#160）。2026-10-26 の回では（未リリース）、`autoDedupe` がオフ（既定）なら各プロジェクトの依存をそのプロジェクトの範囲で解決するようになり（他のプロジェクトの指定子は種にしない。`pnpm dedupe` はまたいで優先）、v12 のバージョンなしの `pnpm add <pkg>` が `tag` の設定の dist-tag で解決してバージョンを lock する。2026-10-28 の回では、スコープを別のレジストリに向けたときにレジストリを持たない lockfile のキーを解決し直すようになり（`registryRoutes` を記録）、名前付きレジストリの指定の optional 依存を lockfile にあれば飛ばさない。v11 の lockfile の確認はローカルの依存のたどりを importer ごとに使い回して速くなった。

## 主な API・オプション

- `autoDedupe` — `pnpm-workspace.yaml` またはコマンドラインの `--auto-dedupe`/`--no-auto-dedupe` で有効化。frozen install はロックファイルを変えない
- カタログエントリの `file:`/`link:` プロトコル — 相対パスは `pnpm-workspace.yaml` の位置を基準に解決
- `pnpm update --peer` / `pnpm up --peer --latest` / `pnpm up --peer <name>` — peerDependencies の更新（オプトイン）
- `catalog:` 指定 — 重複排除の優先バージョン計算で、カタログが固定するバージョンに直接指定と同じ重みを与える
- `minimumReleaseAge` の dist-tag フォールバック — 同じメジャーの安定版 → 同じメジャーのプレリリース（対象より前）→ 下位メジャー（`latest` のみ）の順
- `autoDedupe` とダウングレード — マニフェストが名指しする完全一致のバージョンが直接依存の重みを保ち、他のプロジェクトもそのバージョンに揃う（v12、未リリース）
- 任意の依存のサブツリー（v12）— 下のどこかで解決に失敗したら、最も近い任意の依存をサブツリーごと除外。通常の依存だけでそれを必要とするなら元のエラーで失敗
- `lockfile.includeResolutionSettings` — `true` で `pnpm-lock.yaml` の `settings` に解決に関わる設定を記録。記録と異なる値なら lockfile は古いとみなされ、`--frozen-lockfile` は `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`（v12、未リリース）
- `ERR_PNPM_UNSUPPORTED_PROTOCOL` — 未対応のプロトコル（Yarn の `patch:` など）の指定。ヒントは `overrides` を案内（v11・v12、未リリース）
- `addMissingPeerTypes` — 依存の peer `X` ごとに `@types/X` を任意の peer にする。有効なときだけ lockfile の `settings.addMissingPeerTypes` に記録し、切り替えると解決し直す。`@pnpm/napi` の install オプションにもある（v12.12.0）
- config 依存の保存・更新 — `pnpm add --config <pkg>@latest` は解決し直して `savePrefix`/`saveExact` に従う範囲を保存。`pnpm update [<name>]`・`--latest` で更新（`--interactive`・`--filter` などでは対象外）（v12.12.0）
