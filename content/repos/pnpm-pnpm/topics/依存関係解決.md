## 概要

依存関係の解決・カタログ・更新まわり。解決中に見つかった互換なバージョンをまとめる自動重複排除（`autoDedupe`）、カタログエントリでの `file:`/`link:` プロトコル対応、`pnpm update --peer` による peerDependencies の更新に対応している。重複排除では `catalog:` が固定するバージョンも直接指定と同じく優先されるようになった。lockfile の再利用判定はプレリリースと安定版の範囲を厳密に区別し、npm エイリアスも保持する。`minimumReleaseAge` まわりでは、レジストリから消えたバージョンを `pnpm update <pkg>` で置き換えられるようになり、時間ベースの解決で成熟したバージョンが優先されるよう修正中（未リリース）。`pnpm dedupe` の収束性の修正が続き、ハッシュ化された peer 接尾辞の読み戻し（v12.8.1）と、変種の統合後のキーの付け直し（未リリース）で `pnpm dedupe --check` が通るようになった。`minimumReleaseAge` で `latest` が隠れたときは、同じメジャーのプレリリースを下位メジャーの安定版より優先する（未リリース）。

## 主な API・オプション

- `autoDedupe` — `pnpm-workspace.yaml` またはコマンドラインの `--auto-dedupe`/`--no-auto-dedupe` で有効化。frozen install はロックファイルを変えない
- カタログエントリの `file:`/`link:` プロトコル — 相対パスは `pnpm-workspace.yaml` の位置を基準に解決
- `pnpm update --peer` / `pnpm up --peer --latest` / `pnpm up --peer <name>` — peerDependencies の更新（オプトイン）
- `catalog:` 指定 — 重複排除の優先バージョン計算で、カタログが固定するバージョンに直接指定と同じ重みを与える
- `minimumReleaseAge` の dist-tag フォールバック — 同じメジャーの安定版 → 同じメジャーのプレリリース（対象より前）→ 下位メジャー（`latest` のみ）の順
