## 概要

pnpm が管理する Node.js ランタイムやエンジン（固定された pnpm 自体を含む）のインストール・選択まわり。グローバル `node` シムが `.nvmrc`・`.node-version` を読めるようになり（v12.7.0）、ピン留めされた pnpm/ランタイムのインストールでロック競合時は短い待機のあとプロセス専用のプライベートコピーで実行する。`runtime:` の範囲に `||` を含む場合に npm パッケージ `node` と誤解決される問題が直り、`pnpm-workspace.yaml` の無い単一プロジェクトでも固定された pnpm の `minimumReleaseAge` 承認が記録されるようになった。arm64 musl Linux では pnpm 11 のスタンドアロン実行ファイルの配布をやめる変更が入った（未リリース）。固定された pnpm が対応するオプション（`--auto-dedupe` など）をグローバルの pnpm が切り替え前に拒否しなくなり（v12.8.2・v11.28.3）、v12.8.1 の Linux ppc64le バイナリが起動時にクラッシュする問題は v12.8.2 で直った。未リリースの修正として、pnpm を固定した git 依存の準備でも `pmOnFail` が効くようになり（NixOS 向け）、`devEngines.packageManager` の範囲指定で実行中の pnpm を記録するときも `minimumReleaseAge` と `trustPolicy` を守るようになった。pnpm 本体の配布と更新では、Windows の `pnpm.cmd` がバッチの文脈を終えてから `pnpm.exe` を起動し、Ctrl+C 後の `Terminate batch job (Y/N)?` が出なくなった。Homebrew で入れた pnpm の `pnpm self-update` は `ERR_PNPM_CANT_SELF_UPDATE_IN_HOMEBREW` で止まり `brew upgrade` を案内する。v12.9.1 で `pnpm` の実行ファイルが約 10% 小さくなった（macOS arm64 で 45.1 MB → 40.3 MB）。未リリースの修正として、12.8 以前の `pnpm.cmd` を置き換える `pnpm self-update` が二重に実行される問題が直った。

## 主な API・オプション

- グローバル `node` シムのバージョン解決順（同一ディレクトリ）: `package.json` の `devEngines.runtime`/`engines.runtime` → `.node-version` → `.nvmrc`。ディレクトリをまたぐ場合は最も近い宣言が勝つ
- `.nvmrc` / `.node-version` — コメント・`v` プレフィックス・nvm エイリアスに対応
- ピン留めされたエンジン/ランタイムのインストール — 共有スロットのロックを5秒待ち、取れない場合はストアの `tmp/private` 配下に専用コピーを作って実行
- `devEngines.runtime` の範囲 — `^22.18.0 || ^24.0.0` のような `runtime:` の和集合も npm リゾルバーに渡らない。影響を受けた lockfile は `pnpm install --fix-lockfile` で解決し直せる
- `pmOnFail` / `--pm-on-fail` — `download` 以外なら git 依存の準備で pnpm をダウンロードせず実行中の pnpm を使う（v12、未リリース）
- `devEngines.packageManager`（範囲指定）— 実行中の pnpm が `minimumReleaseAge` より新しければ、範囲内で成熟した最新版を `packageManagerDependencies` に記録。v12 は範囲を満たす記録済みバージョンを上書きしない（未リリース）
- `pnpm self-update` — Homebrew の keg（`Cellar/pnpm/` や `Cellar/pnpm@<major>/`）から実行中なら `ERR_PNPM_CANT_SELF_UPDATE_IN_HOMEBREW`（v11・v12）
- `pnpm.cmd`（Windows）— `pnpm`・`@pnpm/exe` のシムはバッチの文脈を終えてから `pnpm.exe` を起動
