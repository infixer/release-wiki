## 概要

パッケージを保存するストア（content-addressable store）と、その索引・掃除・ロック・プロジェクト登録まわり。`pnpm store prune` は期限切れの `pnpm dlx` キャッシュ（`dlxCacheMaxAge`、既定 1 日）をストアの削除より先に消すようになり（v11・v12、未リリース）、pnpm 11 が書いた索引の行（msgpackr の `undefined`）でも失敗しなくなった（v12、未リリース）。pnpm v12 は Unix でストア操作などのユーザーごとのロックを、`$XDG_RUNTIME_DIR` があればそこに置く（v12.8.2）。TypeScript 版の読み取り専用のストア索引は SQLite の WAL のロックに参加し、並行書き込み中に「database disk image is malformed」にならない（v11.28.3 のリリースノートに記載、`@pnpm/store.index` はメジャーリリース）。未リリースの変更として、pnpm v12 もすべてのインストールを `<store>/projects/` に登録するようになり、明示的な `virtualStoreDir` のグローバル仮想ストアでプロジェクトの状態が分離され、config dependencies がオフラインでストアを再利用できるようになった。すべてのインストールを `<store>/projects/` に登録する変更は v12.9.0 でリリースされた。Android（Termux）ではファイルロックに `flock` を使い、`ERR_PNPM_STORE_DIR_ACQUIRE_OPERATION_LOCK` で失敗しなくなった。pnpm 11 はプロジェクトのディレクトリに書き込めなくてもホームのストアを使う。未リリースの修正として、v12 の `pnpm store prune` も行の削除後に `index.db` を `VACUUM` し、WAL をチェックポイントして索引のファイルを縮めるようになった（v11 と同じ）。

## 主な API・オプション

- `pnpm store prune` — 期限切れの dlx キャッシュを先に削除してからストアを掃除（期限内のエントリは残す）
- `dlxCacheMaxAge` — dlx キャッシュの有効期間（既定 1 日）
- `XDG_RUNTIME_DIR` — 現在のユーザーが所有する絶対パスのディレクトリなら、ストア操作・ディレクトリ・verify-deps のロックをここに置く（v12、Unix）。無ければ `/tmp`（Android は `HOME/.cache`）、Windows は `LocalAppData`
- `<store>/projects/<short-hash>` — インストールした各プロジェクトへのリンク。v12 も既定で毎回登録（グローバル仮想ストアなしの `--frozen-store`・`--lockfile-only`・`--dry-run` は除く、未リリース）
- `ReadOnlyStoreIndex` / `ImmutableStoreIndex`（`@pnpm/store.index`）— 前者は並行書き込みと協調、凍結ストアには後者を使う（メジャーリリース）
- `virtualStoreDir` / `--virtual-store-dir`（グローバル仮想ストア時）— ストアのルートを指す。プロジェクトの状態は常に `<modulesDir>/.pnpm`（v12、未リリース）
- 既定のストアの決定（v11）— プロジェクトのディレクトリに書き込めない（`EACCES`・`EPERM`・`EROFS`）ときはホームのストアを使う
