## 概要

パッケージを保存するストア（content-addressable store）と、その索引・掃除・ロック・プロジェクト登録まわり。`pnpm store prune` は期限切れの `pnpm dlx` キャッシュ（`dlxCacheMaxAge`、既定 1 日）をストアの削除より先に消すようになり（v11・v12、未リリース）、pnpm 11 が書いた索引の行（msgpackr の `undefined`）でも失敗しなくなった（v12、未リリース）。pnpm v12 は Unix でストア操作などのユーザーごとのロックを、`$XDG_RUNTIME_DIR` があればそこに置く（v12.8.2）。TypeScript 版の読み取り専用のストア索引は SQLite の WAL のロックに参加し、並行書き込み中に「database disk image is malformed」にならない（v11.28.3 のリリースノートに記載、`@pnpm/store.index` はメジャーリリース）。未リリースの変更として、pnpm v12 もすべてのインストールを `<store>/projects/` に登録するようになり、明示的な `virtualStoreDir` のグローバル仮想ストアでプロジェクトの状態が分離され、config dependencies がオフラインでストアを再利用できるようになった。すべてのインストールを `<store>/projects/` に登録する変更は v12.9.0 でリリースされた。Android（Termux）ではファイルロックに `flock` を使い、`ERR_PNPM_STORE_DIR_ACQUIRE_OPERATION_LOCK` で失敗しなくなった。pnpm 11 はプロジェクトのディレクトリに書き込めなくてもホームのストアを使う。未リリースの修正として、v12 の `pnpm store prune` も行の削除後に `index.db` を `VACUUM` し、WAL をチェックポイントして索引のファイルを縮めるようになった（v11 と同じ）。v12.13.0 で `storeIndexFormat: files` が加わり、複数のマシンが同時に使うネットワークファイルシステム上のストアでは、索引を SQLite の `index.db` ではなくパッケージごとのファイル（`<store>/v11/index/`）で持てる。未リリースの改善として、ファイル単位の索引の読み取りが共有ハンドルのロックの外で行われ、`enableModulesDir: false` のストアだけのインストールは解決と並行してストアを検証するようになった。何も追加しないインストールではストアのルートの更新日時を元に戻し、CI のキャッシュが変わっていないストアを再アップロードしない（v11・v12）。macOS で owner が読めないストアのディレクトリに group の権限を付ける処理が `EISDIR` で失敗していたのを直した（v11、未リリース）。2026-10-26 の回では、v12 の `pnpm store prune` がレジストリのメタデータのキャッシュ（`<cacheDir>/metadata*`・`<cacheDir>/vN/metadata*`）も消すようになった（ストアなどを含むディレクトリは残し、開いたディレクトリの記述子から消してシンボリックリンクの差し替えを防ぐ。未リリース）。2026-10-28 の回では、`pnpm store prune` がハードリンクの数だけでなく各プロジェクトのインストール済みの lockfile を見て、コピー・clone・パッチ・ビルドしたパッケージを残すようになり（`packageConfigs` の `modulesDir` も見る）、v11 では `cacheDir` の中のほかのストアやグローバルのデータを残す（後者は未リリース）。並行するインストールでストアの索引の行が失われる競合も直った。2026-11-04 の回では（未リリース）、`pnpm store add` がダウンロード済みの tarball を受け付け、`pnpm install --offline --frozen-lockfile` で入れられるようにストアを準備するようになった（flatpak-builder や Nix 向け）。v12 の既定のストアの場所はワークスペースのルートから決めるようになった。2026-11-06 の回では、グローバル仮想ストアのスロットのパスから名前付きレジストリの名前を除き、Windows での失敗を直した（v12.18.0）。`supportedArchitectures` があると、一覧のプラットフォームのバリアントや `any` のアーカイブをリンクせずにストアに取得する（v12.18.0）。未リリースでは、すべてのインストールと `pnpm fetch` がほかのプラットフォームのアーカイブとその依存もストアに入れる。2026-11-09 の回では（未リリース）、`pnpm store add` がローカルの tarball を 1 回の読み込みで `networkConcurrency` まで並行に取り込み、ディレクトリの引数も受け付けるようになった。2026-11-11 の回では、グローバル仮想ストアのビルドがスロットのロックを使わない設計に戻り（ビルドするスロットはハッシュを分け、ステージングのディレクトリでビルド）、macOS のディレクトリの clone のキャッシュが `dir-clone-cache` に分かれて `pnpm store prune` で消えるようになった。2026-11-13 の回では（未リリース）、`pnpm store add` が lockfile の項目の `integrity` に一致する tarball を `<integrity>\t<pkg_id>` のキーでも登録し、tarball の URL や git の依存でもオフラインの frozen install ができるようになった。

## 主な API・オプション

- `pnpm store prune` — 期限切れの dlx キャッシュを先に削除してからストアを掃除（期限内のエントリは残す）
- `dlxCacheMaxAge` — dlx キャッシュの有効期間（既定 1 日）
- `XDG_RUNTIME_DIR` — 現在のユーザーが所有する絶対パスのディレクトリなら、ストア操作・ディレクトリ・verify-deps のロックをここに置く（v12、Unix）。無ければ `/tmp`（Android は `HOME/.cache`）、Windows は `LocalAppData`
- `<store>/projects/<short-hash>` — インストールした各プロジェクトへのリンク。v12 も既定で毎回登録（グローバル仮想ストアなしの `--frozen-store`・`--lockfile-only`・`--dry-run` は除く、未リリース）
- `ReadOnlyStoreIndex` / `ImmutableStoreIndex`（`@pnpm/store.index`）— 前者は並行書き込みと協調、凍結ストアには後者を使う（メジャーリリース）
- `virtualStoreDir` / `--virtual-store-dir`（グローバル仮想ストア時）— ストアのルートを指す。プロジェクトの状態は常に `<modulesDir>/.pnpm`（v12、未リリース）
- 既定のストアの決定（v11）— プロジェクトのディレクトリに書き込めない（`EACCES`・`EPERM`・`EROFS`）ときはホームのストアを使う
- `storeIndexFormat` — `files` でパッケージ索引をパッケージごとのファイル（`<store>/v11/index/`）で持つ。ネットワークファイルシステムを複数のマシンで共有するストア向け（v12.13.0）
- `pnpm store add ./tarballs/*.tgz` — ダウンロード済みの tarball を取り込み、sha512・sha1・tar のハッシュの別名で引けるようにする（未リリース）
- `dir-clone-cache` — macOS のローカルのインストールのディレクトリの clone を置く使い捨てのキャッシュ（ストア内、`storeDir` に従う）。`pnpm store prune` が消す
