## 概要

モノレポ（ワークスペース）固有の挙動まわり。`--filter "[<since>]"` は `<since>` とのマージベースと比較するようになり、分岐後に `<since>` 側で変わったプロジェクトが選ばれなくなった。lockfile を共有しない設定（`shared-workspace-lockfile: false`）では injected なワークスペース依存の変更が反映されるようになり、未リリースの変更でこのモードのインストールが高速化された。frozen install はディレクトリはあるのにマニフェストが無いワークスペースプロジェクトを検出して失敗する。`pnpm-workspace.yaml` への除外エントリの書き込みは既存の引用符スタイルに合わせる。injected なワークスペース依存（`injectWorkspacePackages`）まわりでは、peer をワークスペースから提供すると frozen install が lockfile を拒否する問題が v12.8.1 で直り、毎回フルインストールになっていた問題も v12.8.2 で直った。未リリースの修正として、injected なパッケージの任意の peer を含む lockfile を frozen install が受け付けるようになった（v12）。v11 ではプロジェクトの共通の祖先が `/` や `C:\` のとき何もインストールされない問題が v11.28.2 で直り、依存がすべてワークスペースのリンクのプロジェクトで `dependenciesMeta` が lockfile に記録されない問題も修正された（未リリース）。frozen install はディレクトリごと無いワークスペースプロジェクトを再びスキップし、Docker ビルドでプロジェクトを除外できるようになった（未リリース）。v12.9.0・v11.28.4 で、frozen install がディレクトリごと無いワークスペースプロジェクトを再びスキップし、`nodeLinker: hoisted` のフィルタ付きインストールが他のプロジェクトのパッケージを保つようになった。v12.9.1 では injected なパッケージの catalog の peer を frozen install が受け付け、`[<since>]` セレクタが git 2.24〜2.27 でも動き（2.24 未満はエラー）、非 ASCII のディレクトリ名のプロジェクトの変更も正しく検出する。未リリースの修正として、v11 でルート以外のパッケージの `resolutions` を警告するとき、`pnpm-workspace.yaml` の `overrides` を案内するようになった。未リリースの修正として、`sharedWorkspaceLockfile: false` の injected なコピーには、依存元と同じ回にインストールしてもパッケージのファイル（`files`・`.npmignore`）だけが同期されるようになった（v11・v12）。v12.11.2 で、pnpmfile の `updateConfig` フックが設定した `filter`・`filterProd` を v12 も適用するようになった（コマンドラインの `--filter` が優先）。未リリースの修正として、Node-API で injected なプロジェクトを `dependencyManifest` 付きでメモリから渡しても lockfile を再利用する。`--filter` 付きのインストールは、ディスクに無いプロジェクト（sparse checkout）の lockfile の記録を残す（v11・v12）。v11 の `pnpm dedupe` は自動で入れた peer があってもワークスペースのパッケージの hoist を保つ（v11.28.6）。2026-10-19 の回では、フィルター付きのインストールの後に選んだプロジェクトを wanted lockfile と照らし、未インストールの変更を見逃さないようになった（未リリース）。未リリースの修正として、frozen install がローカルのディレクトリ依存を推移的に確かめ、tarball の URL や git のコミットの変更を拒否し、別名付きの `file:` の子を受け付ける。フィルター付きのインストールは、最初のインストールでもすべてのプロジェクトを hoist し、hoisted リンカーでは選ばないプロジェクトの依存グループを保つ。`sharedWorkspaceLockfile: false` でもパッチが使える。2026-10-26 の回では（v11・v12、未リリース）、injected にしたワークスペースのパッケージで、相対パスの `workspace:../lib` の `catalog:` 依存を解決し、依存の `workspace:` のパスをそのパッケージのディレクトリから解決するようになった。2026-10-28 の回では、v12 の `legacyDirFiltering` のディレクトリの絞り込みがそのディレクトリ自身も含めるようになり、絞り込んだインストールは配置の設定が変わっていれば `node_modules` を作り直さずに失敗する。`bin` を変えたワークスペースのパッケージの古いシムを消し、lockfile を分けたワークスペースでも名前を変えたコマンドをリンクし直す。

## 主な API・オプション

- `--filter "[<since>]"` — `git merge-base <since> HEAD` と作業ツリーを比較（マージベースが無ければ従来どおり `<since>` と比較）
- `shared-workspace-lockfile: false` / `sharedWorkspaceLockfile: false` — injected 依存の変更で再解決。グローバル仮想ストアでは各プロジェクトが自分の `.pnpm` を持つ
- `pnpm install --frozen-lockfile` — lockfile の importer のディレクトリはあるがマニフェストが無いと `ERR_PNPM_OUTDATED_LOCKFILE`（ワークスペース全体を対象にしたときのみ）。ディレクトリごと無いプロジェクトはスキップ（未リリース）
- `minimumReleaseAgeExclude` / `trustPolicyExclude` の書き込み — ダブルクォートが多数派ならダブルクォートで書く
- `injectWorkspacePackages: true` / `dependenciesMeta.*.injected` — 共有 lockfile なら再インストールの高速経路を使う（未リリース）
- `--filter "[<since>]"` — git 2.24 以上が必要。`--no-relative` は 2.28 以上のときだけ渡す。変更ファイルは `git diff --name-only -z` で読む（v12.9.1）
- `updateConfig` フックの `filter`/`filterProd` — 設定のセレクタを置き換える。コマンドラインの `--filter`/`--filter-prod` が優先。フックの filter で再帰モードにはならない（v12.11.2）
