## 概要

モノレポ（ワークスペース）固有の挙動まわり。`--filter "[<since>]"` は `<since>` とのマージベースと比較するようになり、分岐後に `<since>` 側で変わったプロジェクトが選ばれなくなった。lockfile を共有しない設定（`shared-workspace-lockfile: false`）では injected なワークスペース依存の変更が反映されるようになり、未リリースの変更でこのモードのインストールが高速化された。frozen install はディレクトリはあるのにマニフェストが無いワークスペースプロジェクトを検出して失敗する。`pnpm-workspace.yaml` への除外エントリの書き込みは既存の引用符スタイルに合わせる。injected なワークスペース依存（`injectWorkspacePackages`）まわりでは、peer をワークスペースから提供すると frozen install が lockfile を拒否する問題が v12.8.1 で直り、毎回フルインストールになっていた問題も v12.8.2 で直った。未リリースの修正として、injected なパッケージの任意の peer を含む lockfile を frozen install が受け付けるようになった（v12）。v11 ではプロジェクトの共通の祖先が `/` や `C:\` のとき何もインストールされない問題が v11.28.2 で直り、依存がすべてワークスペースのリンクのプロジェクトで `dependenciesMeta` が lockfile に記録されない問題も修正された（未リリース）。frozen install はディレクトリごと無いワークスペースプロジェクトを再びスキップし、Docker ビルドでプロジェクトを除外できるようになった（未リリース）。

## 主な API・オプション

- `--filter "[<since>]"` — `git merge-base <since> HEAD` と作業ツリーを比較（マージベースが無ければ従来どおり `<since>` と比較）
- `shared-workspace-lockfile: false` / `sharedWorkspaceLockfile: false` — injected 依存の変更で再解決。グローバル仮想ストアでは各プロジェクトが自分の `.pnpm` を持つ
- `pnpm install --frozen-lockfile` — lockfile の importer のディレクトリはあるがマニフェストが無いと `ERR_PNPM_OUTDATED_LOCKFILE`（ワークスペース全体を対象にしたときのみ）。ディレクトリごと無いプロジェクトはスキップ（未リリース）
- `minimumReleaseAgeExclude` / `trustPolicyExclude` の書き込み — ダブルクォートが多数派ならダブルクォートで書く
- `injectWorkspacePackages: true` / `dependenciesMeta.*.injected` — 共有 lockfile なら再インストールの高速経路を使う（未リリース）
