## 概要

`pnpm-workspace.yaml` のタスクに、マシン全体で同時実行数を制限する「並行実行グループ」を追加する一連の変更。複数の worktree で重いタスク（Rust ビルドやテストなど）を同時に走らせてメモリ不足になる問題への対応で、枠はアドバイザリなファイルロックで管理される。待機タスクは当初 `try_lock` のポーリングだったが、到着順・優先度順にチケットで枠を取る方式に改善された。スクリプト実行まわりでは、`--filter`/`-r` 付きのショートハンド（`pnpm --filter api vitest run` など）でもスクリプトが無ければ `exec` にフォールバックするようになり、Windows で Ctrl+C 後にバッチシム経由のスクリプトが残って端末が戻らない問題が修正された（未リリース）。

## 主な API・オプション

- `tasks.<name>.concurrencyGroup` — タスクが属するグループ名
- `concurrencyGroups.<group>: <limit>` — グループごとの同時実行数上限
- `<name>.priority` — 待機時に優先して枠を得るための優先度
- `pnpm --filter <project> <command>` / `pnpm -r <command>` — 選択したどのプロジェクトにもスクリプトが無ければ再帰的な `exec` を実行（`--if-present`・`--dry-run`・明示的な `pnpm run` では行わない）
- `pnpm tasks status` — 各グループの実行中/待機中タスクと待ち順・待ち時間を表示（`tasks` という名前のスクリプトがある場合は `pnpm pm tasks status` を使う）
