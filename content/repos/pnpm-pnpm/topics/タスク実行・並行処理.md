## 概要

`pnpm-workspace.yaml` のタスクに、マシン全体で同時実行数を制限する「並行実行グループ」を追加する一連の変更。複数の worktree で重いタスク（Rust ビルドやテストなど）を同時に走らせてメモリ不足になる問題への対応で、枠はアドバイザリなファイルロックで管理される。待機タスクは当初 `try_lock` のポーリングだったが、到着順・優先度順にチケットで枠を取る方式に改善された。スクリプト実行まわりでは、`--filter`/`-r` 付きのショートハンド（`pnpm --filter api vitest run` など）でもスクリプトが無ければ `exec` にフォールバックするようになり、Windows で Ctrl+C 後にバッチシム経由のスクリプトが残って端末が戻らない問題が修正された（未リリース）。実行前の依存確認（`verifyDepsBeforeRun`）では、インストールするものが無いプロジェクトでインストールを省き、フィルタ付きインストール後に lockfile の更新時刻だけで再インストールしないようになった（v12.8.1・v11.28.2）。`autoDedupe` を有効にした CI で `pnpm run` のたびにインストールが走る問題は v12.8.2 で直った。未リリースの修正として、macOS・Linux で `Path` が `PATH` として渡る問題、PID 1 の入れ子の `pnpm run` が `SIGTERM` で止まらない問題が直り、`childConcurrency` の既定値が 5 になった。さらに v12 で `pnpm -s <script>` が受け付けられ、スクリプト名の後ろに `--filter` を書いてスクリプトが見つからないときは置き場所のヒントを出すようになり、グローバル仮想ストアの ESM ローダーが入っていても `ts-node index.ts` のような CommonJS フック経由のエントリポイントを実行できるようになった（いずれも未リリース）。未リリースの修正として、`verifyDepsBeforeRun` が起動する子のインストールに親コマンドの `--config.*` が渡るようになり（v11・v12）、Ctrl+C で止めたスクリプトに `[ELIFECYCLE]` の行を出さなくなった。未リリースの修正として、v12 の `pnpm run "/<regex>/"` が ECMAScript の正規表現エンジンでコンパイルされ、先読みや後方参照を使えるようになった（v11 と同じ）。未リリースの新機能として、v12 の `pnpm -r run`・`--stream`・`--parallel` などの出力で、pnpm の出力が色付きなら子に `FORCE_COLOR=1` を渡してスクリプトの色を保ち、カーソル移動などの制御文字を取り除くようになった。bail 時の `[ELIFECYCLE]` の行が他のプロジェクトの表示に紛れ込む問題も直った。v12.11.0 で、再帰実行の出力でスクリプトの色を保つ変更がリリースされた。v12.11.2 では `--workspace-concurrency=Infinity` が上限なしとして受け付けられる。v12.12.0 では `remoteCache` 設定で、`pnpm pipeline` のタスク結果と依存のビルドを pnpr か Turborepo Remote Cache API のサーバー（Vercel Remote Cache など）で共有できるようになった（署名付きアーティファクトを `trustedKeys` で検証）。v11 の未リリースのサニタイザーで遅くなった色付きの出力の速度も戻った（未リリース）。未リリースの修正として、`packages` がルートだけのワークスペースでも `pnpm pipeline` がルートを選ぶようになった。`pnpm run` の `[ELIFECYCLE]` の行は silent では出ず、ndjson ではエラーの記録になる。Windows では切り離された孫プロセスが残っても `pnpm exec`/`run` が戻る。`pnpm pipeline --dry-run` は選択が空でもレポートを書かない（いずれも未リリース）。2026-10-19 の回では、`verifyDepsBeforeRun` がパッチの中身のハッシュで判断し、単一プロジェクトの確認を毎回やり直さなくなった。再帰の `pnpm run` を Ctrl+C したときはスクリプトの状態で終わる（未リリース）。`verifyDepsBeforeRun` は `overrides`・`packageExtensions`・`readPackage` フックを当ててから manifest を比べる（未リリース）。2026-10-26 の回では、v12 の `pnpm -r run` が `requiredScripts` を守り、選んだプロジェクトに必須のスクリプトが無ければ始める前に `ERR_PNPM_RECURSIVE_RUN_NO_SCRIPT` で失敗するようになった（未リリース）。2026-10-28 の回では、macOS で並列実行中に pnpm を kill すると一部のスクリプトが残る問題（グループの watchdog のパイプの漏れ）が直り、v11 の既定の `workspaceConcurrency` がコンテナの CPU の上限を守るようになった。

## 主な API・オプション

- `tasks.<name>.concurrencyGroup` — タスクが属するグループ名
- `concurrencyGroups.<group>: <limit>` — グループごとの同時実行数上限
- `<name>.priority` — 待機時に優先して枠を得るための優先度
- `pnpm --filter <project> <command>` / `pnpm -r <command>` — 選択したどのプロジェクトにもスクリプトが無ければ再帰的な `exec` を実行（`--if-present`・`--dry-run`・明示的な `pnpm run` では行わない）
- `pnpm tasks status` — 各グループの実行中/待機中タスクと待ち順・待ち時間を表示（`tasks` という名前のスクリプトがある場合は `pnpm pm tasks status` を使う）
- `verifyDepsBeforeRun` — フィルタ付きインストール後は実際に配置したものと lockfile を比較
- `childConcurrency` — 既定値 5（v12 も pnpm 11 に合わせた、未リリース）
- `pnpm -s <script>` — トップレベルの `-s`/`--sequential` を `run` とスクリプトのフォールバックで受け付ける（v12、未リリース）
- `Missing script` のヒント — スクリプト名の後ろに `--filter`/`-F`/`--filter-prod` があれば `pnpm --filter <selector> run <script>` を案内（v12、未リリース）
- `verifyDepsBeforeRun` — 起動する `pnpm install` に親の `--config.<key>=<value>` を引き継ぐ。`prompt` の確認表示には含めない（未リリース）
- `pnpm run "/<regex>/"` — ECMAScript の構文（先読み・後方参照）を受け付け、UTF-16 のコード単位で照合（v12、未リリース）
- `remoteCache` — リモートキャッシュのサーバーと署名鍵。`pnpm pipeline` のタスク結果（`workspace-task` アーティファクト）と依存のビルドに使う。`pnpm pipeline --report` は `remoteCache.org` に実行を記録（v12.12.0）
- `--workspace-concurrency=Infinity` — 上限なし（v12.11.2）
