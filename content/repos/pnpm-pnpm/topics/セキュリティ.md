## 概要

bin シムやランチャー、設定ファイルを悪用されないようにする修正。Nix では `command -p` が呼び出し元の `PATH` にフォールバックするため、依存パッケージの `sed` などの名前の bin が POSIX シムや `pnpm`/`pn`/`pnpx`/`pnx` ランチャーを乗っ取れたが、`node_modules` と相対・空のエントリを除いた `PATH` でヘルパーを探すようになった。v12.7.0・v11.28.0 のリリースノートでは、このほか `pnpm-workspace.yaml` の `userAgent` のプレースホルダーを展開しない修正、ワークスペース内の `storeDir`（v12.7.0）やカスタム `modulesDir`（v11.28.0）のパッケージのライフサイクルスクリプトに関する修正、シェル補完の修正（v11.28.0）がセキュリティ修正として挙げられている。その後、TypeScript 版 CLI が同梱する undici を脆弱性対応の 7.29.1 に上げ（v11.28.3）、プロジェクトの `pnpm-workspace.yaml` の `globalShims` を無視するようになった（未リリース）。v10.34.6 では `pnpm self-update` がプロジェクトの設定でダウンロード先や検証を変えられないようになり、`adm-zip` の脆弱性も修正された。v12.9.0・v11.28.4 では `pnpm login` がリダイレクト時にリクエスト本文の認証情報を別のオリジンへ送らなくなり、v11.28.4 では integrity の失敗のエラーに tarball の URL の認証情報などを表示しなくなった。`pnpm audit signatures` は署名鍵のリクエストのリダイレクトを 1 段ずつたどり、各段に合う TLS 設定と認証情報を使う（v12.9.1）。

## 主な API・オプション

- POSIX シム・ランチャー — `node_modules` と相対・空のエントリを除いた `PATH` でヘルパーを解決。再インストールで修正前のシムが置き換わる
- `pnpm-workspace.yaml` の `userAgent` — プレースホルダーを含むものは無視される（リリースノートより）
- `globalShims` — プロジェクトのマニフェストでは無視（pnpm home の `pnpm-workspace.yaml` は有効）
- `pnpm audit signatures` — 署名鍵（`/-/npm/v1/keys`）のリダイレクトを 1 段ずつたどる。https から始まったリクエストは平文 http の段に認証情報を送らず、応答は 1 MiB まで
