## 概要

bin シムやランチャー、設定ファイルを悪用されないようにする修正。Nix では `command -p` が呼び出し元の `PATH` にフォールバックするため、依存パッケージの `sed` などの名前の bin が POSIX シムや `pnpm`/`pn`/`pnpx`/`pnx` ランチャーを乗っ取れたが、`node_modules` と相対・空のエントリを除いた `PATH` でヘルパーを探すようになった。v12.7.0・v11.28.0 のリリースノートでは、このほか `pnpm-workspace.yaml` の `userAgent` のプレースホルダーを展開しない修正、ワークスペース内の `storeDir`（v12.7.0）やカスタム `modulesDir`（v11.28.0）のパッケージのライフサイクルスクリプトに関する修正、シェル補完の修正（v11.28.0）がセキュリティ修正として挙げられている。その後、TypeScript 版 CLI が同梱する undici を脆弱性対応の 7.29.1 に上げ（v11.28.3）、プロジェクトの `pnpm-workspace.yaml` の `globalShims` を無視するようになった（未リリース）。v10.34.6 では `pnpm self-update` がプロジェクトの設定でダウンロード先や検証を変えられないようになり、`adm-zip` の脆弱性も修正された。v12.9.0・v11.28.4 では `pnpm login` がリダイレクト時にリクエスト本文の認証情報を別のオリジンへ送らなくなり、v11.28.4 では integrity の失敗のエラーに tarball の URL の認証情報などを表示しなくなった。`pnpm audit signatures` は署名鍵のリクエストのリダイレクトを 1 段ずつたどり、各段に合う TLS 設定と認証情報を使う（v12.9.1）。v12.10.0・v11.28.5 では多くのセキュリティ修正が入った。v12 のグローバル仮想ストアでは、依存のマニフェストの `version` のパストラバーサルでストアの外に書き込めた問題（GHSA-jg5c-8mvg-5wph）が直った。config 依存のレジストリとの照合、lockfile の `variations` の中の解決の照合、`pnpm audit signatures` と lockfile の integrity の結び付け、64 MiB を超えるアーカイブのメタデータの拒否、git 依存のリポジトリ引数の検証、`#path:` のサブパスや bundled dependencies でのシンボリックリンク経由の外部ファイルの混入防止、PAX ヘッダーの検証なども加わった（PR はいずれも inbox では未リリース表記）。ビルドスクリプトの許可については、v12.11.0 で依存ごとの `permissions` 設定（`build` は `allowBuilds` より優先、[[repos/pnpm-pnpm/topics/エージェントスキル|エージェントスキル]] を参照）が入り、v12.12.0 で `allowBuilds` の拒否（`false`）が `dangerouslyAllowAllBuilds: true` より優先されるようになった（pnpm v11 からの挙動の変更）。未リリースの修正として、v12 の `pnpm audit`・`pnpm audit signatures` は `devEngines.runtime` の `runtime:` のエントリを対象外にした（v11 と同じ）。rustls を 0.23.46 に上げて RUSTSEC-2026-0346〜0348 に対応した（利用者から見える挙動は変わらない）。v11.28.6 では `pnpm publish` が `aud` の合わない `NPM_ID_TOKEN` を使わない。2026-10-19 の回では、別のパッケージを名乗るレジストリのメタデータを拒否するようになり、`maxTarballUnpackedSize` が pnpm v11 と zip にも適用され、`lockfile.integrityTarget: tar` で展開前の tar のハッシュを lockfile に固定できるようになった（いずれも未リリース）。pnpr は秘密情報の項目に解決されない `${VAR}` があれば起動時に失敗する（未リリース）。2026-10-26 の回では、`pnpm store prune` のメタデータの削除がシンボリックリンクの差し替えで別のディレクトリを消さないようにし、undici を 7.30.1 に上げ（GHSA-xjj6-f33q-929c など）、pnpr のメトリクスを既定で配らないようにした（いずれも未リリース）。v10.34.8 はスタンドアロン版に Node.js 24.22.1 を埋め込む（信頼を外した中間 CA の対策）。

## 主な API・オプション

- POSIX シム・ランチャー — `node_modules` と相対・空のエントリを除いた `PATH` でヘルパーを解決。再インストールで修正前のシムが置き換わる
- `pnpm-workspace.yaml` の `userAgent` — プレースホルダーを含むものは無視される（リリースノートより）
- `globalShims` — プロジェクトのマニフェストでは無視（pnpm home の `pnpm-workspace.yaml` は有効）
- `pnpm audit signatures` — 署名鍵（`/-/npm/v1/keys`）のリダイレクトを 1 段ずつたどる。https から始まったリクエストは平文 http の段に認証情報を送らず、応答は 1 MiB まで
- `enableGlobalVirtualStore` のスロットのパス — 空・`.`・`..`・`/`・`\` を含むバージョンを拒否し、ストア内に収まるか確かめる（v12、未リリース）
- config 依存 — npm レジストリから解決し、インストール・再リンクのときにレジストリと照合。`version+integrity` で固定した integrity を lockfile で置き換えられない（v12.10.0・v11.28.5 のリリースノートより）
- git 依存のリポジトリ — 空・`-` で始まる・NUL を含む値は `ERR_PNPM_INVALID_GIT_REPOSITORY`（v12 のコード）。`git clone` などに `--` を渡す（未リリース）
- `allowBuilds` の `false` と `dangerouslyAllowAllBuilds: true` — 拒否したパッケージ以外のビルドを許可。以前はフラグが拒否を無視した（v12.12.0、v11 は変わらない）
- `lockfile.integrityTarget: tar` — 展開前の tar のハッシュを固定（不一致の frozen install は `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`）（v12、未リリース）
