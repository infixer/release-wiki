## 概要

`pnpm install` による取得・配置（`node_modules` のレイアウト、フック、ネットワーク）まわり。複数階層の `modulesDir`（`www/modules` など）が各プロジェクトに正しく連結されるようになり、`nodeLinker: hoisted` で削除したパッケージのコマンドが `.bin` に残らなくなった。`engineStrict` の判定前に `readPackage` フックが適用されるようになり、レジストリが応答を止めたときはタイムアウトだと分かるエラーを出す。未リリースの新機能として、http/https の tarball 依存でレスポンスの `Cache-Control` に従い、不要なリクエストを省くようになった。v12.8.1 では 12.8.0 で `file:` ディレクトリ依存や injected パッケージのファイルが実行ビットを失っていた後退が直った。CA 証明書の無いシステムで `NODE_EXTRA_CA_CERTS` を設定しても同梱のルートに追加して使い、Nix のビルドでもシムのヘルパーが見つかるようになった（v12.8.2）。tarball の展開には `zlib-rs` を使う（未リリース）。未リリースの新機能として、`registries` のエントリごとに `networkConcurrency` で同時リクエスト数を絞れるようになり、`@pnpm/napi` の `readPackageHook` にチェックサムを渡して lockfile を再利用できるようになった。修正では、`link:` の直接依存のリンク先を要約に表示し（`hideLinkedPkgsDiff` も効く）、hoisted でカスタム fetcher のディレクトリを再インストール時に取り込み直し、v11.28.3 の frozen install がスキップした任意の依存に作業ディレクトリへのリンクを作る問題を直した（未リリース）。`registries` ごとの `networkConcurrency` は v12.9.0 でリリースされた。取得できずスキップした任意の依存は警告（`fetch_failure`）を出し、壊れたリンクを残さない（v12.9.1・v11.28.4）。v12 では `optimisticRepeatInstall: false` のとき、最新状態の再インストールでもプロジェクト自身の `prepare` などを実行する（v12.9.1）。未リリースの修正として、v12 は `"dependencies": {"is-positive": 42}` のような不正な依存の指定を `ERR_PNPM_PACKAGE_MANIFEST_INVALID_ATTRIBUTE` で拒否する。新しい実験的なインストール方式は [[repos/pnpm-pnpm/topics/loaded-リンカー|loaded リンカー]] を参照。2026-10-09 の回の未リリースの修正として、v12 の isolated リンカーは再インストールの近道を通らない場合でもビルド済み・パッチ済みのスロットを取り込み直さず、TLS を傍受するプロキシが `close_notify` なしで切断して終える本文を受け付け、CRLF のパッチファイルのヘッダーを解析できるようになった。v11 では Windows でワークスペースのリンクの掃除が `EPERM` で失敗しなくなった。新機能として `@pnpm/napi` の `rebuild` が `skipIfHasSideEffectsCache` を受け付ける。2026-10-12 の回では、`enableModulesDir: false`（FUSE などでストアから `node_modules` をマウントする用途）で再びストアにパッケージを取得するようになり（v12.11.1、lockfile から再利用したパッケージは v12.11.2）、共有チェックアウトで他のユーザーのシムを chmod して `ERR_PNPM_CMD_SHIM_CHMOD` で失敗する問題が直った（v12.11.1）。git 依存をビルドするツールを lockfile に記録する実験的な `lockBuildTools` は、入った後に取り消された。v12.13.0 に記載の修正として、macOS で pnpmfile を読むコマンドが不定期にハングしなくなり、`nodeLinker: hoisted` で削除した `link:` 依存のシンボリックリンクも消えるようになった（v11・v12）。未リリースの修正で、`pnpm install`・`pnpm add` は日次の更新チェックの完了を待たなくなった（v12）。`sideEffectsCache.exclude` で、ビルドが環境に左右されるパッケージを side-effects キャッシュから外せる（v12.14.0）。インストールのクライアントは zstd で圧縮した応答も受け付ける（未リリース）。2026-10-19 の回では、zstd・gzip の content coding で非圧縮の tar を配るレジストリ（`serverType: pnpr`）からのインストールと、展開後のサイズの上限 `maxTarballUnpackedSize`（4 GiB）が入った。macOS の `PNPM_MACOS_LINK_THREADS=0` でグローバルのプールでのリンクに戻せ、グローバル仮想ストアの resolve フックは利用者のフックに importer の `parentURL` を見せるようになった（いずれも未リリース）。未リリースの変更として、pnpr が配る `requiresBuild` をインストールに使い、強制的な置き換えのロックはインストールごとに 1 つになった。2026-10-28 の回では、hoisted のインストールが途中で止まったときの記録の扱い、絞り込んだインストールで配置の設定が変わったときの失敗（`ERR_PNPM_NODE_LINKER_DIFF` など。v11 の `add`/`remove`/`update` も）、繰り返しのインストールの近道が見落としていた設定（`virtualStoreDirMaxLength`・`dangerouslyAllowAllBuilds`・`trustLockfile`・`globalVirtualStoreDir`）、ワークスペースの `bin` の変更での古いシムの削除、cgroup の CPU の上限によるワーカーの数、hoisted での peer の変種、消しても残るシンボリックリンクでのクラッシュ、非公開で hoist した `.bin` のビルド後の更新が直った（多くは v12.16.0・v11.28.9・v12.16.1 に入った）。

## 主な API・オプション

- `modulesDir` — 相対パスは全体を各プロジェクトのディレクトリに連結（`pnpm bin` も同様）
- `readPackage` フック（`.pnpmfile.cjs`）— `engineStrict` を含むインストール可否の判定前に適用
- `fetchTimeout` — 超えた場合のエラーにタイムアウトであることと設定のヒントを表示
- http/https tarball の `Cache-Control` — `<cacheDir>/v11/tarball-resolutions` に記録し、新鮮なら通信なし、古ければ `If-None-Match` で再検証（v12）
- `NODE_EXTRA_CA_CERTS` — システムの CA ストアが空なら同梱の Mozilla ルートに追加して使う（v12.8.2）
- `registries.<url>.networkConcurrency` — そのレジストリのオリジンへの同時リクエスト数の上限。同じオリジンのエントリは最小値を共有（v12、未リリース）
- `readPackageHookChecksum`（`@pnpm/napi` の install オプション）— 組み込み側の `readPackageHook` を `pnpmfileChecksum` で追跡し、変わるまで lockfile を再利用（未リリース）
- `hideLinkedPkgsDiff`（Node.js API のレポーター）— v12 でも `link:` の直接依存に効く（未リリース）
- `pnpm:skipped-optional-dependency` の理由 `fetch_failure` — 取得できなかった任意の依存。`details` にエラーコードとメッセージ（v12.9.1・v11.28.4）
- `optimisticRepeatInstall: false` — 最新状態でもプロジェクトのライフサイクルスクリプトを実行（v12.9.1）
- 依存の指定の検証 — `readPackage` フックの適用後に 4 つの依存グループを検証し、文字列でない指定は `ERR_PNPM_PACKAGE_MANIFEST_INVALID_ATTRIBUTE`（v12、未リリース）
- `@pnpm/napi` の `rebuild({ skipIfHasSideEffectsCache })` — 副作用キャッシュにビルドがあればスクリプトを再実行せず、キャッシュの出力をスロットに戻す（未リリース）
- `enableModulesDir: false` / `enable-modules-dir=false` — `node_modules` に何も書かず、ホストがインストールできる lockfile のレジストリパッケージをストアに取得。`--lockfile-only`・`--dry-run` は取得しない（v12.11.1・v12.11.2）
- `node_modules/.bin` のシム — すべての実行ビットがある既存のシムは chmod しない。誰でも書き込めるシムは `0755` に戻す（v12.11.1）
- `sideEffectsCache.exclude` — 毎回ビルドし、side-effects キャッシュ（ローカル・`remoteCache`）で復元・保存しないパッケージ。`minimumReleaseAgeExclude` と同じ書式（v12.14.0）
- `Accept-Encoding: zstd,gzip,deflate` — zstd の応答を展開（未リリース）
- `maxTarballUnpackedSize` — 展開後のサイズの上限（既定 4 GiB、超えると `ERR_PNPM_TARBALL_TOO_LARGE`）（未リリース）
- `PNPM_MACOS_LINK_THREADS=0` — macOS でグローバルのプールでリンク（未リリース）
