## 概要

`pnpm install` による取得・配置（`node_modules` のレイアウト、フック、ネットワーク）まわり。複数階層の `modulesDir`（`www/modules` など）が各プロジェクトに正しく連結されるようになり、`nodeLinker: hoisted` で削除したパッケージのコマンドが `.bin` に残らなくなった。`engineStrict` の判定前に `readPackage` フックが適用されるようになり、レジストリが応答を止めたときはタイムアウトだと分かるエラーを出す。未リリースの新機能として、http/https の tarball 依存でレスポンスの `Cache-Control` に従い、不要なリクエストを省くようになった。v12.8.1 では 12.8.0 で `file:` ディレクトリ依存や injected パッケージのファイルが実行ビットを失っていた後退が直った。CA 証明書の無いシステムで `NODE_EXTRA_CA_CERTS` を設定しても同梱のルートに追加して使い、Nix のビルドでもシムのヘルパーが見つかるようになった（v12.8.2）。tarball の展開には `zlib-rs` を使う（未リリース）。未リリースの新機能として、`registries` のエントリごとに `networkConcurrency` で同時リクエスト数を絞れるようになり、`@pnpm/napi` の `readPackageHook` にチェックサムを渡して lockfile を再利用できるようになった。修正では、`link:` の直接依存のリンク先を要約に表示し（`hideLinkedPkgsDiff` も効く）、hoisted でカスタム fetcher のディレクトリを再インストール時に取り込み直し、v11.28.3 の frozen install がスキップした任意の依存に作業ディレクトリへのリンクを作る問題を直した（未リリース）。`registries` ごとの `networkConcurrency` は v12.9.0 でリリースされた。取得できずスキップした任意の依存は警告（`fetch_failure`）を出し、壊れたリンクを残さない（v12.9.1・v11.28.4）。v12 では `optimisticRepeatInstall: false` のとき、最新状態の再インストールでもプロジェクト自身の `prepare` などを実行する（v12.9.1）。未リリースの修正として、v12 は `"dependencies": {"is-positive": 42}` のような不正な依存の指定を `ERR_PNPM_PACKAGE_MANIFEST_INVALID_ATTRIBUTE` で拒否する。新しい実験的なインストール方式は [[repos/pnpm-pnpm/topics/loaded-リンカー|loaded リンカー]] を参照。未リリースの修正として、v12 は `"dependencies": {"is-positive": 42}` のような不正な依存の指定を `ERR_PNPM_PACKAGE_MANIFEST_INVALID_ATTRIBUTE` で拒否する。新しい実験的なインストール方式は [[repos/pnpm-pnpm/topics/loaded-リンカー|loaded リンカー]] を参照。未リリースの修正として、v12 は `"dependencies": {"is-positive": 42}` のような不正な依存の指定を `ERR_PNPM_PACKAGE_MANIFEST_INVALID_ATTRIBUTE` で拒否する。新しい実験的なインストール方式は [[repos/pnpm-pnpm/topics/loaded-リンカー|loaded リンカー]] を参照。

## 主な API・オプション

- `modulesDir` — 相対パスは全体を各プロジェクトのディレクトリに連結（`pnpm bin` も同様）
- `readPackage` フック（`.pnpmfile.cjs`）— `engineStrict` を含むインストール可否の判定前に適用
- `fetchTimeout` — 超えた場合のエラーにタイムアウトであることと設定のヒントを表示
- http/https tarball の `Cache-Control` — `<cacheDir>/v11/tarball-resolutions` に記録し、新鮮なら通信なし、古ければ `If-None-Match` で再検証（v12）
- `NODE_EXTRA_CA_CERTS` — システムの CA ストアが空なら同梱の Mozilla ルートに追加して使う（v12.8.2）
- `registries.<url>.networkConcurrency` — そのレジストリのオリジンへの同時リクエスト数の上限。同じオリジンのエントリは最小値を共有（v12、未リリース）
- `readPackageHookChecksum`（`@pnpm/napi` の install オプション）— 組み込み側の `readPackageHook` を `pnpmfileChecksum` で追跡し、変わるまで lockfile を再利用（未リリース）
- `hideLinkedPkgsDiff`（Node.js API のレポーター）— v12 でも `link:` の直接依存に効く（未リリース）
- `pnpm:skipped-optional-dependency` の理由 `fetch_failure` — 取得できなかった任意の依存。`details` にエラーコードとメッセージ（v12.9.1・v11.28.4）
- `optimisticRepeatInstall: false` — 最新状態でもプロジェクトのライフサイクルスクリプトを実行（v12.9.1）
- 依存の指定の検証 — `readPackage` フックの適用後に 4 つの依存グループを検証し、文字列でない指定は `ERR_PNPM_PACKAGE_MANIFEST_INVALID_ATTRIBUTE`（v12、未リリース）
