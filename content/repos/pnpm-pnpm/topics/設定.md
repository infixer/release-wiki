## 概要

`pnpm-workspace.yaml`・グローバル設定・コマンドラインから読む設定値の扱い（読み込み時の検証と、`pnpm config` での見え方）。TypeScript 版の設定リーダーは、`allowUnusedPatches`（真偽値）、`ignoredOptionalDependencies`・`requiredScripts`（文字列の配列）が不正な形なら `pnpm:INVALID_SETTING` で読み込み時に失敗するようになった（未リリース）。v11.28.3 では `allowBuilds` の不正な値も `ERR_PNPM_INVALID_ALLOW_BUILDS` で失敗する。pnpm 12 では `--config.<setting>=<value>` で渡した設定が `pnpm config get`/`list` に出なかった問題が直った（未リリース）。未リリースの修正として、pnpm v12 も `failIfNoMatch` を `pnpm-workspace.yaml` と `PNPM_CONFIG_FAIL_IF_NO_MATCH` から読むようになった（`--no-fail-if-no-match` で 1 回だけ無効化）。`pnpm config get`/`list` の `--global`・`--location=global` が v11・v12 ともグローバルの設定だけを読むようになった（v11.28.5 のリリースノートにも記載）。v12 では空の `nodeOptions`（`--config.node-options=` など）が下位の設定を上書きし、v11 では `httpProxy`・`httpsProxy` の検証と、設定の読み込みに失敗したときの警告の表示が加わった。v12.11.1 では `https://registry.npmjs.com/` が `https://registry.npmjs.org/` の別名になり、レジストリへのリクエスト・認証情報・TLS のキー・trusted publishing が正規のホスト名を使う。v12.12.0 では、読めない設定があっても読める読み込み元だけで読み直し、固定した pnpm への切り替えを止めないようになった（v11・v12。詳しくは [[repos/pnpm-pnpm/topics/ランタイム管理|ランタイム管理]]）。v12.13.0 で、package map の設定が `nodePackageMap`（`mode`: `off`/`write-only`/`load`、`type`: `standard`/`loose`）にまとまった。旧来の `nodeExperimentalPackageMap`・`nodePackageMapType` も非推奨の書き方として使える。v11 は `httpProxy`・`httpsProxy` の `null`・値なしを再び未設定として受け付ける（v11.28.6）。2026-10-19 の回では、ルートの `pnpm-workspace.yaml` の `include` で設定をローカルの YAML ファイルや config 依存に任せられるようになった（v12、未リリース）。取り込んだファイルの相対パスはそのファイルから測り、1 つの設定の持ち主は 1 つ（重なると `ERR_PNPM_DUPLICATE_SETTING`）。

## 主な API・オプション

- `--config.<setting>=<value>` — 明示的に設定されたものとして記録され、`pnpm config get`/`pnpm config list` に表示（v12、未リリース）
- `allowUnusedPatches` — 真偽値以外は `pnpm:INVALID_SETTING`
- `ignoredOptionalDependencies` / `requiredScripts` — 文字列の配列以外は `pnpm:INVALID_SETTING`
- `allowBuilds` — オブジェクトでない、または値が `true`/`false`/文字列以外なら `ERR_PNPM_INVALID_ALLOW_BUILDS`（v11.28.3）
- `failIfNoMatch` — `pnpm-workspace.yaml`・`PNPM_CONFIG_FAIL_IF_NO_MATCH` から読む。`--fail-if-no-match` で上書き、`--no-fail-if-no-match` で無効化（v12、未リリース）
- `pnpm config get`/`list --global`（`--location=global`）— プロジェクトの `pnpm-workspace.yaml`・`.npmrc`、グローバルパッケージのマニフェストを読まない（v11・v12、未リリース）
- `nodeOptions` — 明示的な空の値が優先度の低い値を上書き。継承した `NODE_OPTIONS` は消さない（v12、未リリース）
- `httpProxy` / `httpsProxy` — 文字列以外や `null` は `INVALID_SETTING`（v11、未リリース）
- npm レジストリの別名 — `https://registry.npmjs.com/` を `https://registry.npmjs.org/` に正規化。ルートの認証情報・TLS のキーはどちらのホスト名でも届き、明示的な `.com` のキーは元のスコープのまま。HTTP・カスタムポート・サブパスなどは対象外（v12.11.1）
- 読めない設定 — 読み込みに失敗したら、読めない読み込み元（グローバルの `config.yaml`、`pnpm-workspace.yaml` の設定、`_auth`、`.npmrc` の `tokenHelper` など）だけを除いて読み直す（v11・v12、v12.12.0）
- `nodePackageMap.mode` — `off`（既定）/ `write-only`（Node に読み込ませずに `node_modules/.package-map.json` を書く）/ `load`（`nodeExperimentalPackageMap: true` と同じ）。環境変数は `PNPM_CONFIG_NODE_PACKAGE_MAP_MODE`（v12.13.0）
- `nodePackageMap.type` — `standard`（既定）/ `loose`。`nodePackageMapType` を置き換える。環境変数は `PNPM_CONFIG_NODE_PACKAGE_MAP_TYPE`（v12.13.0）
- `include` — ルートの `pnpm-workspace.yaml` で設定をファイル・config 依存に任せる（`ERR_PNPM_DUPLICATE_SETTING`・`ERR_PNPM_SETTING_NOT_DELEGATED`）（v12、未リリース）
