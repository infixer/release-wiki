## 概要

`pnpm pack`・`pnpm publish`・`pnpm deploy` と、ワークスペースのバージョン更新（changelog）まわり。isolated リンカーでも bundled dependencies（ワークスペースのパッケージやその依存を含む）を tarball に含められるようになり、`package.yaml`/`package.json5` のパッケージにも `files` が適用されるようになった。`pnpm publish --publish-wait-timeout` の反映待ちはタイムアウト後に余分な確認を送らないよう修正された。private パッケージはレジストリ確認なしでバージョン更新され、changelog はリポジトリの `CHANGELOG.md` に書かれる。未リリースの変更として、`files` に明示されない `.env` ファイルの警告と `pnpm pack --silent` の出力抑制が入った。`.env` の警告と `pnpm pack --silent` は v12.8.0 でリリースされた。`injectWorkspacePackages: true` での `pnpm deploy` の `ERR_PNPM_DEPLOY_AMBIGUOUS_PEER` も修正された（未リリース）。v12.9.1 では GitLab CI からの provenance 付き `pnpm publish` が 422 で拒否されなくなった。未リリースの修正として、パス配下のレジストリ（Gitea など）で `pnpm unpublish` が tarball を正しく削除する。未リリースの修正として、`pnpm unpublish` がレジストリのパスを照合するときにセグメントの境界を守るようになった。未リリースの修正として、v12 の `pnpm publish --provenance=false`（隠しフラグ `--no-provenance`）と `provenance` 設定で provenance を無効にできるようになり（self-hosted のランナーからの trusted publishing 向け）、`pnpm deploy` は依存と `allowBuilds` を名前順に書くようになった。2026-10-12 の回では、v12 の `pnpm pack`・`pnpm publish` が `.npmignore`・`.gitignore` を tarball に入れなくなり、`pnpm stage publish` の拒否のエラーが「Failed to stage package」になった（v12.11.1）。v12.12.0 では `injectWorkspacePackages` なしの `pnpm deploy` がリンクしたワークスペースパッケージの peer を親が提供するバージョンに結び付け、v12.12.1 では `pnpm dist-tag` が OIDC 認証に対応し、`NPM_ID_TOKEN` は `aud` が選んだレジストリと一致するときだけ使う。未リリースの修正として、`pnpm deploy --legacy` が `workspace:` の peer をワークスペースから入れる。未リリースの修正（v12.13.0 に記載）として、v12 の `pnpm pack`・`pnpm publish` は `"files": []` なら常に含まれるファイル（`package.json`・README・LICENSE・`main`/`bin`）だけを入れる。v12 のパックは、`files` があってもサブディレクトリの ignore ファイルを守り、`main`・`browser`・`bin` が指すディレクトリを npm-packlist と同じく ignore から戻す（未リリース）。v11.28.6 では `pnpm publish` が `aud` の合わない `NPM_ID_TOKEN` を使わない。2026-10-19 の回では、pnpm 12 の `pack`・`publish` が npm-packlist の既定の除外パターン（`.*.swp` など）を除くようになり、`pnpm deploy` は lockfile のディレクトリの外の `file:` 依存も配置できるようになった（未リリース）。未リリースの修正として、v12 の packlist は `files`・エントリポイント・既定の除外を 1 つの規則で選び、`part{1..3}.js` のような数値の範囲も展開する。`pnpm deploy` は macOS でパッケージを二重に書かず、deploy 先のワークスペース設定を 1 つの定義から作り、使ったパッチだけを残す。

## 主な API・オプション

- `pnpm pack` / `pnpm publish` — isolated リンカーで bundled dependencies を含める（PnP リンカーでは拒否）
- `files` フィールド — `package.yaml`/`package.json5` のパッケージでも適用
- `.env`/`.env.*` の警告 — `files` に明示されていなければ警告（テンプレートは対象外、v13 でエラー予定）
- `pnpm pack --silent`（`-s`、`--reporter=silent`、`--loglevel=silent`）— ファイル一覧とサマリーを出さない
- `pnpm deploy --package-import-method` — コマンドラインの指定を尊重
- private パッケージのバージョン更新 — 常に `repository` 方式で `CHANGELOG.md` に追記
- `pnpm publish --provenance`（GitLab CI）— SLSA v0.2 の `invocation.parameters` に npm の `libnpmpublish` と同じ CI 変数を入れる（v12.9.1）
- `pnpm unpublish`（パス配下のレジストリ）— レジストリのパスに末尾の `/` の境界を付けて照合（v11・v12、未リリース）
- `provenance` 設定 / `--no-provenance` — `pnpm-workspace.yaml`・グローバルの `config.yaml`・`PNPM_CONFIG_PROVENANCE` から読む。CLI のフラグが優先（v12、未リリース）
- `pnpm pack`（v12）— `.npmignore`・`.gitignore` はどの階層でも除外。`files` で直接名指しすれば入る（v12.11.1）
- `pnpm dist-tag add`/`rm`/`ls` の OIDC — 一時トークンはメモリにだけ置く。trusted publishing の設定で「Allow npm dist-tag」を有効にする（v12.12.1）
- `NPM_ID_TOKEN` — `aud` が選んだレジストリと違えば `ERR_PNPM_ID_TOKEN_REGISTRY_AUDIENCE_MISMATCH` を警告して設定済みの認証情報に戻る（v11・v12）
- `pnpm deploy`（`injectWorkspacePackages` なし）— リンクしたワークスペースパッケージの peer を最も近い提供元の祖先から結び付け、提供元が複数のときだけ `ERR_PNPM_DEPLOY_AMBIGUOUS_PEER`（v12.12.0）
