## 要点

- **認証情報の漏えい対策 2 件**: `pnpm login` がリダイレクトのとき、リクエスト本文の認証情報を別のオリジンへ送らない。integrity チェックに失敗した tarball のエラーに、URL の認証情報・クエリ文字列・フラグメントを表示しない
- `pnpm install --frozen-lockfile` が受け付ける lockfile を拡大: 依存の無いプロジェクトで固定した pnpm のバージョンだけを記録した lockfile（その後の `---` 行が無いものも）、ディレクトリごと無いワークスペースプロジェクト（Docker のビルドコンテキストから外した場合など）、依存がすべてワークスペースのリンクで `dependenciesMeta` を宣言したプロジェクト（`dependenciesMeta` を lockfile に記録する）
- frozen install が巻き上げた依存を同名のワークスペースパッケージで置き換え、その後の `pnpm dedupe` が巻き上げのリンクを消す問題を修正
- `enableGlobalVirtualStore` を有効にしても、`ts-node index.ts` のような CommonJS の require フック経由のエントリポイントを再び実行できる
- **任意の依存**: 取得できずスキップした任意の依存をエラー付きで警告し、壊れたリンクや追加した依存として残さない（`pnpm:skipped-optional-dependency` の理由は `fetch_failure`）。ビルドに失敗した任意の依存のリンクを消し、次の `pnpm install` が「Already up to date」になる。frozen install がスキップした任意の依存や解決できない peer に作業ディレクトリへのリンクを作らない（v11.28.3 の既知の問題）
- `nodeLinker: hoisted` でフィルタ付きインストールが、以前のインストールで入れた他のワークスペースプロジェクトのパッケージを保つ
- Homebrew で入れた pnpm の `pnpm self-update` が、Homebrew 版の横に 2 つめの pnpm を入れなくなった
