## 要点

- 概要の説明によると、`pnpm fund` の追加、`loaded` の node リンカーでビルドが必要なパッケージの扱い、`projectScopedOptionalPeers` の設定、実験的な JSON の lockfile の形式が入った。オフラインのインストールのエラーがレジストリの認証情報を表示しなくなるセキュリティの修正も含む。ワークスペースの全プロジェクトの `engines`・プラットフォームのフィールドを確かめるようになり、hoisted リンカーと frozen lockfile の不具合が多数直った
- **`pnpm fund`**: インストールした依存が宣言する資金提供の URL を `npm fund` と同じツリーで一覧する。`--json` で `npm fund --json` の形式、`--recursive`・`--filter` でワークスペースのプロジェクト。`pnpm fund <pkg>` はそのパッケージの URL を開き、複数あれば `--which` で選ぶ（[#7354](https://github.com/pnpm/pnpm/issues/7354)）
- **`nodeLinker.type: loaded`**: ビルドが必要なパッケージを `nodeLinker.excluded` に並べなくてよくなった。副作用キャッシュに一致する項目があればストアから読み込む。副作用キャッシュの読み書きが有効なら、承認済みのパッケージを 1 回ビルドしてキャッシュに保存し、ストアから読み込む（ファイルを変えないビルドも含むので、同じストアのほかのプロジェクトでスクリプトが再実行されない）。各プロジェクトでビルドが必要なもの（git フックのインストーラーなど）は `sideEffectsCache.exclude` に並べる。そのほかのキャッシュの外れ・ネイティブの `.node` アドオンを持つパッケージとその依存は自動で実体化する。JavaScript のソースのファイルシステムの import や `__dirname`・`import.meta` も調べて実体化するが、計算した import は検出できないので `nodeLinker.excluded` に並べる
- **`projectScopedOptionalPeers`**: `true` のとき、足りない optional の peer は、プロジェクト自身の依存がそのバージョンを入れるときだけ補う。ほかのワークスペースのプロジェクトの依存（`devDependencies` など）からは補わない。`dedupePeerDependents` はそれ以外の重複排除を続ける（[#16666](https://github.com/orgs/pnpm/discussions/16666)）
- **実験的な `lockfile.format: v13`**: `pnpm-lock.yaml` をタブでインデントし各項目の後ろにカンマを付けた JSON のような構文で書く（YAML としても正しい）。`packages` と `snapshots` の代わりにパッケージのバージョンごとに 1 項目の `packages` を持ち、各項目が peer 依存のバージョンをプロパティとして記録するので、peer 依存を更新してもそのバージョンの行だけが変わる。pnpm は設定にかかわらず両方の形式を読める
- **`pnpm store add`**: `pnpm store add ./tarballs` のようにディレクトリを受け付け、中の `.tgz`・`.tar.gz`・`.tar` を再帰的に取り込む。多くのパッケージやローカルの tarball を取り込むときに速くなった（本文はここで切れている）
