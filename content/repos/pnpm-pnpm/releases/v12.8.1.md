## 要点

- `pnpm install --frozen-lockfile` が、peer を持つ injected なワークスペースパッケージを含む生成直後の lockfile を拒否しなくなった（[#16346](https://github.com/pnpm/pnpm/pull/16346)）
- `file:` のディレクトリ依存や injected なワークスペースパッケージのファイルが実行ビットを保つように戻った（12.8.0 での後退、[#16318](https://github.com/pnpm/pnpm/pull/16318)）
- `pnpm dedupe` が、peer 接尾辞がハッシュ化されるパッケージでも安定した lockfile に収束する（[#16335](https://github.com/pnpm/pnpm/pull/16335)）
- CI の既定である `pnpm install --frozen-lockfile` が 9 コア以上のマシンで CPU 使用を抑える（リンクのワーカースレッドは最大 16）。多コアの Windows でウォームインストールが最大 10% 高速化
- `verifyDepsBeforeRun` が、フィルタ付きインストール後に `pnpm-lock.yaml` の更新時刻が新しいだけで依存を古いと判定しなくなった（[#16324](https://github.com/pnpm/pnpm/pull/16324)）
- `pnpm run`/`pnpm exec` が、インストールするものが無い未インストールのプロジェクトをインストールしない（[#16317](https://github.com/pnpm/pnpm/pull/16317)）
- `pnpm update -g --latest` が保存済みの範囲を超えてグローバルパッケージを更新する（[#16325](https://github.com/pnpm/pnpm/pull/16325)）

> [!warning] 既知の問題
> Linux ppc64le 向けのバイナリは起動時にクラッシュする。修正は [#16384](https://github.com/pnpm/pnpm/pull/16384)（未リリース）。
