## 要点

- **Rust ツールチェーンの管理**: `cargo.enabled` で `pnpm install` が `rust-toolchain.toml` のツールチェーンを入れる（リリース署名を検証し、マシンごとに 1 回だけ保存して `.pnpm/rust` にリンク）。`pnpm run`・`pnpm exec` はその `cargo`・`rustc` を `PATH` に置く
- `pnpm add -g rust@<channel>` でグローバルに入れ、`pnpm update -g`・`pnpm ls -g`・`pnpm remove -g` で管理できる。プロジェクトでは `pnpm add rust@<channel>` が `rust-toolchain.toml` に固定し、`pnpm shim add rust` でプロジェクトを見分ける `cargo`・`rustc` などのシムを追加
- **エージェントスキル**: `pnpm install` が直接依存の `skills/<name>/SKILL.md` を `.claude/skills` などにリンクする。`pnpm approve` で承認したパッケージだけで、`skills.dirs` でリンク先を選ぶ（[pnpm/rfcs#35](https://github.com/pnpm/rfcs/pull/35)）
- **`permissions` 設定**: 依存ごとにできることを記録する。`build` は `allowBuilds` と同じ働きで、それより優先。`pnpm approve-builds` は `pnpm-workspace.yaml` に `permissions` があればそこへ書く。`pnpm permissions` で許可・拒否・承認待ちを一覧し、`pnpm approve` でビルドスクリプトとスキルを一度に確認（[pnpm/rfcs#36](https://github.com/pnpm/rfcs/pull/36)）
- **スクリプト出力の色**: `pnpm run`・`pnpm exec`（`--stream` など）がプロジェクト名の下に出す出力の色を保つ（pnpm の出力が色付きなら `FORCE_COLOR=1`）。`\r` で描き直す進捗バーは最後の状態だけ、カーソル移動などの制御は除去、長い色付きの行は端末幅で切る。`pnpm -r run` で失敗したスクリプトがあっても出力が崩れない
- QEMU のユーザーモードエミュレーション（Apple Silicon の Mac の `linux/amd64` コンテナなど）で「unexpected error when polling the I/O driver」で panic しない（[#16696](https://github.com/pnpm/pnpm/issues/16696)）
