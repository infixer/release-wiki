## 要点

- 概要の説明によると、実験的な v13 の lockfile にローカルのディレクトリの依存の指定を記録するようになり、`nodeLinker: hoisted`・peer 依存・`overrides` の不具合がいくつか直った。同梱の `node-gyp` はセキュリティスキャナーが指摘する undici を含まなくなった。リモートの解決と共有のビルドキャッシュは pnpr 0.1.0-alpha.19 以前では使えなくなった
- **`lockfile.format: v13` のディレクトリの依存**（Minor）: `pnpm install` がローカルのディレクトリのパッケージの依存の指定を記録する。frozen install は、ロックしたバージョンがまだ満たしていても、変わった指定を拒否する
- **pnpr との互換**: リモートの解決・共有のビルドキャッシュ・リリースノートは pnpr 0.1.0-alpha.19 以前では使えない。pnpm は pnpr のサーバーが `pnpr.protocols` で示す機能を読み、要求した解決と検証のポリシーをサーバーが確認しなければインストールを失敗させる
- **セキュリティ**: 同梱の `node-gyp` が undici 6（CVE-2026-84947 で指摘される）を含まなくなった。Node.js 26 で、プロキシや独自の CA ファイルを使う `node-gyp` のダウンロードが「invalid onError method」でクラッシュしなくなった（[#17941](https://github.com/pnpm/pnpm/issues/17941)）
- **`overrides`**: `"ms@^2.0.0": "2.1.1"` のようなバージョンのセレクター付きの項目が、カタログの範囲がセレクターに一致すれば `catalog:` の依存にも効く（[#17922](https://github.com/pnpm/pnpm/issues/17922)）。`workspace:./packages/foo` のような `workspace:` のパスの root の `overrides` が、レジストリのパッケージの依存にも効く（pnpm/tasks#270）
- **git の依存**: `github:owner/repo#v1.0.0::path:packages/foo` のような npm の `::` 区切りを受け付ける（それまではフラグメント全体をブランチ名として読んで失敗）（[#17827](https://github.com/orgs/pnpm/discussions/17827)）
- **`pnpm dedupe`**: `devEngines.runtime` や依存の `engines.runtime` のロックしたランタイムのバージョンを、宣言した範囲が許す限り保つ。`pnpm dedupe --check` が範囲内の新しい Node.js のリリースのたびに失敗しなくなった（[#17984](https://github.com/pnpm/pnpm/issues/17984)）
- **peer 依存**: `autoInstallPeersFromHighestMatch` で、衝突する semver でない peer は missing のまま、同じ非 semver の指定は保たれる。足りない peer を入れるとき、優先のレジストリのバージョンがローカルのパスやプロトコル付きの指定を置き換えない（pnpm/tasks#272）
- **`nodeLinker: hoisted`**: トップレベルと違うバージョンに解決した依存（親が提供する peer 依存を含む）の入れ子のコピーを保つ。それまでは重複として消したり、グラフの深くの peer のバリアントにトップレベルの場所を渡したりすることがあった（本文はここで切れている）
