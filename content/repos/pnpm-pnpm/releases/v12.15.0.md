## 要点

- **`pnpm-workspace.yaml` の `include`**: 設定をほかの YAML ファイルや config dependency に任せられる。設定ごとに持ち主は 1 つで、設定を変えるコマンドは持ち主のファイルに書く。config dependency は `package.json` の `pnpm.config` で指す YAML で設定を渡す。新しい `bootConfig` で、config dependencies と `packageManager` の pnpm のバージョンをインストールするときの release-age・trust の方針を決める
- **`lockfile.integrityTarget: tar`**: `pnpm-lock.yaml` に各パッケージの展開前の tar のハッシュを固定し、レジストリが tarball を圧縮し直したり tar で配ったりしても lockfile が変わらない。`pnpm audit signatures` は tar のハッシュを署名済みの `.tgz` の integrity に結び付ける
- **tar のレジストリ**: zstd・gzip の content coding で非圧縮の tar を配るレジストリからインストールできる。`registries` で `serverType: pnpr` と宣言すると lockfile に tarball の URL を書かない。window が 8 MiB を超える zstd の応答は拒否する
- **`maxTarballUnpackedSize`**: 1 パッケージのファイルを展開したときのバイト数の上限（既定 4 GiB）
- **レジストリのリビジョン**: 元の版も含めて常に展開前の tar のハッシュを固定する。`+r0` などで選んだ元の版は lockfile に `revision: 0` と記録する。不完全なリビジョンのメタデータは `ERR_PNPM_MALFORMED_METADATA` で拒否する
- **zstd で圧縮した応答**を受け付ける（`minimumReleaseAge`・`trustPolicy` が読む完全なメタデータが小さくなる）
- `pnpm deploy`・`pnpm install` が `SOURCE_DATE_EPOCH` に従う。要求したものと違うパッケージを名乗るレジストリのメタデータを拒否する。ワークスペースのインストールと macOS のファイルのリンクが速くなった
