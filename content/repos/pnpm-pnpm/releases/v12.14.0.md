## 要点

- **`sideEffectsCache.exclude` 設定**: ビルドがキャッシュのキーに含められないもの（ネイティブアドオンがリンクするシステムのライブラリなど）に左右されるパッケージを、どのプロジェクトでも毎回ビルドし、side-effects キャッシュ（ローカル・`remoteCache`）で復元・保存しない。グローバル仮想ストアでは、そのパッケージと依存するパッケージをプロジェクトごとに持つ。書式は `minimumReleaseAgeExclude` と同じ（[#5271](https://github.com/pnpm/pnpm/issues/5271)）
- **`pnpm login`**: Web ログインで `npm-notice` 応答ヘッダーを表示する（ブラウザでのサインインを完了する確認コードを表示するレジストリ向け）
- `pnpm install`・`pnpm add` が毎日の更新チェックを待たない。接続を受け付けて応答しないレジストリで、何もしないインストールに数分かかっていた（[#16839](https://github.com/pnpm/pnpm/issues/16839)）
- どの依存も参照しないカタログの項目があっても `pnpm-lock.yaml` を再利用する（[#16923](https://github.com/pnpm/pnpm/issues/16923)）
- git 依存のブランチ・タグの照会をインストールごとに 1 回にする（`linkWorkspacePackages` ではプロジェクトごとに `git ls-remote` していた）（[#16899](https://github.com/pnpm/pnpm/issues/16899)）
- `--filter` 付きのインストールが、ディスクに無いワークスペースのプロジェクト（sparse checkout など）の lockfile の記録を残す（[#16931](https://github.com/pnpm/pnpm/issues/16931)）
- 依存かつ任意の peer でもある依存を、最も浅い経路で依存・peer のどちらにするか決める。次のインストールで lockfile の記録が変わることがある（[#16901](https://github.com/pnpm/pnpm/issues/16901)）
- 何も追加しないインストールでストアのディレクトリの更新日時を変えない。出力の読み手が終了しても core dump で落ちない
- リリースノートの本文は途中で切れている
