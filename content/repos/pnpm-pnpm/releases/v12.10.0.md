## 要点

- **実験的な `loaded` リンカー**: `nodeLinker: { type: loaded }` で、互換性のある依存を自動で登録される Node.js のローダーを通じてコンテンツアドレス可能ストアから直接読み込む。`nodeLinker.excluded` で選んだパッケージとその依存ツリーはグローバル仮想ストアにインストールする
- **解決に関わる設定を lockfile に記録**: `lockfile.includeResolutionSettings: true` で `pnpm-lock.yaml` に `autoDedupe`・`dedupeInjectedDeps`・`dedupePeerDependents`・`linkWorkspacePackages` を記録し、異なる値を記録した lockfile は古いとみなす。`autoDedupe` を記録した lockfile はどのマシンでも再利用され、`pnpm install --frozen-lockfile` の後の `pnpm run` がもう一度インストールを始めなくなる
- **セキュリティ**: `pnpm install` が、パストラバーサルを含む依存のバージョンでグローバル仮想ストアの外にファイルを書くのを防ぐ
- **セキュリティ**: config 依存をインストール前にレジストリと照合する（npm レジストリから取得する必要があり、`version+integrity` で固定した integrity を lockfile で置き換えられない）。lockfile の検証が `variations` の中の tarball も照合し、空の `variations` を持つ `name@version` のエントリを拒否する。`pnpm audit signatures` は lockfile に記録された integrity に対して署名を検証する
- **セキュリティ**: 64 MiB を超えるアーカイブのメタデータを読み込む前に拒否する。`+`・`#`・`:`・`?` と `/` だけが異なる URL・ローカルパスの依存が仮想ストアのディレクトリを共有しない（ディレクトリ名にハッシュを付ける）。無視したプロジェクトの `.npmrc` のレジストリ設定の警告で、URL にスコープしたキーのユーザー名とパスワードを表示しない
- 依存が Yarn の `patch:` のような未対応のプロトコルを使うと `ERR_PNPM_UNSUPPORTED_PROTOCOL` で失敗する（Windows では `os error 123`、他のプラットフォームでは存在しないディレクトリへのリンクになっていた）。読み込みに失敗した `package.json` のファイル名を示す
- リリースの冒頭によると、キャッシュしたレジストリのメタデータの読み込みも速くなった
