## 要点

- **`loaded` リンカーの生成ファイルの場所が変わった**: `nodeLinker.type: loaded` の生成ファイルは `node_modules` に置かれる（`node_modules/.pnpm/.store-manifest.json`・`node_modules/.pnpm/.store-loader.mjs`、bin シムは `node_modules/.bin`）
- `loaded` リンカー: 独自の `node_modules` を同梱するパッケージ（bundled dependencies を持つ `npm` など）をストアから読み込む。以前は 1 つでもあるとすべての Node.js プロセスが起動しなかった
- `loaded` リンカー: スクリプトから `devEngines.runtime` で入れた Node.js を実行できる（以前は `node` を呼ぶスクリプトが自分のシムを繰り返し実行し「Argument list too long」で失敗）。プロセスの起動が速くなった（13,000 ファイルのプロジェクトで 67 ms → 18 ms）
- `overrides` の変更後、lockfile が任意の peer を別パッケージの npm エイリアスに解決していると `ERR_PNPM_NO_MATCHING_VERSION` で失敗していた問題を修正
- `catalogPrune` の frozen install が lockfile に記録されたカタログのエントリを消さない（以前は一部のワークスペースプロジェクトがディスクに無いと `pnpm install --frozen-lockfile --filter` が `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH` で失敗）
- `pnpm install --fix-lockfile` が lockfile の `deprecated`・`hasBin` を消さない
- `enableGlobalVirtualStore` で、中断したインストールが不完全に残したグローバル仮想ストアのパッケージを修復する
- 自分の `pnpm-workspace.yaml` や `.git` を持つ入れ子のディレクトリ（同じワークスペースの git worktree など）の Cargo・Python のプロジェクトを飛ばす。メタデータの `Request took` 警告は、リクエストの送信から計測する

> [!warning] 移行が必要（`loaded` リンカーの利用者）
> 以前のバージョンがプロジェクトのルートに書いた `.pnpm-store.json`・`.pnpm-store-loader.mjs` と、ルート・各ワークスペースパッケージの `.pnpm` ディレクトリは、再インストール後に削除する。
