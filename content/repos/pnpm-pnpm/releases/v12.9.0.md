## 要点

- **StackBlitz WebContainers 対応**: WebContainers では自動で WebAssembly 版を使う（インストールスクリプトが無効でも）。スクリプトが有効なネイティブのインストールは引き続きネイティブの実行ファイルを使う（この同梱方式は v12.9.1 で別パッケージ `@pnpm/wasm` に変わった）
- **レジストリごとの `networkConcurrency`**: `registries` のエントリに、そのレジストリのオリジンへの同時リクエスト数の上限を書ける（他のレジストリは全体の上限のまま）。`pnpm-workspace.yaml` またはグローバルの `config.yaml` に書く
- **すべてのプロジェクトをストアに登録**: `pnpm install` がインストールしたすべてのプロジェクトをストアの `projects` ディレクトリにシンボリックリンクとして記録する（グローバル仮想ストアなしの `--frozen-store` を除く）。以前はグローバル仮想ストアを使うプロジェクトだけだった
- **セキュリティ修正**: `pnpm login` がリダイレクトのとき、リクエスト本文の認証情報を別のオリジンへ送らなくなった
- Android で `pnpm install` が `ERR_PNPM_STORE_DIR_ACQUIRE_OPERATION_LOCK` で失敗する問題を修正
- `pnpm install --frozen-lockfile` の修正: lockfile にあるワークスペースプロジェクトのディレクトリごと無い場合（Docker のビルドコンテキストから外した場合など）に再び成功する。依存の無いプロジェクトで `pnpm-lock.yaml` を求めず、固定した pnpm のバージョンだけを記録した lockfile も受け付ける。injected なワークスペース依存の任意の peer を別のプロジェクトが提供する場合の新しい lockfile も受け付ける
- `nodeLinker: hoisted` の修正: フィルタ付きインストール（`pnpm --filter <selector> run`/`exec` の前のインストールを含む）が、以前のインストールで入れた他のワークスペースプロジェクトのパッケージを消さない。再インストール時にカスタム fetcher のディレクトリを取り込み直し、その中のシンボリックリンクも保つ
- `enableGlobalVirtualStore` を有効にしても、`ts-node index.ts` のような CommonJS の require フック経由のエントリポイントを再び実行できる
