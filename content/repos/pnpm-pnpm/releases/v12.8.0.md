## 要点

- `pnpm pack`/`pnpm publish` が、`package.json` の `files` に書かれていない `.env`・`.env.*` ファイルを tarball に含むときに警告する（`.env.example` などのテンプレートは対象外）。意図して公開するなら `files` に書き、そうでなければ `.npmignore`・`.gitignore` で除外する
- `pnpm pack` が `--silent`・`--reporter=silent`・`--loglevel=silent` で tarball の中身とサマリーを出さない（`--json` ではライフサイクルスクリプトの出力と最終の JSON は表示される）
- `sharedWorkspaceLockfile: false` のワークスペースを並行してインストールし、`--config.<name>=<value>` で渡した設定をすべて適用し、Windows でスクリプト中に Ctrl+C を押した後に端末が固まらなくなった（リリースノートの冒頭より）
- `pnpr` サーバー経由のインストールで pnpmfile のチェックサムを lockfile に記録し、後の `pnpm install --frozen-lockfile` が通るように。pnpmfile に `readPackage`・`afterAllResolved`・`preResolution` フックやカスタムリゾルバーがあれば、ローカルで解決して警告を出す。`publishConfig.directory` を転送しないサーバーでは `ERR_PNPM_PNPR_PUBLISH_DIRECTORY_MISMATCH` で失敗する
- ビルドが必要な git 依存の準備で、その依存の未承認のビルドスクリプトをスキップして失敗しないように。lockfile を持たない pnpm ワークスペースの git 依存を pnpm プロジェクトとして検出
- `pnpm install --dev`/`pnpm fetch --dev` が devDependencies の optional dependencies（Biome や oxlint のプラットフォームバイナリなど）もインストールする
- `pnpm install --offline`/`pnpm add --offline` が、ストアに tarball がある中で最も新しい一致バージョンを選ぶ（以前は `ERR_PNPM_NO_OFFLINE_TARBALL` で失敗）
