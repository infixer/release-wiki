## 要点

- `pnpm peers check` が `--global`（`-g`）でグローバルにインストールしたパッケージを調べる。グローバルの install/update の後の peer 依存の警告は `pnpm peers check -g` を案内する（[#17504](https://github.com/pnpm/pnpm/issues/17504)）
- `pnpm outdated`・`pnpm update` が `devEngines.packageManager`・`packageManager`・`devEngines.runtime`・`engines.runtime`・`runtime:` の依存のパッケージマネージャーとランタイムのバージョンを調べ・更新する。`cargo.enabled`・`python.enabled` では `Cargo.toml`/`Cargo.lock` と `pyproject.toml`/`pylock.toml` の依存も扱う
- `overrides` のセレクターが依存の種類の擬似セレクター `:prod`・`:optional`・`:peer` と、親・対象のパッケージ名の `*` のワイルドカードに対応。`npm:`・`file:` のような範囲でない値の override は `dependencies` に peer 依存を足さない。`"-"` で optional 依存を消すと `dependencies` の重複も消える（[#5391](https://github.com/pnpm/pnpm/issues/5391)）
- pnpm がプロジェクトに作るファイル（`node_modules/.pnpm-workspace-state-v1.json`・`pnpm-workspace.yaml`・`pnpm deploy` の出力・`pnpm patch-commit` のパッチ・`pnpm dedupe --check` で戻す lockfile・Cargo と Python のファイル）が umask に従った権限（`0644` など）になる。別ユーザーで動く Docker イメージで壊れていた。既存のファイルを編集するときは権限を保つ（[#17435](https://github.com/orgs/pnpm/discussions/17435)）
- プロジェクトの `node_modules` が別のディレクトリへのシンボリックリンクのとき、`pnpm install` が解決できないリンクを書かない（[#17448](https://github.com/pnpm/pnpm/issues/17448)）
- `pnpm add --global` で入れたコマンドが、そのパッケージのために hoist した依存を見つける。該当するパッケージは `pnpm add --global` で入れ直すと既存のコマンドが更新される（[#17503](https://github.com/pnpm/pnpm/issues/17503)）
- 概要の説明によると、ローカルの依存の変更を見逃していた繰り返しのインストールも修正（本文は途中で切れている）
