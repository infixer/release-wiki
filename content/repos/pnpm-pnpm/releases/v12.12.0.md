## 要点

- **リモートキャッシュ**: `pnpm pipeline` のタスク結果を、pnpr か Turborepo Remote Cache API のサーバー（Vercel Remote Cache など）に署名付きアーティファクトとして置き、マシン間で共有できる。リモートの副作用キャッシュも依存のビルドを Turborepo のサーバーに置ける。どちらも新しい `remoteCache` 設定（サーバーと署名鍵）を読む。`pnpm pipeline --report` は `remoteCache.org` の組織に実行を記録
- **`addMissingPeerTypes` 設定**: peer 依存の `@types` パッケージを、それを peer にするパッケージの隣にリンクする（`react` を peer にするパッケージの隣にプロジェクトの `@types/react`）。グローバル仮想ストアで TypeScript が peer の型を見つけられるように（[#15689](https://github.com/pnpm/pnpm/discussions/15689)）
- **config 依存の保存・更新**: `pnpm add --config` が `pnpm add` と同じ規則で範囲を保存し（`my-config@latest` → `^1.2.0`）、lockfile に古いバージョンがあっても解決し直す。`pnpm update` は範囲内で、`--latest` は最新版に更新し、`pnpm update my-config` は名指ししたものだけ（[#16814](https://github.com/pnpm/pnpm/issues/16814)）
- `allowBuilds` で `false` にしたパッケージは、`dangerouslyAllowAllBuilds: true` でもビルドスクリプトを実行しない（2 つを組み合わせると「拒否したもの以外すべて」）
- 設定を読めなくても、プロジェクトが固定した pnpm に切り替える（以前はグローバルの設定ファイル・`.npmrc`・`_auth` の拒否された設定や解析できない `pnpm-workspace.yaml` で、`pnpm --version` を含むすべてのコマンドが止まった）
- `pnpm update`・`pnpm why` が再び `--depth Infinity` を受け付ける（[#16817](https://github.com/pnpm/pnpm/issues/16817)）
- `injectWorkspacePackages` なしの `pnpm deploy` が、リンクしたワークスペースパッケージの peer を親が提供するバージョンに結び付ける（以前は `ERR_PNPM_DEPLOY_AMBIGUOUS_PEER`、[#16807](https://github.com/pnpm/pnpm/issues/16807)）

> [!warning] 挙動の変更
> `dangerouslyAllowAllBuilds` と `allowBuilds` の拒否を併用している場合、拒否したパッケージはビルドされなくなる。
