## 要点

- **セキュリティ**: `pnpm publish` は `NPM_ID_TOKEN` の `aud` クレームが選んだレジストリ（`npm:registry.npmjs.org` など）と一致するときだけ使う。別のレジストリ向けのトークンは警告して飛ばし、設定済みの認証情報を使う
- **セキュリティ**: 名前が不正で改名したパッケージのファイルの警告に、ファイル名の制御文字を出さない
- **設定**: `pnpm-workspace.yaml` とグローバル設定の `httpProxy`・`httpsProxy` に `null` や値なしを再び受け付け、未設定として扱う（11.28.5 から `ERR_PNPM_INVALID_SETTING` になっていた）
- **設定**: 設定を読めなくても、プロジェクトが固定した pnpm のバージョンに切り替える（それまでは拒否された設定で `pnpm --version` を含む全コマンドが止まっていた）。`_auth` のレジストリ URL の下の `@` で始まらないキーは警告して飛ばす
- **依存解決**: 任意の peer でもある依存（`ajv-formats` の `ajv` など）を落とさない（11.28.0 から）（[#16901](https://github.com/pnpm/pnpm/issues/16901)）。`overrides` の変更後に npm の別名の任意 peer で `ERR_PNPM_NO_MATCHING_VERSION` にならない（[#16654](https://github.com/pnpm/pnpm/issues/16654)）。任意の peer をワークスペースのパッケージにリンクする（[#16706](https://github.com/pnpm/pnpm/issues/16706)）。削除の overrides が `peerDependenciesMeta` だけの任意 peer にも効く（[#16681](https://github.com/pnpm/pnpm/issues/16681)）
- `pnpm dedupe` が、同名の別にインストールした peer があってもワークスペースのパッケージの hoist を保つ（[#16935](https://github.com/pnpm/pnpm/issues/16935)）
- config 依存の解決に `minimumReleaseAge` を適用する（[#16660](https://github.com/pnpm/pnpm/issues/16660)）
- リリースノートの本文は途中で切れている
