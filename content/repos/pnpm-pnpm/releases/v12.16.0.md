## 要点

- **グローバルの `--env-file <path>`**（繰り返し指定できる）: コマンドの前に dotenv 形式のファイルから環境変数を読み込む。後のファイルが前のファイルを上書きし、すでに環境にある変数は残す。読み込んだ変数はユーザーレベルの `.npmrc` の置き換えとライフサイクルスクリプトから見える（[#7111](https://github.com/pnpm/pnpm/issues/7111)）
- **シンボリックリンクの `pnpm-lock.yaml` を更新できる**: `symlinkedLockfileTargetDirs`（グローバルの設定か `PNPM_CONFIG_SYMLINKED_LOCKFILE_TARGET_DIRS`）に挙げたディレクトリの中なら、リンク先のファイルに書き込む。リンクは残る。`pnpm-workspace.yaml` のこの設定は無視する（[#17222](https://github.com/pnpm/pnpm/issues/17222)）
- **`pnpm setup --no-modify-path`**: `PATH` に加えずに pnpm を入れ、シェルの設定ファイル・Windows のレジストリ・GitHub Actions の環境ファイルを変えない。追加する行を表示する
- **セキュリティ**: zstd で圧縮したデータの処理でのメモリの露出と確保の扱いの脆弱性を修正（[#17388](https://github.com/pnpm/pnpm/pull/17388)）。pnpm と pnpr の署名が、タイミングで秘密鍵を漏らしうる演算を使わなくなった（共有の成果物・OCI レジストリのトークン・OIDC のログインの状態。[RUSTSEC-2026-0387](https://rustsec.org/advisories/RUSTSEC-2026-0387)）
- **インストール**: 望むリンク先に向けられない依存のシンボリックリンクは、リンクの名前を示すエラーで失敗する（それまでは消し続けてセグメンテーション違反で落ちていた）。並行するワークスペースのインストールで共有の SQLite の索引の行が失われない
- エージェントスキルのリンクが、peer の組み合わせが違う同じバージョンのコピーの間で同じ先を保ち、`ERR_PNPM_AGENT_SKILL_PATH_OCCUPIED` で失敗しない（[#17319](https://github.com/pnpm/pnpm/issues/17319)）。拒否したエントリのパスを含むアーカイブは再試行せずすぐ失敗する（[#17205](https://github.com/pnpm/pnpm/issues/17205)）
- git でホストされた依存を、リンクする新しい場所（グローバル仮想ストアの新しいスロットなど）ごとにビルドする
- リリースノートの本文は途中で切れている
