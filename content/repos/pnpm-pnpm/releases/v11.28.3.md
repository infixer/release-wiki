## 要点

- 同梱の `undici` を 7.29.1 に更新し、セキュリティスキャンで [GHSA-3wwx-pv8p-q78v](https://github.com/advisories/GHSA-3wwx-pv8p-q78v) が報告されなくなった
- 複数の pnpm プロセスが同じストアを使うとき「database disk image is malformed」で失敗したり古いエントリを読んだりしなくなった
- `constructor`・`toString`・`__proto__` のような JavaScript の組み込みプロパティと同じ名前が、依存・カタログ・ワークスペースプロジェクト・レジストリの接頭辞・override の参照・巻き上げ・`pnpm list`/`pnpm why`・コマンド名などで普通に使える（以前はクラッシュ・誤った lockfile・無視が起きていた）
- パッチを当てたパッケージが peer の循環の中にあっても、最新の lockfile を毎回解決し直さない
- POSIX の bin シムとランチャーが Nix のビルド内で動く。固定した pnpm へ知らないオプションを引き渡す
- `allowBuilds` が不正な形なら `ERR_PNPM_INVALID_ALLOW_BUILDS` で失敗する（以前は黙って無視）
- `directories.bin` で bin を宣言した依存を削除しても `node_modules/.bin` に壊れたシムが残らない。カスタムリゾルバーの `shouldRefreshResolution` フックが reject してもクラッシュしない
- `minimumReleaseAge` で `latest` が隠れたとき、同じメジャーのプレリリースを下位メジャーの安定版より優先する

> [!warning] 既知の問題
> v11.28.3 の frozen install は、スキップした任意の依存に作業ディレクトリへのシンボリックリンクを作る。修正は [#16455](https://github.com/pnpm/pnpm/pull/16455)（未リリース）。
