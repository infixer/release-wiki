## 要点

- `cacheDir` がほかのストアの親ディレクトリを指していても、`pnpm store prune` がほかのストアやグローバルのパッケージのデータを消さない
- `pnpm add --global` で入れたコマンドが、そのパッケージのために hoist した依存を見つける。該当するパッケージは `pnpm add --global` で入れ直すと既存のコマンドが更新される（[#17503](https://github.com/pnpm/pnpm/issues/17503)）
- 前の Docker のビルドステージからコピーした `node_modules` で、`pnpm prune --prod` が `ERR_PNPM_EXDEV` で失敗しない（[#17424](https://github.com/pnpm/pnpm/issues/17424)）
- Node.js のランタイムの zip のダウンロードが途中で切れたら再試行し、それでも失敗したら URL を示す（[#17411](https://github.com/pnpm/pnpm/issues/17411)）
- グローバル仮想ストアで、依存の循環の中の 1 つのパッケージの依存が変わると、循環のすべてのパッケージが新しいディレクトリになる（[#17466](https://github.com/pnpm/pnpm/issues/17466)）。循環にある・循環に依存するパッケージは更新後に一度だけ新しいディレクトリに移り、ビルドするものは一度だけ副作用キャッシュを外す
- `pnpm install`・`pnpm rebuild` が、ビルドでスクリプトがネイティブの実行ファイルに置き換わった後に `node_modules/.pnpm/node_modules/.bin` のシムを更新する（[#17402](https://github.com/pnpm/pnpm/issues/17402)）。Node.js の `latest` は最新の安定版を選ぶ（[#17490](https://github.com/pnpm/pnpm/issues/17490)）。単体の `@pnpm/exe` は Node.js 26.13.0 を埋め込む
- 繰り返しのインストール: override や package extension でレジストリのパッケージの依存に加えたローカルのディレクトリを、`package.json` が変わったら解決し直す（`--frozen-lockfile` は古い依存を記録した lockfile で失敗）（[#17486](https://github.com/pnpm/pnpm/issues/17486)）。`injectWorkspacePackages` とプロジェクトごとの lockfile で、injected のプロジェクトが依存するローカルの tarball が置き換わったら lockfile を更新する。pnpmfile の `readPackage` フックだけが依存するローカルの tarball・ディレクトリの変更も検知する（本文はここで切れている）
