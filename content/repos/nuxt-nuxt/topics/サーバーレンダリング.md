## 概要

サーバー側のレンダラー（`packages/nuxt/src/runtime/server/renderer`）まわり。レンダリング中のエラーは、これまで `/__nuxt_error` への新しいリクエストで描画し直していたが、`experimental.inlineErrorRendering`（`compatibilityVersion: 5` でデフォルト有効）を使うとレンダラーの `fetch` 内の try/catch で同じイベントのまま `error.vue` を描画する。この場合、失敗したレンダリングのヘッダー・Cookie は残り、Nitro のミドルウェアやルートルールは 2 回目には通らない。エラーレスポンスの形式は user-agent/accept ヘッダーで切り替えず、API ルートのエラーは常に JSON、Vue アプリのページの描画中のエラーは常に HTML で返す（破壊的変更、エラーのキャッシュがしやすくなる）。エラー時も Cookie は保たれる。また、ペイロードの URL（`_payload.json`）はオリジン相対パスとして解釈される。失敗したレンダリングのレスポンスヘッダーは、投げられたエラー（`error.headers`）ではなくリクエストの状態（`event.context.nuxt['~response-headers']`）に記録され、リクエストをまたいで共有されるエラーでヘッダーが別のユーザーに漏れることはない（未リリース）。vite-server では、サーバーのチャンクが読むアセット URL のヘルパー（`__buildAssetsURL` / `__publicAssetsURL`）を、ビルドディレクトリとビルド ID のハッシュをキーにしてビルドごとに分けた。1 つのプロセスに複数のアプリを import しても、別のアプリのアセット URL で描画されない（未リリース）。
サーバー側では ESM のバンドラー向けビルドの Vue が強制され（重複インストールも防ぐ）、nitro では `process.env.NODE_ENV` による dead-code elimination が有効になり、Vue の `propsCache`・`emitsCache` はリクエスト間で共有される。UI ライブラリ独自のカスタムリンクも RouterLink を経由せずにサーバー描画される（いずれも未リリース）。
描画した HTML はチャンクのまま再利用バッファに書き込んでエンコードし、通常の NuxtLink は SSR のバッファへ直接描画する。インライン化したコンポーネントの style はエントリの style を除いてスタイルシートの link の後に出し、dev やハイドレーション後のクライアントと同じ優先順位になる（いずれも未リリース）。
本番ビルドのサーバーでは、`#build/routes` の遅延ページコンポーネントを `memoizeRouteComponent` で包み、リクエストごとのルーターで同じ import の Promise を使い回す（未リリース）。
v4.6.4（セキュリティリリース）では、本番でサーバーのページ描画に失敗したとき、エラーページとペイロードには `createError` で作ったエラーの message と data だけが入り、信頼できない throw されたエラーの詳細は公開しない。レンダラーのリクエストパスの先頭の二重スラッシュも保たれる。
`inlineStyles` では、`ssr: false` のページとだけ共有する CSS に `<link rel="stylesheet">` を付けない（未リリース）。
さらなる SSR の高速化として、ペイロードの reducer・`mayMatchCurrentRoute`・インライン style・`<RouteProvider>`・`buildAssetsURL` のリクエストごとのコストを減らし、SSR の `<NuxtLink>` の `route` はプロトタイプの getter で遅延解決し、Latin1 以外の文字を含む大きなチャンクは使えるなら `buffer.transcode`（ICU）で UTF-8 にする（Node 24 の遅さへの対策）。HTML からはエントリのスクリプトの modulepreload と `__NUXT_DATA__` の空のコンテナを省き、インライン化した CSS は `disabled` の link でハイドレーション中の再取得を防ぐ。クライアント専用のレスポンスでは、一致したページのチャンクもプリロードする（いずれも未リリース）。
レンダラープラグイン（`addRendererPlugin`、型は `nuxt/server` の `RendererPlugin`）は、レンダラーごとに 1 回専用のフックで呼ばれ、サーバーのランタイムのフックより先に `render:html` などを処理する（Nitro ではレンダラー自身、vite-server では描画するランタイムにバンドル、静的な SPA ではビルド時に実行）。island の head では、共有の配列を `useHead` に渡したときに後のエントリがその配列に push されて別の描画に漏れる問題が直った（いずれも未リリース）。

## 主な API・オプション

- `experimental.inlineErrorRendering` — エラーページをレンダラー内で直接描画する（`compatibilityVersion: 5` でデフォルト有効）
- `captureError` / `onDevError` — インライン描画時に捕捉したエラーが渡される
- `render:html` — エラーページでは元のイベントで発火する
- `/__nuxt_error` — 従来のエラー描画用エンドポイント（インライン描画では使われない）
- `event.context.nuxt['~response-headers']` — 失敗したレンダリングのレスポンスヘッダーの記録先（内部）
- `RendererPlugin`（`nuxt/server`）— レンダラープラグインの型。`({ hooks }) => { hooks.hook('render:html', ...) }` の形で、`render:html` から `event.res.headers` を設定できる
