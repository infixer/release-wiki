## 概要

クライアント側のナビゲーション時のプリフェッチ/プリロード実装。ルートチャンク・レイアウト/ミドルウェアチャンク・`_payload.json`・island の JSON・リソースヒントを、1つの内部スケジューラーでまとめて扱うようになった。タスクはキー（重複排除）・優先度・スコープ（ナビゲーション時のクリーンアップ用）・グループ（遷移先のパス・クエリ単位）を持ち、低速回線やタブ非表示時には破棄せずバックログに保持して条件解消後に再開する。ルート変更時には、遷移先の `meta.layout` の非同期レイアウト（`defineAsyncComponent()` で包まれたもの）を `nuxt:prefetch` プラグインと同じ方法で読み込み、ナビゲーション前に待つ。
表示されたらプリフェッチする `<NuxtLink>` は共有のオブザーバーのキューに入り、ハイドレーション中のリスナーとアイドルコールバックは 1 つにまとめられる。`navigator.connection` の `change` リスナーは、回線の状態で作業を保留したときだけ付ける（いずれも未リリース）。
SSR でページ内のすべての動的 import に出していたプリフェッチの link は、ページがハイドレーションされて操作できるようになってからブラウザにプリフェッチさせる実験的機能になった（クライアントプラグイン `deferred-prefetch.client.ts`。未リリース）。
プリフェッチの URL は `document.baseURI` で解決し、`<iframe srcdoc>` の中のアプリでも初期化できる。抽出した `_payload.json` には `buildId` が入り、別のビルドのペイロードはナビゲーション時ならリロード、プリフェッチ時なら `app:manifest:update` で扱う。ストリーミングの応答では遅延したプリフェッチを link ヘッダーに出さず、dev では island のプリフェッチでページを import しない（いずれも未リリース）。
遅延したプリフェッチのヒントは、アイドルの期限を守る単位に分けて有効にする（リンクが多いページで長いタスクになり TBT が悪化した退行の修正）。app manifest のアイドル時の先読みはやめ、バックグラウンドでルートのプリフェッチが始まったときに読み込む。組み込みのエラーページ（404・500）のチャンクはエントリのプリフェッチの一覧から外した。本番のクライアントビルドでは、`to` が内部の文字列の `<NuxtLink>` をコンポーネントのインスタンスなしで描画し、クリックと表示時のプリフェッチはアプリごとの共有ハンドラーで扱う（いずれも未リリース）。
キャッシュするルート（`isr`・`swr`・`cache`）のペイロード URL には `?_b=<buildId>` を付けず、別のビルドの判定はペイロード自体の `buildId`（`isOutdatedPayload`）に任せる（未リリース）。

## 主な API・オプション

- 内部スケジューラー（`prefetch-scheduler.ts`）— キュー種別ごとの優先度: ルート（cap 4）・レイアウト/ミドルウェア（`route`、cap 4）・`_payload.json`（`payload`、cap 8）・island JSON（`island`、cap 4）・転送されたリソースヒント（`hint`、cap 8）
- Prioritized Task Scheduling API を利用
- `loadPayload()` — 別のビルドのペイロードなら `null` を返す
