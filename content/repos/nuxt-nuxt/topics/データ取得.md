## 概要

`useFetch`・`useAsyncData` とそのファクトリー `createUseFetch`・`createUseAsyncData` まわり。ファクトリーに `addons` オプションが追加され、呼び出し側のオプション追加・マージ後のオプションの書き換え・`middleware` によるハンドラーのラップ・戻り値の拡張などをユーザー側で行えるようになった。アドオンは `defineUseFetchAddon` などで定義し、複数のカスタムインスタンスで再利用できる。`hydrate-never` 境界の中で付ける `serialize: false` は、共有されたオプションを書き換えずローカルに留められる。同じキーのエントリが作り直された後に古いエントリが破棄されても、新しいエントリには影響しない。アドオン機能の追加（#35797）で export が漏れていた、`useAsyncData`・`useFetch` の定義・型付けに必要な型も export されている。クライアントビルドでも `onServerPrefetch` の登録を空の関数として残すことで、`useId()` のサーバー・クライアント間の不一致を防ぎ、`useAsyncData` は Vue 内部の `instance.sp` に頼らなくなった。サーバールートの戻り値の型（`Serialize`）は、インデックスシグネチャを持つ型でも名前付きのキーを保つ。

## 主な API・オプション

- `createUseFetch` / `createUseAsyncData` の `addons` — `useFetch`・`useAsyncData` を拡張するアドオンを渡す
- `defineUseFetchAddon({ setup })` — アドオンを定義する。`setup` は内部の `useAsyncData` 呼び出し前に実行され、返した関数が呼び出し後に `asyncData` を受け取る
- `UseFetchAddonOptions<T>` — アドオンが追加する呼び出し側オプションの型
- `Serialize<T>` — サーバールートの戻り値を JSON にしたときの型（`routeTypedFetch` などで使われる）。インデックスシグネチャ付きの型でも名前付きのキーと optional 修飾子を保つ
