## 概要

`nuxt.config` のオプションとスキーマ（`packages/schema`）、モジュールから設定を操作する `@nuxt/kit` の API まわり。トップレベルの `prerender` が `nitro.prerender` の別名として追加され（`runtimeConfig`・`routeRules` と同じ位置づけ）、トップレベルに同じオプションがある `nitro.*` は非推奨になった。ビルダーに依存しないトップレベルのオプションを使うよう案内されている。モジュールの `setup()` から `updateRuntimeConfig()` を呼んでも、Nitro の初期化前に `NUXT_B8003` の警告が出ないようになった。デフォルトの無視対象に `.wrangler` ディレクトリが加わり、miniflare の書き込みによるリロードの繰り返しが起きない。`@nuxt/kit` の互換性チェックのバージョンの正規表現は nightly のバージョン形式に対応した。`sourcemap.client` / `sourcemap.server` には `'nosource'` を指定でき、ファイル名と行のマッピングは残して元のソース（`sourcesContent`）を含めないソースマップを出力する（Vite・Nitro・webpack / rspack に対応。boolean として読む箇所では `true` 扱い）。webpack の dev で hidden のクライアントソースマップに有効な devtool を使うよう修正された（いずれも未リリース）。
`vite.config.ts` が vite-plus の設定ファイルなら警告を出さない（未リリース）。
v4.6.4 で `devServer.allowedHosts` が加わった（webpack・rspack の dev サーバーも想定外の `Host` ヘッダーを拒否するため、独自のホスト名やトンネルはここに追加する）。`workspaceDir` を設定していないとき、`rootDir` より外に広げるのは明示的なワークスペースのルートか最も近い git リポジトリまでになった。
`workspaceDir` の自動検出では、`gitdir:` で始まる `.git` ファイル（git の worktree・submodule）もリポジトリのルートとして扱う（未リリース）。
`runtimeConfig` の各値は推論されたスキーマとして扱われ、既定値の型に合わせて環境変数での上書きを変換・検証する（nitro v3 が上書きを `destr` で解析しなくなったことへの対応）。値に Standard Schema（Standard JSON Schema も実装したもの）を書けば、型と既定値を指定できる（`z.string()` なら必須）。`typescript.typeCheck` には `'dev'`（`nuxt dev` でだけ型チェック）を指定できる。kit の `updateRuntimeConfig` は nitro に設定全体を渡し、既存の nitro の設定を上書きしない（nitro 側の修正までの応急処置）（いずれも未リリース）。
Standard Schema による `runtimeConfig` では、nitro v2 で `null` と解析される環境変数でもオブジェクトの値は空のオブジェクトにフォールバックする。`@nuxt/kit` の `isNuxtMajorVersion` は Nuxt 5 を受け付け、`getNuxtModuleVersion` は渡された Nuxt のインスタンスを使う。グローバルの `defineNuxtSchema` が閉じた Nuxt のインスタンスを保持しなくなった（いずれも未リリース）。

## 主な API・オプション

- `prerender` — `nitro.prerender` の別名（トップレベル）。今後 Nuxt 独自のプリレンダリング用オプションも追加予定
- `nitro.*`（トップレベルと重複するもの）— 非推奨。トップレベルのオプションを使う
- `updateRuntimeConfig()`（`@nuxt/kit`）— 内部で `tryUseNitro()?.updateConfig()` を使い、Nitro の初期化前でも警告しない
- `sourcemap.client` / `sourcemap.server` の `'nosource'` — `sourcesContent` を含めないソースマップを出力
- `devServer.allowedHosts` — dev サーバーが受け付ける `Host`（v4.6.4）
- `runtimeConfig` の値に Standard Schema — 型・既定値・必須を指定し、環境変数の上書きを変換・検証する（例: `apiSecret: z.string()`、`port: 3000` に `NUXT_PORT=abc` は失敗）
- `typescript.typeCheck` — `true`（dev・build）/ `'build'` / `'dev'`（dev だけ）/ `false`。判定は `@nuxt/schema` の `shouldEnableTypeCheck()`
