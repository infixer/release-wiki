## 概要

Vite・Nitro によるモジュール解決と外部化（externalisation）、レイヤー・型生成などビルドまわり。`vue`・`vue-router` のように dedupe すべきパッケージを絶対パスによる外部化から除外したり、nitro とその暗黙の依存関係をホイスティングに依存せず解決したりする修正が入っている。開発サーバー（vite dev 環境）では `nuxt` 自体が誤って外部化されないようにし、public ファイル探索は1度のインデックス化にまとめられた。レイヤーについては、`node_modules` にインストールしたレイヤーのエントリを明示的にスキャンして依存関係を事前バンドルし、シンボリックリンク経由のレイヤーディレクトリは実パスに解決される。ほかに、開発中のコンポーネント名変更時の import 更新、移したビルドディレクトリでの型の保持、`@nuxt/kit` の peer dependency 範囲の拡大が入っている。`@nuxt/kit` の依存パッケージのインストールは、corepack に依存しない `package-manager-detector` でパッケージマネージャーとコマンドを解決する（Node 26 以降にも対応）。`@nuxt/vite-server` は、cloudflare のようなデプロイ先のプラグインと組み合わせても開発時にアプリと `public/` を配信でき、開発時も `#server-entry` をビルド時と同じレンダラーに解決する。インライン style の URL の書き換えは `js-tokens` で区切り文字（バッククォートを含む）を検出する。Nitro の開発時については、dev ハンドラーの登録を 1 回にし、`buildAssetsDir` の接頭辞が保たれるよう `nitro/vite` の前に応急処置のプラグインを入れている。devtools は 50kb の `@nuxt/devtools-onboard` を依存に持ち、`@nuxt/devtools`（約 50MB）は必要なときに有効にする形になった。

## 主な API・オプション

- 開発者が直接設定する API はほぼ無く、主に Vite/Nitro 内部の解決ロジック・`noExternal` 設定に関する修正
- `optimizeDeps` — ユーザーのディレクトリに無いパッケージも pnpm で解決できるようになった
- `vite.resolve.preserveSymlinks` — シンボリックリンク経由のレイヤーの不具合（[#36401](https://github.com/nuxt/nuxt/issues/36401)）の修正前の回避策
- `@nuxt/devtools-onboard` — `@nuxt/devtools` を後から有効にするための最小限のパッケージ（`nuxt` の依存）
