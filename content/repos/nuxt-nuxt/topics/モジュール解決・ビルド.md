## 概要

Vite・Nitro によるモジュール解決と外部化（externalisation）、レイヤー・型生成などビルドまわり。`vue`・`vue-router` のように dedupe すべきパッケージを絶対パスによる外部化から除外したり、nitro とその暗黙の依存関係をホイスティングに依存せず解決したりする修正が入っている。開発サーバー（vite dev 環境）では `nuxt` 自体が誤って外部化されないようにし、public ファイル探索は1度のインデックス化にまとめられた。レイヤーについては、`node_modules` にインストールしたレイヤーのエントリを明示的にスキャンして依存関係を事前バンドルし、シンボリックリンク経由のレイヤーディレクトリは実パスに解決される。ほかに、開発中のコンポーネント名変更時の import 更新、移したビルドディレクトリでの型の保持、`@nuxt/kit` の peer dependency 範囲の拡大が入っている。`@nuxt/kit` の依存パッケージのインストールは、corepack に依存しない `package-manager-detector` でパッケージマネージャーとコマンドを解決する（Node 26 以降にも対応）。`@nuxt/vite-server` は、cloudflare のようなデプロイ先のプラグインと組み合わせても開発時にアプリと `public/` を配信でき、開発時も `#server-entry` をビルド時と同じレンダラーに解決する。インライン style の URL の書き換えは `js-tokens` で区切り文字（バッククォートを含む）を検出する。Nitro の開発時については、dev ハンドラーの登録を 1 回にし、`buildAssetsDir` の接頭辞が保たれるよう `nitro/vite` の前に応急処置のプラグインを入れている。devtools は 50kb の `@nuxt/devtools-onboard` を依存に持ち、`@nuxt/devtools`（約 50MB）は必要なときに有効にする形になった。Vite 8.1 以降で文言が変わった optimizer のメッセージにも、実行時の依存関係のヒントが出る。絶対パスの transpile ディレクトリの下にある依存関係は Nitro でインライン化せず、宣言していない依存関係にアクセスしないことで pnpm のグローバル仮想ストアへの対応が進んだ。`@nuxt/kit` はモジュールが依存するモジュールを、宣言したモジュールの解決パスから解決する。dev で NUL バイトを含む仮想 CSS（`@unocss/nuxt` など）は、Vite と同じく `/@id/` 経由のリンクになる。`nitroViteEnvironment` を有効にすると、nitro のコンテキストにビルダー環境の型が含まれる。ルートに `vue` の依存が無くても、dev でインライン化した `vue` はバンドラー向けのビルドに解決され（CJS のエントリによる `module is not defined` を回避）、`cloudflare_module` の dev（miniflare）では Nitro が設定した `workerd` の conditions が保たれる（いずれも未リリース）。`nitro: { static: true }` のビルドでは、Nitro を Vite の environment として動かす経路でも `dist` → `.output/public` のリンクを作るようになった（未リリース）。
生成する tsconfig では、モジュールのディレクトリの除外を拡張子ごとの glob で書き、生成した宣言を `include` の先頭に保ち、`nuxt/schema` を `@nuxt/schema` と同じモジュールとして扱う（未リリース）。
`experimental.buildCache` では、`srcDir` の外にある `shared/` もハッシュに含め、キャッシュヒット時もクライアントビルドの状態（`ssr-styles`・`stable-entry`・クライアントマニフェスト）を復元してコールドビルドと同じ HTML を出す。自動 import した `#app` のコンポーザブル（`definePageMeta` など）はサブパスから読み込まれても tree-shake される。dev では `@vite-ignore` の worker の `import.meta` キーを `nuxt:replace` で置換しない。ビルドの高速化として、`ssr: false` のサーバーバンドルに `serverEntry` だけを入れる、サーバーの自動 import のプラグインを 1 回だけ登録する、`fs.allow` の入れ子ディレクトリの除去を `removeNestedDirs` で効率化する、サーバービルドで通常の style ブロックをコンパイルしない、といった変更が入った（いずれも未リリース）。
型チェックは `.nuxt` の `tsBuildInfoFile` を使ってインクリメンタルに実行できる。初期チャンクに V8 のコンパイルヒントを付ける実験的機能が加わり、デコレーターのトークン化・エイリアスの正規化・nitro の互換プラグインの二重登録が減らされた。dev の CSS は重複を除き、Windows・仮想 CSS の SSR の link もハイドレーション後に取り除く（いずれも未リリース）。
`typescript.typeCheck: true` の型チェッカー（vite-plugin-checker）は client 環境の 1 つだけを登録する（ssr のワーカーのリークの修正）。Nitro を Vite の環境として動かす `nuxt dev` では、`nuxt.server.upgrade` から Nitro の dev サーバーへ WebSocket のアップグレードを渡す（いずれも未リリース）。

## 主な API・オプション

- 開発者が直接設定する API はほぼ無く、主に Vite/Nitro 内部の解決ロジック・`noExternal` 設定に関する修正
- `optimizeDeps` — ユーザーのディレクトリに無いパッケージも pnpm で解決できるようになった
- `vite.resolve.preserveSymlinks` — シンボリックリンク経由のレイヤーの不具合（[#36401](https://github.com/nuxt/nuxt/issues/36401)）の修正前の回避策
- `@nuxt/devtools-onboard` — `@nuxt/devtools` を後から有効にするための最小限のパッケージ（`nuxt` の依存）
- `experimental.buildCache` — ビルドキャッシュ。`shared/` もハッシュの対象。キャッシュヒット時はクライアントビルドの状態を `addClientBuildState()`（`@nuxt/kit/internal`、内部 API）で復元する
- `optimization.treeShake.composables` — `#app` に挙げた名前は自動 import 元のサブパスからの import にも適用される
- `tsBuildInfoFile` — 生成する tsconfig で `.nuxt` の中に設定。インクリメンタルモードのときだけ使われ、`nuxt typecheck` などで利用できる
