## 概要

クライアント側のルーター・レイアウト遷移・ルートルールまわり。Vue Router が知らないパス（`public/` のファイルへのリンクなど）へのクライアント側ナビゲーションは、404 を出さずにハードリロードへ切り替える（experimental オプション、デフォルト有効）。アプリ側のルートルールは base URL からの相対パスで照合される。`pages/` を使わない場合のルーターも base URL を考慮し、ミドルウェアのフラグをクリアする。レイアウトが切り替わる遷移では、`NuxtLayout` の `onBeforeLeave` が pending 中の `nuxtApp['~transitionPromise']` を再利用し、離脱したページの head エントリが確実に破棄される。アンカーの href はルーター経由で解決され、`pages/` を使わないユニバーサルルーターの挙動は vue-router に揃えられた。絶対 URL でないリンクの描画は速くなっている（絶対 URL はわずかに重い）。

## 主な API・オプション

- `external` 属性 — クライアント側ルーティングを使わないリンクにする。付け忘れた public ファイルへのリンクはハードリロードで表示される
- `NuxtLayout` / `NuxtPage` — レイアウト・ページの遷移。`nuxtApp['~transitionPromise']` で head エントリの破棄を遅らせる
- ルートルール（`routeRules`）— アプリ側では base からの相対パスで照合
- `setPageLayout()` — レイアウト名、または `false`（型でも許可）を渡す
