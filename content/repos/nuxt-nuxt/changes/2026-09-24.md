## 新機能

### ローディング画面を WebGPU パーティクルの山脈アニメーションに変更（[#36178](https://github.com/nuxt/nuxt/pull/36178)）

> [!tip] 何ができるようになったか
> Nuxt のローディング画面が、WebGPU でパーティクルによる山脈を描画する新しいアニメーションに置き換わった。
>
> - **仕組み**: シェーダー1つ・描画コール1つで、リッジ状の高さマップを遠近法でサンプリングし、スカイラインのオクルージョンも計算して山脈を表現する
> - **UI**: ロゴ周辺は空けてあり、ホバーするとパーティクルに衝撃波が走る。進捗バーは `window.__NUXT_LOADING_STATE__` か `nuxt:loading-state` イベントを読み取り、無ければ不確定表示のまま
> - **フォールバック**: WebGPU が使えない環境では canvas を出さずロゴのみの画面になる。`prefers-reduced-motion` ではアニメーションを止める

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/UIテンプレート・ローディング画面|UIテンプレート・ローディング画面]]

### 開発時の SSR スタックトレースをソースへ正しくマッピング（[#36258](https://github.com/nuxt/nuxt/pull/36258)）

> [!tip] 何ができるようになったか
> 開発中にサーバー側でエラーが起きたとき、スタックトレースが自分のソースコードの位置・コードフレームまで正しくマッピングされるようになった。
>
> - **仕組み**: Nuxt のエラーハンドラー内で、エラーを読み取る前にマッピング処理を行うよう変更。`charset=utf-8` の指定が無いインラインソースマップも読めるようにし、マッピング後の列番号は V8 のスタックと同じ 1-based に統一した
> - **Vite の変換エラー**: vite-node のソケット経由で転送される Vite の変換失敗が `loc`・`plugin`・`pluginCode` を保持するようになり、エラーハンドラーが `message` を再パースせずに正確な位置を表示できる
> - **公開先**: マッピング済みのソースマップは `nitroApp.ssrSourceMaps`（`getSourceMap`・`getCode` など）として Nitro 側に公開される

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/開発時エラー表示|開発時エラー表示]]

### 統一されたクライアント側プリフェッチスケジューラーを追加（[#36391](https://github.com/nuxt/nuxt/pull/36391)）

> [!tip] 何ができるようになったか
> ルートチャンク・レイアウト/ミドルウェアチャンク・`_payload.json`・island の JSON・リソースヒントなど、これまでバラバラな方式で行っていたプリフェッチ/プリロードを、1つの内部スケジューラーに統一した。
>
> - **タスクの単位**: 各プリフェッチ処理は「キー（重複排除用）」「優先度」「スコープ（ナビゲーション時のクリーンアップ用）」「グループ（遷移先のパス・クエリ単位）」を持つタスクとして扱われる
> - **ナビゲーション時**: 進行中の `navigation` スコープの作業は中断してキューを破棄するが、遷移先のペイロードだけは残す
> - **低速回線・非表示タブ**: `saveData` や 2G 回線の検出、タブが非表示、ナビゲーション中といった条件では作業をバックログに保持し、条件が解消すると再開する（以前は単に破棄されていた）
> - Prioritized Task Scheduling API を利用する

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/プリフェッチ・ナビゲーション|プリフェッチ・ナビゲーション]]

## 変更・修正

### dedupe 対象パッケージが importer ベースの外部化対象から除外されるよう修正（[#36363](https://github.com/nuxt/nuxt/pull/36363)）

> [!quote] Before
> nitro のトレーシングに関する問題（nitrojs/nitro#4468、nitrojs/nitro#4456）により、同じベア指定子を指す絶対パスが複数あると、出力に必要なファイルが欠落することがあった（例: 新しいバージョンの vue-router が持つ `vue-router.node.mjs` を、古いバージョンを先に見つけたために nitro がコピーしない）。

> [!success] After
> `vue`・`vue-router` のように dedupe（重複排除）されるべきパッケージについては、絶対パスによる外部化（externalisation）を無視するようにした。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/モジュール解決・ビルド|モジュール解決・ビルド]]

### nitro とその暗黙の依存関係をホイスティングに依存せず解決するよう変更（[#36366](https://github.com/nuxt/nuxt/pull/36366)）

> [!quote] Before
> nitro とその暗黙の依存関係の解決が、パッケージマネージャーのホイスティングに依存する形になっていた（[#35375](https://github.com/nuxt/nuxt/issues/35375)）。

> [!success] After
> ホイスティングに依存せずに nitro とその暗黙の依存関係を解決するよう変更した。以前の試み（[#35380](https://github.com/nuxt/nuxt/pull/35380)）を、現在の nitro 解決の形に合わせて作り直したもの。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/モジュール解決・ビルド|モジュール解決・ビルド]]

### `consola`・`cookie-es`・`hookable` の型を nuxt core の公開 API として切り出し（[#36368](https://github.com/nuxt/nuxt/pull/36368)）

> [!quote] Before
> `consola`・`cookie-es`・`hookable` の型を、Nuxt 自身が追跡できる形の公開 API として持っていなかった。

> [!success] After
> これらの型を nuxt core の API として切り出し、`nuxt/app` の公開 API のうちより多くの部分を Nuxt 自身が持つようにした。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/アプリコンテキスト・ランタイム|アプリコンテキスト・ランタイム]]

### クライアント環境から `unctx` を除去し、単一 `app.config` での `defu` 呼び出しを省略（[#36371](https://github.com/nuxt/nuxt/pull/36371)）

> [!quote] Before
> ブラウザには存在しない `AsyncLocalStorage` のために、クライアント環境でも `unctx`（約 1KB）を読み込んでいた。また `app.config` が1つしか無い場合でも、`defu` による不要なマージ処理を行っていた。

> [!success] After
> クライアント環境では `unctx` を使わないようにし、`app.config` が1つだけの場合は `defu` の呼び出しを省略するようにした。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/アプリコンテキスト・ランタイム|アプリコンテキスト・ランタイム]]

> [!quote] Before
> nitro と vite-server のビルダーが、それぞれ独立に `my-bad` のエラーレポートを組み立て、スタックのマッピングなどを重複して行っていた。
