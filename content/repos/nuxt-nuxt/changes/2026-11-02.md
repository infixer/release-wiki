## 変更・修正

### SSR のプリフェッチのヒントをアプリの準備ができるまで遅らせる（[#36794](https://github.com/nuxt/nuxt/pull/36794)）

> [!quote] Before
> ページ内のすべての動的 import に対してプリフェッチの link を SSR で出力していた。大きなサイトや UI ライブラリを使うサイトでは数が増え、ハイドレーション中に重要な JS・CSS と競合しうる。

> [!success] After
> ページがハイドレーションされて操作できるようになってから、ブラウザにプリフェッチさせる（クライアントプラグイン `deferred-prefetch.client.ts` を追加）。約 690 個の nuxt/ui コンポーネントのデモページで、Lighthouse 13 のモバイル（シミュレーション）の LCP が 1153ms → 1071ms、読み込んだバイト数が 303KB → 288KB。experimental のオプションとスキーマ、実験的機能とパフォーマンスのドキュメントも更新されている（`5.x` ラベル）。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/プリフェッチ・ナビゲーション|プリフェッチ・ナビゲーション]]

### render-list の import を AST を作らずに読む（[#36787](https://github.com/nuxt/nuxt/pull/36787)）

> [!quote] Before
> `nuxt:render-list` プラグインは `renderList`・`ssrRenderList` を含むサーバーのモジュールごとに `parseModule(code, id).program.body` を読み、AST 全体を JS オブジェクトに `JSON.parse` していた。

> [!success] After
> `parseModule(code, id).module.staticImports` を読む（#36784 の `ssr-styles` と同じ変更）。インラインの `type` 指定子があるときだけ AST を作る。12 レイヤー・2,860 コンポーネントのアプリで、サーバー側のフック時間が 918〜977ms → 412〜439ms。ビルド結果は同一（`5.x` ラベル）。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/モジュール解決・ビルド|モジュール解決・ビルド]]
