## 変更・修正

### nitro・vite: `dist` を常に静的出力へリンク（[#36592](https://github.com/nuxt/nuxt/pull/36592)）

> [!quote] Before
> `nitro: { static: true }` で `main` の `nuxt build` を実行すると、v4 のような `dist` → `.output/public` のシンボリックリンクではなく、SSR のソースマップ（`*.map.json`）だけが入った本物の `dist` ディレクトリができていた。Nitro を Vite の environment として動かすときは、レガシーなビルド経路でしかリンクを作っていなかった。また `existsSync` がシンボリックリンクをたどるため、リンク切れの `dist` が置き換えられなかった。

> [!success] After
> Vite の environment の経路でも `compiled` フックで `dist` をリンクする。その経路では誰も読んでいなかったソースマップの書き出しも省き、リンク切れの `dist` も置き換える。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/モジュール解決・ビルド|モジュール解決・ビルド]]

### vite-server: アセット URL のヘルパーをビルドごとに分ける（[#36591](https://github.com/nuxt/nuxt/pull/36591)）

> [!quote] Before
> サーバーのチャンクはプロセス全体のグローバル `__buildAssetsURL` / `__publicAssetsURL` からアセット URL を読んでいた。複数の vite-server のハンドラーを 1 つのプロセスに import すると、最後に import したものがすべてに答え、別のアプリのアセット URL で描画されていた（#36589）。

> [!success] After
> サーバービルドでは `renderBuiltUrl` を包み、式を `globalThis["__nuxt_assets:<hash>"].buildAssetsURL(...)` に書き換える。キーはビルドディレクトリとビルド ID のハッシュ（ビルド ID はコミットハッシュなどで複数アプリで同じになりうるため）。生成したハンドラーが同じキーを `createRendererOptions` に渡してヘルパーを登録する。スコープなしのグローバルも、直接読むコードのために引き続き設定される。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/サーバーレンダリング|サーバーレンダリング]]

### nitro: v2 の `render:response` のリスナーに実際に送るレスポンスを渡す（[#36596](https://github.com/nuxt/nuxt/pull/36596)）

> [!quote] Before
> 互換モードで、（レガシーな）`render:response` フックに古い `event.res` のコピーを渡していた。

> [!success] After
> 実際に送られるレスポンスのステータスとヘッダーを受け取れるようになった。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/サーバー互換性|サーバー互換性]]
