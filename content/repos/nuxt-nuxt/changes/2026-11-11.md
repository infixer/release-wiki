## 新機能

### サーバーに依存しないレンダラープラグイン（`addRendererPlugin`）（[#36601](https://github.com/nuxt/nuxt/pull/36601)）

> [!tip] 何ができるようになったか
> モジュールのコードを特定のサーバーではなくレンダラーに付けられる。`nuxt/server` に移行したモジュールで、Nitro を使わない構成にはサーバーの「インスタンス」が無いため、`@nuxtjs/color-mode` のように初期描画に HTML を足すことができなかった。
>
> - **使い方**: モジュールで `addRendererPlugin(resolve('./runtime/server/renderer'))`。プラグインは `export default (({ hooks }) => { hooks.hook('render:html', (html) => { html.head.push(...) }) }) satisfies RendererPlugin`（型は `nuxt/server`）
> - **挙動**: レンダラーごとに 1 回、専用のフックで呼ばれ、サーバーのランタイムに登録したフック（nitro のプラグインなど）より先に動く。`nuxt/server` から `useRuntimeConfig`・`getRouteRules` などを import でき、`render:html` で `event.res.headers` にレスポンスヘッダーを設定できる。Nitro ではレンダラー自身が実行し、`@nuxt/vite-server` では描画するランタイム（node・workers）にバンドルされる。静的な SPA の描画では、ビルド時にプリレンダーするルートとしてフックを実行する
> - **古い Nuxt**: レンダラープラグインが無い Nuxt では、`addRendererPlugin` は同じファイルを nitro のプラグインとして登録する
> - **嬉しい場面**: Nitro・vite-server のどちらでも動く形で、モジュールから初期描画の HTML やヘッダーを加工したいとき

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/サーバーレンダリング|サーバーレンダリング]]、[[repos/nuxt-nuxt/topics/サーバー互換性|サーバー互換性]]

### `nuxt/server` から `defineHandler` を提供し、`defineEventHandler` を別名に（[#36929](https://github.com/nuxt/nuxt/pull/36929)）

> [!tip] 何ができるようになったか
> Nitro v3 に合わせて `nuxt/server` に `defineHandler` が加わり、`defineEventHandler` は後方互換のための別名になった。
>
> - **使い方**: `import { defineHandler } from 'nuxt/server'`
> - **ドキュメント**: Nuxt v5 向けに、サーバーのコード例すべてに import を書き加えた（`docs/2.directory-structure/1.server.md`・アップグレードガイド）
> - **嬉しい場面**: Nitro v3 と同じ名前でサーバーのハンドラーを書きたいとき

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/サーバー互換性|サーバー互換性]]

### vite-server: 相対パスの `$fetch` をリクエストのコンテキスト付きでプロセス内で処理（[#36919](https://github.com/nuxt/nuxt/pull/36919)）

> [!tip] 何ができるようになったか
> これまで vite-server での相対パスの `$fetch` は解決の基準になるオリジンが無く、アプリに届かなかった。相対パスはアプリのハンドラーにプロセス内で直接送られ、呼び出し元のリクエストイベントのコンテキストも内部の第 3 引数として渡される。
>
> - **注意**: リダイレクトはたどらない
> - **嬉しい場面**: `@nuxt/vite-server` の構成で、サーバー側から `$fetch('/api/...')` のように自分の API を呼びたいとき

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/モジュール解決・ビルド|モジュール解決・ビルド]]、[[repos/nuxt-nuxt/topics/データ取得|データ取得]]

### `useRequestFetch` などのサブリクエストに `Range` ヘッダーを転送しない（[#36924](https://github.com/nuxt/nuxt/pull/36924)）

> [!quote] Before
> ページのリクエストに `Range` ヘッダー（`Range: bytes=0-10` など）があると、`useRequestFetch()` やサーバー側の相対 URL の `useFetch` がそれを内部の API リクエストに転送し、API が `206` の部分的な本文を返してページが壊れたデータで描画されることがあった。

> [!success] After
> 転送しないヘッダーに `range` を加えた（条件付きの `if-*` ヘッダーは既に除外済み）。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/データ取得|データ取得]]
