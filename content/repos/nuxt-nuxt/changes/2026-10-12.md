## 新機能

### `<NuxtLoadingIndicator>` に `finishColor` プロップを追加（[#36533](https://github.com/nuxt/nuxt/pull/36533)）

> [!tip] 何ができるようになったか
> 読み込みが終わったとき（進捗が 100% に達したとき）だけ、ローディングバーを別の色にできる。
>
> - **使い方**: `<NuxtLoadingIndicator color="#a7f3d0" finish-color="#16a34a" />`
> - **優先順位**: エラー時は引き続き `errorColor` が優先。`finishColor` を指定しなければ `color` のままで、既存の挙動は変わらない
> - **嬉しい場面**: 完了時に彩度の高い緑にする、など読み込み完了を色で示したいとき

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/UIテンプレート・ローディング画面|UIテンプレート・ローディング画面]]

### sourcemap に `'nosource'` オプションを追加（nuxt・vite・webpack）（[#36534](https://github.com/nuxt/nuxt/pull/36534)）

> [!tip] 何ができるようになったか
> `sourcemap.client` / `sourcemap.server` に `'nosource'` を指定できる。ファイル名と行のマッピングは残しつつ元のソースコード（`sourcesContent`）を含めないソースマップを生成するので、ソースを公開せずにマップを公開できる（#23547）。
>
> - **使い方**: `defineNuxtConfig({ sourcemap: { client: 'nosource' } })`
> - **Vite（クライアント・SSR）**: `build.sourcemap: true` と `rolldownOptions.output.sourcemapExcludeSources: true`。明示した `vite.build.sourcemap` は従来どおり優先
> - **Nitro**: `sourcemap.server` が `'nosource'` のとき `rollupConfig.output.sourcemapExcludeSources`
> - **webpack / rspack**: `nosources-` 系の devtool（本番は `nosources-source-map`、dev のクライアントは `eval-nosources-cheap-module-source-map`、dev のサーバーは `nosources-cheap-module-source-map`）
> - それ以外でこのオプションを boolean として読む箇所では、`'nosource'` は `true` と同じ扱い
> - **検証**: playground で `client: 'nosource'` にすると、`.map` ファイル 3 件のうち `sourcesContent` を含むものが 0 件になった（`true` では 3 件）。Nitro は既定でサーバーのマップから `sourcesContent` を除くため、サーバー側の違いは playground では見えない

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/設定・スキーマ|設定・スキーマ]]

## 変更・修正

### 型引数で応答の型を指定した fetch でも任意の `baseURL` を受け付ける（[#36523](https://github.com/nuxt/nuxt/pull/36523)）

> [!quote] Before
> 4.6.0 から、`useFetch<{ items: number[] }>('/x', { baseURL: useRuntimeConfig().public.apiBase })` のように応答の型を指定すると `baseURL` が受け付けられず、TS2769 になっていた（4.5.x では動いていた。#36521）。型引数を 1 つ指定すると残りが推論されず、base が既定の `''` に落ちていたため。

> [!success] After
> リクエストの型が自身の既定値に落ちたときは、base の既定を `string` にする。型のテスト（`fetch-types.ts`）を追加。

### vite-server: `spaLoadingTemplateLocation` の指定どおりに SPA ローディングテンプレートを置く（[#36536](https://github.com/nuxt/nuxt/pull/36536)）

> [!quote] Before
> `ssr: false`・`experimental.spaLoadingTemplateLocation: 'within'`・`server.builder: 'vite'` の組み合わせで、`@nuxt/vite-server` がローディングテンプレートを `#__nuxt` の外（`<div id="__nuxt-loader">`）に描画していた。クライアントは `#__nuxt` の中にある前提で Vue のマウントによる置き換えを期待するため、マウント後も `#__nuxt-loader` が消えずに表示されたままだった。

> [!success] After
> `'within'` のときはテンプレートを `#__nuxt` の中に直接描画し、マウント時に Vue が置き換える。既存の Nitro のレンダラーと同じ挙動。`body` の場合の挙動は変わらない（両方のケースのテストを追加）。

### vite・nitro: dev で NUL バイトを含む仮想 CSS を `/@id/` 経由でリンクする（[#36549](https://github.com/nuxt/nuxt/pull/36549)）

> [!quote] Before
> dev で `@unocss/nuxt` を使うと、SSR の HTML に NUL バイトをそのまま含む `<link rel="stylesheet" href="/_nuxt/\0/__uno.css">` が出ていた。HTML のトークナイザーが NUL を U+FFFD に置き換えるため、ブラウザは `/_nuxt/%EF%BF%BD/__uno.css` を要求する。uno はたまたま末尾で解決できたが、スタイルシートが 2 つ注入されていた。

> [!success] After
> Vite 自身と同じように、パスでない ID はリンクにする前に `/@id/` に変換する（`\0` は `__x00__`）。`virtual:foo.css` のような素の仮想 ID にも適用される（これまではたまたま動いていただけ）。

### 離れるページが無いときはページ遷移を始めない（[#36535](https://github.com/nuxt/nuxt/pull/36535)）

> [!quote] Before
> ページ遷移はあってレイアウト遷移が無い状態で、別のレイアウトかつ async setup のページへ移動すると、`nuxtApp['~transitionPromise']` が永遠に pending のままになっていた。`scrollBehavior` と head の破棄がこの Promise を待つため、スクロールせず、前のページのタイトルが残り、以後のナビゲーションでもスクロールしなかった（#36484）。新しいレイアウト内に作られた `<NuxtPage>` の `<Transition>` には離れるページが無く、`_finishTransition()` を呼ぶ唯一の場所である `onAfterLeave` が走らないのが原因。

> [!success] After
> `<NuxtPage>` の `onPending` は、その `<NuxtPage>` が一度ページを解決した後（`hasResolvedOnce`、つまり離れるページがあるとき）だけ遷移を始める。レイアウト遷移を設定している場合は、従来どおり `<NuxtLayout>` が自身の `onBeforeLeave` / `onAfterLeave` で Promise を始めて終わらせる（#36395 の head 破棄の挙動は変わらない）。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/ルーティング・レイアウト|ルーティング・レイアウト]]
