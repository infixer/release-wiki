## 新機能

### `runtimeConfig` を Standard Schema で検証・型変換（[#36905](https://github.com/nuxt/nuxt/pull/36905)）

> [!tip] 何ができるようになったか
> nitro v3 は実行時の設定の上書き（環境変数）を `destr` で解析しなくなり、数値や真偽値もすべて文字列になる。`destr` を戻す（数字に見える文字列が数値になってしまう問題があった）代わりに、`runtimeConfig` の各値を推論されたスキーマとして扱う。値は既定値で、その型が環境変数での上書きを変換する型になる。それで足りない場合は、Standard JSON Schema も実装した [Standard Schema](https://standardschema.dev) を値に書け、型と既定値を指定できる。
>
> - **使い方**: `runtimeConfig: { apiSecret: z.string(), port: 3000, session: z.object({ secure: z.stringbool().default(true), maxAge: z.number().int().optional() }), public: { mode: z.enum(['preview', 'production']).default('preview') } }`
> - **挙動の例**（PR の例より）: `apiSecret: z.string()` は必須で実行時に設定が必要、`port: 3000` に `NUXT_PORT=abc` を渡すと失敗する
> - **嬉しい場面**: 実行時の設定を型付きで検証したいとき、プログラムから設定を定義したいとき（#15366 などの要望をまとめて解決）

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/設定・スキーマ|設定・スキーマ]]

### `typescript.typeCheck` に `'dev'` を追加（[#36164](https://github.com/nuxt/nuxt/pull/36164)）

> [!tip] 何ができるようになったか
> 既存の `'build'` と対になる `'dev'` を `typescript.typeCheck` に指定でき、`nuxt dev` でだけ型チェックし、`nuxt build` では行わない（`true` は両方、`'build'` は build だけ、`false` はどちらも無し）。
>
> - **使い方**: `typescript: { typeCheck: 'dev' }`
> - **実装**: 有効・無効の判定を `@nuxt/schema` の `shouldEnableTypeCheck()` にまとめ、vite・webpack（・rsbuild）の型チェックで共有する
> - **嬉しい場面**: CI では `nuxt typecheck` を `nuxt build` と別に走らせつつ（nx の monorepo など）、ローカルの dev サーバーでは型チェックしたいとき（`$development.typescript.typeCheck` でも同じことはできた）

> [!quote] Before

### perf: Latin1 以外の文字を含む大きな HTML のチャンクを ICU で UTF-8 に変換（[#36892](https://github.com/nuxt/nuxt/pull/36892)）
