## 新機能

### `nuxt.request` の tracing channel を追加（[#36483](https://github.com/nuxt/nuxt/pull/36483)）

> [!tip] 何ができるようになったか
> `@nuxt/vite-server` に切り替えると、srvx・h3 が出していたリクエストの span が無くなり、`nuxt.*` の span に親が無くなっていた。レンダラーの `fetch` を囲む `nuxt.request` の tracing channel を追加し、どのサーバービルダー・ランタイムでも同じ階層の span が得られる。
>
> - **挙動**: `nuxt.render` が `nuxt.request` の中に入れ子になる。Nitro 構成では span が 1 つ増える（害はないとしている）
> - **性能**: PR のベンチマークでは、tracing のオン・オフやサブスクライバーの有無でほぼ差が無い（約 113〜115 µs）
> - **注意**: 現状 vite-server は API だけのルートに対応していないため、すべての HTTP パスを覆うには channel の位置の変更や再送が必要になるかもしれない、と PR に書かれている

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/トレーシング|トレーシング]]

### vite-server: デプロイ先のプラグインと組み合わせても開発サーバーが動くよう修正（[#36491](https://github.com/nuxt/nuxt/pull/36491)）

> [!quote] Before
> `@nuxt/vite-server` を cloudflare のプラグインと使うと、`nuxt dev` がアプリも `public/` のファイルも配信しなかった。cloudflare のプラグインがすべてのリクエストに応答する post ミドルウェアを登録しており、ドキュメントと public アセットは Vite のミドルウェアの後で処理されていたため。

> [!success] After
> public アセットと（`ssr: false` のとき）ナビゲーションや `text/html` を受け付けるリクエストを、他のプラグインの post ミドルウェアより前に処理する。開発時も `#server-entry` をビルド時と同じレンダラーに解決し、デプロイ先の環境が自身のモジュールグラフで実行できるようにした。Nuxt のランタイム依存はその環境の dep optimizer から除外する（リクエスト中に検出されてリロードが起きるのを防ぐ）。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/モジュール解決・ビルド|モジュール解決・ビルド]]、[[repos/nuxt-nuxt/topics/開発時エラー表示|開発時エラー表示]]
