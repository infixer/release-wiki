## 新機能

### テンプレートの auto-import コンポーネントを Vue のテンプレートコンパイラーで解決（[#36763](https://github.com/nuxt/nuxt/pull/36763)）

> [!tip] 何ができるようになったか
> auto-import したコンポーネントを、コンパイル後の出力から復元するのではなく、Vue のテンプレートコンパイラーのカスタム `nodeTransforms` で解決するようになった。
>
> - `<Foo />` は正規表現での出力の書き換えをやめ、テンプレートコンパイラーが import する
> - `<LazyFoo hydrate-on-visible />` のハイドレーション戦略は同じパスで読み取る（SFC の名前変更はしない）
> - `<ClientOnly>` と `.client` のスロットは、oxc での再パースではなく codegen 前に AST から取り除く
> - テンプレートから消えた `<script setup>` のバインディングは記録し、ほかで参照されていなければ `TreeShakeTemplatePlugin` で削除する
> - コンパイル後のテンプレート AST で動くので、`<template lang="pug">` でも遅延ハイドレーションの props が使えるようになった
> - lazy・client-only・server コンポーネントは importer ごとの小さな仮想モジュールから import し、チャンク分割は今までと同じ
> - スクリプトの `resolveComponent('X')` と JSX の `h(X)` は引き続きコンポーネントローダーのプラグインで扱う
> - **嬉しい場面**: 大きなアプリでのコンパイルの手間が減り、pug のテンプレートでも同じ機能が使える（#31604 を解決）

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/コンポーネント・テンプレート|コンポーネント・テンプレート]]

### Nuxt の知識を使ったテンプレートの診断 `experimental.templateDiagnostics`（[#36754](https://github.com/nuxt/nuxt/pull/36754)）

> [!tip] 何ができるようになったか
> Vue のコンパイラーだけでは見つけられない、アプリのページやサーバーコンポーネントに依存するテンプレートのミスを、ビルド時に警告する。`experimental.templateDiagnostics` で、デフォルト有効。
>
> - `NUXT_B4025` — どのページのルートにも一致しない静的な `<NuxtLink to>`（または `href`）。サーバールート・`public/` のファイル・外部サイトへのリンクなら `external` を付ける
> - `NUXT_B3014` — サーバーコンポーネントへの `v-on`・`v-model`（`@error` は可）
> - `NUXT_B3015` — サーバーコンポーネントの props や `<NuxtIsland>` の `props` / `context` に、インラインの関数・クラス・`new X()`、または `<script setup>` のトップレベルの関数・クラスを渡している
> - **嬉しい場面**: `<NuxtLink to="/abuot">` のようなタイポをビルド時に見つけたいとき（警告にはソースの位置と修正方法が出る）

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/コンポーネント・テンプレート|コンポーネント・テンプレート]]

### `onNuxtReady` に `timeout` と `signal` オプション（[#36743](https://github.com/nuxt/nuxt/pull/36743)）

> [!tip] 何ができるようになったか
> `onNuxtReady` のコールバックがいつまでも遅れないよう `timeout` を指定でき、`signal` で保留中のコールバックを取りやめられるようになった（ドキュメントも追加）。
>
> - **使い方**: `onNuxtReady(() => { /* ... */ }, { timeout: 2000, signal: controller.signal })`、`onBeforeUnmount(() => controller.abort())`
> - **嬉しい場面**: アプリの準備ができる前にコンポーネントがアンマウントされたとき、コールバックを飛ばしたい場合

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/アプリコンテキスト・ランタイム|アプリコンテキスト・ランタイム]]

### kit: 生成するプロジェクトのビルド情報を `buildDir` に保存（[#36746](https://github.com/nuxt/nuxt/pull/36746)）

> [!tip] 何ができるようになったか
> 生成する tsconfig に `.nuxt` の中の `tsBuildInfoFile` を設定し、Nuxt の型チェックをインクリメンタルに実行できるようにした。`nuxt typecheck` やほかのツールが使える。
>
> - インクリメンタルモードを有効にしていなければ何も起きない

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/モジュール解決・ビルド|モジュール解決・ビルド]]

### vite: 初期チャンクに V8 のコンパイルヒントを出力（[#36758](https://github.com/nuxt/nuxt/pull/36758)）

> [!tip] 何ができるようになったか
> エントリ・レイアウト・ページのチャンクと、それらが静的に import するチャンクの先頭に、V8 の明示的なコンパイルヒント（`//# allFunctionsCalledOnLoad`）を付ける実験的機能（experimental のオプションとドキュメントを追加）。
>
> - Chrome 136 以降は、ストリーミング中にメインスレッド外でこれらのチャンクを先にコンパイルする。ほかのブラウザはコメントを無視する
> - Nuxt UI のマーケティングページの計測で、ハイドレーション 477ms → 311ms、読み込み時の TBT 137ms → 40ms、最長タスク 187ms → 90ms
> - **嬉しい場面**: ハイドレーションの大部分が関数の遅延コンパイルに使われているとき

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/モジュール解決・ビルド|モジュール解決・ビルド]]

### `router.options.sensitive` は `nuxt.config` からだけ読む（破壊的変更）（[#36732](https://github.com/nuxt/nuxt/pull/36732)）

> [!tip] 何が変わったか
> vue-router の `sensitive` オプションを実行時に変えられないようにした。ルートルールのチェックをビルド時に行うため（アップグレードガイドとカスタムルーティングのドキュメントも更新）。

> [!warning] 移行が必要
> `app/router.options.ts` などで実行時に `sensitive` を設定していた場合は、`nuxt.config` の `router.options.sensitive` で設定する。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/ルーティング・レイアウト|ルーティング・レイアウト]]

### 大文字・小文字を区別しないルーティングで、大文字・小文字に依存するルートルールを拒否（[#36733](https://github.com/nuxt/nuxt/pull/36733)）

> `sensitive: false` のルーティングで大文字・小文字に依存するルートルールを書くと、ルートルールをすり抜けられる可能性があった（ほぼ誰も踏んでいないと思われる設定ミス）。

> [!success] After

### nitro: 大文字・小文字を区別しないルートルールでワイルドカードの末尾を保つ（[#36761](https://github.com/nuxt/nuxt/pull/36761)）

> [!success] After

### `definePageMeta` から setup 専用の値を巻き上げない（[#36751](https://github.com/nuxt/nuxt/pull/36751)）

> [!quote] Before
> ページが `defineProps` の値など setup 専用の値を `definePageMeta` に渡すと、そのページだけでなくアプリのすべてのルートが 500 になっていた。

> [!success] After
> 巻き上げる内容を調べ、setup の状態にアクセスして例外になるものを検出する（診断も追加）。判断できないとき（メタの中で関数を直接呼ぶなど）は小さな try/catch で包み、アプリ全体が 500 になるのを防ぐ。

### 外部へのナビゲーションでアプリのスコープの破棄を遅らせる（[#36713](https://github.com/nuxt/nuxt/pull/36713)）

> [!quote] Before
> 新しい location を代入する前にアプリのスコープを止めていたため、古いページがまだ表示されているうちに head のエントリが消えていた（遅いリダイレクトのときなど）。

> [!success] After
> スコープの破棄は、ページが実際にアンロードされる `pagehide` で行う。ページがアンロードされない外部ナビゲーション（ダウンロード・204 のレスポンス・同じドキュメント内のハッシュ）でも、スコープが止まったままにならない（#36659 を解決）。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/ルーティング・レイアウト|ルーティング・レイアウト]]

### `useCookie` の CookieStore 同期が `refresh` で書き直しを繰り返さないように（[#36673](https://github.com/nuxt/nuxt/pull/36673)）

> [!quote] Before
> `useCookie(..., { refresh: true, maxAge })` で、Chromium で CookieStore の `change` イベントが届くと、Cookie を書き直し続ける無限ループになっていた（4.6.0 / #36006 からの退行、#36656）。一時停止中に発火したトリガーで watcher が再実行され、`refresh: true` では `isEqual` の判定を飛ばして書き込み、`maxAge` で有効期限が更新されるたびに新しい `change` が起きていた。

> [!success] After
> 外部からの `handleChange` の更新を反映している間は、`syncing` フラグで `writeClientCookie` を止める。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/アプリコンテキスト・ランタイム|アプリコンテキスト・ランタイム]]

### ハイドレーションの修飾子は lazy の接頭辞の後だけで照合（[#36750](https://github.com/nuxt/nuxt/pull/36750)）

> [!quote] Before
> `Line.vue` と `TimeLine.vue` があると、`<TimeLine />` が `Line` を描画していた。名前がハイドレーション戦略の名前で始まるコンポーネントすべてで同じことが起きていた。

> [!success] After
> 正規表現を直し、ハイドレーションの修飾子は `Lazy` の接頭辞の後にあるときだけ扱う。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/コンポーネント・テンプレート|コンポーネント・テンプレート]]

### インライン化したコンポーネントの style をスタイルシートの link の後に出力（[#36714](https://github.com/nuxt/nuxt/pull/36714)）

> [!quote] Before
> コンポーネントの style は、どのスタイルシートの link よりも前に `<style>` としてインライン化されていたが、ハイドレーション時に Vite は同じチャンクの CSS を `<head>` の末尾に追加する。そのため詳細度が同じルールが衝突すると、ハイドレーションで見た目が変わっていた（#36056 で共有チャンクの重複 link を出さなくなってから増えた）。

> [!success] After
> エントリの style は link の前に残し、残りのコンポーネントの style は link の後に出す。本番の SSR でも、詳細度が同じならコンポーネントの CSS がグローバルの CSS に勝ち、dev やハイドレーション後のクライアントと一致する（#36620 を解決。#33041 は未解決）。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/サーバーレンダリング|サーバーレンダリング]]

### 描画した HTML をチャンクごとにエンコード（perf）（[#36719](https://github.com/nuxt/nuxt/pull/36719)）

> [!quote] Before
> ページに非 Latin1 の文字（`→` など）が 1 つでもあると、V8 は連結したドキュメント全体を 2 バイト文字列として持つため、UTF-8 へのエンコードがかなり遅くなっていた。

> [!success] After
> Vue の SSR の出力を描画したチャンクのまま保ち、HTML を変更するものが無ければ各チャンクを再利用するバッファ（上限 4MB）に書き込む。変更されたときは従来どおり連結して `createResponse` する。約 250KB のドキュメントで、`→` を 1 つ含む場合は 870µs → 498µs（-43%）、ASCII のみの場合は 324µs → 450µs（+39%、約 4ms の描画のごく一部）。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/サーバーレンダリング|サーバーレンダリング]]

### NuxtLink の SSR を高速化（perf）（[#36759](https://github.com/nuxt/nuxt/pull/36759)）

> [!quote] Before
> SSR で NuxtLink ごとに `router.resolve` を呼び、コンポーネントのインスタンスを作って描画していた。

> [!success] After
> アクティブになり得ないリンクでは `router.resolve` を省き、通常の NuxtLink はインスタンスを作らずに SSR のバッファへ直接描画する。300 ルート・500 リンクのページで、どのルートにも一致しないリンクは 5.32 → 1.20、別のルートに一致するリンクは 3.75 → 1.11 になった。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/サーバーレンダリング|サーバーレンダリング]]

### `<NuxtLink>` のフックを 1 つのアイドルコールバックにまとめる（perf）（[#36755](https://github.com/nuxt/nuxt/pull/36755)）

> [!quote] Before
> 表示されたらプリフェッチするリンクが N 個あるページでは、ハイドレーション中の `app:suspense:resolve` リスナーが N 個、アイドルコールバックが 2N 個登録されていた。

> [!success] After
> リンクを共有のオブザーバーのキューに入れ、リスナーもアイドルコールバックも 1 個にした（`IntersectionObserver.observe` の呼び出しは N 回のまま）。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/プリフェッチ・ナビゲーション|プリフェッチ・ナビゲーション]]

### nitro, vite: Windows と仮想 CSS の dev の SSR の link をハイドレーション後に取り除く（[#36765](https://github.com/nuxt/nuxt/pull/36765)）

> [!quote] Before

> [!success] After
