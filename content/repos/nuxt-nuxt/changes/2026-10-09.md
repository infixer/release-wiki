## 変更・修正

### `useId` のハイドレーション不一致を防ぐため、クライアントでも `onServerPrefetch` の登録を残す（[#36430](https://github.com/nuxt/nuxt/pull/36430)）

> [!quote] Before
> 本番のクライアントビルドで `onServerPrefetch` が tree-shaking により丸ごと消え、サーバーとクライアントで Vue の非同期境界が変わることがあった。そのため `useId()` がサーバーとクライアントで別の ID を生成し、ハイドレーション不一致が起きていた（#36428）。

> [!success] After
> クライアントビルドでも `onServerPrefetch` の登録を空の `() => {}` として残す（サーバー専用のハンドラーのコードは引き続きクライアントのバンドルから除ける）。`useAsyncData` は Vue 内部の `instance.sp` を直接使う回避策に頼らなくなった。tree-shaking の回帰テストを追加。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/データ取得|データ取得]]

### kit・nitro: 1 回の登録で、どちらの Nitro メジャーでも dev ハンドラーが同じパスに一致するように（[#36515](https://github.com/nuxt/nuxt/pull/36515)）

> [!quote] Before
> 両方の Nitro メジャーで同じパスを扱うため、モジュールは dev ハンドラーを 2 回登録する必要があった（例: `@nuxt/fonts` は `/_fonts` と `/_fonts/**` を登録）。nitropack v2 では `/foo/**` が何にも一致せず、nitro v3 では `/foo` が `/foo` だけに一致していた。

> [!success] After
> nitropack v2 では、`addDevServerHandler` が `/foo/**` のベースパスも登録する（`addServerHandler` は #36325 から同様）。nitro v3 では、互換レイヤーが v2 の dev ハンドラーをルート以下のミドルウェアとしてマウントし、`event.path` からベースを取り除く。`/foo`・`/foo/**` のどちらも「`/foo` とその下」に一致する。`NUXT_B9004` はミドルウェアとして登録された dev ハンドラーだけで報告される。

> [!info] 対象
> 影響するのは `nuxt2` のハンドラーだけ。`nuxt`・`nitro3` の variant は、nitro v3 / h3 v2 に合わせて引き続きルートに完全一致する。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/サーバー互換性|サーバー互換性]]

### vite-server: SSR 無効時、設定された `outDir` を public ディレクトリとして使う（[#36501](https://github.com/nuxt/nuxt/pull/36501)）

> [!quote] Before
> Cloudflare の Vite プラグインは出力ディレクトリを変更するが、その設定が使われず、書き出したファイルが期待する場所に置かれなかった。

> [!success] After
> SSR 以外の環境では、設定された `outDir` を public ディレクトリとして使う。クライアントの出力をサーバーの出力と分けられる、SSR 無効時だけに適用する。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/モジュール解決・ビルド|モジュール解決・ビルド]]

### kit: 見つからないサブパスが属するパッケージをインストールする（[#36507](https://github.com/nuxt/nuxt/pull/36507)）

> [!quote] Before
> `ensureDependencyInstalled` には PostCSS プラグインの設定キーがそのまま渡されていた。`postcss.plugins: { 'tailwindcss/nesting': {} }` のサブパスが存在しないと `pnpm add -D tailwindcss/nesting` を提案・実行し、pnpm が `owner/repo` の GitHub 省略形と解釈して失敗。手でインストールしても直らず、起動のたびにプロンプトが出ていた（nuxt/cli#1603）。

> [!success] After
> インストールコマンドに渡す前に指定をパッケージ名に縮める（`tailwindcss/nesting` → `tailwindcss`、`@scope/pkg/sub` → `@scope/pkg`）。サブパスの属するパッケージが既にインストール済みならプロンプトを出さない（呼び出し側は失敗を報告する。PostCSS プラグインなら `NUXT_B7007`）。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/モジュール解決・ビルド|モジュール解決・ビルド]]

### vite: インストール済みパッケージ内の仮想 import で依存関係スキャンを止めない（[#36477](https://github.com/nuxt/nuxt/pull/36477)）

> [!quote] Before
> Nuxt 4.6 で i18n を使うアプリでは、開発時の依存関係スキャンが止まり、事前バンドルが飛ばされていた（#36473、nuxt-modules/i18n#4162）。#36208 で増えたスキャン対象に i18n の `NuxtLinkLocale.js` が含まれ、その `#components` の import を、Vite が i18n 自身の package.json の `imports` から解決しようとしてエラーになっていた（スキャンでは Nuxt の変換が走らない）。

> [!success] After
> スキャン中に解決できない `#` の import は、スキャン対象から外す。事前バンドルが再び動く。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/モジュール解決・ビルド|モジュール解決・ビルド]]

### `Serialize` のオブジェクト型を JSON に揃える（[#36503](https://github.com/nuxt/nuxt/pull/36503)）

> [!quote] Before
> インデックスシグネチャを持つ型では `SerializeObject` の `Omit` の中でシグネチャだけが残り、名前付きのキーがすべて消えていた。Zod の `.catchall()`・`z.looseObject()`・`.passthrough()` はこうした型を推論するため、`routeTypedFetch` でそれを返すルートの型から名前付きのフィールドが落ちていた（#36500）。

> [!success] After
> `Omit` を通さないキーの再マッピングで同じ取捨を行い、名前付きのキー・シグネチャ・optional 修飾子を保つ。使われなくなった `FilterKeys` は削除。

⏳ 未リリース · トピック: [[repos/nuxt-nuxt/topics/データ取得|データ取得]]

### `setPageLayout` の型で `false` を許可（[#36506](https://github.com/nuxt/nuxt/pull/36506)）

> [!quote] Before
> #33805 で引数の型が `PageMeta['layout']`（`false` を含む）から `keyof NuxtLayouts` に変わり、`false` を渡すと型エラーになっていた（実行時は動いていた）。

> [!success] After
> 型でも `false` を受け付けるように戻した。
