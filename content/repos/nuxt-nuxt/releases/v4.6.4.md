## 要点

v4.6.4 はセキュリティリリース（[compare changes](https://github.com/nuxt/nuxt/compare/v4.6.3...v4.6.4)）。Nuxt の [8 件のアドバイザリ](https://github.com/nuxt/nuxt/security/advisories)を修正し、Nitro の [3 件](https://github.com/nitrojs/nitro/security/advisories)を修正した `nitropack` 2.13.6 を取り込む。できるだけ早い更新が推奨されている（取り込んだ Release 本文は途中で切れているため、以下はその範囲の要約）。

> [!warning] 挙動の変更（多くのアプリには影響しない見込み）
> 1. **本番のエラーの詳細**: サーバーでページの描画に失敗したとき、エラーページとペイロードには `createError` で作ったエラーの message と data だけが入り、それ以外は取り除かれる。
> 2. **dev サーバーの `Host` の確認**: webpack・rspack の dev サーバーも Vite と同じく、想定外の `Host` ヘッダーのリクエストを拒否する。独自のホスト名やトンネルを使う場合は、新しい `devServer.allowedHosts` に追加する。
> 3. **`workspaceDir` の検出**: `workspaceDir` を設定していないとき、`rootDir` より外に広げるのは明示的なワークスペースのルートか最も近い git リポジトリまで。
> 4. **nitropack のキャッシュするルート**: `cache`・`swr`・`isr` のルートルールは `GET`・`HEAD` だけをキャッシュし、cookie を設定する・`Cache-Control: private` / `no-store` を送る応答は保存しない。ワイルドカードの `proxy`・`redirect` ルールは、解決した宛先がルールの範囲から出るリクエストを拒否する。
> 5. **ルートルールとエンコードされたスラッシュ**: エンコードされたスラッシュを含むパスにもルートルールが一致する（`/api%2Fadmin` は `/api/**` の対象）。

- **修正（nitro）**: unrouting 0.3.2・nitropack 2.13.6 を必須に、大文字・小文字を区別しないルートルールでワイルドカードの末尾を保つ、レンダラーのリクエストパスの先頭の二重スラッシュを保つ
- **修正（nuxt）**: island のハッシュに曖昧さのないエンコードを使う、信頼できない throw されたエラーの詳細を公開しない、末尾のスラッシュを線形時間で取り除く
- **修正（dev サーバー）**: vite-server でワイルドカードのリダイレクトの末尾を一致したセグメントから解決、rspack・webpack の dev ミドルウェアで想定外の `Host` ヘッダーを拒否、禁止された dev リクエストで webpack の hot middleware を飛ばす、設定の読み込み後に CLI が許可するホストを含める、`devServer.allowedHosts` を追加（schema・nitro・vite）
