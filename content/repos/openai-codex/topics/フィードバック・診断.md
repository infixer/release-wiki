## 概要

利用状況・設定・機能フラグをレポートに記録する内部の診断/フィードバック機構。この期間、サンプリングリクエストごとに許可されたスカラー設定値と個別の機能フラグを明示的に記録するようになり、設定されたコンテキストウィンドウの上書き値と実際の適用上限を区別できるようになった。あわせてレポートのタグ数上限が引き上げられた。2026-10-05 の回では、`codex doctor` のレポートに設定された TUI モード（`fullscreen` / `scrollback`）が表示されるようになった。2026-10-23 の回では、app-server に診断レポートをアップロードせずにサーバーのホスト上へ ZIP で保存する RPC が入った（アップロードが無効でも使え、200 MiB・添付 128 件まで）。2026-10-28 の回では、既定で無効の `critical_path_timing` でルートエージェントのターンのツールのクリティカルパスを記録できるようになり、CUA のツール呼び出しの開始のイベント `codex_cua_tool_call_started` が入った（いずれも未リリース）。

## 主な API・オプション

- レポートのタグ数上限 — 64 → 512（上限到達時も既存の値は更新可能）
- `tags_json` — レポートメタデータへの展開
- `codex doctor` の `configured TUI mode` — `tui.fullscreen_transcript` が有効なら `fullscreen`、無効なら `scrollback`（人間向け・JSON の両方）
- 診断レポートのローカル保存（`FeedbackSaveParams` / `FeedbackSaveResponse`）— 絶対パスの `savePath` に ZIP を保存し `savedPath`・`threadId`・`promptHash` を返す。既存のファイルは置き換えず、`includeLogs` に従う
- `critical_path_timing`（既定は無効）— 直接のツールの振り分け・実行ロックの受け渡し・ツールのまとまりをターンの計時につなぐ。未対応の依存（CodeMode・承認のレビューなど）は記録しない
- `codex_cua_tool_call_started` — Node REPL のコネクターでの `js` の MCP 呼び出しの開始のイベント（ツールの引数は含まない）
