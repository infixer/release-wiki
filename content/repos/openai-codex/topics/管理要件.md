## 概要

管理者が `requirements.toml`（クラウド管理の requirements を含む）などの managed requirements で、ユーザー設定より優先して Codex の機能を制御する仕組み。2026-10-02 の回では、デスクトップアプリでの音声の許可を制御する `in_app_voice` と、Web サイトによるブラウザのアノテーションツールの利用を制御する `browser_annotation_api` が、stable・既定で有効な機能ゲートとして追加された。requirements で `false` にするとユーザー設定で `true` にしていても無効になり、ユーザー設定そのものは書き換えない。2026-10-07 の回では、ブラウザ拡張のリクエストヘッダー `browser_use.extension.request_headers` を requirements で指定し、`config/requirements/read` で読めるようになった。優先度の高い層はリスト全体を置き換える。2026-10-23 の回では、新しい Desktop のワークスペースの保存先を指定する `application.storage.default_project_parent`・`application.storage.projectless_workspace_root` が入り、ローカルの設定より優先され、`config/requirements/read` で読めるようになった。2026-10-26 の回では、`config_server` を設定すると独自の設定サーバー（`<base_url>/codex/config/bundle`）から管理された設定のバンドルを読み込むようになった（OAuth のセッション、エンドポイントと認可の ID ごとのキャッシュ）。

## 主な API・オプション

- `in_app_voice` — デスクトップアプリでの音声の許可。許可しても音声が使えることやプロバイダの対応を保証するものではない
- `browser_annotation_api` — デスクトップアプリで Web サイトがアノテーションツールを開いたりカスタマイズしたりすることの許可（ユーザー自身の通常のアノテーション操作とは別）
- `browser_use.extension.request_headers` — `name`/`value` の組のリスト。`config/requirements/read` では `browserUse.extension.requestHeaders`。値はそのまま保持し、Rust のデバッグ出力では伏せる
- `application.storage.default_project_parent` / `application.storage.projectless_workspace_root` — 絶対パスのみ。`desktop.defaultProjectParent`・`desktop.projectlessWorkspaceRoot` に適用し、その設定への書き込みを拒否
- `config_server` — 管理された設定のバンドルの取得先。無ければ ChatGPT のバンドル。検証エラーは設定の中身を含まない汎用のメッセージ
