## 概要

スレッド（会話セッション）の起動・再開・状態管理まわり。直近では、最初のターン前のスレッドもアーカイブできるようになり（アーカイブ前に永続化）、スレッド起動時に作成元の接続を先に登録して Responses WebSocket のハンドシェイクで attestation を要求できるよう修正された。以前の回では、アップロード画像のファイル ID の表示履歴への反映や、スレッド起動メタデータとリプレイ履歴の分離も行われている。2026-09-30 の回では、手動・ターン後のコンパクションで利用上限に達した場合も、ターンの lifecycle 拡張にエラーが通知されるようになった。2026-10-02 の回では、スレッドの再開で書き込みの所有権を得てから最新のリプレイ履歴を返し、変わっていないスナップショットは再利用するようになった。ゴールの編集に `origin` が付き、ユーザーの編集はモデルの履歴に残る。`--remote` のセッションコマンドは接続先サーバーの認証を使い、`TurnAborted` は中止コールバックの完了後に出る。

## 主な API・オプション

- `ThreadStartupMetadata` / `startup_metadata()` — リプレイ履歴を含まないスレッド起動メタデータ。再合流時は渡された再開履歴から起動レスポンスを再構築
- `active_turn_environment_selections` — `initial_environments` を参照し、ターン開始時点で捕捉された環境選択を返す
- `thread/goal/set` / `thread/goal/clear` の `origin` — `user` / `automatic`。省略時と自動更新はユーザーの認可として扱わない
- `ThreadStore::resume_thread` — リプレイのコンテキストを返す
- `queue` / `archive` / `unarchive` / `delete` の `--remote` — 指定したリモートの app-server に直接接続
