## 概要

スレッド（会話セッション）の起動・再開・状態管理まわり。直近では、最初のターン前のスレッドもアーカイブできるようになり（アーカイブ前に永続化）、スレッド起動時に作成元の接続を先に登録して Responses WebSocket のハンドシェイクで attestation を要求できるよう修正された。以前の回では、アップロード画像のファイル ID の表示履歴への反映や、スレッド起動メタデータとリプレイ履歴の分離も行われている。2026-09-30 の回では、手動・ターン後のコンパクションで利用上限に達した場合も、ターンの lifecycle 拡張にエラーが通知されるようになった。2026-10-02 の回では、スレッドの再開で書き込みの所有権を得てから最新のリプレイ履歴を返し、変わっていないスナップショットは再利用するようになった。ゴールの編集に `origin` が付き、ユーザーの編集はモデルの履歴に残る。`--remote` のセッションコマンドは接続先サーバーの認証を使い、`TurnAborted` は中止コールバックの完了後に出る。2026-10-05 の回では、`SessionConfiguredEvent` から `initial_messages` が削除され、起動イベントにリプレイ履歴が付かなくなった。ページ分割の履歴に保存するコマンド出力は 64 KiB までに制限され、必須の MCP の起動中に切断されたスレッドもアンロードされるようになった。2026-10-07 の回では、コンパクションの置き換え履歴に更新された指示やスキルのカタログを含む完全な初期コンテキストを入れるようになり、misalignment のエラーには `reviewTarget` が載るようになった。2026-10-09 の回では、`thread/list` に除外するスレッド ID のリスト `excludedThreadIds` が入り、DB のみの一覧やカーソルの繰り返しの失敗は履歴の終わりと区別して JSON-RPC エラー `-32603` を返すようになった。2026-10-12 の回では、app-server に実験的なスレッドの既読状態（`thread/read`・`thread/list` の `readState`・`readStates`、`thread/readState/changed` 通知、revision 確認付きの `thread/readState/update`）と、ID でアイテムを取得する `thread/items/read` が入った。`turn/start` のツールの出力に `retain` を付けるとモデル履歴に残すよう要求でき、中断された goal の自動継続も無活動の 3 ターンの上限に数えるようになった。2026-10-14 の回では、リモート V2 のコンパクションをバックグラウンドで先行して要求する非同期コンパクション（既定で無効の `async_compaction`、しきい値 `model_async_compact_threshold_percent`）の設定と土台が入り、フォアグラウンドのコンパクションで互換性のあるバックグラウンドの結果を再利用できるようになった。ターンの記録の仕上げ中は入力の受け付けを閉じ、保存したスレッドの権限は設定の読み込み中（ネットワークの準備と検証の前）に復元するようになった。2026-10-16 の回では、コンパクションの失敗時に途中の出力を履歴に残さない修正、圧縮したロールアウト（`.jsonl.zst`）からのセッションの検索・再開の修正、設定の更新後も実行中のターンを復旧できる修正、内容の出所（`ContentItemMetadata`）の追跡が入った（未リリース）。2026-10-21 の回では、app-server がアイドルのスレッドをアンロードするまでの時間を各スレッドの `thread_unload_delay_secs` から決めるようになり（`0` で即時。`experimentalPredictionMode` の fork でも上書きできる）、ロールアウトの圧縮・復元で Unix の所有者・権限・macOS の ACL を保つようになった。2026-10-23 の回では、スレッドの再開で保存済みのサービスティア・推論の要約・パーソナリティを戻し、巻き戻しでもモデルの設定を引き継ぐようになった。2026-10-26 の回では、`thread/fork` の `attachToSource` でソースに結び付けた fork を作れるようになり（実験的）、`thread/sample` で `threadSource` を指定できるようになった。2026-10-28 の回では、app-server の `ThreadItem` に `startedAtMs`・`completedAtMs` の時刻が付き、信頼しない追加のコンテキストに `name` を付けられるようになり（`untrusted_as_tool_output` の機能フラグも登録）、`features.rollout_budget.enforce_limit = false` でロールアウトの予算を上限で止めない助言のモードにできるようになった（いずれも未リリース）。2026-10-30 の回では、`review/start` の `"detached"` の配信が削除されインラインのレビューだけになり（別スレッドは `thread/start` の後に `review/start`）、`thread/unarchive` が子孫のスレッドも戻すようになった。`notify` のためにサンプリングのプロンプト全体を持ち続けないようにもなった（いずれも rust-v0.166.0）。

## 主な API・オプション

- `ThreadStartupMetadata` / `startup_metadata()` — リプレイ履歴を含まないスレッド起動メタデータ。再合流時は渡された再開履歴から起動レスポンスを再構築
- `active_turn_environment_selections` — `initial_environments` を参照し、ターン開始時点で捕捉された環境選択を返す
- `thread/goal/set` / `thread/goal/clear` の `origin` — `user` / `automatic`。省略時と自動更新はユーザーの認可として扱わない
- `ThreadStore::resume_thread` — リプレイのコンテキストを返す
- `queue` / `archive` / `unarchive` / `delete` の `--remote` — 指定したリモートの app-server に直接接続
- `SessionConfiguredEvent` — `initial_messages` を削除（リプレイ履歴は付かない）
- 保存するコマンドの `aggregated_output` — ページ分割の履歴では切り詰めの印を含めて 64 KiB まで（先頭と末尾を残す）
- `reviewTarget` — misalignment のエラーに載る不透明なレビューの対象。対象に基づく `misalignment_override` はターンのリクエストに残る（コンパクションと外部の MCP のメタデータからは除く）
- `thread/list` の `excludedThreadIds` — 除外するスレッド ID（最大 100 件）。件数制限の前に適用してページを補充する。不正な値は `-32602`
- `thread/list` の `useStateDbOnly: true` — 状態データベースを照会できないときやカーソルが繰り返されたときは `-32603`（再試行可）。`nextCursor: null` の成功応答が履歴の終わり
- `thread/read` の `readState` / `thread/list` の `readStates`（実験的）— `firstUnread` と不透明な `revision` を持つ既読のレシート
- `thread/readState/update`（実験的）— `threadId`・`expectedRevision`・`{type:"read"}` / `{type:"unread"}`。revision の不一致は `-32600`（`readStateConflict`）。成功時は `thread/readState/changed` を購読者に通知
- `thread/items/read`（実験的）— `threadId`・`turnId`・1〜100 件の `itemIds` で永続化したアイテムを保存順に取得
- `TurnToolOutput` の `retain`（`turn/start`、既定は `false`）— ツールの出力をモデル履歴に残すよう要求。コアでは `TurnInput::AnnotatedResponseItem`
- `async_compaction`（既定は無効、真偽値か `[features.async_compaction]`）/ `model_async_compact_threshold_percent`（既定 65、1〜100）— バックグラウンドで先行するリモート V2 のコンパクション
- `thread_unload_delay_secs` — スレッドごとのアンロードまでの遅延（秒）。`0` で購読者・処理が無くなりしだいアンロード
- `thread/fork` の `attachToSource`（実験的）— 通常の一覧に出さない結び付けた fork。`thread/list` の `attachedToThreadId` で探す。結び付いたスレッドがあるとソースを削除できない
- `thread/sample` の `threadSource` — 一時的な fork のスレッドのソース（既定は `thread_sample`）
- `ThreadItem.startedAtMs` / `completedAtMs` — アイテムの開始・完了の Unix ミリ秒（null がありうる）。ライブの通知・ターンの履歴・再開で保つ
- `AdditionalContextEntry.name` — `untrusted` のコンテキストだけに付けられる名前（`[a-z][a-z0-9_]{0,63}`）。不正なら `turn/start`・`turn/steer` の invalid-request のエラー
- `untrusted_as_tool_output`（開発中、既定は無効）— 信頼しないコンテキストを名前付きのツール出力として描画
- `features.rollout_budget.enforce_limit`（既定 `true`）— `false` で予算を使い切ってもターンを続ける（集計とリマインダーは続ける）
