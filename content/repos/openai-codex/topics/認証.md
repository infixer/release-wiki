## 概要

TUI のオンボーディングで行う ChatGPT へのサインイン（ブラウザでのサインイン）まわり。直近では、embedded サーバーとローカルデーモンの app-server でもログイン URL をブラウザで自動的に開くようになり（リモートのワークスペースでは従来どおり自動では開かない）、ブラウザを開いている最中にログイン完了が届いても対応できるよう、ブラウザを開く前に保留中のログイン状態を設定するようになった。サインイン画面の描画で読み取りロックを二重に取得してデッドロックしうる問題も解消された。2026-09-30 の回では、ChatGPT サインイン成功画面から「Before you start」の前置きが消え、権限・承認のドキュメントへのリンクと、ChatGPT プランのレート制限・学習データの設定が適用される旨が明記された。2026-10-02 の回では、embedded の app-server の設定発見（bootstrap）をログイン・ワークスペース変更後も維持しつつ、以前のアカウントのコンテンツへのアクセスは取り消すようになった。rust-v0.159.3 では、ChatGPT でサインインしたローカルセッションにアカウントのセキュリティ設定のリマインダーが入った。2026-10-12 の回では、サインアウト中や API キーの利用時は、app-server の起動時・接続の初期化時のワークスペースのルーティングのための読み取り（ChatGPT 認証が必要）を省くようになった。2026-10-14 の回では、macOS のユーザー確認（生体認証）のプロンプトの取り消しを、鍵のアクセス制御のポリシーを `LAContext` で明示的に評価する方式で確実にした。2026-10-21 の回では、Responses API プロキシの認証が共通の `Auth` の抽象にまとめられ、GitHub Actions の OIDC でのトークン取得（`GithubOidc`）と、JWT のサブジェクトトークンを OpenAI のアクセストークンに交換するフェデレーションの認証（キャッシュと先回りの更新、`401` での取り直し、失敗時の 1〜30 秒の指数バックオフ）の部品が入った。2026-10-28 の回では、`sk-proj-fedramp-`・`sk-svcacct-fedramp-` の API キーを既定で政府向けのエンドポイント（`gov.api.openai.com`・`gov.chatgpt.com`）に振り分け、`X-OpenAI-Fedramp: true` を送るようになった。モデルへのリクエストには `ModelClient::with_runtime_auth` によるオプトインのランタイムの認証（試行ごとのアサーションの署名、WebSocket の再接続）が入った（いずれも未リリース）。2026-10-30 の回では、ランタイムの認証を `ProviderAuthContext` でモデルのプロバイダーとカタログの取得にも共有し、ランタイムの登録に API の組織・プロジェクトを含めるようになった（rust-v0.166.0）。

## 主な API・オプション

- `AppServerTarget` — 接続先（embedded / ローカルデーモン / リモート）に応じて、ログイン URL をブラウザで開くかどうかを判断
- Responses API プロキシの `Auth` — 認証ヘッダーとリダイレクトのポリシーを供給する抽象（静的な API キー・`GithubOidc`・フェデレーション）
- FedRAMP の API キー（`sk-proj-fedramp-`・`sk-svcacct-fedramp-`）— 既定の OpenAI API は `https://gov.api.openai.com/v1`、ChatGPT のバックエンドは `https://gov.chatgpt.com/backend-api/`。明示的なエンドポイントの指定が優先
- `ModelClient::with_runtime_auth` — ランタイムの認証をモデルへのリクエストに適用（プロバイダーとランタイムのマネージャーが同じ資格情報を共有することが条件）
