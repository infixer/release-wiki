## 概要

app-server をバックグラウンドで共有実行する daemon モードと embedded モードの切り替え。この期間、機能フラグの上書きを指定していても、共有デーモンと両立できる内容であれば embedded モードに強制されず共有デーモンを使えるようになった。デーモン側の機能設定は起動前に確認され、不一致や非対応の場合は警告のうえ embedded モードにフォールバックする。worktree セッションからのデーモン自動起動にも対応した。直近では、コントロールソケットのパスが Unix ソケットのパス長制限を超える場合に、パスを解決して接続を再試行するよう修正された。2026-10-02 の回では、デーモンが起動する app-server に `--analytics-default-enabled` を渡し、分析を既定で有効にするようになった（`analytics.enabled = false` で無効化可能）。2026-10-05 の回では、リモートコントロールの WebSocket の自動再接続がジッター付きの指数バックオフ（5 秒〜30 秒）になり、60 秒以上続いた接続でだけバックオフがリセットされるようになった。2026-10-07 の回では、Unix の app-server の制御ソケットの終了時に、起動時のロックファイルも削除されるようになった。2026-10-12 の回では、共有のバックグラウンドサーバーとの機能の互換性の確認が、コマンドラインで明示的に上書きした機能だけに限られ、設定ファイルや既定値の違いでは警告や再起動の要求が起きなくなった（安定版 rust-v0.162.1 のリリースノートにも記載）。2026-10-14 の回では、`codex app-server daemon restart` で `--enable`・`--disable`・真偽値の `-c features.*` を適用し、以後の再起動のために保存するようになった（不正な切り替えは停止・保存の前に拒否）。2026-10-16 の回では、WinGet のパッケージからのインストール、使わなくなったリリースの安全な削除（`selection-history`）、Unix での更新処理のソケットのパス長と起動の準備完了の修正が入った（いずれも未リリース）。rust-v0.163.0 では `/daemon` からの再起動に対応した。2026-10-19 の回では、app-server の WebSocket・Unix ドメインソケットの zstd 圧縮を `features.app_server_websocket_compression` で有効にできるようになり、macOS で管理されたデーモンにバックグラウンドの優先度（`taskpolicy -b`）を適用しなくなった。

## 主な API・オプション

- `experimentalFeature/list` — 起動前にデーモン側の機能設定を確認する問い合わせ
- `suppress_unstable_features_warning` — デーモンモードでも上書き可能に
- `codex app-server daemon restart --enable/--disable/-c features.*` — 再起動時に機能の上書きを適用して保存
- `features.app_server_websocket_compression`（既定は無効）— TCP の WebSocket と Unix ドメインソケットで、クライアントが提示すれば zstd 圧縮を交渉。TUI のデーモンの起動時にも上書き可能
