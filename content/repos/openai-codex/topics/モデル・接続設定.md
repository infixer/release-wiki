## 概要

使用するモデル・サービスティアの選択、ワークスペースに応じた接続ルーティング、ネットワークプロキシの初期化まわり。この期間は、`service_tier = "flex"` を明示指定した場合に fast mode 無効時やカタログ非対応時でも設定が保持されるよう修正され、Amazon Bedrock 向けリクエストからは非対応の `service_tier` が除外されるようになった。app-server のワークスペース発見処理はモデルリクエストのルーティングに接続され、推論エフォート上書きの無効化はスレッド再開後にも正しく適用されるようになった。standalone のネットワークプロキシの起動時の初期化不備も修正されている。2026-09-30 の回では、TUI の履歴でモデルプロバイダを実効設定の入れ子の `config` から読むよう修正された。安定版 rust-v0.159.1 では GPT-6.1 Sol が同梱カタログと Amazon Bedrock のカタログの既定モデルになった。2026-10-02 の回では、Responses の過負荷・リクエスト回数超過のエラーでもサーバーの再試行の指示があれば再試行し、WebSocket から HTTP へのフォールバックは `Retry-After` の時刻まで待つようになった。2026-10-05 の回では、ストリームの `response.failed` イベントの `response.error.headers` にある `Retry-After` にも従い、利用上限のメッセージより有効なヘッダーを優先するようになった。2026-10-07 の回では、標準の Responses のリクエストでも基本の指示をトップレベルの `instructions` ではなく `input` の先頭の `developer` メッセージとして送るようになり（差分のツール履歴でも記録）、Responses Lite の差分のツール更新では名前空間の更新・削除の案内が明確になった。2026-10-09 の回では、Amazon Bedrock の GPT-6.1 Sol（Mantle の `openai.gpt-6.1-sol`、Runtime の `global.`・`us.` の各モデル）に `ultrafast` のサービスティアが加わり、`/ultrafast` が使えるようになった。安定版 rust-v0.161.0 で GPT-6.1 Sol が同梱・Bedrock のカタログの既定のモデルになっている。2026-10-14 の回では、`max_output_tokens` などの不完全な応答を `ResponseIncomplete` の終端のエラーとして扱い、再試行やコンパクションのモデルのフォールバックをしないようになった。2026-10-21 の回では、復旧や再試行で連続した推論の強さの更新（`configuration_update`）を、Responses のリクエストでは最新の 1 つにまとめるようになった（保存される履歴は変えない）。2026-10-23 の回では、プロバイダーのモデルカタログの更新がアクセスの拒否以外で失敗したときは最後に成功したカタログを保ち、ツール検索が無効にならないようになった。2026-10-26 の回では、モデルカタログで書き込み可能なルートの権限の文言と `history`・`notes`・`new_context`・`get_context_remaining` のツールの定義を上書きできるようになり、プロバイダーの `model_not_found` は再試行しない終端の失敗になった。安定版 rust-v0.165.0 では、組み込みの Google Cloud Vertex AI のプロバイダー（`model_provider = "gcp"`）と GPT-6.1 Terra が入った。2026-10-28 の回では、`model_providers.gcp.credential_file` で GCP のプロバイダーの認証に使う ADC のファイルを指定できるようになった（未リリース）。安定版 rust-v0.166.0 では、GPT-6.1 Terra が組み込み・Vertex AI・Amazon Bedrock のモデルカタログに入り、`model_provider = "openai"` を明示してもオンボーディングで Bedrock の設定を選べるようになった。

## 主な API・オプション

- `service_tier = "flex"` — fast mode 無効時・モデルカタログ非対応時も保持。Amazon Bedrock 向けリクエストからは除外
- `ReasoningEffortOverride` — 無効時はスレッド再開後も保存済み `configuration_update` をリクエストから除外
- ワークスペースルーティング（Responses HTTP・圧縮・WebSocket）— アカウントプロセッサがリゾルバとして解決
- GPT-6.1 Sol — 同梱のモデルカタログと Amazon Bedrock（Mantle・Runtime）のカタログで既定のモデル（rust-v0.159.1）
- 基本の指示 — `input` の先頭の `developer` メッセージとして送信（安定した ID 付き）。HTTP・WebSocket のリクエストの型から `instructions` を削除
- `ultrafast`（サービスティア）— Bedrock の GPT-6.1 Sol で `/ultrafast` から選べる（オプトイン）
- `ResponseIncomplete` — サーバーが返した理由を保つ不完全な応答のエラー。再試行しない
- `writable_root` / `writable_roots`（モデルカタログの権限のメッセージ）— `{{ roots }}` を 1 つ含むテンプレート。不正なら同梱の文に戻る
- `modelNotFound` — HTTP 400・403・404 やストリームのエラーの `model_not_found`。再試行せずにターンを終える
- `model_providers.gcp.credential_file` — Google の ADC のファイルの絶対パス。認証コマンドの環境に `GOOGLE_APPLICATION_CREDENTIALS` として渡す（親プロセスの環境は変えない）
