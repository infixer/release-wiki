## 新機能

### app-server でモデルプロバイダーの一覧と設定の書き込み（[#58845](https://github.com/openai/codex/pull/58845)、[#58876](https://github.com/openai/codex/pull/58876)）

> [!tip] 何ができるようになったか
> app-server に `modelProvider/list` と `modelProvider/config/write` が追加され、クライアントからモデルプロバイダーの一覧の取得と設定の保存ができるようになった。
>
> - `modelProvider/list` は OpenAI と明示的に設定したプロバイダー、プロバイダーごとの設定、選択中の既定のプロバイダーを返す。設定の要件・レイヤーの優先順位・ユーザー設定の有効性から `canEdit`・`canChangeDefault` を報告する。ゲートウェイの認証は資格情報を解決せずに説明し、表示に向かないエンドポイントの URL は省く（#58845）
> - `modelProvider/config/write` はカスタムのゲートウェイを作成し、既存のカスタムのゲートウェイ・Bedrock・GCP の設定にパッチを当てる。省略したフィールドは値を保ち、明示的な `null` はユーザーの上書きを消す。保存は共有の設定のキューで後勝ちに適用し、フィールドの編集可否と検証を守り、公開していない認証の設定は保つ（#58876）
> - 保存してもプロバイダーの選択と認証は変えない。`model/list` が使うプロバイダーを保存すると、次のアクセスでカタログを取り直す（#58876）
> - API の文書と、生成した JSON スキーマ・TypeScript の型・Python のモデルを追加

### ローカルの履歴の発見を現在の ChatGPT アカウントに絞る（[#58918](https://github.com/openai/codex/pull/58918)）

> [!tip] 何ができるようになったか
> `thread/list` と `thread/search` に `currentAccountOnly`（既定は `false`）が追加され、TUI の履歴の発見・再開のピッカー・タスクのメンションで有効になった。
>
> - 新しく作るスレッドはアカウントのスコープ付きになり、記録した作成者のユーザーまたはアカウントの ID が現在のログインと一致する必要がある。古いスレッドや作成者の ID が無いスレッドは共有のまま。API キーでのログインでは引き続きすべてのローカルの履歴が見える
> - 再開と revert でもスコープを保つ（古いバイナリがマーカーを落とした場合は元のロールアウトのメタデータにフォールバック）。fork は新しいスレッドのスコープになる
> - スレッド ID による直接のアクセスは引き続き使える

⏳ 未リリース · トピック: [[repos/openai-codex/topics/セッション・スレッド管理|セッション・スレッド管理]]

### CLI のスレッドの再開でアカウントを確認する機能フラグ（[#58890](https://github.com/openai/codex/pull/58890)）

> [!tip] 何ができるようになったか
> 既定で無効の `cli_resume_account_check` を追加。`codex-tui` と `codex_exec` で有効にすると、記録した作成者のユーザーやワークスペースが現在の ChatGPT アカウントと違うローカルのスレッドの再開・アタッチを拒否し、元のアカウントでサインインするよう促すエラーを返す。
>
> - 作成者の ID をスレッドのメタデータに保存し、再開の履歴を読み込む前に確認する
> - タグの無いスレッド・他のクライアント・比較できる ChatGPT アカウントの無い認証モードでは従来どおり

### 直接の Guardian のレビューでパッチと権限のリクエストを評価（[#58899](https://github.com/openai/codex/pull/58899)、[#58903](https://github.com/openai/codex/pull/58903)、[#58931](https://github.com/openai/codex/pull/58931)）

> [!tip] 何ができるようになったか
> `guardian_review` が、記録した `exec_command` の呼び出しに加えて、ネイティブの `apply_patch` の呼び出しと最後の `request_permissions` の呼び出しも評価できるようになった。
>
> - パッチは既存の準備・承認のロジックで評価し、適用はしない。承認が不要なら評価を省く（#58899）
> - `apply_patch` として傍受した `exec_command`（heredoc）も、実行時と準備を共有して検証済みのパッチを評価する。以前は直接のレビューで拒否されていた（#58931）
> - 権限のリクエストは権限を与えずに評価する。履歴の途中の権限のリクエストは引き続き拒否し、承認のポリシーが `never` のときや granular のポリシーで権限のリクエストが無効なときは評価を返さない（#58903）

⏳ 未リリース · トピック: [[repos/openai-codex/topics/Guardian|Guardian]]

### メッセージボードの単体の HTTP の MCP サーバーとプラグイン（[#58904](https://github.com/openai/codex/pull/58904)、[#58908](https://github.com/openai/codex/pull/58908)、[#58909](https://github.com/openai/codex/pull/58909)）

> [!tip] 何ができるようになったか
> `codex-message-board-mcp` がメッセージボードの議論のツールを `/mcp` で提供する単体の HTTP サーバーになり、通常の MCP の設定で接続できるようになった。既存の SQLite のボードと読み取り専用の Codex のレジストリを使う。
>
> - ベアラー認証が必須で、`threadId`・`sessionId` のメタデータを永続化したエージェントのメンバーシップと照合する。`--allowed-host` で許可する HTTP のホストを追加できる。再利用できる `serve_http` のライブラリの入口も公開（#58904）
> - `message-board` のプラグインで接続情報を配布する。既定の接続先は `http://127.0.0.1:7777/mcp`、ベアラー認証に `CODEX_MESSAGE_BOARD_TOKEN` を使い、サーバーを必須とする。接続先は `mcp_servers.codex_message_board` で上書きでき、プラグインをインストールしてもサーバーは起動しない（#58908）
> - `launch_in_memory()` と `LocalServer` で、生成したベアラーの資格情報付きのループバックの HTTP のエンドポイントを起動できる。`add_board(session_id, host)` でセッションごとにインメモリのボードを登録し、SQLite のレジストリは使わない。ハンドルを破棄すると HTTP・MCP のセッションを取り消し、`shutdown().await` は完了まで待つ（#58909）
> - **嬉しい場面**: 子のエージェントが投稿した決定を、再起動した親が同じボードから読みたいとき（テストのシナリオ）

⏳ 未リリース · トピック: [[repos/openai-codex/topics/マルチエージェント|マルチエージェント]]、[[repos/openai-codex/topics/MCP|MCP]]

### 既存のリアルタイムの通話に呼び出し側のチャンネルでアタッチ（[#58953](https://github.com/openai/codex/pull/58953)）

> [!tip] 何ができるようになったか

## 変更・修正

### `daemon_auto_start` の機能フラグを廃止し、共有のデーモンを常に使う（[#58940](https://github.com/openai/codex/pull/58940)）

> [!quote] Before
> 対象のインタラクティブな起動で共有のデーモンを起動・再利用するかは `features.daemon_auto_start` に従い、リモートコントロールのデーモンの適格性もこのフラグを確認していた。

> [!success] After
> フラグに関係なく、対象のインタラクティブな起動では共有のデーモンを起動または再利用する。リモートコントロールのデーモンの適格性もフラグを確認しない。共有のバックグラウンドのサーバーを使わないときは `--no-daemon` を使う。

> [!warning] 移行が必要
> `daemon_auto_start` は削除扱いになり、設定した値は移行の告知付きで無視、managed requirements の値は警告付きで無視される。デーモンを使わずに起動したい場合は `--no-daemon` を指定する。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/デーモン|デーモン]]

### 一時的な HTTP のフォールバックの後に WebSocket に戻る（[#58950](https://github.com/openai/codex/pull/58950)）

> [!quote] Before
> 一時的な WebSocket の失敗で、接続が回復してもセッションの残りの間ずっと HTTP を使い続けていた。

> [!success] After
> HTTP のフォールバック中に裏で WebSocket の接続を確かめ、準備できた接続を次のリクエストで使う（HTTP のリクエストは遅らせない）。回復は実際のリクエストで確認し、最初の応答を 5 秒まで待つ。HTTP 426 や回復のタイムアウトではセッションの残りを HTTP のままにする。回復した接続が出力の前に失敗したら、通常の再試行の回数を使わずに HTTP で送り直す。確認は頻度を制限し、`Retry-After` の期限を守る。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/モデル・接続設定|モデル・接続設定]]

### プロバイダーの設定後のモデルの選択を修正（[#58945](https://github.com/openai/codex/pull/58945)）

> [!quote] Before
> プロバイダーの設定後も、新しいスレッドがサーバーの起動時のプロバイダーで作ったモデルの管理を使うことがあり、既定のモデルがモデルのピッカーと食い違っていた。

> [!success] After
> スレッドのプロバイダーが起動時と違えば、そのスレッドの設定からモデルの管理を作る。Amazon Bedrock の設定が成功したらモデルのカタログを無効にし、以後のモデルの一覧が設定したプロバイダーを反映する。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/モデル・接続設定|モデル・接続設定]]

### 最後のトランスクリプトの書き出し中に受け付けたステアを処理する（[#58877](https://github.com/openai/codex/pull/58877)）

> [!quote] Before
> 通常のターンがトランスクリプトを書き出している間に受け付けた入力が、最後の保留中の入力の確認から漏れ、ターンの完了時に処理されないまま残ることがあった。

> [!success] After
> ステアの受け付けを閉じるのと同時に保留中の入力をアトミックに確認する。入力があれば同じターンでサンプリングを再開し（MCP の起動の要件は保つ）、更新した回答でターンを完了する。

### スレッドのページ分けで同じ時刻のスレッドを飛ばさない（[#58886](https://github.com/openai/codex/pull/58886)）

> [!quote] Before

### メッセージボードの HTTP サーバーの終了時に状態を解放する（[#58933](https://github.com/openai/codex/pull/58933)）

> [!quote] Before
> 接続中の従来の MCP のセッションや HTTP の keep-alive の接続が、終了後もメッセージボードの状態を持ち続けることがあった。保留中のボードのバインディングがツール呼び出しを送る前に取り消す必要もあった。

> [!success] After
> HTTP の処理を終えた後に MCP のセッションを明示的に閉じ、状態を解放するまでバインディングを追う。終了時は保留中のバインディングを取り消し、すでに送ったボードの操作は完了させる。`LocalServer::shutdown` は後片付けを待ち、破棄は後片付けを始めるだけであることを明確にした。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/マルチエージェント|マルチエージェント]]

### ストリーミング中の回答を会話に割り当てた幅で折り返す（[#58927](https://github.com/openai/codex/pull/58927)）

> [!quote] Before
> ストリーミング中の回答や計画は、ターミナルの幅と違うことがある会話に割り当てた幅で折り返す必要があった。また、新しい出力が無いのにリサイズで新しいアクティビティが報告されないようにする必要があった。

> [!success] After
> 会話のレイアウトを準備するときに、割り当てた幅でライブのストリームを折り返す。表示だけの折り返しでは観測したリビジョンを更新し、`New activity` を出さない（未読の出力の通知は保つ）。
