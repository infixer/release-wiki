## 新機能

### Code Mode に Promise の決着順に結果を受け取るヘルパー（[#51126](https://github.com/openai/codex/pull/51126)）

> [!tip] 何ができるようになったか
> Code Mode の JavaScript に、入力が決着した順に結果を消費するためのグローバル関数が 2 つ追加された。
>
> - `as_settled(promises)` — fulfilled・rejected のレコードを決着順に返す非同期イテレータ。消費側が処理中でも結果はキューに保持される
> - `stream_settled(promises, emit)` — 同じレコードをコールバックに渡す。呼び出しごとに await し、コールバックのエラーは伝播する
> - レコードは `index`・`status` と `value` または `reason` を持つ。イテラブルの入力は位置のインデックス、`Map` はキーを保持。Promise・thenable・通常の値を受け付ける

### Code Mode でランク付きのツール検索 `tools.tool_search`（[#51209](https://github.com/openai/codex/pull/51209)）

> [!tip] 何ができるようになったか
> 既定で無効の機能 `code_mode_tool_search` を有効にすると、モデルがツール検索に対応している場合、Code Mode で `await tools.tool_search({query: "...", limit: 8})` が使える。
>
> - BM25 でランク付けした遅延ツールを `{tools: [{name, description}]}` で返す。呼び出し可能な名前と、後のコードセルで使う TypeScript の宣言を含む
> - 結果は件数制限の前に現在のステップの入れ子のツールのポリシーで絞り込み、名前空間の制限やスキーマの予算を維持する
> - 既存の `ALL_TOOLS` によるカタログの発見と説明文の上書きはそのまま使える

### 環境ごとに必須のスキルを指定する `skills.required`（[#51157](https://github.com/openai/codex/pull/51157)）

> [!tip] 何ができるようになったか
> `environment/add` と `environments.toml` で、環境ごとに `skills.required` のリストを指定できるようになった。
>
> - 推論の前に、指定したスキルが有効で、選択された環境から提供されていることを確認する。足りなければ（環境のセットアップが失敗した場合も含め）モデルへのリクエスト前にターンを失敗させる
> - 環境の選択が外れたらその要件は適用しない。スキルのカタログを持たない隔離された Guardian のレビュアーは対象外

### Windows 10 のドライブレターのパスでの no-follow のファイル操作を修正（[#51511](https://github.com/openai/codex/pull/51511)）

> [!quote] Before
> Windows 10 では、厳格なネイティブの open が DOS のドライブのエイリアス自体をリパースポイントとして拒否することがあり、通常のドライブレターのパスで no-follow のファイル操作ができなかった。

> [!success] After
> 拒否されたドライブレターの open を、検証したローカルのボリュームのルートからの相対で再試行する。ルートはリパース属性の無い物理ディスクのボリュームのディレクトリであることを要求し、その下のパスには `OBJ_DONT_REPARSE` を保つため junction は引き続きブロックされる。
