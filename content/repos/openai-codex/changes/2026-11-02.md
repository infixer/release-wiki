## 新機能

### TUI のコマンドセンターを embedded のセッションでも使える（[#58238](https://github.com/openai/codex/pull/58238)、[#58239](https://github.com/openai/codex/pull/58239)、[#58240](https://github.com/openai/codex/pull/58240)）

> [!tip] 何ができるようになったか
> これまで共有の app-server（デーモン）が必要だったエージェントのコマンドセンターを、embedded のセッションでも開けるようになった。`codex agents --no-daemon` も受け付け、embedded の app-server でコマンドセンターを開く。
>
> - embedded のセッションでもコマンドセンターでのチャットの切り替え・セッションの一覧が使える。読み取り専用の会話や安全のための対処のメニューからも移動できる（#58238）
> - セッションをアーカイブ・削除すると TUI を終了せずにコマンドセンターへ戻る。ディレクトリの信頼やアーカイブ済みセッションの確認を取り消したときも戻る（#58238、#58239）
> - embedded のサーバーを終了すると実行中のセッションやサイドの会話が止まる場合は、終了前に確認する（#58238）
> - `codex agents` は通常のデーモンの起動・適格性・互換性のチェックを通り、該当する場合は embedded にフォールバックする。デーモンが動いていても `--no-daemon` なら embedded を使う（#58239）
> - embedded のセッションでもタスクのツール（`set_thread_title` など）を使える。タスクのツールと worktree のツールは `codex_tui` の MCP の名前空間にまとめられ、embedded のセッションの `codex_worktrees` の名前空間を置き換える（#58240）
> - **嬉しい場面**: デーモンを使わない構成でも、複数のチャットをコマンドセンターから切り替えたいとき

⏳ 未リリース · トピック: [[repos/openai-codex/topics/TUI|TUI]]、[[repos/openai-codex/topics/デーモン|デーモン]]

### コマンドセンターとセッションのピッカーに未読の表示（[#58263](https://github.com/openai/codex/pull/58263)、[#58264](https://github.com/openai/codex/pull/58264)）

> [!tip] 何ができるようになったか
> TUI のコマンドセンターで、未読の結果を青い塗りの点、既読のアイドルのタスクを灰色の白抜きの点で示すようになった。セッションのピッカー（両方のレイアウト）にもバックエンドの既読状態を使った青い未読の点が付く。
>
> - フォーカスされて遮られていない表示で会話を描画したときに、観測した受信のリビジョンを既読として送る（読み取り専用のスナップショットを含む）。それより新しい結果は既読にしない
> - ピッカーでは、キャッシュしたトランスクリプトをバックエンドとスレッドの組で持ち、未読のリビジョンが違えば読み直す。トランスクリプトにターンのエラーも含める（#58264）
> - **嬉しい場面**: 複数のタスクのうち、どれに新しい結果が出たかを一目で知りたいとき

⏳ 未リリース · トピック: [[repos/openai-codex/topics/TUI|TUI]]

### TUI のコンポーザーに添付画像のサムネイル（[#58261](https://github.com/openai/codex/pull/58261)）

> [!tip] 何ができるようになったか
> 対応するターミナルとローカルのワークスペースでは、下書きに添付した画像のサムネイルを参照の順に、インラインとフルスクリーンの両方の表示で見せるようになった。
>
> - 収まらない添付は `+N` で件数を表示する。プレビューが使えない・場所が足りないときは編集できる画像の参照のまま残す
> - 添付したファイルが変わるとプレビューを更新し、画像の向きのメタデータを反映する。ターミナルの引き渡し・画面の切り替え・終了の前にフレームのグラフィックを消す

### メッセージボードのツールの MCP アダプター（[#58341](https://github.com/openai/codex/pull/58341)）

> - リクエストの重複の排除は MCP のセッションごとに行い、新しい接続で JSON-RPC の ID が再利用されても以前の投稿とぶつからない

### Apps のカタログをツールの一覧の完了前に発見できる機能フラグ（[#58352](https://github.com/openai/codex/pull/58352)）

> [!tip] 何ができるようになったか

> - 早期の取得は設定した起動のタイムアウトで打ち切る。発見の途中で接続・認証のスコープ・リソースのキャッシュの世代が変わったページは拒否する

### エージェントの MCP のメタデータを送るプラグインの登録をホストが選ぶ（[#58378](https://github.com/openai/codex/pull/58378)）

> [!tip] 何ができるようになったか
> スレッドの拡張 `AgentMcpMetadataRecipient` を追加し、ツール呼び出しのメタデータの `x-codex-root-turn-id` と `x-codex-cyber-access-program` をどの MCP のプラグインの登録に送るかをホストが選べるようになった。
>
> - `local` の MCP の環境で、プラグイン ID・インストールのルート・サーバー名・トランスポートの設定が完全に一致する必要がある
> - ホストのオプトインが無いとき、または登録が一致しないとき（同名のユーザーの上書きを含む）は両方のキーを省く。一致した登録で値が未設定なら JSON の null を送る

### スレッドのセクションの変更を接続中のクライアントへ通知（[#58380](https://github.com/openai/codex/pull/58380)）

> [!tip] 何ができるようになったか
> `thread/section/move` が成功したら（同じセクション内の並べ替えを含む）、`thread/section/changed` の通知を送るようになった。通知は応答の後に送り、`threadId` と移動先の `sectionId`（外したときは `null`）を含む。失敗した移動では通知しない。

### realtime V3 の文字起こしを会話の履歴に残す（[#58221](https://github.com/openai/codex/pull/58221)）

### リモートの executor の資格情報をトークンのローテーションに追従して読み直す（[#58251](https://github.com/openai/codex/pull/58251)）

> [!quote] Before
> リモートの executor がアイドルの間に ChatGPT の資格情報がローテーションされることがあり、レジストリへのリクエストが保存済みのローテーションに追従しつつ、ログアウト後に続けたり executor の ID を切り替えたりしないようにする必要があった。並行する更新が新しい資格情報を上書きするおそれもあった。

> [!success] After
> レジストリへのリクエストの前に ChatGPT の資格情報を読み直して検証し、資格情報のモード・アカウント・ユーザー・ワークスペースのポリシーを固定する。一時的な資格情報の解決の失敗でリクエストを送れなかったときは登録を再試行する。永続的な資格情報の書き込みはプロセス間で直列化し、`auth.json` はアトミックに置き換える。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/認証|認証]]

### リモートの executor の認証のタイムアウトからの復旧を修正（[#58355](https://github.com/openai/codex/pull/58355)、[#58381](https://github.com/openai/codex/pull/58381)）

> [!quote] Before
> 資格情報の解決中に（リクエストを送る前に）登録がタイムアウトすると、トランスポートのタイムアウトとして扱われて安全な再試行ができなかった。OAuth の更新の交換が始まっていないのに、資格情報の解決のタイムアウトで資格情報が隔離されることもあった。

> [!success] After
> 最初の送信前に期限に達した登録は `RequestNotSent` に分類し、既存の登録の再試行で復旧する。`AuthManager` は OAuth の交換の開始から資格情報の保存までの未完了の ChatGPT の更新を追い、executor の認証のプロバイダーはそのような資格情報を渡さない。ワークスペースの切り替えでトークンのクレームが書き換わっても、現在の auth JSON のトークンと比べて未完了の更新を検出する（#58381）。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/認証|認証]]

### 認証の読み直しの失敗をトークンの更新中は一時的な失敗として扱う（[#58324](https://github.com/openai/codex/pull/58324)）

> [!quote] Before
> 読めない・壊れた `auth.json` が、トークンの更新や unauthorized からの復旧の際にアカウントの不一致として扱われ、恒久的な失敗になることがあった。

> [!success] After
> ガード付きの認証の読み直しの保存先のエラーを一時的な失敗として伝え、キャッシュした資格情報を保って復旧を再試行できる。ファイルのデシリアライズとエージェントの ID の JWT のデコードのエラーは資格情報を出さない形で整形する。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/認証|認証]]

### キーリングを読めないときのフォールバックのトークンの更新を保存する（[#58343](https://github.com/openai/codex/pull/58343)）

> [!quote] Before
> 自動の資格情報の保存先では、キーリングを読めないときにフォールバックの資格情報を読み込めるが、その資格情報を更新してもローテーションしたトークンを保存できなかった。解決できない `auth.json` のシンボリックリンクが、キーリングの資格情報の更新とログアウトを妨げることもあった。

> [!success] After
> キーリングを読めないときは、更新したフォールバックの資格情報をファイルの保存先に保存する（古い資格情報やログアウト後の更新は引き続き拒否し、読めなかったキーリングのエントリーには触れない）。フォールバックのシンボリックリンクの解決に失敗してもキーリングへの保存を進める。
