## 新機能

### スレッドごとのアンロードの遅延 `thread_unload_delay_secs`（[#55270](https://github.com/openai/codex/pull/55270)、[#55255](https://github.com/openai/codex/pull/55255)）

> [!tip] 何ができるようになったか
> app-server が、アイドルで購読者のいないスレッドをアンロードするまでの時間を、サーバー全体の値ではなく各スレッドの `thread_unload_delay_secs` の設定から決めるようになった。`0` にすると、購読者も実行中の処理も無くなった時点ですぐにアンロードする。
>
> - `experimentalPredictionMode` の fork でもこの上書きだけは許可する（他の設定の上書きは引き続き拒否）。負の値やスケジュールできないほど大きな値は拒否する
> - 先に入った、`thread_source` が `composer_predictions` の一時的なスレッドを遅延なしでアンロードする特別扱い（[#55255](https://github.com/openai/codex/pull/55255)）は、この明示的な設定に置き換えられた
> - **嬉しい場面**: クライアントが個々のスレッドをどれだけ読み込んだままにするかを制御したいとき

⏳ 未リリース · トピック: [[repos/openai-codex/topics/セッション・スレッド管理|セッション・スレッド管理]]

### Responses API プロキシの認証を拡張（GitHub Actions の OIDC・フェデレーション）（[#55296](https://github.com/openai/codex/pull/55296)、[#55297](https://github.com/openai/codex/pull/55297)、[#55298](https://github.com/openai/codex/pull/55298)、[#55299](https://github.com/openai/codex/pull/55299)）

> [!tip] 何ができるようになったか
> Responses API プロキシの認証ヘッダーとリダイレクトのポリシーを共通の `Auth` の抽象にまとめ（[#55296](https://github.com/openai/codex/pull/55296)）、その上に GitHub Actions の OIDC とフェデレーションの認証の部品を追加した。
>
> - **GitHub Actions の OIDC**（[#55297](https://github.com/openai/codex/pull/55297)）: stdin から読んだ bearer の資格情報で新しいトークンを取得する `GithubOidc`。HTTPS の URL を検証し、`audience` のクエリを置き換える。CLI への組み込みはこの PR には含まれない
> - **フェデレーション**（[#55298](https://github.com/openai/codex/pull/55298)）: JWT のサブジェクトトークンを、ID プロバイダーとサービスアカウントの ID を使って OpenAI のアクセストークンに交換する。交換を直列化してキャッシュし、新しいサブジェクトトークンで先回りして更新する
> - **拒否時の更新**（[#55299](https://github.com/openai/codex/pull/55299)）: 上流の `401` で資格情報を無効にして次のリクエストで取り直す（`401` はリクエストを再送せずにそのまま返す。`403` では資格情報を残す）。失敗した交換は 1〜30 秒の指数バックオフで再試行する
> - 資格情報のバッファはゼロ化され、エラーやログに資格情報・URL・応答の本文を含めない。ヘッダーの取得に失敗すると空の `502` を返す

⏳ 未リリース · トピック: [[repos/openai-codex/topics/認証|認証]]

### 起動時の設定を 1 回だけ調べる `codex app-server --print-startup-config`（[#55300](https://github.com/openai/codex/pull/55300)）

> [!tip] 何ができるようになったか
> ローカルとクラウドの設定を検証し、app-server のバージョンと設定の要件を JSON で出力する。環境・スレッドのストレージ・プラグインは初期化しない。設定のエラーは構造化された JSON のエラーと 0 以外の終了コードになる。
>
> - **使い方**: `codex app-server --print-startup-config`。`--startup-sign-out` でアカウントの資格情報を消してサインアウト時の要件を読み直す（ホスト側が持つ外部認証では拒否）。`--startup-client-info` で設定・認証のリクエストのクライアントを示す
> - **嬉しい場面**: app-server を起動する前に、設定や管理された要件が通るかを確かめたいとき

⏳ 未リリース · トピック: [[repos/openai-codex/topics/デーモン|デーモン]]

### デーモンの機能フラグの上書きを照合し、不一致時に選択肢を表示（[#55442](https://github.com/openai/codex/pull/55442)）

> [!tip] 何ができるようになったか
> 固定の許可リストをやめ、真偽値の機能フラグの上書きをすべてデーモンで使えるようにした。明示的な上書きをデーモンが報告する設定と比べ、不一致があれば embedded へ黙って切り替えずにプロンプトを出す。
>
> - プロンプトでは「デーモンなしで実行」「管理されたデーモンを再起動」「キャンセル」を選べる。再起動できるときは推奨として示し、機能の一覧は 3 件と残りの件数まで表示する
> - 自動の起動では保存済みのデーモンの設定を保ち、確認なしに上書きを永続化しない。削除された機能は無視し、報告されない機能は無効とみなす

⏳ 未リリース · トピック: [[repos/openai-codex/topics/デーモン|デーモン]]

### V2 の executor のプラグインをクラウドのカタログと突き合わせる（[#55301](https://github.com/openai/codex/pull/55301)）

> [!tip] 何ができるようになったか
> プラグインの MCP の提供に V2 の discovery のインベントリを使い（無いときは従来の discovery）、プラグインを正規の ID でまとめる。リモートのプラグインはクラウドのメタデータと有効・無効を使い、executor のインストールはバージョンが一致するときだけ結び付ける。
>
> - クラウドのデータが無いときは、設定済みの executor ローカルのプラグインと executor 側の有効・無効を保つ
> - 更新をまたいでインストールの順を安定させ、まとめた MCP の宣言は最初の executor のインストールで動かす
> - 部分的な更新が来ても完全なクラウドのカタログを保つ。ツールの説明に付けるプラグインの帰属の文は 1,024 バイトまで

⏳ 未リリース · トピック: [[repos/openai-codex/topics/プラグイン|プラグイン]]

### スレッドの履歴の SQLite への具体化をバッチに分ける（[#55244](https://github.com/openai/codex/pull/55244)）

> [!quote] Before
> 履歴の追いつきでロールアウトの全体を集めてから、1 つの SQLite のトランザクションで適用していた。

> [!success] After

### TUI の権限の選択とセッションの状態の扱いを修正（[#55682](https://github.com/openai/codex/pull/55682)）
