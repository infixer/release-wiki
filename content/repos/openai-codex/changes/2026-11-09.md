## 新機能

### TUI のサイドバーで複数のサイドのチャット（[#59784](https://github.com/openai/codex/pull/59784)）

> [!tip] 何ができるようになったか
> サイドの保持（side retention）が有効なとき、サイドバーのチューザーからメインのチャットに対して追加のサイドのチャットを作ったり、既存のものを開き直したりできるようになった。
>
> - チューザーに番号付きのクリックできるタブとキーボードでの操作。幅が足りないときも選択中のタブを表示し続ける
> - 兄弟のサイドのチャットの間を切り替えても、下書き・トランスクリプトの履歴・サイドバーのレイアウトを保つ
> - **使い方**: プロンプト付きの `/side` は新しいサイドのチャットを作り、引数なしの `/side` は選択中のサイドのチャットを開き直す。サイドの保持が無効なときは従来どおり再利用する

⏳ 未リリース · トピック: [[repos/openai-codex/topics/TUI|TUI]]

### サイドバーのチューザーの幅を変更（[#59824](https://github.com/openai/codex/pull/59824)）

> [!tip] 何ができるようになったか
> これまでサイドのチャットを開いているときしかできなかったサイドバーの幅の変更が、チューザーでもできるようになった。
>
> - キーボードでの幅の変更、幅のプリセット、区切り線のドラッグ。狭いサイドバーにも収まる幅の変更のヒント
> - 起動時のスレッドの割り当てや、チューザーが新しいサイドのチャットに置き換わる間もキーボードの幅の変更モードを保つので、`Enter` は親の下書きを送信せずに幅の変更を終える
> - 分割が使えるときだけ幅の変更のキーを有効にし、分割のアニメーション中は区切り線のドラッグを始めない

⏳ 未リリース · トピック: [[repos/openai-codex/topics/TUI|TUI]]

### TUI にクラウドのバックエンド（機能ゲート付き）（[#59828](https://github.com/openai/codex/pull/59828)）

> [!tip] 何ができるようになったか
> `TuiMultiBackend` が有効なとき、対応する macOS・Linux での起動で、選択中の ChatGPT アカウントとローカルのネットワークのポリシーを使うクラウド（Cloud）の接続が追加で登録されるようになった。
>
> - 接続の操作と状態の表示でクラウドを識別し、バックエンドの設定を保つ
> - スレッドを開くときはクラウドがモデルを指定し、ローカルのスキルのリクエストを省く。ローカルの作業ディレクトリの上書きなしで再開できる
> - クラウドのスレッドのスナップショットで Git のメタデータを保ち、絞り込みで空になったページの先も走査の予算内で履歴を読み込む
> - クラウドの接続の失敗は報告され、再接続には Codex を開き直す必要がある

⏳ 未リリース · トピック: [[repos/openai-codex/topics/TUI|TUI]]

### ゲートウェイの認証で資格情報を書き出すコマンドを使う（[#59787](https://github.com/openai/codex/pull/59787)、[#59816](https://github.com/openai/codex/pull/59816)）

> [!tip] 何ができるようになったか
> `model_providers.<id>.gateway_oauth.credential_export` で、ブラウザでの OAuth の代わりにコマンドからゲートウェイのアクセストークンを受け取れるようになった。
>
> - 設定したコマンドを初回の利用時に実行し、トークンをメモリにキャッシュして、設定したヘッダーまたは Cookie で送る。コマンドの失敗はそのまま表面化し、コマンドを使うプロバイダーには OAuth のセッションが要らない（#59787）
> - OAuth と書き出しの設定は排他。コマンドの資格情報ではモデルカタログへのアクセスを同一オリジンに限り、HTTP のリダイレクトを拒否する。上限とタイムアウト付きのコマンドの実行は AWS の資格情報の書き出しと共通（#59787）
> - 推論の HTTP の `401` や WebSocket のアップグレードの `401` を受けたら、キャッシュしたトークンを捨ててコマンドを 1 回だけ再実行する。再試行も `401` なら、その後の主の認証の回復は従来どおり（#59816）

⏳ 未リリース · トピック: [[repos/openai-codex/topics/認証|認証]]

### ゲートウェイの OAuth の読み取り・ログインでプロバイダーを選べる（[#59819](https://github.com/openai/codex/pull/59819)）

> [!tip] 何ができるようになったか
> 既定のプロバイダーを変えずに、別の設定済みのプロバイダーを認可できるようになった。
>
> - **使い方**: `account/gatewayOAuth/read`・`account/gatewayOAuth/login` の任意の `modelProvider` パラメーター。省略・`null` なら従来どおり現在のプロバイダー
> - 明示したプロバイダーは現在の managed なポリシーで検証し、既定やスレッドのプロバイダーは変えない
> - プロバイダーをまたいで準備状態を保ち、変更した資格情報を共有するすべての設定済みのプロバイダーに `account/gatewayOAuth/changed` を送る

⏳ 未リリース · トピック: [[repos/openai-codex/topics/認証|認証]]

### ゲートウェイの OAuth でデバイスコードの認可（[#59822](https://github.com/openai/codex/pull/59822)）

> [!tip] 何ができるようになったか
> ブラウザを開けない端末向けに、ゲートウェイへのサインインでデバイスコードの認可を使えるようになった。
>
> - **設定**: 任意の `gateway_oauth.device_authorization_url`。`login_with_device_code` の API が確認用の URL とユーザーコードを示し、承認をポーリングして資格情報を保存する
> - 設定したプロキシとネットワークのポリシーを使い、確認用の URL を検証し、OAuth の応答に上限を設ける。取り消しに対応し、拒否・期限切れのコードは発行元のエラーの詳細を出さずに報告する

⏳ 未リリース · トピック: [[repos/openai-codex/topics/認証|認証]]

> [!tip] 何ができるようになったか

### fork したスレッドの履歴をまたいで更新の順序でページ分け（[#59793](https://github.com/openai/codex/pull/59793)）

> [!tip] 何ができるようになったか
> 更新の境界を指定したアイテムの読み取りが、fork したスレッドの履歴でも使えるようになった（従来は拒否し、下限の指定しかできなかった）。

> - 更新の順の並べ替えには更新の境界が必須。アイテムのアンカーやアイテム ID での絞り込みとは併用できない

### ローカルのメッセージボードの固定の読み取りビュー（[#59993](https://github.com/openai/codex/pull/59993)）

> [!tip] 何ができるようになったか
> 同時の追記でページの間で結果がずれないよう、チャンネルのカタログと投稿の境界を固定して閲覧できるようになった。
>
> - **API**: `LocalAgentMessageBoard::read_view` と `LocalBoardReadView`（取得したチャンネルのカタログと読み取り専用のボードのハンドル）
> - チャンネルの要約を固定し、検索・スレッドの一覧・返信の要約・個別の読み取りに投稿の順番の上限を適用する。後からの追記は日時をさかのぼっていても含めない
> - 固定のビューからの変更（購読の変更を含む）はすべて拒否する。ビューは SQLite のストレージを共有するがトランザクションは保持せず、削除した投稿は保持しない

### TUI のメッセージの送信の受領と不確かな下書きの保持（[#59817](https://github.com/openai/codex/pull/59817)）

> [!quote] Before
> クラウドへのメッセージの送信時に TUI がキャッシュしたアクティブなターンが古いことがあり、返信が失われると届いたかどうかが分からないまま下書きを自動で送り直して、二重に送信するおそれがあった。

> [!quote] Before
> 明示的な API キーとコマンドの資格情報について、キャッシュした接続や処理中の作業が資格情報の取得元をまたがないよう独立して扱う仕組みが無かった。

### Git の帰属の設定のリクエストの認証を修正（[#60035](https://github.com/openai/codex/pull/60035)）

> [!quote] Before
> Git の帰属（git-attribution）の設定のリクエストが、送信先のランタイムの認証に従っていなかった。資格情報の更新後に認可の失敗が続くと、World State への反映が終わらないことがあった。

> [!success] After
> スレッドの `ProviderAuthContext` の資格情報とランタイムの認証を使い、設定のクライアントのネットワークのポリシーを認証済みのアカウントに結び付ける。設定の取得の失敗・タイムアウトの後はポリシーの解決をやめ、`401` が続いても資格情報の更新は 1 回だけ。

> 待ち行列の入力は送信したクライアントの Responses API のメタデータ無しで保存・送信され、待ち行列のターンの開始時に `client_type` などの帰属が失われていた。

> [!success] After
> 待ち行列の送信の追加・更新で `responsesapiClientMetadata` を受け付け、返す項目にも含める。入力と一緒に保存し、選んだ項目の開始やアイドル時の送信（復元後を含む）で転送する。更新で省略・空のマップなら既存を保ち、空でないマップなら置き換える。古い待ち行列のワーカーも保存した入力を読める。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/セッション・スレッド管理|セッション・スレッド管理]]

### gRPC の Code Mode の接続の寿命をセッションに結び付け（[#59783](https://github.com/openai/codex/pull/59783)）

> [!quote] Before
> 接続ごとにワーカーを割り当てるホストでは、アイドルの接続の追い出しで静かなセッションがリースを持つワーカーに届かなくなることがあり、逆に最後のセッションが閉じた後も接続を残すとワーカーを無駄に確保し続けていた。

> [!success] After
> gRPC の Code Mode の接続では HTTP の接続プールのアイドルのタイムアウトを無効にし、URL ごとのクライアントを弱参照でキャッシュして、生きているセッションが共有のクライアントを所有する（閉じる・失敗すると手放す）。遅延の RPC は必要なときだけクライアントを取得し、解放済みならセッションのエラーを返す。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/Code-Mode|Code Mode]]

### managed なプロキシの準備とサンドボックスのルーティングを集約（[#59792](https://github.com/openai/codex/pull/59792)）

> [!quote] Before
> プロキシの設定とルーティングの選択が各所に分かれていた。

> [!success] After
> `prepare_managed_network` に集約し、ネイティブの Windows の起動では資格情報の仲介の前に managed なプロキシの環境変数を取り除いて直接起動する（呼び出し側の環境変数と API の資格情報は保つ）。専用のリスナーは Windows の MXC の起動でだけ選ぶ。managed なネットワークのコンテキストの絞り込みは `SandboxManager` にまとめ、macOS の Seatbelt のコンテキストは保つ。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/サンドボックス|サンドボックス]]
