## 新機能

### `codex doctor --network-only` でネットワークだけを診断（[#57606](https://github.com/openai/codex/pull/57606)）

> [!tip] 何ができるようになったか
> `codex doctor --network-only` で、レポートを有効な設定・ネットワーク環境・プロバイダーへの HTTP の到達性・Responses の WebSocket の確認に絞れるようになった。データベースや MCP のスキャンなどの関係ない診断は飛ばす。
>
> - 設定の警告は残し、設定の読み込みにかかった時間も報告する
> - 設定の読み込みに失敗したら、伏せ字にした設定のエラーを報告して止まり、推測した接続先には問い合わせない
> - **嬉しい場面**: 接続できない原因が設定かネットワークかを手早く切り分けたいとき

📦 rust-v0.166.0 に収録 · トピック: [[repos/openai-codex/topics/フィードバック・診断|フィードバック・診断]]

### `requirements.toml` で OpenTelemetry の設定を管理（[#57649](https://github.com/openai/codex/pull/57649)、[#57638](https://github.com/openai/codex/pull/57638)、[#57658](https://github.com/openai/codex/pull/57658)）

> [!tip] 何ができるようになったか
> `requirements.toml` で OpenTelemetry のログのフラグ、ツールの結果のバイト数の上限、環境、ログ・トレース・メトリクスのエクスポーターを管理できるようになった。
>
> - 管理された値はユーザーの設定より優先し、エクスポーターは丸ごと置き換える。値が食い違うときは警告する
> - `configRequirements/read` で管理された `otel` の設定を公開し、`config/read` にも反映する。管理されたフィールドと重なる設定の書き込みは拒否する
> - app-server のプロトコルの `ConfigRequirements` に任意の `otel`（OTLP の HTTP/gRPC のヘッダー・TLS の設定を含む）の型を追加（#57638）
> - `otel.span_attributes`・`otel.tracestate` も要件で指定でき、属性・メンバーのフィールド単位でマージする。要件にしたエントリーとその祖先だけを書き込みから守る（例: `otel.tracestate.vendor.tenant` を要件にしても `vendor.region` は書ける）（#57658）
> - OTLP HTTP のクライアント証明書と秘密鍵を設定したときは Rustls を使い、PEM のクライアントの ID を受け付ける（#57658）
> - **嬉しい場面**: 組織のテレメトリの送信先やメタデータを全員に強制したいとき

📦 rust-v0.166.0 に収録 · トピック: [[repos/openai-codex/topics/管理要件|管理要件]]

### Guardian の判定を応答のストリームで受け取る（[#57757](https://github.com/openai/codex/pull/57757)）

> [!tip] 何ができるようになったか
> `response.metadata` の Guardian の判定を、SSE と WebSocket で型付きの `GuardianAssessment` イベント（`response_id`・`item_id`・`requires_review`）として取り出すようになった。
>
> - 必須のフィールドが欠けている・空・型が違う判定は無視し、他のメタデータの配信には影響しない
> - リクエスト単位の拡張のインターセプターから判定の型を使える。判定は会話の履歴に入れず、ツールの実行を認可するものでもない

📦 rust-v0.166.0 に収録 · トピック: [[repos/openai-codex/topics/Guardian|Guardian]]

### Code Mode のホストの出力の切り詰めの機能フラグ（[#58159](https://github.com/openai/codex/pull/58159)）

> [!tip] 何ができるようになったか
> 既定で無効の `code_mode_host_output_truncation` の機能フラグを追加。有効にすると、Core は組み込みの Code Mode のセッションのプロバイダー（stdio・gRPC の両方）にサーバー側での出力の切り詰めを求める。
>
> - 注入したプロバイダーは自分のセッションの設定を保ち、明示したセッションのオプションはそのまま通る

⏳ 未リリース · トピック: [[repos/openai-codex/topics/Code-Mode|Code Mode]]

## 変更・修正

### `review/start` の detached の配信を削除（[#57667](https://github.com/openai/codex/pull/57667)）

> [!quote] Before
> `review/start` の `delivery` に `"detached"` を指定すると、別のスレッドでレビューを実行できた。

> [!success] After
> `review/start` は渡したスレッドでのインラインのレビューだけに対応し、そのスレッドの ID を `reviewThreadId` として返す。`delivery` は省略・`null`・`"inline"` のいずれか。

> [!warning] 移行が必要
> 別のレビューのスレッドが欲しいときは `thread/start` の後に `review/start` を呼ぶ。独自のレビューの指示で会話の履歴を保ちたいときは `thread/fork` の後に `turn/start` を呼ぶ。

📦 rust-v0.166.0 に収録 · トピック: [[repos/openai-codex/topics/セッション・スレッド管理|セッション・スレッド管理]]

### スレッドのアーカイブを戻すと派生したスレッドも戻す（[#57635](https://github.com/openai/codex/pull/57635)）

> [!quote] Before
> スレッドをアーカイブすると起動した子孫のスレッドもアーカイブされるが、`thread/unarchive` では親だけが戻っていた。

> [!success] After
> アーカイブされた子孫（親とは別にアーカイブしたものも含む）も戻し、戻した各スレッドに `thread/unarchived` を送る。動いている子孫は飛ばし、子孫の発見に失敗したら親だけを戻す。

> [!quote] Before

### app-server のスレッドのリスナーの起動・終了の競合を修正（[#57787](https://github.com/openai/codex/pull/57787)）

> [!quote] Before
> リスナーの準備中にスレッドのランタイムが終了したり、前のリスナーが `ShutdownComplete` を転送する前にコールドの再開が始まったりすると、終端のイベントが失われることがあった。

> [!success] After
> リスナーの導入と接続の購読を保留中のアンロードと調整し、終了の処理が終わるまでコールドの再開とランタイムの置き換えを待たせる。アイドルのアンロードはゴールの編集・コールドの再開と直列化する。

### ランタイムの認証をモデルのプロバイダーとカタログで共有（[#57607](https://github.com/openai/codex/pull/57607)）

> [!quote] Before
> ランタイムの認証を有効にしても、モデルカタログの更新はモデルへのリクエストと同じ登録済みのアクター・資格情報の持ち主を使っていなかった。

> [!success] After
> `ProviderAuthContext` で資格情報と任意のランタイムの認証をプロバイダーとカタログのクライアントに渡し、推論とカタログの接続先ごとに選ぶ。ランタイムの登録に API の組織・プロジェクトを含め、組織内ではプロジェクトをまたいで再利用し、組織が変わったら置き換える。別オリジンへのリダイレクトでは機密のヘッダーを外す。

### Guardian のレビューで親の接続のルーティングを保つ（[#57710](https://github.com/openai/codex/pull/57710)）

> [!quote] Before
> 共有のルーティングの Cookie は親の接続の確立後に変わりうるため、関係ない通信で Guardian のレビューのルーティングのヒントが置き換わることがあった。

> [!success] After

### アカウントの切り替え後にトレースのエクスポーターが動かない問題を修正（[#57657](https://github.com/openai/codex/pull/57657)）

> [!quote] Before
> トレースを無効にして起動した app-server は、アカウントの切り替えでトレースが有効になってもスパンを送れなかった。無効にしても前のグローバルのトレーサーのプロバイダーが残っていた。

> [!success] After
