## 新機能

### ファイルシステムの抽象にストリーミングでのファイルの置き換えを追加（[#54505](https://github.com/openai/codex/pull/54505)）

> [!tip] 何ができるようになったか
> `ExecutorFileSystem` と `EnvironmentAccess` に `write_file_stream` を追加した。アクセサーが捕捉したサンドボックスの権限を保ったまま、ファイルを上限付きのチャンクごとに置き換え、書き込んだバイト数を返す。
>
> - ローカルとストリーミングに対応したリモートのファイルシステムはチャンクごとに書き込む。古い executor では入力をバッファしてから 1 回の `writeFile` リクエストで送る
> - 完了・失敗時にリモートのハンドルを閉じ、取り消し後もできる範囲で後始末し、保留中のメタデータの検索を無効にする
> - 失敗や取り消しでファイルが切り詰められたり途中までになったりすること、実行中の I/O が取り消しより長く続くことがあると明記された

📦 rust-v0.164.0-alpha.3 に収録 · トピック: [[repos/openai-codex/topics/実行環境アクセス|実行環境アクセス]]

### 環境の間でファイルをコピーするオプトインのツール `multi_env_copy_file`（[#54674](https://github.com/openai/codex/pull/54674)、[#54741](https://github.com/openai/codex/pull/54741)）

> [!tip] 何ができるようになったか
> 拡張 `codex-multi-env-copy-file` が、ホストが登録したときに `multi_env_copy_file` ツールを公開する。選択した別々の環境の間で、内容をモデルのコンテキストに読み込まずにファイルをコピーし、完了時に `bytes_copied` を返す。
>
> - 各環境のネイティブのパスの書き方で絶対パスを要求し、両端のサンドボックスのポリシーと権限の付与を適用する
> - 対応していればストリーミングでコピーし、古い executor ではバッファしてから送る。同じ環境の間のコピーは拒否する。書き込みに失敗すると対象が切り詰められたり途中までになったりすることがある
> - **使い方**: 機能フラグ `multi_env_copy_file`（既定は無効、開発中）を有効にすると、app-server のスレッドと CLI のデバッグ用のプロンプトの組み立てに拡張が入る（[#54741](https://github.com/openai/codex/pull/54741)）
> - **嬉しい場面**: ローカルとリモートの executor の間で、バイナリを含むファイルをモデルを介さずに受け渡したいとき

📦 rust-v0.164.0-alpha.3 に収録 · トピック: [[repos/openai-codex/topics/実行環境アクセス|実行環境アクセス]]

### 動的ツールの呼び出しを並列に実行（[#54654](https://github.com/openai/codex/pull/54654)）

> [!tip] 何ができるようになったか
> `DynamicToolHandler` で並列実行を有効にした。クライアントの応答を待つ動的ツールの呼び出しが互いをブロックしなくなり、Code Mode のプログラムから `Promise.all` で同時に動的ツールを呼べる。
>
> - **嬉しい場面**: Code Mode で複数の動的ツールの結果を待ち合わせたいとき（結果の順序は `Promise.all` の順のまま）

📦 rust-v0.164.0-alpha.3 に収録 · トピック: [[repos/openai-codex/topics/Code-Mode|Code Mode]]

### MCP のツール一覧の変更をターンの途中でも反映（[#54656](https://github.com/openai/codex/pull/54656)）

> [!tip] 何ができるようになったか
> MCP サーバーのツール一覧の変更通知を受けたらカタログを更新し、同じターンの中で新しいツールを見つけて呼べるようにした。
>
> - **使い方**: 機能フラグ `mcp_tool_list_changed`（既定は無効。通常の MCP サーバーが対象）
> - 通知を転送の順に追跡し、次の発見やツールの紐付けの前にカタログを更新する。同時の更新はまとめ、通知で無効になった一覧の取得（ページ分割中を含む）はやり直す
> - 更新に失敗したら前のカタログを残し、再試行までの待ち時間を置き、影響する起動時のキャッシュを無効にする。受け付け済みの呼び出しが終わるのを待たずに更新を進める

📦 rust-v0.164.0-alpha.3 に収録 · トピック: [[repos/openai-codex/topics/MCP|MCP]]

### サーバーの状態で MCP のツール一覧のメタデータ `toolListMeta` を公開（[#54686](https://github.com/openai/codex/pull/54686)）

> [!tip] 何ができるようになったか
> これまでツールの発見で捨てていた応答の `_meta` を、最初の `tools/list` のページからカタログの更新とキャッシュを通して保ち、`McpServerStatus` の `toolListMeta`（無ければ `null`）として返すようになった。
>
> - キャッシュした Apps のカタログのメタデータを、クライアントの機能や拡張を含む発見の設定ごとに分ける。メタデータの無い古いキャッシュのツールも引き続き使う
> - 状態のスナップショットのサーバーの機能は、選んだサーバーのものに限る
> - 生成するスキーマとバインディング（TypeScript の `McpServerStatus` など）も更新

### app-server の WebSocket の zstd 圧縮を機能フラグで有効に（[#54949](https://github.com/openai/codex/pull/54949)）

> [!tip] 何ができるようになったか
> `features.app_server_websocket_compression`（既定は無効）を追加した。有効にすると、TCP の WebSocket と Unix ドメインソケットのリスナーが、クライアントが対応するプロトコルを提示したときに zstd 圧縮を交渉する。それ以外の接続は通常のテキストのメッセージを使う。
>
> - 設定のスキーマに含まれ、TUI のデーモンの起動時にも上書きできる

### エージェントのメッセージでアイドルの root のセッションを起こす（[#54961](https://github.com/openai/codex/pull/54961)）

> [!tip] 何ができるようになったか
> 親が最終回答を返した後にワーカーが終わることがある。これまで `trigger_turn` の無いエージェントのメッセージでアイドルのセッションを起こすには、待機中の durable sleep が必要だった。
>
> - **使い方**: 機能フラグ `wake_on_agent_messages`（既定は無効）。直接の配信またはホストのメールボックスでエージェントのメールが届くと、新しい root のターンを始める
> - `trigger_turn` の無いメッセージでは直前のターンのコンテキストを使う
> - 中断したセッション・Plan モード・子エージェントでは自動で起こさない
> - **嬉しい場面**: 子エージェントの完了を、親の最終回答の後でも親に受け取らせたいとき

⏳ 未リリース · トピック: [[repos/openai-codex/topics/マルチエージェント|マルチエージェント]]

### プラグインのフックの承認をプラグインの内容に結び付ける（[#54619](https://github.com/openai/codex/pull/54619)）

> [!quote] Before
> 承認はフックの宣言だけを対象にしていたため、宣言を変えずにプラグインのスクリプトが変わると、変わったコードが既存の承認のまま実行できた。

> [!success] After
> プラグインのバンドルの内容のハッシュを `hooks/list` が返す承認の値に含め、`trusted_content_hash` として保存する（古いクライアント向けに `trusted_hash` も保つ）。コマンドと MCP のフックの実行ごとに（フックのタイムアウト内で）内容を確認し、承認した内容が変わっていれば承認をやり直させる。生成された Python のバイトコード・`.venv`・`.egg-info` はハッシュの対象から外す。

> [!warning] 移行が必要
> 宣言だけの従来の承認は、プラグインと設定のホームごとに共有の変更できない内容の基準へ移行される。プラグインの更新やロールバックで内容が変わると、フックの承認をやり直す必要がある。

📦 rust-v0.164.0-alpha.3 · トピック: [[repos/openai-codex/topics/プラグイン|プラグイン]]

### MCP の承認の取り消しの理由を区別（[#54679](https://github.com/openai/codex/pull/54679)）

> [!quote] Before
> 中断や `exec` モードでの自動の取り消しも含め、承認が打ち切られた MCP のツールの呼び出しはすべて「user cancelled MCP tool call」と報告されていた。

> [!success] After
> 取り消しの理由 `user`・`interrupted`・`non_interactive` を MCP の承認のメタデータと解決に通し、承認の前に取り消されたこと、`exec` モードで対話の承認が使えないことを報告する。理由を送らないクライアントには従来のメッセージを使う。

### TUI のセッションの選択をバックエンドに結び付ける（[#54681](https://github.com/openai/codex/pull/54681)）

> [!quote] Before
> スレッドの ID だけではセッションを持つバックエンドが分からず、接続の入れ替えをまたいだ再開や fork の選択が、ID が一致する別のバックエンドで操作される可能性があった。

> [!success] After
> app-server のセッションとセッションの対象にプロセス内の `BackendId` を付け、再接続や補助のピッカーの接続でも保つ。別のバックエンドからの選択は、状態を変えたり再開・fork・アーカイブ解除のリクエストを送ったりする前に拒否する。補助のピッカーとセッションの選択後は、ローカルのデーモンから embedded のサーバーへのフォールバックをしない（新規の起動ではフォールバックを残す）。

📦 rust-v0.164.0-alpha.3 · トピック: [[repos/openai-codex/topics/TUI|TUI]]
