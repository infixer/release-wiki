## 新機能

### 既存の Codex のログインを使う Git の資格情報ヘルパー（[#60746](https://github.com/openai/codex/pull/60746)）

> [!tip] 何ができるようになったか
> 隠しコマンド `codex git-credential` を追加。ファイルに保存された既存の ChatGPT のログインを、Git の `authtype` のプロトコルで一時的な Bearer の資格情報として渡す。
>
> - **対象**: `chatgpt.com` または `chatgpt-staging.com` の `backend-api/codex/sites/git/` 以下への HTTPS のリクエストだけ（設定したオリジンと一致するもの）。managed なワークスペースのポリシーを確認し、期限切れ・変更されたログインは拒否する。リポジトリの設定は認証の設定の選択に使わない
> - **振る舞い**: トークンの更新や保存済みのログインの変更はしない（`store`・`erase` は何もしない）。認証が使えない・失敗したときは `quit=true` を返し、Git がプロンプトにフォールバックしないようにする

⏳ 未リリース · トピック: [[repos/openai-codex/topics/認証|認証]]

### ネイティブのヘルパーに保存済みの Daybreak の選択を引き継ぐ（[#60749](https://github.com/openai/codex/pull/60749)）

> [!tip] 何ができるようになったか
> 既定で無効の機能 `daybreak_program_propagation` を追加。ネイティブのヘルパーを起動するときに、親の保存済みの Daybreak の選択を取り込む。
>
> - ヘルパーのターンと入れ子の起動で、選択とアカウントの識別情報を保つ。明示的な `cyber_access_program` の上書きは保ち、以降のターンではヘルパー自身の保存済みの設定を優先する
> - 保留中のメタデータを永続化されたメタデータより先に読み、スレッドの実体化をまたいで設定を保つ（保存済みの選択が優先）。この解決のロジックを `thread/read` と共有し、ユーザーの設定から機能を更新できる

⏳ 未リリース · トピック: [[repos/openai-codex/topics/マルチエージェント|マルチエージェント]]

### 承認したプランを新しいセッションに添付ファイルで引き継ぐ（[#60763](https://github.com/openai/codex/pull/60763)）

> [!tip] 何ができるようになったか
> 「Yes, clear context and implement」で、承認したプランを app-server の添付ファイルとして保存し、それを参照する短いプロンプトを送るようになった。実験的な `thread/prepareApprovedPlan` のリクエストで、新しいスレッドの実行側がファイルを読めて内容が承認したプランと一致するかを確認する。
>
> - 添付ファイルの書き込み・読み取りができないときは、プラン全体をモデルのコンテキストと切り詰めの上限の範囲で `proposed_plan` のツール出力として入れる。収まらないときはエラーを報告して現在のセッションを保つ
> - プランの準備が成功してから UI をクリアしてスレッドを切り替える

⏳ 未リリース · トピック: [[repos/openai-codex/topics/TUI|TUI]]

### ツールの出力でファイルに基づく音声を保つ（[#60735](https://github.com/openai/codex/pull/60735)）

> [!tip] 何ができるようになったか
> `input_audio` のツール出力のアイテムが `audio_url` か `file_id` のどちらかを持てるようになり、メッセージの内容をツール出力に変換するときに両方の形を保つ（以前はファイルに基づく音声がテキストのファイル ID になり、音声の型が失われていた）。
>
> - 履歴の見積もりと出力の切り詰めでファイルに基づく音声を数え、インラインの音声データだけを準備する
> - 生の関数・カスタムツールの出力の差し込みでアップロードした音声は拒否する（アップロードした音声は型付きのターンの入力で送る）
> - app-server のスキーマと TypeScript・Python の型を再生成（Python のインラインの音声のクラス名は保つ）

⏳ 未リリース · トピック: [[repos/openai-codex/topics/モデル・接続設定|モデル・接続設定]]

### 大きすぎる WebSocket のリクエストはすぐ HTTP にフォールバック（[#60840](https://github.com/openai/codex/pull/60840)、[#60841](https://github.com/openai/codex/pull/60841)）

> [!quote] Before
> テキストが届く前にコード `1009` で WebSocket が閉じられた（メッセージの大きさの上限を超えた）ときも、別の WebSocket で再試行していた。

> [!success] After
> 早い段階の大きさによる拒否は HTTP へのフォールバックが必要と分類し、WebSocket の再試行を使い切らずに切り替える（プリウォーム中も）。さらにハンドシェイクの応答の `x-codex-websocket-max-message-bytes` を読み、送る前にシリアライズしたリクエストの大きさを確認して、超えるものは最初から HTTP で送る（上限が無い・不正なら無視）。テキストの後の大きさによる切断や他のコードの切断は従来どおり再試行する。
