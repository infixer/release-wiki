## 新機能

### 設定サーバーのポリシーを起動とサインインに組み込む（[#57175](https://github.com/openai/codex/pull/57175)）

> [!tip] 何ができるようになったか
> CLI・exec・TUI・app-server の設定の読み込みで、管理された設定のローダーを使うようになり、`requirements.toml` で設定サーバーを選べるようになった。
>
> - 対話的な TUI の起動と CLI のログインで必要なら設定サーバーにサインインし、CLI のサインイン後に設定を読み直す。CLI のログアウトでは設定サーバーの資格情報も消す
> - app-server は OpenAI のログイン・ログアウトをまたいで設定サーバーの設定と更新のワーカーを保つ
> - CLI と `doctor` の設定の読み込みでは、設定サーバーの設定の適用を必須にする
> - **嬉しい場面**: 組織の設定サーバーで配るプロバイダーや指示の設定を、どの入口から起動しても確実に適用したいとき

⏳ 未リリース · トピック: [[repos/openai-codex/topics/管理要件|管理要件]]

### FedRAMP の API キーを既定で政府向けのエンドポイントに振り分ける（[#57178](https://github.com/openai/codex/pull/57178)）

> [!tip] 何ができるようになったか
> これまで FedRAMP の発行の印がある API キーも、商用のエンドポイントの既定値を使い、FedRAMP のリクエストヘッダーも送っていなかった。
>
> - `sk-proj-fedramp-`・`sk-svcacct-fedramp-` の接頭辞をルーティングのヒントとして認識し、`X-OpenAI-Fedramp: true` を送る（認証にはキー全体をそのまま使う）
> - 既定の OpenAI API には `https://gov.api.openai.com/v1`、既定の ChatGPT のバックエンド（モデルの発見・analytics を含む）には `https://gov.chatgpt.com/backend-api/` を使う
> - 明示的に設定したエンドポイント（商用の既定の URL を明示した場合を含む）はそのまま。ルーティングと認証は同じ資格情報のスナップショットから決め、realtime の WebSocket の開始にも適用する

### モデルへのリクエストにランタイムの認証を組み込む（[#57171](https://github.com/openai/codex/pull/57171)）

> [!tip] 何ができるようになったか
> `ModelClient::with_runtime_auth` でオプトインのランタイムの認証を使えるようになった。プロバイダーとランタイムのマネージャーが同じ OpenAI の資格情報を共有していることが条件。
>
> - リクエストとその再試行の間、ランタイムの ID・資格情報・ルーティング・トランスポートを一貫させ、試行ごとに新しいアサーションに署名する
> - WebSocket のハンドシェイクにも非同期に認証を適用し、古い認証ヘッダーを置き換え、ランタイムが変わったら再接続する
> - 登録したランタイムと食い違うアカウント・組織・プロジェクトの指定は拒否し、ゲートウェイの OAuth との組み合わせは保つ

⏳ 未リリース · トピック: [[repos/openai-codex/topics/認証|認証]]

### GCP のプロバイダーの認証に資格情報ファイルを指定（[#57188](https://github.com/openai/codex/pull/57188)）

> [!tip] 何ができるようになったか
> `model_providers.gcp.credential_file` に Google の Application Default Credentials（ADC）のファイルの絶対パスを指定できるようになった。
>
> - プロバイダーの認証コマンドの環境に `GOOGLE_APPLICATION_CREDENTIALS` として渡し、トークンの更新（`401` の後を含む）でも保つ。親プロセスの環境は変えない
> - GCP の既定値とマージする前にパスを検証し、スレッドの設定のシリアライズでも保つ
> - **嬉しい場面**: 既定の ADC とは別のサービスアカウントの資格情報で Vertex AI のプロバイダーを使いたいとき

### スレッドのアイテムに開始・完了の時刻（[#57172](https://github.com/openai/codex/pull/57172)）

> [!tip] 何ができるようになったか
> app-server の `ThreadItem` に、null になりうる `startedAtMs`・`completedAtMs`（記録があれば Unix ミリ秒）を追加した。ライブの通知とターンの履歴の両方に入る。
>
> - 履歴の再構築・ページ分割・再開でも記録した時刻を保つ（承認の間に記録したコマンドの開始時刻を含む）
> - Rust ではアイテムの中身を `ThreadItemPayload` に分けたが、JSON は平らなまま。スキーマと TypeScript・Python の生成された型も更新した
> - **嬉しい場面**: クライアントでツール呼び出しやメッセージの所要時間を表示したいとき

⏳ 未リリース · トピック: [[repos/openai-codex/topics/セッション・スレッド管理|セッション・スレッド管理]]

### 信頼しない追加のコンテキストに名前を付ける（[#57181](https://github.com/openai/codex/pull/57181)、[#57204](https://github.com/openai/codex/pull/57204)）

> [!tip] 何ができるようになったか
> `AdditionalContextEntry` に任意の `name` を追加した（プロトコル・app-server のスキーマ・生成されたクライアント）。
>
> - `name` は `[a-z][a-z0-9_]{0,63}` に合うものだけを、`untrusted` のコンテキストにだけ受け付ける。不正な名前や `application` のコンテキストへの名前は、入力を受け付ける前に `turn/start`・`turn/steer` の invalid-request のエラーにする
> - モデルへの入力の描画は従来どおりで、名前だけが変わったコンテキストは重複として扱う（[#57181](https://github.com/openai/codex/pull/57181)）
> - 信頼しないコンテキストを名前付きの独立したツール出力として描画するための、開発中で既定は無効の機能フラグ `untrusted_as_tool_output` を登録した（[#57204](https://github.com/openai/codex/pull/57204)）

⏳ 未リリース · トピック: [[repos/openai-codex/topics/セッション・スレッド管理|セッション・スレッド管理]]

### ネットワークプロキシの MITM のフックでリクエストの本文のシークレットを置き換える（[#57174](https://github.com/openai/codex/pull/57174)）

> [!tip] 何ができるようになったか
> バージョン 2 の MITM の設定に `body_secret_substitution` のアクションを追加した。一致したフックの範囲の中で、決まった不透明なプレースホルダーを環境変数やファイルのシークレットで置き換える。
>
> - 本文のサイズ・展開量・置き換えの回数・探索の量に上限を設け、重なる一致・圧縮した本文・トレーラー・呼び出し元が付けた本文の整合性のヘッダーは拒否する
> - `Content-Length` を計算し直し、SigV4 の署名の前に置き換えるので、署名は実際に送る本文を対象にする
> - **嬉しい場面**: エージェントに実物のシークレットを見せずに、外部の API のリクエストの本文に資格情報を入れたいとき

⏳ 未リリース · トピック: [[repos/openai-codex/topics/サンドボックス|サンドボックス]]

### 制約付きの単体のネットワークプロキシの設定（[#57180](https://github.com/openai/codex/pull/57180)）

> [!tip] 何ができるようになったか
> 制約（`constraints`）付きのネットワークのポリシーを読み書きする `StaticNetworkProxyConfig` を公開し、プロキシの状態を作る前に制約を検証するようにした。
>
> - 管理する呼び出し元向けに `--strict` と `from_slice_strict` を追加。明示的な `constraints` を必須にし、どの階層でも未知のフィールドを拒否する。既定の読み込みではトップレベルの `metadata` と制約の省略を許すが、未知のポリシーのフィールドは拒否する
> - 制約の検証で、許可する Unix ソケットのパスは大文字小文字を区別して照合する。設定ファイルの読み込みはサイズの上限 + 1 バイトまで

### ツールのクリティカルパスの計測と CUA のツール呼び出しの開始のイベント（[#57201](https://github.com/openai/codex/pull/57201)、[#57167](https://github.com/openai/codex/pull/57167)）

> [!tip] 何ができるようになったか
> 計測のための仕組みが 2 つ入った。
>
> - **`critical_path_timing`**（既定は無効）: ルートエージェントのターンの依存の経路を記録する。直接のツールの振り分け・実行ロックの受け渡し・完了したツールのまとまりをターンの計時につなぎ、重なった作業は共通の履歴を二重に数えない。CodeMode・エージェント間の通信・承認のレビュー・ユーザーの待ちなど未対応の依存は記録しない。実行時の機能の変更は次のターンから（[#57201](https://github.com/openai/codex/pull/57201)）
> - **`codex_cua_tool_call_started`**: Node REPL のコネクターでの `js` の MCP 呼び出しの開始を、開始時刻・ツール・プラグインとコネクターの ID・スレッドと応答の帰属付きで記録する（ツールの引数は記録しない）。CUA の呼び出しの重複した開始とリプレイした完了は抑える（[#57167](https://github.com/openai/codex/pull/57167)）

## 変更・修正

### トランスクリプトの選択モードの入力の振り分けを直し、コンポーザーの下書きを保つ（[#57224](https://github.com/openai/codex/pull/57224)）

> [!quote] Before
> キーを押したままトランスクリプトの選択を抜けると、繰り返しの入力がコンポーザーに送られ、保っていた下書きが送信されることがあった。

> [!success] After
> 選択のショートカットと操作をトランスクリプトとそのオーバーレイの両方で振り分け、下書きを保ち、検索の外の貼り付けは無視する。選択を閉じたときや非同期のコピーの完了で押したままの終了キーを消費し、送信やキューの操作には新たなキーの押下を求める。固定の選択の操作とページャーの動きは衝突するキーより優先する（検索と音声の操作は使える）。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/TUI|TUI]]

### macOS の単体のインストールで古いリリースの片付けを直す（[#57503](https://github.com/openai/codex/pull/57503)）

> [!quote] Before
> macOS の `lsof +D` は開いているファイルを見つけても終了コード 1 を返すことがあり、片付けが飛ばされていた。また ASCII でないインストール先のパスをエスケープするため、使用中のリリースをフルパスで見分けられなかった。

> [!success] After
> `lsof` の終了コード 1 は一致を保ったまま受け入れ、ほかの失敗や stderr への出力は引き続き拒否する。macOS ではインストーラーが所有する ASCII のパスの末尾で照合し、作業ディレクトリがリリースのルートのプロセスも見分ける。削除のためにリリースを移す前と後の両方で確認する。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/インストール|インストール]]

### Linux の拒否 glob の展開で探索のルートを読めないときは失敗にする（[#57186](https://github.com/openai/codex/pull/57186)）

> [!quote] Before
> Linux のサンドボックスの拒否 glob の展開で、探索のルートのメタデータの取得に失敗するとそのルートを黙って飛ばし、拒否のルールが失われるおそれがあった。

> [!success] After
> メタデータの取得に失敗したら、ルートと元のエラー付きの致命的なエラーを返す（存在しない・ディレクトリでないルートは従来どおり一致なし）。ディレクトリのシンボリックリンクは引き続きたどる。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/サンドボックス|サンドボックス]]

### 機能の発見の V2 を executor のバージョンで判定（[#57192](https://github.com/openai/codex/pull/57192)）

> [!quote] Before
> `0.164.0` より古い executor が最終的な仕様を実装しないまま V2 の発見の対応を名乗ることがあり、V2 を有効にすると V1 の発見も止まって、選んだ機能のルートやスキルが見えなくなっていた。

> [!success] After
> V2 の機能のフラグと executor のバージョン `0.164.0` 以上の両方がそろったときだけ `capabilities/discoverV2` を送る。互換でない executor が V2 のスナップショットを返さないときは V1 に戻り、保存していた V2 の一覧を消す。

⏳ 未リリース · トピック: [[repos/openai-codex/topics/実行環境アクセス|実行環境アクセス]]

### unified exec の出力を stdout・stderr から直接読む（[#57191](https://github.com/openai/codex/pull/57191)）

> [!quote] Before
> ローカルの出力は中間のブロードキャストのチャンネルを経由しており、遅れると出力のかたまりを飛ばすことがあった。

> [!success] After
> `tokio::select!` で stdout・stderr の受信側を直接読み、両方が閉じるまで読み切る。ローカル・リモートの出力の収集で `ExecOutputStream` を渡し、結合した出力のバッファも保つ。

### Guardian の Node REPL の出力の切り詰めをプロンプトの準備まで遅らせる（[#57176](https://github.com/openai/codex/pull/57176)）
