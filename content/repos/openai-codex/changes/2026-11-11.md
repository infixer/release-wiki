## 新機能

### TUI のサイドのチャットの探しやすさと移動を改善（[#60319](https://github.com/openai/codex/pull/60319)）

> [!tip] 何ができるようになったか
> 保存したサイドのチャットのタイトルの下に、最新のユーザーのプロンプトのプレビューを表示するようになった（チューザーの更新時に、見えている項目のプレビューだけを取得する）。
>
> - 発見の間もキャッシュしたチャットを使え、読み込み中・更新中の状態を表示し、失敗したときはその場で再試行できる
> - 一覧の更新をまたいで選択中のチャットを保ち、非同期の変更や押したままの決定キーで意図しない項目を開かない
> - サイドのチャットはメインのチャットで最初のメッセージを送った後に使えることを説明し、`Ctrl+C` でメインの下書きを保ったままチューザーを閉じられる
> - タブの間に操作できない隙間を入れ、タブ・はみ出しの矢印・追加ボタンのホバーの表示を改善

### スレッドのアイテム一覧で MCP のプレーンテキストの出力を後回しにできる（[#60390](https://github.com/openai/codex/pull/60390)）

> [!tip] 何ができるようになったか
> `turnId` で絞った `thread/items/list` のリクエストで、実験的な `deferOutput.mcpToolCall` を指定できるようになった。
>
> - 成功・完了した MCP の呼び出しで、注釈の無い空でないプレーンテキストの結果は、`result.content` を空にして `outputDeferred: true` で返せる。保存された出力は `thread/items/read` で取得する。コネクターの識別情報は一覧の項目に残る
> - リッチな結果、JSON やフェンス付きのテキスト、アプリの UI の結果、組み込みの `codex_app` の結果はインラインのまま
> - 大きすぎる MCP の結果の上限付きのプレビューでもプレーンテキストを保ち、後回しの対象にする。出力が履歴の上限（64 KiB）を超えるときは、読み取りで保存したプレビューを返す

### ゲートウェイの OAuth でモデルカタログを発見（[#60414](https://github.com/openai/codex/pull/60414)）

> [!tip] 何ができるようになったか
> ゲートウェイの OAuth と明示的なモデルカタログを持つカスタムのプロバイダーが、API キーや API キーによるモデルの発見の設定なしでモデルを発見できるようになった。
>
> - `model_catalog_url` と `base_url` が同じオリジンのとき、カスタムのゲートウェイのプロバイダーでカタログの更新を有効にする
> - カタログの更新ではゲートウェイの資格情報を再利用し、対話的なログインを始めない
> - 無関係な保存済みの API キーがあっても、ゲートウェイのカタログの発見が API キーの発見の設定に左右されない

### MCP のリソース一覧に待機中のサーバーを表示（[#60423](https://github.com/openai/codex/pull/60423)）

> [!tip] 何ができるようになったか
> まとめての `list_mcp_resources`・`list_mcp_resource_templates` の結果に、準備できたサーバーのリソースと並んで、ソートした `deferredServers` の一覧が入るようになった（これまでは休止中の MCP サーバーが省かれ、呼び出し側が名前を知る手段が無かった）。
>
> - 一覧の絞り込みは待機中のサーバーにも適用し、空なら項目を省く
> - 発見では休止中のサーバーを起動しない。`server` を明示して問い合わせればそのサーバーのリソースを一覧・読み取りできる（直接の呼び出しと Code Mode の両方）

### リアルタイムのアタッチの取り消しと期限（[#60443](https://github.com/openai/codex/pull/60443)）

> [!tip] 何ができるようになったか
> 保留中のリアルタイムの接続のハンドシェイクが後続のアタッチを止めてしまうため、呼び出し側が古い試行を取り消したり、接続の確立にかけられる時間を制限したりできるようになった。
>
> - **API**: `Op::RealtimeConversationAttach` に `RealtimeAttachmentOptions`（任意の取り消しの受信側と `start_before` の期限）
> - 取り消しを確認する前に保留中の接続の処理を中断して片付ける。取り消し済み・期限切れのリクエストは既存の会話を置き換える前に拒否し、接続を公開する前にも取り消しと期限を確認し直す
> - 公開に成功した接続は、後から取り消しが届いても保つ。値が `false` の取り消しの送信側を破棄した場合は試行を続ける

### ローカルのコンパクションでエラーの再試行のポリシーを守る（[#60473](https://github.com/openai/codex/pull/60473)）

> [!quote] Before
> ローカルのコンパクションは、不正なリクエストや再試行の助言の無いサーバーの過負荷のエラーも再試行し、サーバーが `Retry-After` を返してもローカルのバックオフを使っていた。

> `CodexErr::retry_delay` で再試行するかどうかと時期を決め、`Retry-After` があればその期限を守る。設定した再試行の上限とコンテキストウィンドウの切り詰めは従来どおり。

### ワークスペースのアクセスの拒否を終端のエラーに（[#60475](https://github.com/openai/codex/pull/60475)、[#60480](https://github.com/openai/codex/pull/60480)）

> [!quote] Before
> `invalid_workspace_selected` や `codex_workspace_access_denied` の HTTP 403 は想定外のステータスのエラーとして扱われ、再試行や、コンパクションでの別のモデルへのフォールバック、WebSocket から HTTP へのフォールバックが起きていた。

> [!success] After

### アクセスプログラムの拒否を終端のエラーに（[#60476](https://github.com/openai/codex/pull/60476)、[#60481](https://github.com/openai/codex/pull/60481)）

> [!quote] Before
> `access_program_not_enabled`・`invalid_access_program`・`unsupported_access_program` のエラーで、再試行のヘッダーや後続の `response.completed` があるとストリームの処理が続くことがあった。

> [!success] After
