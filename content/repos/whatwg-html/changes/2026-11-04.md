## 変更・修正

### node navigable が null の文書で「has focus steps」が false を返すように（[#13163](https://github.com/whatwg/html/pull/13163)）

> [!quote] Before
> 「has focus steps」は、対象の文書の node navigable が null のときも top-level traversable にアクセスしようとしていた。

> [!success] After
> node navigable が null なら、top-level traversable にアクセスする前に false を返す。`document.implementation.createHTMLDocument()` で作った文書がこれに当たり、Chromium・Gecko・WebKit の既存の挙動と一致する（WPT の `document-level-apis.html` の「`hasFocus()` は Document に browsing context が無ければ false を返す」で確認済み）。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/フォーカス|フォーカス]]

### パーサーが挿入したフォームコントロールでも挿入手順の残りを実行するように（[#13182](https://github.com/whatwg/html/pull/13182)）

> [!quote] Before
> parser inserted フラグが立っていると、挿入手順（insertion steps）のアルゴリズム全体から return していたため、後の手順（内部リソースのリンクの処理など）に到達しなかった。

> [!success] After
> parser inserted フラグが抑止するのはフォームオーナーのリセットだけなので、リセットの部分だけを条件で囲み、後の手順も実行されるようにした。WebKit と Chromium は既に正しく実装している。Gecko は `rel=expect` を実装していないため、この問題は起こりえない。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/フォーム|フォーム]]
