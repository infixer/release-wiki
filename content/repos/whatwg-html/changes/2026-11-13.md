## 新機能

### canvas にトーンマッピングを追加（[#11734](https://github.com/whatwg/html/pull/11734)）

> [!tip] 何ができるようになったか
> 2D canvas のコンテキストを作るときに、HDR の内容をどうトーンマッピングするかを指定できるようになった。canvas を出力デバイスに描画するときは、色空間の変換の前に、`dynamic-range-limit` で制限されたデバイスの HDR headroom に合わせてトーンマッピングされる。
>
> - **使い方**: `CanvasRenderingContext2DSettings` の新しいメンバー `toneMapping`（`CanvasToneMapping` 辞書。モードは `CanvasToneMappingMode` の `"standard"` / `"extended"`）。指定した値は `getContextAttributes()` で読み返せる
> - **嬉しい場面**: HDR の内容を 2D canvas に描くとき
>
> これらの型は WebGPU の `GPUCanvasToneMapping`・`GPUCanvasToneMappingMode` を置き換えるもので、WebGPU は `PredefinedColorSpace` と同じように HTML 側の定義を参照する。2D canvas と WebGL の float16 対応を待って、WebGPU だけの API から HTML に移された（issue #11424 を修正）。Chromium が提案、WebKit が支持、Gecko は反応なし。WPT のテストあり。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/canvas要素|canvas要素]]

## 変更・修正

### `selectedcontent` 要素を更新するタイミングを精密化（[#13005](https://github.com/whatwg/html/pull/13005)）

> [!quote] Before
> #12263 の後も、`selectedcontent` 要素の更新が足りない場合と多すぎる場合が残っていた。たとえば、選択済みの `option` が無い `select`（`selectedIndex` を -1 にした後など）に `option` を挿入して別の `option` が選択されても `selectedcontent` が更新されず、`option` を含む `select` を挿入すると更新が 2 回走っていた。

> [!success] After
> 選択が変わる `option` の挿入で `selectedcontent` を更新し、`option` を含む `select` や `option` の前の `selectedcontent` の挿入では更新を 1 回だけにする。`option` の削除・移動の後に積むマイクロタスクは `select` ごとにまとめ、その間に更新済みなら何もしない。`selectedcontent` を移動したときは `select` 側の同じ更新を積み（他の `selectedcontent` も更新される）、`select` と無効状態が変わらない移動では更新しない。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/select要素|select要素]]

### パーサーが要素の子のパースを終えたときの処理（「finish parsing the children」）を定義（[#13228](https://github.com/whatwg/html/pull/13228)）

> [!quote] Before
> 「foo 要素が HTML パーサーまたは XML パーサーの stack of open elements から pop されたとき」という記述が仕様のあちこちに散らばっていた。

> [!success] After
> 要素が stack of open elements から外れるとき（pop されたとき、current node でないまま取り除かれたとき（`form` の終了タグ、head element pointer、adoption agency algorithm）、adoption agency algorithm でエントリーが置き換えられたとき）に走る「finish parsing the children」を定義し、要素のローカル名ごとの「HTML element children parsed steps」に置き換えた。`style`・`audio`/`video`・`option`・`textarea` の記述をこの仕組みに移し、「update a style block」は `style` 要素を引数に取るようになった。`object` 要素の条件は従来の書き方のまま。
>
> current node でないまま取り除かれたときにも走らせるのは WebKit・Chromium の挙動に合わせたもので、Gecko は pop されたときだけ走らせる。WPT のテストあり（issue #11781 を閉じる）。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/HTMLパーサー|HTMLパーサー]]、[[repos/whatwg-html/topics/style要素|style要素]]

### `window.close()` で incumbent の文書の sandboxing flag を確認（[#12960](https://github.com/whatwg/html/pull/12960)）

> [!quote] Before
> ナビゲーションの書き直し（0a97a81da）で後退し、`window.close()` の sandboxing flag の確認が incumbent の文書を見ていなかった。

> [!success] After

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/Windowオブジェクト|Windowオブジェクト]]

### `SharedWorker()` の文字列の第 2 引数でも `SharedWorkerOptions` を使う（[#13248](https://github.com/whatwg/html/pull/13248)）

> [!quote] Before
> `SharedWorker()` の第 2 引数に文字列（name）を渡す旧来のオーバーロードでは、`SharedWorkerOptions` が使われていなかった。

> [!success] After
> 文字列が渡されたときも `SharedWorkerOptions` を使い、辞書のオーバーロードと同じく `extendedLifetime: false` が既定になる。後に続くワーカーの再利用の確認と初期化はどちらもこの値を読む。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/ワーカー|ワーカー]]

### `NavigateEvent` の中止手順で API method tracker を束縛（[#13247](https://github.com/whatwg/html/pull/13247)）

> [!quote] Before
> `NavigateEvent` を中止する手順で、ongoing API method tracker の null チェックはしていたが、promise を reject するアルゴリズムには束縛されていない `apiMethodTracker` を渡していた。

> [!success] After
> ongoing API method tracker を `apiMethodTracker` に読み込んでから使う。既存のテストは、ナビゲーション結果の `finished` の promise が `committed` の promise の解決後に reject されることを確認している。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/Navigation-API|Navigation-API]]
