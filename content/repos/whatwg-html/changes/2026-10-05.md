## 変更・修正

### `MessagePort` の `close` イベントを削除（[#13016](https://github.com/whatwg/html/pull/13016)）

> [!quote] Before
> `MessagePort` に `close` イベントが定義されており、もう一方のポートの所有者の文書が破棄されたときにポートを明示的に切り離す（disentangle）GC の仕組みを持っていた。

> [!success] After
> `close` イベントを追加したコミット（cc2634f）を差し戻し、以前の GC の扱いに戻した。ポートは簡単には GC されず、相手側の所有者の文書が破棄されても明示的には切り離されず、相手側が生きているかはポーリングで確認する（Firefox の挙動に合うとしている）。`close` イベントを出荷しているブラウザが無いことが理由。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/MessagePort|MessagePort]]

### イベントハンドラの「scripting is disabled」チェックを条件ごとに分割（[#13009](https://github.com/whatwg/html/pull/13009)）

> [!quote] Before
> [#12944](https://github.com/whatwg/html/pull/12944) でチェックをコンパイル時に移したことで、WebDriver BiDi でスクリプトを無効にしたときの扱い（#11441 の変更）が元に戻ってしまい、イベントハンドラ IDL 属性が null を返し、値が関数のハンドラは実行されていた。

> [!success] After
> 「scripting is disabled」に含まれる 3 つの条件を別々に扱う。ブラウジングコンテキストが null の場合と sandboxed scripts フラグが立っている場合は、内部の未コンパイルのハンドラのコンパイルだけを止める（関数を設定したハンドラは実行される。実装の挙動に合わせた）。WebDriver BiDi でスクリプトが無効な場合はハンドラの実行を止めるが、IDL 属性は関数を返したままにする。テストは [wpt#62719](https://github.com/web-platform-tests/wpt/pull/62719) など。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/イベントハンドラ|イベントハンドラ]]

### Navigation API の scroll behavior 処理で「reload」のときはスクロール位置を復元しないように（[#12993](https://github.com/whatwg/html/pull/12993)）

> [!quote] Before
> `#process-scroll-behavior`（スクロールの扱いを処理する手順）で、「reload」のナビゲーションでもスクロール位置を復元していた。

> [!success] After
> 「reload」ではスクロール位置を復元しない。Chromium と WebKit はすでにこの挙動で、Gecko には実装バグ（Bug 2075579）が登録された。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/Navigation-API|Navigation-API]]

### ongoing API method tracker の null チェックを追加（[#13024](https://github.com/whatwg/html/pull/13024)）

> [!quote] Before
> Navigation API 以外から始まったナビゲーションでは ongoing API method tracker が存在しないのに、null かどうかを確かめずに使っていた（#13014）。

> [!success] After
> 使う前に tracker が null でないことを確認する。テストは [wpt#63208](https://github.com/web-platform-tests/wpt/pull/63208)。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/Navigation-API|Navigation-API]]

### COEP/COOP の `report-to` は URL ではなくエンドポイント名を取ると修正（[#11366](https://github.com/whatwg/html/pull/11366)）

> [!quote] Before
> COEP の `report-to` パラメータが「有効な URL 文字列」を取ると書かれていた。

> [!success] After
> Reporting API に合わせ、`Reporting-Endpoints` ヘッダーで送られるエンドポイント名を取ると修正した（#11365）。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/COOP-COEP|COOP-COEP]]

### XML パーサーで DOM のノード作成アルゴリズムを使うように（[#13037](https://github.com/whatwg/html/pull/13037)）

> [!quote] Before
> XML パーサーは要素の作り方（create an element for a token、prefix は常に null）しか定めておらず、それ以外のノードは realm が未定義で、処理命令（processing instruction）には属性マップが無く `getAttribute()` が null を返していた。

> [!success] After
> create an element for a token に省略可能な prefix を追加し、ノードの種類ごとに作成アルゴリズムを定めた（HTML パーサーで 85f453b が行ったのと同じ方式）。

⏳ 未リリース · トピック: [[repos/whatwg-html/topics/XMLパーサー|XMLパーサー]]
