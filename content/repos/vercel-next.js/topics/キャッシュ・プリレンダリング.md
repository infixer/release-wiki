## 概要

Cache Components（`"use cache"`）・ISR・Partial Prerendering（PPR）まわりの実装。ルートの「静的シェル」と「ランタイムプリフェッチ」を分けて扱う仕組みが土台にあり、ルートパラメータ（`params`）や root params が、意図せず別のパラメータ値のキャッシュ・シェルに混入しないようにする修正が多く入っている。`ensureStatic` セグメント設定（`unstable_` 接頭辞は外れて安定 API になった）は、セグメントごとに静的化の強さを指定するための新しい仕組みで、`"shell"` 以上では Instant Validation が静的シェルを基準に検証するようになった。`'use cache'` の root params を静的に追跡するための準備も進んでいる。`"navigation"` は初期実装が入り、すべての params を `generateStaticParams` で指定させてリクエストごとの計算を無くす。`navigation()` / `prefetch()` は `unstable_` 接頭辞が外れ、`create-next-app` は Cache Components を既定で有効にするようになった。プリレンダー時の `notFound()`・`redirect()` などの HTTP ステータス保持や、起動直後のカスタムキャッシュハンドラーの修正も入っている。Cache Components では `unstable_paramMatching` / `unstable_generateParamMatching` で未知のパラメータ値の扱い（404・ブロッキング・フォールバック・動的）を指定できるようになった。`revalidateTag` のカスタムハンドラーへの伝播、ISR エントリのキャッシュ期間のインスタンス間共有、レスポンスキャッシュキーのルートごとの分離などの修正も続いている。安定版 v16.3.8 / v15.5.27 では SSG・ISR のキャッシュポイズニングや `use cache` の漏えいに関するセキュリティ修正が公開された。

## 主な API・オプション

- `"use cache"` / `"use cache: private"` / `"use cache: remote"` — キャッシュ関数の宣言
- `ensureStatic`（旧 `unstable_ensureStatic`）— セグメント設定。`"auto" | "shell" | "prefetch" | "navigation" | false` を指定し、静的化の強さを段階的に制約する
- `ensureStatic = "navigation"` — すべてのプリレンダーをブロッキングにし、全 params を `generateStaticParams` で指定させる（リクエストごとの計算なし）
- `unstable_paramMatching` / `unstable_generateParamMatching`（Cache Components）— パラメータごとに `'not-found'` / `'blocking'` / `'fallback'` / `'dynamic'` を指定。レイアウトからページへマージされる。型は `next` の `ParamMatching`
- `CacheHandlerValue.cacheControl` — カスタムキャッシュハンドラーが `get()` でエントリのキャッシュ期間を返せる
- `navigation()` / `prefetch()`（`next/cache`）— `unstable_` 接頭辞が外れた（旧 `unstable_navigation` / `unstable_prefetch`）
