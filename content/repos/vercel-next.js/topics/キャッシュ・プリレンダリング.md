## 概要

Cache Components（`"use cache"`）・ISR・Partial Prerendering（PPR）まわりの実装。ルートの「静的シェル」と「ランタイムプリフェッチ」を分けて扱う仕組みが土台にあり、ルートパラメータ（`params`）や root params が、意図せず別のパラメータ値のキャッシュ・シェルに混入しないようにする修正が多く入っている。実験的な `unstable_ensureStatic` セグメント設定は、セグメントごとに静的化の強さを指定するための新しい仕組みで、`"shell"` 以上では Instant Validation が静的シェルを基準に検証するようになった。`'use cache'` の root params を静的に追跡するための準備も進んでいる。`"navigation"` は初期実装が入り、すべての params を `generateStaticParams` で指定させてリクエストごとの計算を無くす。`navigation()` / `prefetch()` は `unstable_` 接頭辞が外れ、`create-next-app` は Cache Components を既定で有効にするようになった。プリレンダー時の `notFound()`・`redirect()` などの HTTP ステータス保持や、起動直後のカスタムキャッシュハンドラーの修正も入っている。

## 主な API・オプション

- `"use cache"` / `"use cache: private"` / `"use cache: remote"` — キャッシュ関数の宣言
- `unstable_ensureStatic`（実験的）— セグメント設定。`"auto" | "shell" | "prefetch" | "navigation" | false` を指定し、静的化の強さを段階的に制約する
- `ensureStatic = "navigation"` — すべてのプリレンダーをブロッキングにし、全 params を `generateStaticParams` で指定させる（リクエストごとの計算なし）
- `navigation()` / `prefetch()`（`next/cache`）— `unstable_` 接頭辞が外れた（旧 `unstable_navigation` / `unstable_prefetch`）
