## 概要

Cache Components（`"use cache"`）・ISR・Partial Prerendering（PPR）まわりの実装。ルートの「静的シェル」と「ランタイムプリフェッチ」を分けて扱う仕組みが土台にあり、ルートパラメータ（`params`）や root params が、意図せず別のパラメータ値のキャッシュ・シェルに混入しないようにする修正が多く入っている。`ensureStatic` セグメント設定（`unstable_` 接頭辞は外れて安定 API になった）は、セグメントごとに静的化の強さを指定するための新しい仕組みで、`"shell"` 以上では Instant Validation が静的シェルを基準に検証するようになった。`'use cache'` の root params を静的に追跡するための準備も進んでいる。`"navigation"` は初期実装が入り、すべての params を `generateStaticParams` で指定させてリクエストごとの計算を無くす。`navigation()` / `prefetch()` は `unstable_` 接頭辞が外れ、`create-next-app` は Cache Components を既定で有効にするようになった。プリレンダー時の `notFound()`・`redirect()` などの HTTP ステータス保持や、起動直後のカスタムキャッシュハンドラーの修正も入っている。Cache Components では `unstable_paramMatching` / `unstable_generateParamMatching` で未知のパラメータ値の扱い（404・ブロッキング・フォールバック・動的）を指定できるようになった。`revalidateTag` のカスタムハンドラーへの伝播、ISR エントリのキャッシュ期間のインスタンス間共有、レスポンスキャッシュキーのルートごとの分離などの修正も続いている。`cacheComponents` を有効にして `partialPrefetching` を明示していないと警告が出るようになり、次のメジャーリリースで両機能がすべてのアプリで有効になり古い設定は削除されると案内されている。安定版 v16.3.8 / v15.5.27 では SSG・ISR のキャッシュポイズニングや `use cache` の漏えいに関するセキュリティ修正が公開された。`'use cache'` の root params の依存は `experimental.useCacheStaticRootParamTracking` を有効にすると Turbopack の本番ビルドで収集され、マニフェストに `rootParamDependencies` として出力される。パラメータのマッチング API を使っているかは `prerender-manifest.json` の一時的なフィールドで分かるようになった。ランタイムプリレンダーで Sync IO により最適化が外れた場合は、エラーがログに出るようになった。`next build` のルート表では、`ensureStatic = 'navigation'` などで生成パスがすべて静的な catch-all ルートの `[+N more paths]` の行に、子のパスの記号（○ Static）が使われる（v16.5.0-canary.8）。`generateStaticParams` 中の `workStore.page` が正規化前のパスになり、そこから呼ばれた `"use cache"` 関数も `durableUseCacheEntries` でビルドをまたいで再利用できるようになった。Durable use cache では、tree shaking の違いでエンドポイントごとに Server Action の `codeHash` が変わらないようにした。Turbopack で `cacheHandlers` を設定した Edge のルートハンドラーのビルド失敗も修正され、Redis で `cacheHandlers` を使うサンプル `cache-handler-redis-turbo` が加わった（いずれも v16.5.0-canary.10）。安定版 v16.4.1 では、`use cache` 関数が型付き配列を返す場合のリモートコード実行（Critical）のセキュリティ修正が公開された。`cacheComponents` と Turbopack の共有ランタイムを使う本番ビルドでは、ルートのブートストラップが静的シェルではなく PPR の resume からリクエストの nonce 付きで出力されるようになり、nonce ベースの CSP でもハイドレーションする（未リリース）。クライアントのセグメントキャッシュでは、プリフェッチの `FetchStrategy` が描画のステージ（`AppStage`: shell・prefetch・navigation）と完全性（`Completeness`。`isPartial` を置き換え）に分けられた（v16.5.0-canary.17、リファクタ）。プリレンダーの `Static` ステージは削除され、入力が止まる（hanging input）キャッシュも `NavigationStatic` のタスクまでに確定する（v16.5.0-canary.21）。v16.5.0-canary.24 では、Pages Router の ISR のエントリのキャッシュ期間が既定の `FileSystemCache` で再起動後も保たれるようになり（App Router は #99289 で対応済み）、ストリーミング中に積まれた再検証はレスポンスのクローズ時に flush される（Flight・ルートハンドラー・ストリーミングする Server Actions も対象）。バックグラウンドの再検証は Resume Data Cache を書き換えず、最終のランタイムプリレンダーが予備のプリレンダーと同じキャッシュ値を使う。Durable use cache で Node.js の worker を読み込む関数のクラッシュと、開発時の prerender マニフェストの更新の競合も修正された。v16.5.0-canary.29 では、`FileSystemCache` が再検証とエントリの時刻をモノトニッククロックで記録するようになり（壁時計が進んでいると `revalidateTag` 後も古いページが返る問題の修正）、完全に静的な PPR のページの RSC ペイロードもディスクに保存されて再起動後も再利用される。Partial Prefetching で `'use cache'` のエラーの後に HTML が終わらない問題、MPA の Server Actions の後に完全な HTML が返らない問題、フォールバックシェルの静的生成で全バッチに RDC のシードを送って `RangeError: Invalid string length` になる問題も修正された。

## 主な API・オプション

- `"use cache"` / `"use cache: private"` / `"use cache: remote"` — キャッシュ関数の宣言
- `ensureStatic`（旧 `unstable_ensureStatic`）— セグメント設定。`"auto" | "shell" | "prefetch" | "navigation" | false` を指定し、静的化の強さを段階的に制約する
- `ensureStatic = "navigation"` — すべてのプリレンダーをブロッキングにし、全 params を `generateStaticParams` で指定させる（リクエストごとの計算なし）
- `unstable_paramMatching` / `unstable_generateParamMatching`（Cache Components）— パラメータごとに `'not-found'` / `'blocking'` / `'fallback'` / `'dynamic'` を指定。レイアウトからページへマージされる。型は `next` の `ParamMatching`
- `CacheHandlerValue.cacheControl` — カスタムキャッシュハンドラーが `get()` でエントリのキャッシュ期間を返せる
- `navigation()` / `prefetch()`（`next/cache`）— `unstable_` 接頭辞が外れた（旧 `unstable_navigation` / `unstable_prefetch`）
- `partialPrefetching` — Cache Components と併用する設定。`cacheComponents` 有効時は `true` / `false` の明示が求められる（`false` は古い Cache Components アプリの段階的移行用）
- `experimental.useCacheStaticRootParamTracking` — `'use cache'` の root params の依存をビルド時に収集する（既定は `false`、Turbopack の本番ビルドのみ）
- `cacheHandlers` / `cacheHandler` — カスタムキャッシュハンドラー（複数形は `'use cache'` 用、単数形は Pages Router の ISR 用）。Redis の例は `examples/cache-handler-redis-turbo`
