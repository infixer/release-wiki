## 概要

`next/image`（Image コンポーネント・`getImageProps`）と、サーバー側の画像最適化（image optimizer）の実装。外部画像を取得するときは DNS 解決の結果を固定するようになった。Vercel アダプターのデプロイで不変（immutable）な設定を扱えるように、画像のオプションを設定を書き換えずに一度だけ用意して使い回す変更が入っている。安定版 v16.3.8 では、画像最適化での SSRF（High）のセキュリティ修正が公開された。画像最適化の変換処理は公開のサブパス `next/image-optimizer-transform` から import でき、場所とエクスポートが安定した契約になった（`next/dist/server/image-optimizer/*` への依存が不要に）。Turbopack の画像処理では webp が wasm 版も含めて常に有効（いずれも v16.5.0-canary.8）。`next/image` の非推奨の props（`priority` など）は、エディターで `@deprecated` として表示されるようになった。Turbopack の画像処理は AVIF の幅・高さを正しく取得するようになった（最適化・エンコードはまだ行わない）（いずれも v16.5.0-canary.10）。安定版 v16.4.1 / v15.5.28 では、SVG ファイルを使う場合の画像最適化 API でのリモートコード実行（Critical）のセキュリティ修正が公開された。安定版 v16.4.5 / v15.5.29 では、画像最適化での SVG の拒否の回避（Moderate）のセキュリティ修正が公開された。画像最適化 API はローカル画像のリダイレクトも外部画像と同じく `images.maximumRedirects` 回までたどるようになった。16.5 の安定版より前に `next/image-optimizer-transform` の公開 API が整理され、`optimizeImage` の削除、`handleDevOutput` から `ImageOptimizerResult` の `optimized` フラグへの置き換え、前回のキャッシュエントリの再利用の呼び出し側への移動が入った（いずれも v16.5.0-canary.42）。`nextConfig`（`NextConfigComplete`）を受け取る形をやめる変更は未リリース。
同梱の `is-animated` は 3.0.19 になり、アニメーションの判定が平均で速くなった（形式によっては遅くなる。v16.5.0-canary.45）。

## 主な API・オプション

- `images.qualities` — 許可する画質。開発時の blur 用の品質はこの配列に追加せず、検証時に直接許可される
- `getImageProps` — 固定のオプションをモジュール初期化時に一度だけ用意する
- `next/image-optimizer-transform` — 画像最適化の変換処理の公開サブパス（`imageOptimizerTransform`・`getSharp`・`getMaxAge`・`ImageError`。`optimizeImage` は v16.5.0-canary.42 で削除、結果の `ImageOptimizerResult` は `optimized` フラグを持つ）
- `priority`・`onLoadingComplete`・`layout`・`objectFit`・`objectPosition`・`lazyBoundary`・`lazyRoot`（`next/image`）— 非推奨の props。`priority` の代わりは `preload`
- `images.maximumRedirects` — 画像の取得でたどるリダイレクトの上限。v16.5.0-canary.42 からローカル画像にも適用
