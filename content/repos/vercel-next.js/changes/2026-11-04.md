## 新機能

### Turbopack: モジュール単位で先に minify する実験的なフラグ（[#98760](https://github.com/vercel/next.js/pull/98760)）

> [!tip] 何ができるようになったか
> これまで minify はチャンク単位で行われ、大きなチャンクがあると 1 つの長い処理になって空いたコアを活かせなかった。`experimental.turbopackMinifyBeforeChunking` を有効にすると、モジュールのファクトリごとに minify してその結果をキャッシュする。各処理が小さくなって並列に配りやすくなり、再ビルドでは変更されたモジュールだけを minify し直す。
>
> - **使い方**: `experimental.turbopackMinifyBeforeChunking`（ビルドのみ。開発時は minify しない）。クライアント・サーバー・Edge のチャンク化に適用される
> - **嬉しい場面**: 大きなチャンクがあるアプリのビルド時間を短くしたいとき（PR では、バイトサイズはほぼ変わらない想定だが、実アプリのベンチマークでの検証が必要としている）

### React の外部ブラウザーランタイムを使う実験的なフラグ `experimental.externalBrowserRuntime`（[#97570](https://github.com/vercel/next.js/pull/97570)）

> [!tip] 何ができるようになったか
> React の Fizz は命令をインラインの `<script>` で流すため、CSP で `unsafe-inline` を許可するか、静的生成と両立しないレスポンスごとの nonce が必要だった。このフラグを有効にすると React の `unstable_server-external-runtime` に切り替わり、命令は `<template data-rci>` 要素として出力され、別のランタイムスクリプトがブラウザーで適用する。
>
> - **使い方**: `experimental.externalBrowserRuntime`。React の実験版チャンネルにしかないため、有効にすると `app` ディレクトリは `react@experimental` を使う。App Router のみ
> - **見た目の違い**: `/_next/static/chunks` の静的アセットが 1 つと、`<head>` の `<script>` タグ（`async`、nonce・integrity 付き）が 1 つ増える。React のインラインのフォーム再生ランタイムは注入されなくなる
> - **注意**: Flight のペイロードと `bootstrapScriptContent` はまだインラインのスクリプト。`unsafe-inline` を完全に不要にする取り組みの一歩

### `router.experimental_prepare()` を追加（[#101050](https://github.com/vercel/next.js/pull/101050)）

> [!tip] 何ができるようになったか
> `useRouter()` のルーターに `experimental_prepare(href)` が加わった。動的リクエストを含めて通常の遷移と同じ手順を進めるが、ルーターは更新しない。結果は戻る/進むの遷移と同じローカルキャッシュ（bfcache）に書き込まれる。返されるハンドルの `push()` / `replace()` で確定すると、準備開始以降に書かれた bfcache のエントリを stale time に関係なく使い、リクエストが飛行中ならそれを再利用する。
>
> - **使い方**: pointerdown で `experimental_prepare(href)`、click でハンドルの `push()`（将来 `Link` に組み込む可能性がある）
> - **注意**: 確定しなくてもデータは bfcache に残る。準備したデータは期限切れにならない。準備と確定の間の refresh や Server Action で無効になる。ハンドルは 1 回だけ確定でき、2 回目以降は何もしない（開発時は警告）

### Turbopack CLI で `.go` ファイルをコンパイル（実験）（[#99980](https://github.com/vercel/next.js/pull/99980)）

> [!tip] 何ができるようになったか
> Turbopack とその CLI に実験的な Go のコンパイルが加わった。パッケージの発見・コンパイル・リンクは Go が行い、Turbopack は報告されたソース・モジュール・埋め込みアセットなどを追跡して、通常の出力パイプラインで実行ファイルを出力する。
>
> - **使い方**: CLI に同じディレクトリの Go ファイルを明示して渡す（Go と JavaScript のエントリの混在、build / watch / dev に対応）。`--persistent-caching` でプロセスをまたいでコンパイル結果を復元
> - **嬉しい場面**: フレームワーク側が Go のパースやコンパイラーの管理を実装せずに独自のエントリポイントを生成したいとき（ルートハンドラーとの統合は [#100130](https://github.com/vercel/next.js/pull/100130)）

### App Router の `route.go` ハンドラー（実験）（[#100130](https://github.com/vercel/next.js/pull/100130)）

> [!tip] 何ができるようになったか
> `experimental.goRoutes: true` と Turbopack で、Go の `package main` に `func GET(w http.ResponseWriter, r *http.Request)` や `POST` などを宣言した `route.go` をルートハンドラーとして使える。HEAD / OPTIONS は自動で扱われる。
>
> - **使い方**: `experimental.goRoutes: true`（Turbopack が必要）
> - **動き**: 開発時とセルフホストの `next start` では、ルーティング・rewrites・`proxy.ts` は Node.js のまま、監督下の Go のワーカーが処理する（ストリーミング・ヘッダー・Cookie・パラメータ・キャンセルに対応）
> - **アダプター向け**: `APP_ROUTE` の出力に `runtime: 'go'` と実行ファイルの `filePath` が入る。`goTarget` オプションでターゲットを選べる

### アダプターなどが instrumentation を差し込める `instrumentationInject`（[#100658](https://github.com/vercel/next.js/pull/100658)）

> [!tip] 何ができるようになったか
> 設定オプション `instrumentationInject?: string[]` が加わった。各エントリの `register` と `onRequestError` を配列の順に実行し、その後にプロジェクト自身の `instrumentation.{ts,js}`（あれば）を実行する 1 つのモジュールがコンパイルされる。クライアントの `instrumentationClientInject` と同じ考え方。
>
> - **使い方**: デプロイアダプターの `modifyConfig` や `withSentry` のような設定ラッパーで `config.instrumentationInject ??= []; config.instrumentationInject.push('./path/to/instrumentation.js')`
> - **嬉しい場面**: ホスティング側が OpenTelemetry のトレースなどの既定の instrumentation を、ユーザーのファイル・`package.json`・lockfile に手を入れずにビルド時に供給したいとき

### create-next-app: Tailwind を 4.3.3 に固定（[#101061](https://github.com/vercel/next.js/pull/101061)）

> [!quote] Before
> 2026-11-02 に公開された `@tailwindcss/node@4.3.4` が ESM 専用の `magic-string@^1.1.0` に移ったため、テンプレートの `^4` の範囲でこれを取り込むと、ES モジュールを `require()` できない Node.js（20.19 より前、22.0〜22.11。Next.js の最低対応の 20.9.0 を含む）で、Tailwind を使う新規プロジェクトのビルドが `require() of ES Module` で失敗していた。

> [!success] After
> `tailwindcss` と Tailwind のバンドラープラグイン（`@tailwindcss/turbopack` / `@tailwindcss/postcss`）を一時的に `4.3.3` に固定する。Tailwind が修正を出したら `^4` に戻す。

📦 v16.5.0-canary.40 · トピック: [[repos/vercel-next.js/topics/create-next-app|create-next-app]]

### 読み込んだ設定が既定値や呼び出し側とオブジェクトを共有しないように（[#99942](https://github.com/vercel/next.js/pull/99942)）

> [!quote] Before
> `loadConfig` は入れ子の設定（`images.localPatterns`、`basePath` 付きの `images.path`、`experimental.staleTimes` など）をその場で正規化していたが、既定値（`imageConfigDefault` など）を参照のまま使っていたため、同じプロセスで 2 つ目の設定を読むと前の値を引き継いだり、前の設定を書き換えたりした（`basePath` が `/docs` → `/blog` で 1 つ目の `images.path` が `/blog/docs/_next/image` になる）。`next({ conf })` の呼び出し側のオブジェクトや、アダプターの `modifyConfig` の戻り値にも書き込んでいた。

> [!success] After
> `loadConfig` が書き込むオブジェクトはすべて自前のコピーにする（`defaultConfig`・カスタム設定・`modifyConfig` の結果を `cloneObject` で複製し、設定の関数には凍結したコピーを渡す）。

⏳ 未リリース · トピック: [[repos/vercel-next.js/topics/next-config|next.config]]
