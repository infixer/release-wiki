## 新機能

### `next upgrade --ai` で AI エージェントによるセキュリティアップグレードが可能に（[#98562](https://github.com/vercel/next.js/pull/98562)）

> [!tip] 何ができるようになったか
> 使用中の Next.js バージョンにセキュリティ勧告がある場合、`next upgrade --experimental-ai="security"`（エイリアス `--ai`）で、AI エージェントを使った安全なメジャーバージョンへのアップグレードを開始できるようになった。
>
> - **使い方**: `next upgrade --ai` を実行すると、対応エージェントハーネス（現時点では Codex・Claude）を検出し、承認後にエージェントセッションを開始する。既にエージェントセッション内から呼び出した場合は、その場で作業を継続する
> - **仕組み**: 移行に必要なコンテキストを一時ディレクトリに用意し、実行すべきコードモッドと移行チェックリストへ誘導する引き継ぎプロンプトを出力する

📦 v16.4.0-canary.42 · トピック: [[repos/vercel-next.js/topics/AI-アップグレード|AIアップグレード]]

### 実験的な `agentFeedback` でコーディングエージェントの困りごとを収集（[#98582](https://github.com/vercel/next.js/pull/98582)）

> [!tip] 何ができるようになったか
> `next dev` 実行中に、コーディングエージェントが遭遇した Next.js の使いにくさ（friction）を、作業を妨げずに収集する実験的な `agentFeedback` ワークフローを追加。
>
> - **仕組み**: `next dev` がプロジェクトのエージェント指示ファイルに小さな管理ブロックを書き込み、エージェントの区切りのよいタイミングでリモートのゲートを確認、該当する問題があれば匿名化したうえでレビューフォームを一度だけ開く（ブラウザが開けない場合は URL を出力するのみ）
> - **無効化**: `agentFeedback` や `agentRules` を無効にすると、次回の `next dev` で管理ブロックだけが削除され、ユーザーが書いた内容は保持される

### Turbopack の `resolveAlias` に `false` を指定してモジュールを空スタブ化できるように（[#93331](https://github.com/vercel/next.js/pull/93331)）

> [!tip] 何ができるようになったか
> `experimental.turbopack.resolveAlias` の値に `false` を指定すると、対象モジュールが空オブジェクトのスタブに解決されるようになった。webpack の従来からの挙動に合わせたもので、Node 専用パッケージをクライアント/エッジバンドルから除外する用途などに使える。
>
> - **使い方**:
> ```js
> experimental: {
>   turbopack: {
>     resolveAlias: { 'some-server-only-module': false },
>   },
> }
> ```

### `unstable_ensureStatic` セグメント設定を追加（実験的）（[#98190](https://github.com/vercel/next.js/pull/98190), [#98357](https://github.com/vercel/next.js/pull/98357)）

> [!tip] 何ができるようになったか
> セグメントごとに `"auto" | "shell" | "prefetch" | "navigation" | false` を指定できる `unstable_ensureStatic` の土台を追加。
>
> - **階層**: `auto < shell < prefetch < navigation` の順に制約が強くなり、子セグメントは親の制約を緩めることはできず、より厳しくすることだけができる（`auto` はどの制約とも両立する）
> - **`false`**: そのルート上の他のセグメントが `auto` より高い制約を課すことを禁止する。「このセグメントは意図的にランタイムシェルを使う」という宣言として使う

### webpack モードでプロジェクト側の webpack を使える `customWebpack` オプションを追加（実験的）（[#98862](https://github.com/vercel/next.js/pull/98862)）

> [!tip] 何ができるようになったか
> 実験的な `customWebpack` 設定オプションを追加し、webpack モードのアプリが Next.js にバンドルされた webpack ではなく、プロジェクトにインストールされた webpack バージョンを使えるようになった。
>
> - **対象**: webpack のみ（Turbopack・Rspack には影響しない）。webpack は `^5.98.0` のオプショナルな peer dependency として扱われる
> - **フォールバック**: 指定したバージョンを解決できない場合は既存のバンドル済み実装に戻り、インストールを促すエラーを表示する
