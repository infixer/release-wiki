## 新機能

### アップグレードのリマインダー用ルールを `experimental.agentUpgrade` で制御する専用ブロックに（[#99990](https://github.com/vercel/next.js/pull/99990)）

> [!tip] 何ができるようになったか
> `AGENTS.md` に、ドキュメントやフィードバックのルールとは別の管理ブロック `nextjs-agent-upgrade` を追加した。エージェントへのアップグレードの委任が、既存の `experimental.agentUpgrade` のポリシーだけに従うようになる。ポリシーが有効なら検出したエージェント向けにブロックを生成し、`agentUpgrade: false` なら `next dev` の実行時にほかの指示は残したままこのブロックを削除する。create-next-app の既定のプロジェクトにもこのブロックが含まれる。
>
> - **使い方**: `next.config` の `experimental.agentUpgrade`（`false` でブロックを削除）
> - **嬉しい場面**: エージェントがビルド出力のアップグレード通知を指示として受け入れなかったり、元の作業の後に通知を書き漏らしたりするのを防ぎたいとき

### サンプル `cache-handler-redis-turbo` を追加（Cache Components + Redis）（[#96622](https://github.com/vercel/next.js/pull/96622)）

> [!tip] 何ができるようになったか
> `@trieb.work/nextjs-turbo-redis-cache` を使って Redis を共有キャッシュにするサンプル `examples/cache-handler-redis-turbo` を追加した。`cacheHandler`（単数形、Pages Router の ISR）と `cacheHandlers`（複数形、`'use cache'` / `cacheComponents: true`）の両方を示し、`cacheLife("minutes")`・`cacheTag`・`revalidateTag(..., "max")` の Server Actions のデモを含む。ビルド時は何もしないハンドラーを使うため、Redis 無しでも `next build` が通る。ローカル開発用に `redis/redis-stack` の docker compose も付く。
>
> - **使い方**: `examples/cache-handler-redis-turbo` を参照
> - **嬉しい場面**: 既存の `examples/cache-handler-redis`（`@neshca/cache-handler`、`next` < 15 に固定）では扱えない、Next.js 16 の Cache Components と `cacheHandlers` を Redis で使いたいとき

## 変更・修正

### turbo-tasks: 最低優先度のタスクをロックフリーのキューに（[#99773](https://github.com/vercel/next.js/pull/99773)）

> [!quote] Before
> turbo-tasks の `PriorityRunner` では、すべての `schedule` とワーカーの `pop` が 1 つの `Mutex<Queue>` を通っていた。ゼロからのビルドではほぼすべてのタスクが最低優先度（`TaskPriority::Initial`）のため、ワーカー数が多いとここで競合していた。

> [!success] After
> 最低優先度のタスクはロックフリーの MPMC `ConcurrentQueue`（FIFO）へ、それ以外は `Mutex<BinaryHeap>` へ分けた。`schedule` はグローバルなロックを取らず、ヒープが空なら `Queue::pop()` はヒープのロックも取らない（[#94841](https://github.com/vercel/next.js/pull/94841) を置き換え）。

📦 v16.5.0-canary.10 · トピック: [[repos/vercel-next.js/topics/ビルド・Turbopack|ビルド・Turbopack]]

### next/image: 非推奨の props がエディターで非推奨として表示されるように（[#98597](https://github.com/vercel/next.js/pull/98597)）

> [!success] After
> `Image` の型に `ImageProps` を明示し、`priority`・`onLoadingComplete`・`layout`・`objectFit`・`objectPosition`・`lazyBoundary`・`lazyRoot` の `@deprecated` がエディターに表示される。破壊的変更ではない。

### codemod `agents-md`: ドキュメントの `root` を出力ファイル基準の相対パスに（[#100016](https://github.com/vercel/next.js/pull/100016)）

> [!quote] Before

> [!success] After
