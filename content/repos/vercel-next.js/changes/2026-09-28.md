## 新機能

### Turbopack の `additionalRoots` がデプロイアダプターでも使えるように（[#99015](https://github.com/vercel/next.js/pull/99015)）

> [!tip] 何ができるようになったか
> [#98003](https://github.com/vercel/next.js/pull/98003) の続きとして、Turbopack の `additionalRoots` が `vc deploy` などアダプター API を使うデプロイでも動くようになった（破壊的変更ではない）。
>
> - **仕組み**: ルートをまたぐシンボリックリンクのターゲットを書き換える必要がある場合、「合成」シンボリックリンクを作成する
> - **ドキュメント**: `next.config.js` の `turbopack` リファレンスも更新

📦 v16.4.0-canary.51 · トピック: [[repos/vercel-next.js/topics/ビルド・Turbopack|ビルド・Turbopack]]

### バンドルアナライザーの比較画面が URL で共有できるように（[#98530](https://github.com/vercel/next.js/pull/98530)）

> [!tip] 何ができるようになったか
> バンドルアナライザーの比較機能を専用の `/compare` ルートに移し、選択したベースライン・比較スナップショット・ルート・表示を URL の検索パラメータに保存するようにした。
>
> - **嬉しい場面**: 比較結果の画面をリンクとして共有したいとき
> - **補足**: データ URL をルート相対にし、開発時は過去のスナップショットをプロキシすることで、ネストしたルートからもデータを読み込める

📦 v16.4.0-canary.51 · トピック: [[repos/vercel-next.js/topics/ビルド・Turbopack|ビルド・Turbopack]]

### Git の無いアプリでもエージェントによるアップグレードが可能に（[#99217](https://github.com/vercel/next.js/pull/99217)）

> [!tip] 何ができるようになったか
> Git リポジトリが無いアプリでも、設定したリマインダーから始めたものを含め、エージェントによるアップグレード（agentic upgrade）を使えるようになった。
>
> - **仕組み**: Git が無い場合はその場でアップグレードするようエージェントに指示し、Git がある場合は worktree・コミット・プルリクエストを使う
> - **重複作業の確認**: アプリで使えるリポジトリ・プロバイダーの機能を使って確認する

📦 v16.4.0-canary.51 · トピック: [[repos/vercel-next.js/topics/AI-アップグレード|AIアップグレード]]

### アップグレードを別の worktree で行うかユーザーに確認するように（[#99232](https://github.com/vercel/next.js/pull/99232)）

> [!tip] 何ができるようになったか
> エージェントによるアップグレードを別の worktree で実行するかどうかを、ユーザーが選べるようになった。
>
> - **仕組み**: 既存のエージェント内ではアップグレード時の 1 回の質問の中で、新しくエージェントを起動する場合は起動前に確認し、その選択をアップグレードの指示に渡す

## 変更・修正

### 実験的な `customWebpack` サポートを revert（[#99227](https://github.com/vercel/next.js/pull/99227)）

> [!quote] Before
> 実験的な `customWebpack` オプション（[#98862](https://github.com/vercel/next.js/pull/98862)）で、プロジェクトにインストールした webpack を使えた。

> [!success] After
> 新しい依存チェーンによりモノレポ構成で Next.js のバージョンが重複しうること、内部同期が壊れていたことから、変更を取り消した。依存グラフの調整で直せる可能性はあるが、先に調査とドキュメント化が必要としている。

> [!warning] 移行が必要
> canary で `customWebpack` を試していた場合、このオプションは使えなくなる。

📦 v16.4.0-canary.51 · トピック: [[repos/vercel-next.js/topics/ビルド・Turbopack|ビルド・Turbopack]]

### PPR ページへ遷移した後に Server Action がハングする不具合を修正（[#99252](https://github.com/vercel/next.js/pull/99252)）

> [!quote] Before
> Vercel 上で `/a` から PPR の `/b` に遷移した後に `/a` が持つ Server Action を呼ぶと、転送処理が消費済みのリクエストストリームを再度読もうとし、関数がタイムアウトするまで待ち続けていた。

> [!success] After
> 保存済みの `actionBody` があればそれを転送し、転送元ルートの resume ヘッダーを取り除くようにした。`actionBody` が無いリクエストは従来どおりリクエストストリームを使う（[#99153](https://github.com/vercel/next.js/issues/99153) の修正）。

📦 v16.4.0-canary.51 · トピック: [[repos/vercel-next.js/topics/Server-Actions|Server Actions]]

### Edge SSR でメタデータのストリーミング方針が守られない不具合を修正（[#99128](https://github.com/vercel/next.js/pull/99128)）

> [!quote] Before
> Edge ランタイムの App Router SSR では常にメタデータをストリーミングしていたため、既定の HTML 制限ボット一覧に該当するリクエストでも、最初の `<head>` にメタデータが含まれないことがあった。

> [!success] After
> Node SSR と同じユーザーエージェントベースの方針を使い、該当するリクエスト（Twitterbot・TelegramBot など）には `</head>` より前にメタデータを返す。ChatGPT-User・GPTBot・ClaudeBot やブラウザは引き続きストリーミング。既定のボット一覧は変更なし。

📦 v16.4.0-canary.51 · トピック: [[repos/vercel-next.js/topics/レンダリング・DevTools|レンダリング・DevTools]]

### `%` を含む URL がプリレンダー済みルートで 500 になる不具合を修正（[#99121](https://github.com/vercel/next.js/pull/99121)）

> [!quote] Before
> プリレンダーのメタデータ選択時にルートパラメータを二重にデコードしており、`/open/docs/space%20here/with%2Fslash/fallback%25` のような有効な URL がパラメータのデコードエラーで 500 を返していた（ビルド時生成・ランタイム生成の両方）。

> [!success] After
> ルートの正規表現を直接使ってマッチを判定するようにし、200 を返すようにした。マッチの優先順位やサーバー側のパラメータのエンコード挙動は変わらない。

### `ensureStatic` が `"shell"` / `"prefetch"` のときの Instant Validation を静的シェル基準に（[#98249](https://github.com/vercel/next.js/pull/98249)）

> [!quote] Before
> Instant Validation は `ensureStatic` の値にかかわらず、ランタイムシェル（`ShellRuntime` ステージ）を検証していた。

> [!success] After

### パッケージ内のコードからプロジェクト全体がトレースされる不具合を修正（[#99238](https://github.com/vercel/next.js/pull/99238)）

> [!quote] Before
> `node-gyp-build` の `path.resolve(dir || '.')` のような静的な `'.'` を含むコードを、アプリのルートからディレクトリとしてトレースしてしまい、無関係なアプリのアセットまで再帰的に含まれていた。

> [!success] After
> パッケージ由来のプロジェクトルートからのトレースは、静的に名前が決まる「ファイル」だけに限定し、元のリクエストはこれまでどおりパッケージ基準で解決する。パッケージが明示的に名前を指定したアプリの設定ファイルは引き続き見つけられる。

### クライアント参照プロキシと WASM ローダーのエクスポート使用判定を修正（[#99115](https://github.com/vercel/next.js/pull/99115)）

> [!quote] Before

### turbo-tasks の GC に関する不具合を修正（[#98591](https://github.com/vercel/next.js/pull/98591), [#98614](https://github.com/vercel/next.js/pull/98614), [#99145](https://github.com/vercel/next.js/pull/99145)）

> [!quote] Before
> GC 中に集約グラフの更新が競合して再試行上限を超えたり、削除中のノードを操作しようとしたりすることがあった。また、削除済みタスクの無効化や、削除済みタスクを参照する逆方向の依存エッジが残ることで、panic につながる穴があった。

> [!success] After
> GC 中は集約グラフのリバランスをバッファし、GC が落ち着いてからまとめて処理する（[#98591](https://github.com/vercel/next.js/pull/98591)）。削除済みタスクの無効化は何もしないようにし（[#98614](https://github.com/vercel/next.js/pull/98614)）、タスク回収時に逆方向の依存エッジも取り除く（[#99145](https://github.com/vercel/next.js/pull/99145)）。
