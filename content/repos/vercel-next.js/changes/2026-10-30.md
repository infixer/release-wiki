## 新機能

### `experimental.hydrationChangeEvent` フラグを追加（[#99610](https://github.com/vercel/next.js/pull/99610)）

> [!tip] 何ができるようになったか
> `experimental.hydrationChangeEvent` を有効にすると、`app` ディレクトリが React の experimental チャンネル（`react@experimental`）を使うようになる。experimental 版の React には、canary チャンネルにまだ入っていない内部の機能フラグ `enableHydrationChangeEvent` が含まれており、それを先に試せる。フラグ自体は experimental 版の React を選ぶ以外の効果を持たない。
>
> - **使い方**: `next.config` の `experimental.hydrationChangeEvent` を有効にする（`taint`・`transitionIndicator`・`gestureTransition`・`blockingSSR` と同じく experimental 版の React を選ぶ）
> - **対象**: webpack（`needsExperimentalReact`）と Turbopack（`use_react_experimental`）の両方
> - **嬉しい場面**: React の hydration change event を canary 入りの前に試したいとき

## 変更・修正

### create-next-app が App Router の質問をやめ、常に App Router を使う（[#100850](https://github.com/vercel/next.js/pull/100850)）

> [!quote] Before
> 対話形式で「Would you like to use App Router? (recommended)」と聞いており、誤って Pages Router を選べた。前回の実行で保存された `app: false` の設定が残っていると、黙って Pages Router のプロジェクトが作られ続けた。

> [!success] After
> この質問を削除し、`--no-app` か `--api` を渡さない限り App Router を使う。保存済みの `app` の設定は無視され、既定値・前回の設定の要約にも「App Router / Pages Router」は表示されない。

> [!warning] 移行が必要
> Pages Router のプロジェクトを作りたい場合は、明示的に `--no-app` を渡す。

📦 v16.5.0-canary.32 · トピック: [[repos/vercel-next.js/topics/create-next-app|create-next-app]]

### ルートハンドラーと重複排除された fetch で 204 レスポンスが固まる・落ちる問題を修正（[#100159](https://github.com/vercel/next.js/pull/100159)）

> [!quote] Before
> `new Response(body, { status })` は 204・205・304 で `body` が空のバッファでも例外になる。`cacheComponents` 有効時のルートハンドラーのプリレンダーでは、204 を返すルートハンドラー（自動実装の `OPTIONS` を含む）が関数のタイムアウトまで固まり、GET で 204 を返すと `next build` も固まった。キャッシュ済みのアプリのルートのレスポンスを返す処理は 500 になり、`pendingRevalidates` で重複排除された fetch では 2 番目以降の呼び出し元が例外を投げた。

> [!success] After
> 元のレスポンスの `body === null` を確認し、本文の無いレスポンスでは `arrayBuffer()` を呼ばないようにした。

### adapter: 再検証のあるメタデータのルートをプリレンダーとして出力（[#100861](https://github.com/vercel/next.js/pull/100861)）

> [!quote] Before
> `robots.ts` や `sitemap.ts` などのメタデータのルートは、再検証を設定していても静的ファイルとして出力され、adapter のデプロイでは更新されなかった。

> [!success] After

### 開発オーバーレイのエラーを、インジケーターの状態が分かる前に表示（[#100629](https://github.com/vercel/next.js/pull/100629)）

> [!quote] Before

### Agent Feedback: 想定どおりのアップグレードの促しを報告しない（[#100840](https://github.com/vercel/next.js/pull/100840)）

> [!quote] Before
> Next.js のアップグレードゲートは、成功したコマンドを 1 回だけ止めてアップグレードを勧め、次の実行で続けさせる。エージェントがこの想定どおりの停止を Next.js のエラーと見なし、重複したフィードバックを送っていた。

> [!success] After
> 1 回だけの `SecurityFatalError` と `UpgradeNudgeError` を Agent Feedback の報告対象から外した。再試行しても止まり続ける場合や、ドキュメントの対処法が失敗する場合は引き続き報告対象。評価 `agent-061-agent-feedback-upgrade-nudge` を追加。

📦 v16.5.0-canary.32 · トピック: [[repos/vercel-next.js/topics/AI-アップグレード|AIアップグレード]]

### Turbopack: ファイルトレースで完全に動的な候補を無視（[#100651](https://github.com/vercel/next.js/pull/100651)）

> [!quote] Before
> `readFileSync(options.path ?? path.join(process.cwd(), 'manifest.json'))` や、既定値付きの引数を読むコードのように、パスが「不明な値」か「既知のファイル」のどちらかになる読み込みで、`public/` を含むプロジェクト全体が `.nft.json` にトレースされ、「Dynamic filesystem access causes tracing of the whole project」と表示されていた。既定値付きの引数の形は 16.4 でのリグレッション。

> [!success] After
> 動的なリクエストを無視する設定のとき、定数部分を持つ候補だけをトレースする（fs の読み込み・`fs.readdir`・`path.join`・`path.resolve`・`child_process.spawn`・`child_process.fork`）。既知のファイルはトレースされ、不明な候補は無視される。

### turbo-persistence: 大きな `batch_get` を並列化（[#100620](https://github.com/vercel/next.js/pull/100620)）
