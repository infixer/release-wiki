## 新機能

### `prefetch()` / `navigation()` の Instant Insights を追加（[#97801](https://github.com/vercel/next.js/pull/97801)）

> [!tip] 何ができるようになったか
> Instant Navigation の検証で、`prefetch()` による待ちと URL データによる待ちを区別できるようになった。`prefetch()` と `navigation()` は、ルート本体・メタデータ・viewport のどこで使われても同じように報告される。
>
> - **表示**: ブロッキングにならない指摘はアンバーの「Instant Insights」として表示し、プリレンダーの失敗は従来どおり赤いエラーとして表示する。DevTools のカード・ターミナルの案内・エラーページで同じ修正方法を示す
> - **修正方法**: メタデータでは、ステージ API を外すか、ページ側で遅延を確認できる。viewport では、API を外すか `instant = false` で検証を無効にできる
> - **ドキュメント**: navigation stages の説明を追加し、`prefetch()` / `navigation()` のリファレンスと Optimizing Prefetching ガイドを相互リンクした

### `eslint-config-next` が ESLint 10 に対応（[#99628](https://github.com/vercel/next.js/pull/99628)）

> [!tip] 何ができるようになったか
> ESLint 10 でクラッシュしていた `eslint-config-next` が、ESLint 9 と 10 の両方で動くようになった。Next.js の Node.js の最小要件（`>=20.9.0`）は変わらない。ESLint 10 自体は Node.js `^20.19.0 || ^22.13.0 || >=24` を要求するので、それより古い Node.js 20 では ESLint 9 を使い続ける。
>
> - **依存の更新**: `typescript-eslint` を `^8.56.0`、`eslint-plugin-react-hooks` を `^7.1.0` に。7.1 では非推奨の `react-hooks/component-hook-factories` ルールが推奨設定から外れたため、有効ではなくなった
> - **パッチ**: ESLint 10 に対応したリリースが無い依存は `eslint-config-next` 側で挙動を補う（ESLint 9 では何もしない）。たとえば `next` に同梱の Babel パーサー（`@babel/eslint-parser` 7.24.6）には `scopeManager.addGlobals()` が無く `TypeError` になるため、`eslint-config-next/parser` がこのメソッドを足す（無い場合だけ）

### `next analyze --export-graph` でアナライザーのグラフを JSON Lines で出力（[#99387](https://github.com/vercel/next.js/pull/99387)）

> [!tip] 何ができるようになったか
> バンドルアナライザーの「取得」と「グラフの再生」が分かれ、保存済みのスナップショットからグラフを 1 行 1 レコードの JSON（JSON Lines）として出力できるようになった。ビルドや子プロセスの起動はしない。
>
> - **使い方**: `next analyze` はデータを作って UI を表示する。`next analyze --output --snapshot-name <name>` はバイナリのスナップショットと UI を保存するだけで、サーバーは起動しない。`next analyze --export-graph --snapshot-name <name>` で保存済みスナップショットを JSON Lines で出力する（`--export-graph` だけなら最新のスナップショット、`--snapshot <id>` で ID 指定、`--route` でルートを絞り込み）
> - **スキーマ**: v1 のレコードのスキーマは `next/analyze/graph-v1.schema.json` として `next` パッケージに同梱される
> - **注意**: 以前の `--output=json` と `--graph-json` は受け付けない。再生時はアプリの設定を読まないので、独自の出力ディレクトリを使うアプリは `--dist-dir <relative-dir>` を明示する

### `'use cache'` の root params の依存をビルド時に収集（[#99274](https://github.com/vercel/next.js/pull/99274)）

> [!tip] 何ができるようになったか
> キャッシュキーの root params の部分を前もって計算するための準備。Turbopack が生成された getter モジュールから root params の依存を集め、server-reference マニフェストに `rootParamDependencies` として出力する。
>
> - **使い方**: `experimental.useCacheStaticRootParamTracking`（既定は `false`）を `true` にすると、Turbopack の本番ビルドで収集する
> - **補足**: 同じコンパイル済みモジュールを共有するキャッシュ関数は同じ依存リストを受け取るため、実際に読むより多くの root params がキーに入ることがある（安全だが、キャッシュの再利用は減る）。実行時の値として渡されたコードが読む root params は検出できない場合がある

### パラメータのマッチングを使っているかをビルドのメタデータに記録（[#99594](https://github.com/vercel/next.js/pull/99594)）

> [!tip] 何ができるようになったか
> 実験的なパラメータのマッチング API に、アダプターを使わずに Next.js のビルドをパッケージするホストがまだ対応していない場合がある。そうしたホストが API の使用を検出して警告できるよう、`prerender-manifest.json` に任意のフィールド `__private_unstable_hasParamMatching: true` を追加した。
>
> - **補足**: 一時的なプライベートなフィールドで、将来削除される。デプロイの制限や実行時の挙動、アダプターの公開インターフェースは変わらない

### `forbidden()` / `unauthorized()` の安定化と、その取り消し（[#99689](https://github.com/vercel/next.js/pull/99689)、[#99734](https://github.com/vercel/next.js/pull/99734)）

> [!quote] Before
> [#99689](https://github.com/vercel/next.js/pull/99689) で `forbidden()` / `unauthorized()` を experimental から外し、機能フラグ `authInterrupts` を非推奨にした。

> [!success] After

### turbo-tasks: copy-on-write のスナップショットを複製ではなく bincode でエンコード（[#99644](https://github.com/vercel/next.js/pull/99644)）

> [!quote] Before
> 永続化中のスナップショットに含まれるタスクが再び変更されると、`TaskStorage` を複製して保持していた。セルの中身は `Arc` で共有されるため、内部可変性のある値が後で変わると「凍結した」はずの複製にも反映され、永続化される状態が一貫しなくなることがあった。

> [!success] After
> 変更前の状態をその場で bincode でエンコードしてバイト列として保持する。永続化はそれをそのまま書き込むので、二重にエンコードされることはない。
