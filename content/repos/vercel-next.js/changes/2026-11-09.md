## 新機能

### Turbopack: `new URL()` で `turbopackIgnore` に対応（[#99965](https://github.com/vercel/next.js/pull/99965)）

> [!tip] 何ができるようになったか
> 呼び出し側がワーカーの URL を渡したときだけ通る分岐にある `new URL(options.workerUrl, import.meta.url)` で、`next build` が `Module not found: Can't resolve (<dynamic> | 'undefined')` で失敗し、URL を実行時だけのものと指定する方法が無かった。`new URL()` が `new Worker()` と同じマジックコメントを解釈するようになった。
>
> - **使い方**: `new URL(/* turbopackIgnore: true */ url, import.meta.url)`（`webpackIgnore` も可）でアセットの参照を作らず、出力にそのまま残して実行時に解決する。`turbopackOptional` は解決エラーを抑える
> - **エラーメッセージ**: 一部が動的な `new URL()`・`import()`・`require()` の解決に失敗したとき、「Module not found」のメッセージで対応する `turbopackIgnore` のコメントを提案する
> - **変わらない点**: 一部が動的な `new URL()` の解決の失敗は引き続きエラー。注釈を付けられないサードパーティのパッケージでは `next.config` の `turbopack.ignoreIssue` で抑える

## 変更・修正

### Cache Components で、プリレンダーした `Link` ヘッダーが再検証のたびに増える問題を修正（[#100960](https://github.com/vercel/next.js/pull/100960)）

> [!quote] Before
> `cacheComponents: true` のとき、`next.config.js` の `headers()`（または middleware）で設定した `Link` ヘッダーが、React のプリロードの `Link` も出す ISR のページで重複し、バックグラウンドの再検証のたびに 1 つずつ増えていた。ビルド時にプリレンダーしていないページのオンデマンドの描画（キャッシュの `MISS`）でも、設定の `Link` とプリロードの `Link` が 2 回ずつ返っていた。

> [!success] After
> `prerenderToStream` が `res.getHeader(name)` を丸ごとキャッシュエントリの `headers` に保存していたため、描画で作られていない値（設定の `Link`・前のキャッシュエントリから再生した値）まで保存されていたのを修正（`app-render.tsx` を変更）。

📦 v16.5.0-canary.45 · トピック: [[repos/vercel-next.js/topics/キャッシュ・プリレンダリング|キャッシュ・プリレンダリング]]

### Cache Components と互換の無いセグメント設定のエラーから移行ガイドへリンク（[#101348](https://github.com/vercel/next.js/pull/101348)）

> [!quote] Before
> Cache Components と互換の無いルートセグメント設定のエクスポートのエラーに、移行ガイドへのリンクが無かった。

> [!success] After
> エラーから既存の移行ガイドへ直接リンクする（移行方法はエクスポートの値とルートの描画・キャッシュの要件で変わるため）。削除された `experimental.dynamicIO` の設定の診断も同じ移行ガイドの URL を使う。

### Turbopack: Pages Router のページのエントリをファサードに分割しない（[#101152](https://github.com/vercel/next.js/pull/101152)）

> [!quote] Before
> Turbopack の Pages Router で、編集でページの re-export を追加・削除すると、Fast Refresh は更新済みと報告するのに、後の編集でフルリロードされるまで古い内容が表示されていた（webpack ではフルリロードになる）。`follow_reexports` で re-export の有無によりモジュールがファサードとローカルのモジュールに分かれ、ページのエントリが指すモジュールが変わっても HMR が追わなかったため。

> [!success] After
> ページのエントリは分割しない。Next.js は Pages Router のエントリを `EntryReferenceSubType` の新しいプロパティ `standalone` で印し、Turbopack は standalone のエントリの re-export をたどらず、ファサードやモジュールの断片に分けない。

📦 v16.5.0-canary.45 · トピック: [[repos/vercel-next.js/topics/ビルド・Turbopack|ビルド・Turbopack]]

### turbopack-ecmascript: `AstPathTrie` のノードを親と種類のインデックスで持つ（[#101370](https://github.com/vercel/next.js/pull/101370)）

> [!quote] Before
> `AstPathTrie` のノードは `AstParentKind` をそのまま持ち、32 バイトだった。トライは解析したモジュールごとの `CodeGens` のセルにあり、ビルドの終わりまで残る。

> [!success] After
> トライごとに種類を 1 度だけ表に持ち、ノードは親と種類のインデックス（`u32` 2 つ、8 バイト）にする。大きな Next.js アプリのコールドの `next build --experimental-build-mode=compile` で、`AstPathTrie` が 701 MiB → 269 MiB、ライブヒープが 13.55 GiB → 13.11 GiB。永続キャッシュも小さくなる。

📦 v16.5.0-canary.45 · トピック: [[repos/vercel-next.js/topics/ビルド・Turbopack|ビルド・Turbopack]]

### turbo-tasks-backend: タスクのストレージの使っていない容量を解放（[#101344](https://github.com/vercel/next.js/pull/101344)）

> [!quote] Before
> タスクのストレージのいくつかのコレクションが容量を返さず、中身より多くのメモリを持っていた（大きなビルドの終わりで遅延フィールドの vec が 1 エントリあたり約 1.75 スロット、`followers` のハッシュテーブルがエントリの 4.8 倍のバイト数、空の `followers` が 13.7 万個）。

> [!success] After
> 遅延フィールドは `TinyVec::push_exact` で 1 スロットずつ増やし、`TinyVec` は `realloc` でサイズを変える。`CounterMap` はエントリの削除後に容量が長さの 3 倍を超えたら縮め、空になった遅延フィールドは取り除く。

📦 v16.5.0-canary.45 · トピック: [[repos/vercel-next.js/topics/ビルド・Turbopack|ビルド・Turbopack]]

### `eslint-config-next` の TypeScript の peer を `typescript-eslint` に揃える（[#101247](https://github.com/vercel/next.js/pull/101247)）

> [!quote] Before
> `eslint-config-next` の省略可能な TypeScript の peer は `>=3.3.1` で、TypeScript 7 のようにサポートしていないコンパイラーの API も対象に見えていた（TypeScript 7 で設定を import すると `typescript-eslint` が例外を投げる）。

> [!success] After
> peer を `typescript-eslint` の依存と同じ `>=4.8.4 <6.1.0` に狭め、インストール時にパッケージのメタデータで互換性の制約が分かるようにした。JavaScript の利用者向けに peer は省略可能のまま。TypeScript 6 の API と TypeScript 7 のコンパイラーを並べて使う設定は [#101246](https://github.com/vercel/next.js/pull/101246) でドキュメント化。

📦 v16.5.0-canary.45 · トピック: [[repos/vercel-next.js/topics/ESLint|ESLint]]
