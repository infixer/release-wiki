## 新機能

### 画像最適化 API がローカル画像のリダイレクトをたどるように（[#98271](https://github.com/vercel/next.js/pull/98271)）

> [!tip] 何ができるようになったか
> ローカルのソース画像のパスがリダイレクトを返すルートに解決されると、画像最適化 API は `500 "url" parameter is valid but internal response is invalid` を返していた（`fetchLocalImage()` がリダイレクトをたどらなかった、[#98237](https://github.com/vercel/next.js/issues/98237)）。外部画像の `fetchExternalImage()` と同じく、`images.maximumRedirects` 回までリダイレクトをたどるようになった。
>
> - **使い方**: 設定は不要。上限は既存の `images.maximumRedirects`
> - **嬉しい場面**: 画像のパスを Route Handler などでリダイレクトしているとき（絶対・相対のリダイレクトの e2e テストを追加）

📦 v16.5.0-canary.42 · トピック: [[repos/vercel-next.js/topics/画像最適化|画像最適化]]

### Request Insights: リクエストと fetch の詳細表示を改善（[#96925](https://github.com/vercel/next.js/pull/96925)）

> [!tip] 何ができるようになったか
> 開発オーバーレイの Request Insights で、サニタイズしたリクエストの URL と一致したルートのテンプレートを表示する（ルートパラメータはパスが有効なテンプレートに一致するときだけ）。同一オリジンと外部の fetch を区別し、長いラベルは切り詰めて完全な URL をツールチップに残す。
>
> - **プライバシー**: 表示する URL と fetch のスパンのラベルから、認証情報・フラグメント・クエリの値を取り除く
> - **操作**: キーボードでのトレースの確認とスクロールの閉じ込めに対応し、省略したワーカーのスパン数を表示する

📦 v16.5.0-canary.42 · トピック: [[repos/vercel-next.js/topics/レンダリング・DevTools|レンダリング・DevTools]]

### Request Insights: コンテキストメニューとトレースの操作を改善（[#97796](https://github.com/vercel/next.js/pull/97796)）

> [!tip] 何ができるようになったか
> リクエストとスパンにメニューが加わり、ID や対象を絞った MCP 用のプロンプトをコピーできる（完全な ID はリクエストのヘッダーではなくメニューに置く）。メニューは一度に 1 つだけ開き、外側の操作や Escape で閉じる。
>
> - **その他の変更**: タイムラインから離れたときに古いホバーの強調を消す。常に出ていた「No proxy」のバッジを削除

⏳ 未リリース · トピック: [[repos/vercel-next.js/topics/レンダリング・DevTools|レンダリング・DevTools]]

### `next build --analyze` でビルドと分析を 1 回で行う（[#99962](https://github.com/vercel/next.js/pull/99962)）

> [!tip] 何ができるようになったか
> `next build --analyze` で、アプリの出力とアナライザーのアセットを 1 回のビルドで作る。ユーザーが設定したソースマップの出力と内部で使うマップの生成を分け、分析用の部分的なマップを必要に応じて完全なマップと一緒に保持する。
>
> - **出力**: 通常のビルドと分析付きのビルドで、出力される JavaScript・CSS・ソースマップの中身とファイル名は（どのソースマップ設定でも）変わらない
> - **嬉しい場面**: バンドル分析のためにビルドを 2 回走らせたくないとき

⏳ 未リリース · トピック: [[repos/vercel-next.js/topics/ビルド・Turbopack|ビルド・Turbopack]]

## 変更・修正

### `experimental.lockDistDir` のオプトアウトを削除（[#100747](https://github.com/vercel/next.js/pull/100747)）

> [!quote] Before
> `experimental.lockDistDir: false` で dist ディレクトリのロックファイルを無効にできた。PR によると、使われ方の多くは「同じコードベースで 2 つのサーバーを動かすためにロックを外す」といった誤解によるもので、その結果、壊れてクラッシュする原因になっていた。

> [!success] After
> オプションを削除し、ロックファイルは常に使われる。ネットワークファイルシステムでエラーになる件は [#100684](https://github.com/vercel/next.js/pull/100684) で修正済み。

> [!warning] 移行が必要
> `next.config` から `experimental.lockDistDir` を削除する。同じプロジェクトで複数の開発サーバー・ビルドを同時に動かす使い方は避ける。

📦 v16.5.0-canary.42 · トピック: [[repos/vercel-next.js/topics/ビルド・Turbopack|ビルド・Turbopack]]

### Turbopack: `require.context()` を合成モジュールとして生成（[#100526](https://github.com/vercel/next.js/pull/100526)）

> [!quote] Before
> `require.context()` は専用の仮想モジュールと独自のコード生成で処理していた。同じファイルで同じディレクトリに別のフィルターの context を作ると衝突していた。

> [!success] After
> 呼び出し元の隣の合成 CommonJS ソース（`<file>.require-context.cjs`）として通常のモジュール処理を通す（約 270 行の特別扱いを削除）。フィルターの正規表現はモジュールの識別子に含まれ、webpack と同じく拡張子なし・ディレクトリ（`index`）のキーも `keys()` に入って並び替えられる。問題は `require.context()` の呼び出し位置で報告される。PR では `require.context` の性能が少し下がるとしている。

### Turbopack: PURE 注釈付きの呼び出しを callee にする IIFE を本番ビルドで残す（[#100477](https://github.com/vercel/next.js/pull/100477)）

> [!quote] Before
> 本番ビルドで、`(/* @__PURE__ */ __name(function () { … }, "x"))()` のような副作用のある IIFE が削除されていた。esbuild の `keepNames` の出力がこの形で、Radix UI の配布物などが影響を受けた。SWC の `fixer` にコメントを渡していなかったため括弧が落ち、minifier が外側の呼び出しを PURE とみなしていた。

> [!success] After

### `router.experimental_prepare()`: 確定時に再取得しないように（[#101234](https://github.com/vercel/next.js/pull/101234)）

> [!quote] Before
> 準備開始時にルートキャッシュに無く、ビルド時にプリレンダーされたページでは、`InliningHintsStale` によりルートキャッシュのエントリが期限切れで書かれるため、`router.experimental_prepare()` で準備した遷移を確定するとルートをもう一度取得していた。

> [!success] After
> 準備でのルートのリクエスト結果を準備の記録に保存し、確定時はそれを使う（飛行中のリクエストの引き継ぎと同じ検査を通る）。`InliningHintsStale` が無くなれば外せる回避策としている。

📦 v16.5.0-canary.42 · トピック: [[repos/vercel-next.js/topics/ルーティング|ルーティング]]

### Turbopack: コンポーネントチャンク有効時に失敗したチャンクの読み込みを再試行できるように（[#101179](https://github.com/vercel/next.js/pull/101179)）

> [!quote] Before
> `experimental.turbopackChunking.generateComponentChunks` を有効にすると、dynamic `import()` のチャンクの読み込みが（ネットワーク切断などで）失敗した後、同じ `import()` を呼んでも新しいリクエストをせず同じ `ChunkLoadError` ですぐ reject され、フルリロードまで読み込めなかった。

> [!success] After
> ブラウザランタイムの読み込みキャッシュは、promise が reject されたらそのエントリを取り除く。重複排除や React が頼る promise の同一性、既存の 1 回の自動再試行は変わらない。

📦 v16.5.0-canary.42 · トピック: [[repos/vercel-next.js/topics/ビルド・Turbopack|ビルド・Turbopack]]

### セルフホストで Route Handler のレスポンスが圧縮されない問題を修正（[#101220](https://github.com/vercel/next.js/pull/101220)）

> [!quote] Before
> `NodeNextResponse.appendHeader` が 1 つの値も配列で保存していたため、圧縮のミドルウェアの `Content-Type` の判定（文字列のみ受け付ける）に通らず、すべての App Router の Route Handler（キャッシュから返すプリレンダー済みのものを含む）のレスポンスが圧縮されていなかった（[#101120](https://github.com/vercel/next.js/issues/101120)）。

> [!success] After
> 1 つの値は文字列のまま保持し（Node の `appendHeader` と同じ）、まだ圧縮されていないレスポンスは `next start` やホスティング側で圧縮される。PR では、Route Handler から `fetch()` の結果を本文を処理せずに返すのは避け、専用のプロキシライブラリを使うよう勧めている。

📦 v16.5.0-canary.42 · トピック: [[repos/vercel-next.js/topics/ルーティング|ルーティング]]

### Request Insights: フレームワークのリクエストの種類を分類（[#96914](https://github.com/vercel/next.js/pull/96914)）

> [!quote] Before
> Request Insights のリクエストの識別はブラウザーの相関 ID に頼っていた。

> [!success] After
> サーバーが識別子を割り当て、ページ・API・画像・アセット・RSC・Proxy・Instant Insights の処理をフレームワークのメタデータから分類する。ストリーミングの App Route はハンドラーの完了前に分類し、Proxy とページの処理はリクエストの識別子で結び付ける。ブラウザーの相関 ID は検証済みのデバッグ用のヒントとして扱う。Request Insights が無効なときはこの処理を行わず、公開の OpenTelemetry のスパン名や親子関係は変わらない。
