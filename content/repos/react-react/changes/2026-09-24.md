## 新機能

### Server Reference が任意のオブジェクトを参照できるように（実験的）（[#37636](https://github.com/react/react/pull/37636)）

> [!tip] 何ができるようになったか
> 実験的フラグ `enableFlightObjectReferences` の下で、Server Reference が関数だけでなくオブジェクトも参照できるようになった。`registerServerObjectReference` でオブジェクトを登録すると、クライアントは中身を読み書きできない不透明なハンドルを受け取り、それを Server Function に渡すとサーバー側のマニフェスト経由で解決される。
>
> - **使い方**: `registerServerObjectReference()` でオブジェクトにモジュール ID を付与して登録する（現時点では Turbopack バインディングのみ対応）
> - **嬉しい場面**: `searchParams` のようなリクエストスコープの値を、リクエストボディに二重に含めずフレームワーク側で参照渡ししたいとき

⏳ 未リリース · トピック: [[repos/react-react/topics/Server-Components|Server Components]]

## 変更・修正

### エフェクト内で `await` 後の setState を誤検知しないよう修正（[#36734](https://github.com/react/react/pull/36734)）

> [!quote] Before
> `react-hooks/set-state-in-effect` lint ルールが、エフェクト内の非同期関数で `await` の後に呼ばれる setState まで誤って警告していた。データ取得後に setState する一般的なコードでよく起きる誤検知だった。

> [!success] After
> HIR 上のデータフロー解析で「すべてのパスで await 済み」と証明できるブロックの setState だけを許可対象から除外するようにした。条件分岐で await されるなど確実に await 済みと言えない setState は引き続き警告される。

⏳ 未リリース · トピック: [[repos/react-react/topics/React-Compiler|React Compiler]]

### Rust 版コンパイラで shorthand・computed property の判定を修正（[#37674](https://github.com/react/react/pull/37674)）

> [!quote] Before
> 一部の computed property が誤って shorthand プロパティとして検出されていた。Babel 版では問題にならなかったが、SWC（Rust）版はこれで判定を打ち切ってしまい、誤ったコード生成につながっていた。

> [!success] After
> shorthand と computed property の検出条件を修正し、Rust 版コンパイラでも正しく判定されるようにした。

⏳ 未リリース · トピック: [[repos/react-react/topics/React-Compiler|React Compiler]]

### `arguments` オブジェクトの使用でコンパイラが誤ってメモ化しないよう修正（[#37645](https://github.com/react/react/pull/37645)）

> [!quote] Before
> コンパイラが `arguments` オブジェクトを誤ってメモ化しており、再レンダリングが正しく動かないことがあった。

> [!success] After
> `arguments` の使用を検出した場合はメモ化をあきらめる（bail out）ようにし、誤ったコード生成を防ぐ。

⏳ 未リリース · トピック: [[repos/react-react/topics/React-Compiler|React Compiler]]

### Flight クライアントが先頭の `U+FEFF` を保持するよう修正（[#37625](https://github.com/react/react/pull/37625)）

> [!quote] Before
> Flight クライアントがバイナリ入力をデコードする際、outlined text row 先頭の `U+FEFF` を `TextDecoder` がエンコーディングの目印として消費してしまい、文字列から失われていた。

> [!success] After
> Node・Web 両方のデコーダーで `ignoreBOM: true` を指定し、先頭の `U+FEFF` をそのまま保持するようにした。

⏳ 未リリース · トピック: [[repos/react-react/topics/Server-Components|Server Components]]
