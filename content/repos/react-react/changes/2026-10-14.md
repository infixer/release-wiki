## 変更・修正

### 拡張不可の thenable を `use()` に渡すと DEV でクラッシュする問題を修正（[#37796](https://github.com/react/react/pull/37796)）

> [!quote] Before
> DEV では `trackUsedThenable` が thenable に `_debugInfo` プロパティを追加して非同期の debug info を推定していた。thenable が拡張不可（例: `status` を持つユーザー側の thenable を不変キャッシュが freeze したもの）だと、この代入が `TypeError: Cannot add property _debugInfo, object is not extensible` を投げ、本番では動くコードが開発中だけレンダーごとクラッシュしていた。[#37772](https://github.com/react/react/pull/37772) で OSS 向けに `enableAsyncDebugInfo` が入ってからは、DEV のすべての `use(thenable)` 呼び出しでこの処理が走っていた。

> [!success] After
> 新しいプロパティを追加できない thenable では debug info の推定をスキップする（Flight の `addAsyncInfo` が freeze された値で `_debugInfo` を省くのと同じ扱い）。debug info は付かないが、`use()` は値を通常どおり取り出す。なお、計装されていない freeze 済み Promise（`use(Object.freeze(promise))`）は別の箇所で失敗するため、この PR の対象外（issue で別途報告）。

⏳ 未リリース · トピック: [[repos/react-react/topics/Reconciler|Reconciler]]

### ref を読む関数の比較を ref アクセスとして誤検知しないよう修正（[#37688](https://github.com/react/react/pull/37688)）

> [!quote] Before
> `react-hooks/refs` のバリデーション（`ValidateNoRefAccessInRender`）で、呼び出すと ref を読む関数（`ref.current` を参照する `useCallback` など）を `===` / `!==` で比較すると、"Cannot access refs during render" と報告されていた。

> [!success] After
> 二項演算子はオペランドを呼び出さないため、`BinaryExpression` では直接の ref の値だけを検出する `validateNoDirectRefValueAccess` を使うようにした。`ref.current === x` は引き続きエラーになり、`fn !== otherFn` はエラーにならない。Rust 版コンパイラ（`validate_no_ref_access_in_render.rs`）にも同じ変更を入れた。

⏳ 未リリース · トピック: [[repos/react-react/topics/React-Compiler|React Compiler]]

### dehydrate 状態の Activity を隠すと後ろの兄弟要素まで隠れる問題を修正（[#37814](https://github.com/react/react/pull/37814)）

> [!quote] Before
> `hideOrUnhideDehydratedBoundary` は Activity のインスタンスを受け取るのに Suspense のマーカーしか認識していなかった。dehydrate 状態の Activity を隠すと、その終端を越えて親の中の後続の兄弟要素すべてに `display: none` を設定し、Activity を再表示しても兄弟要素は隠れたままだった。

> [!success] After
> 走査が Activity の終端マーカーで止まり、入れ子の Activity の深さも数えるようになった（`clearHydrationBoundary` と同じ扱い）。

⏳ 未リリース · トピック: [[repos/react-react/topics/SSR-ハイドレーション|SSR・ハイドレーション]]

### プリレンダーの中断時、リトライ中のタスクを開始位置から postpone するよう修正（[#37710](https://github.com/react/react/pull/37710)）

> [!quote] Before
> リトライ中のレンダータスクの実行中にプリレンダーが中断されると、`retryRenderTask` はセグメントを開始位置に戻すが、`task.keyPath` と `task.childIndex` は最も内側の子のままだった。そのため `abortUnwoundTask` がその子の位置でタスクを postpone し、再開（resume）時にはその子だけがバウンダリのセグメントに描画されていた。

> [!success] After
> 中断を終える前に、試行を始めたときの key path と child index に戻す。postpone された穴が破棄した試行全体を覆うようになり、再開時に要素全体（テストでは `<section>` 全体）が描画される。

⏳ 未リリース · トピック: [[repos/react-react/topics/SSR-ハイドレーション|SSR・ハイドレーション]]
