## 変更・修正

### コンパイラ: react-native の `PanResponder.create` に型を付け、`react-hooks/refs` の誤検知を修正（[#37970](https://github.com/react/react/pull/37970)）

> [!quote] Before
> `react-native` から import した `PanResponder` は未知の関数として扱われ、`PanResponder.create({...})` に渡したコールバックで ref を使うと「Passing a ref to a function may read its value during render」と報告されていた（[#37955](https://github.com/react/react/issues/37955)）。正しいシグネチャはテスト用の `shared-runtime` の型プロバイダーにしか無かった。

> [!success] After
> `defaultModuleTypeProvider`（TypeScript 版と Rust 版）に `react-native` の `PanResponder.create` のシグネチャ（設定を freeze し、レンダー中には呼ばない）を加え、コールバックを後で呼ばれるものとして扱う。[#37975](https://github.com/react/react/pull/37975) が前提。ほかの未知の関数は引き続きエラーになる。

⏳ 未リリース · トピック: [[repos/react-react/topics/React-Compiler|React Compiler]]

### コンパイラ: `PerformanceObserver` / `ReportingObserver` のコールバックでの ref アクセスを許可（[#37996](https://github.com/react/react/pull/37996)）

> [!quote] Before
> `new PerformanceObserver(cb)` や `new ReportingObserver(cb)` のコールバックで ref を触ると「Cannot access refs during render」と誤検知されていた。2 つは未知のコンストラクタの既定の扱いになっていた。

> [!success] After
> `IntersectionObserver`・`ResizeObserver`・`MutationObserver` と同じく型付きのグローバル（TypeScript の `TYPED_GLOBALS` と Rust の `build_typed_globals`）に加えた。`PerformanceObserver` は `(callback)` → `[Freeze]`、`ReportingObserver` は第 2 引数も読む `(callback, options)` → `[Freeze, Read]`。

⏳ 未リリース · トピック: [[repos/react-react/topics/React-Compiler|React Compiler]]

### コンパイラ: 定数伝播とコード生成で `-0` を保つ（[#37995](https://github.com/react/react/pull/37995)）

> [!quote] Before
> TypeScript 版と Rust 版のコンパイラが、分岐の定数をまとめるときとコード生成で `0` と `-0` を区別せず、`1 / value` が常に `Infinity` になるなど結果が変わることがあった（[#37994](https://github.com/react/react/issues/37994)）。

> [!success] After
> 定数のマージで符号付きのゼロを保ち、負のゼロを明示的に出力する。NaN のマージや JavaScript の等値の意味は変わらない。

⏳ 未リリース · トピック: [[repos/react-react/topics/React-Compiler|React Compiler]]

### DOM: `onTransitionRun` / `onTransitionStart` / `onTransitionCancel` で `SyntheticTransitionEvent` を使う（[#37985](https://github.com/react/react/pull/37985)）

> [!quote] Before
> [#27345](https://github.com/react/react/pull/27345) で追加された 3 つのイベントが `SimpleEventPlugin.js` の分岐に無く、基本の `SyntheticEvent` になっていたため、`propertyName`・`elapsedTime`・`pseudoElement` が `undefined` だった（`onTransitionEnd` は正しかった。[#37984](https://github.com/react/react/issues/37984)）。

> [!success] After
> 3 つのイベントも `SyntheticTransitionEvent` を作り、これらのプロパティが取れる。

⏳ 未リリース · トピック: [[repos/react-react/topics/React-DOM|React DOM]]

### React Native: イベントの対象が null でも `dispatchNativeEvent` を呼ぶ（[#38007](https://github.com/react/react/pull/38007)）

> [!quote] Before
> `enableNativeEventTargetEventDispatching` が有効だと、Fabric レンダラーはタッチしたビューがアンマウント済みのとき `dispatchNativeEvent` を呼ばず、タッチの終了が JS のレスポンダーに届かずに次のタップが失われていた（[#38006](https://github.com/react/react/issues/38006)）。

> [!success] After
> null の対象をそのまま渡し、React Native がレスポンダーを解放できるようにする。React Native 側の react/react-native#59522（null の対象で例外を投げないようにする変更）が先に入る必要がある。

⏳ 未リリース · トピック: [[repos/react-react/topics/React-Native-レンダラー|React Native レンダラー]]
