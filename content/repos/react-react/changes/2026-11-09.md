## 変更・修正

### Flight: ストリームで描画される Server Components の中で hooks が throw する問題を修正（[#38128](https://github.com/react/react/pull/38128)）

> [!quote] Before
> Flight はストリームの項目や非同期イテレーターの戻り値を promise のコールバックから直接描画しており、これらの経路では `performWork` が hook のディスパッチャーを戻した後に Server Components を描画することがあるため、`useId` などの対応している hooks が throw していた（#38105）。`performWork` はサーバーの request を戻す一方、hooks 側の request を null にリセットしていた。

> [!success] After
> 個別の経路ごとの対処（#38108・#38114）に代えて、共通の描画の入口で hook の context を用意する（開発時の非同期のエラーの cause も対象）。共通のヘルパーが `ReactFlightServer` と `ReactFlightHooks` それぞれで直前の request を hook のディスパッチャーとともに戻すため、イテレーターの thenable が同期的に解決したときも外側の描画の hook の context が保たれる。

⏳ 未リリース · トピック: [[repos/react-react/topics/Server-Components|Server Components]]

### `useDeferredValue` とサスペンドしたハイドレーション・リトライによる無限ループを修正（[#38132](https://github.com/react/react/pull/38132)）

> [!quote] Before
> 更新を持たないレンダー（ハイドレーションや Suspense のリトライ）で初期値付きの `useDeferredValue` をマウントしてからサスペンドすると、データが届くまで React がサスペンドした作業をスケジューラーの速度でループして再試行していた。deferred レーンを要求しても、ハイドレーション・リトライのレーンは更新レーンではないため何も entangle されず、deferred タスクが空のツリーをコミットし、そのコミットがサスペンドしたレーンをクリアして再試行が繰り返されていた。Next.js の App Router は `useDeferredValue` に初期値を渡すため、ハイドレーションがサスペンドするたびに起きていた（リトライではスロットルされている場合のみ。#37739 とは別のループ）。

> [!success] After
> サスペンドしたレーンに更新レーンが含まれないときは deferred レーンを作らない。deferred の値はサスペンドした作業の再試行時にあらためて要求され、それを完了させるコミットが通常どおり deferred タスクを作る（`ReactFiberLane.js`）。
