## 概要

`mods/telemetry` は、Claude Code のアナリティクスが有効な環境で、ビルトインのプラグイン向けにもテレメトリを収集する mod。呼び出し元（`next.origin`）を確認し、個人がインストールしたプラグインや管理者が拒否したプラグインは理由付きで拒否する。行は CLI 本体と同じ内容（デバイス・アカウント ID、クライアント種別、entrypoint、`env` ブロックなど）を `$` 経由でセッションに 1 回集めて持ち、`$.session.version()` に答えるエンジン（2.1.281 以降）ではバージョン・ベースバージョン・ビルド時刻も記録する。`$.telemetry.log` / `$.telemetry.mark` はイベント `telemetry.log` / `telemetry.mark` へのフックとして実装され、`$.telemetry` を自前で持つエンジンでも動く（エントリの `to` で `anthropic` / `collector` の宛先を指定）。行はキューに入り、最初の数秒後・100 件到達時・セッション終了時にバッチで送信され（1 回リトライ）、`log` / `mark` はキューに入った時点で解決する。CLI が守るアナリティクスのオプトアウトはすべて尊重し、送信の都度読み直す。リリースでは Claude Code 本体の OpenTelemetry 出力も拡充されている。v2.1.300 で `api_request` イベントにキャッシュ書き込みを寿命で分けた `cache_creation_5m_tokens`・`cache_creation_1h_tokens` が、トレースの span に GenAI のセマンティック規約の属性（`gen_ai.provider.name`・`gen_ai.conversation.id`・`gen_ai.tool.name`・`error.type` など）が加わり、v2.1.301 で `tool_decision` イベントに `classifier_verdict`・`permission_mode`・`classifier_category`（`OTEL_LOG_TOOL_DETAILS=1` のとき）が加わった。

## 主な API・オプション

- `$.telemetry.log` / `$.telemetry.mark` — イベント `telemetry.log` / `telemetry.mark` へのフックで処理。ルール違反のエントリは `{ deny }` され、promise は `$.telemetry.log: <reason>` で reject
- `to` — ログエントリの宛先（`anthropic`（既定）/ `collector`）。型は `TelemetryDestination`
- `$.session.version()` — `{ version, base?, builtAt? }`。行の `version`・`version_base`・`build_time` 列に記録
- OpenTelemetry の `api_request` の `cache_creation_5m_tokens` / `cache_creation_1h_tokens`、span の `gen_ai.*` 属性（v2.1.300）
- OpenTelemetry の `tool_decision` の `classifier_verdict` / `permission_mode` / `classifier_category`（v2.1.301）
