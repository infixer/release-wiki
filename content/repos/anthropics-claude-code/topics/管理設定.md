## 概要

組織が配布する managed settings（`managed-settings.json`）と `managed-mcp.json` まわり。
リポジトリの `examples/settings/` には設定例があり、HIPAA の構成が適用された組織向けに、セッションの内容が開発者のコンピューターの外へ出る経路を絞る例（`settings-hipaa.json`・`managed-mcp-hipaa.json`・`README-hipaa.md`）が加わった（Claude Code v2.1.285 以降が必要。出発点としてのサンプルで、要件を満たすかの確認は各組織の責任）。
v2.1.296 では、managed settings の `PreToolUse` フックが `"continue": false` で拒否したとき（managed の `prompt` フックのブロックも同様）にターンが終わらない問題や、managed settings の PostToolUse フックで `updatedMCPToolOutput` が効かないことがある問題が修正された。
v2.1.299 で、managed settings でインストールした mod が `$.prompt.media` と `$.session.identity()`（managed の `forceLoginOrgUUID` にある組織ならその組織とメールアドレス）を使えるようになり、`/plugin`・`claude plugin validate` は組織が管理する環境で飛ばされる mod のフックを示す。v2.1.300 では `forceLoginOrgUUID` で拒否されたログインのトークンが残る問題が修正された。
v2.1.312 で、VS Code 拡張機能からサインインした後、managed settings と組織のポリシーがセッションの残りで取得されない問題が修正された。
v2.1.314 で `permissions.blockWritesOutsideWorkingDirectories` が加わり、どの権限モードでも Write・Edit・NotebookEdit が作業ディレクトリの外のパスを拒否できる。管理者がモデルの effort に上限を設けたときの「Invalid effort level」の連続失敗、Claude Desktop で TLS の信頼設定が効かない問題、リモートの managed settings だけにある `forceRemoteSettingsRefresh` が保存済みのコピーの期限切れ後に効かない問題なども修正された。
v2.1.317 で、Claude Desktop の Code タブは組織のリモートの managed settings がセッションに読み込まれていないときと、読み込まれたときに通知を出す。v2.1.318 で、同じマシンの別のログインが保存した `allowedProviders` の一覧でセッションが起動時に拒否される問題が直った。
v2.1.319 で `permissions.denyInsteadOfPrompting` が加わり、権限の確認待ちになるツール呼び出しを拒否してターンを続けられる（ターミナルのセッション・サブエージェント・チームメイト）。managed settings で `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` を設定している場合、LLM gateway の背後で auto mode のサーバー側の確認を使うには `CLAUDE_CODE_AUTO_MODE_SERVER=1` も設定する必要がある。
v2.1.321 では権限まわりのセキュリティ修正が入った（読み取り専用の Bash コマンドが確認なしにサンドボックス外で実行される場合、Bash の権限チェックが誤ったフォルダーを基準に書き込みを判定した場合、ディレクトリへの `cp`・`mv` の書き込み先に deny ルールと保護ファイルの確認が適用されなかった問題）。`/config` は auto mode で始まる場合に既定の権限モードを正しく表示する。`claude remote-control --settings <file>` で、起動するすべてのセッションに設定ファイルを適用できる。
v2.1.323 で、サードパーティプロバイダーを使う Claude Desktop のセッション向けに managed settings で `CLAUDE_CODE_AUTO_MODE_MODEL` を設定できるようになった（Claude Desktop がこのバージョンを取り込んでから有効）。変数の値に `*` を含む Bash の allow ルール（例: `Bash(PORT=* npm run dev)`）には起動時に警告が出る。セッション中に保存した設定が直前の `settings.json` の手編集を元に戻す問題も直り、セッション中に削除した設定ファイルは削除されたままになる。

## 主な API・オプション

- `examples/settings/settings-hipaa.json` — HIPAA 向けの `managed-settings.json` の例
- `examples/settings/managed-mcp-hipaa.json` — HIPAA 向けの `managed-mcp.json` の例
- `examples/settings/README-hipaa.md` — 各設定の理由・編集箇所・確認方法・対象外の範囲
- `permissions.blockWritesOutsideWorkingDirectories` — 作業ディレクトリの外への Write・Edit・NotebookEdit を拒否（v2.1.314）
- `permissions.denyInsteadOfPrompting` — 権限の確認待ちになるツール呼び出しを拒否してターンを続ける（v2.1.319）
- `claude remote-control --settings <file>` — Remote Control が起動するセッションに設定ファイルを適用（v2.1.321）
- managed settings の `CLAUDE_CODE_AUTO_MODE_MODEL` — サードパーティプロバイダーの Claude Desktop のセッションの auto mode のモデル（v2.1.323）
