## 概要

会話のコンテキストの compact（要約による圧縮）と、コンテキストに入れるものの扱い（リリースノートに載った変更）。
v2.1.299 でターミナルにアイドル時の compaction が入った。200K トークン以上の会話を約 54 分放置すると、1 時間のプロンプトキャッシュが切れる前に compact し、次のメッセージで会話全体を処理し直さずに済む。
最小トークン数は `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` で変えられ、settings.json の `"idleCompaction": false` で無効にできる。
`CLAUDE_CODE_DISABLE_FILE_MENTIONS` を設定すると、`@` のファイルメンションはファイルの中身ではなくパスとして渡り、Claude がファイルツールで読む。
`/autocompact` で小さい自動 compact のウィンドウを選んだときに出ていた高トークン使用の警告は v2.1.300 で修正された。
v2.1.302 で `/config` に `Idle compaction` の行が入り、アイドル時の compaction をオフ・オンにできる（compaction 後の通知にもオフにする方法が出る）。compact 中にターンを止めたときの「Prompt is too long」エラーも修正された。
v2.1.304 で transcript ビューの compaction の要約にそれまでのツール名が出るようになり、v2.1.305 でクラウドセッションやチームメイトでも要約から古いメッセージを省いたことが Claude に伝わるようになった。
v2.1.306〜v2.1.309 では、MCP ツールが多いセッションで API エラーが「prompt is too long」に置き換わり不要な compaction が起きる問題、大きなツール結果（PDF のページ・画像など）を多く読んだターンでの「Autocompact is thrashing」エラーの一部、クラウドセッションの再起動で `/autocompact` が既定のウィンドウに戻る問題、とても大きなネストした CLAUDE.md の下のファイルを読むと compact を繰り返す問題が修正された。サイズ上限を超えるネストした CLAUDE.md は先頭だけが読み込まれる。
v2.1.310 では、「Prompt is too long」エラーの後の compaction が密なテキスト（base64・SVG など）を残しすぎて次のリクエストも失敗しうる問題が直り、非対話セッションで大きな transcript を compact するときのメモリ使用量が改善された。
v2.1.311 で、標準コンテキストのセッションで 1 リクエストが 200K トークンを超えると「Usage credits required for 1M context」で止まる問題が直り、会話を compact して続けるようになった。自動 compaction の直後に、セッション中に編集した MEMORY.md・CLAUDE.md の古い内容を Claude が見てしまう問題も修正された。
v2.1.314 でアイドル時の compaction が VS Code と Claude Desktop の Code タブにも入った（200K トークン以上の会話を放置すると要約し、プロンプトキャッシュが切れていれば次のメッセージで要約を使う）。Bedrock で画像が多いセッションが毎ターンと `/compact` で「400 Input is too long.」になる問題も直り、古い画像を外して compact するようになった。

## 主な API・オプション

- `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` — アイドル時の compaction の最小トークン数（既定 200K）
- settings.json の `"idleCompaction": false` — アイドル時の compaction を無効にする
- `CLAUDE_CODE_DISABLE_FILE_MENTIONS` — `@` メンションでファイルの中身ではなくパスを渡す
- `/config` の `Idle compaction` — アイドル時の compaction のオフ・オン（v2.1.302）
- `/autocompact` — 自動 compact のウィンドウを選ぶ
