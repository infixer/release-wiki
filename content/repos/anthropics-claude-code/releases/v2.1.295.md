## 要点

- command・HTTP フックに `onFailure: "block"` を追加（起動できない・タイムアウト・想定外の終了コードのフックが、操作を通さずにブロックする）
- Program Status Protocol（OSC 7501）に対応（対応するターミナルで、Claude Code が作業中・入力待ち・完了のどれかを表示できる）
- Claude apps gateway: すべての upstream に任意の `models` 一覧（一覧のモデルだけをそこへ送る。failover でも同じ。`*` 1 つでワイルドカード）、Bedrock・Vertex・Foundry などのクラウド upstream で `timeouts.upstream_ttfb_ms` に対応、`inference` 監査イベントに `upstream_request_id`、成功した推論レスポンスに `request-id` ヘッダーを追加。managed settings の無いマシンでは、ユーザー設定の `forceLoginMethod: "gateway"` と `forceLoginGatewayUrl` で `/login` がその gateway を開く
- mod 向け: `$.ui.notify`（自分の通知設定を通してネイティブ通知を出し、どのチャネルから送ったかを示す）、mod の `Button` の子要素（文字列と `Text`）を追加
- CLI: `/copy` のピッカーに引用テキストを追加（下書きのメッセージを `>` なしでコピー）、`claude plugin install`・`enable`・`disable`・`marketplace add` が書き込む設定ファイルが読み込まれないときに警告、`claude plugin validate` が README にインストール行の無いプラグインに貼る行を提案（終了コードは変えない。`--strict` でも同じ）、`claude -p` が最後のターンの後も開いたままのとき、何を待っているかを stderr（ターミナルのとき）に 1 行出す、`←` が現在のツールの終了を待っている間にターンを止めると「Backgrounding cancelled」を表示
- 環境変数 `CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS` を追加（無人のリトライモード `CLAUDE_CODE_RETRY_WATCHDOG` が 429・529 を待つ時間の上限）
- 修正: gateway・Bedrock・Vertex・Foundry が context-1m beta を拒否すると `[1m]` モデルのリクエストがすべて失敗する問題（beta なしで再送）、バックグラウンドの作業が別のターンを始めると `claude -p` のテキスト出力が前の応答を落とす問題、ヘッドレス・SDK セッションでリモート MCP サーバーが 15 秒を超える障害の後に切断されたままになる・接続直後に切るサーバーへ短い間隔で再接続し続ける問題（最大 30 秒までバックオフ）など（本文は途中まで）
