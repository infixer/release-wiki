## 要点

- 変更: テレメトリや feature flag を切った環境（LLM gateway の背後を含む）の auto mode は、サーバーで確認できない呼び出しを確認に回すか拒否し、ビルトインの分類器にはフォールバックしない。`CLAUDE_CODE_AUTO_MODE_SERVER=0` で従来どおり分類器を使える（Bedrock・Vertex・Foundry は変わらない）
- 変更: LLM gateway の背後では `CLAUDE_CODE_AUTO_MODE_SERVER=1` で、`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` を設定していてもサーバー側の確認が有効になる（managed settings で後者を設定している場合は `1` も設定する必要がある）
- 追加: ターミナルで MCP tasks に対応。MCP サーバーがツール呼び出しを task として実行すると、すぐにバックグラウンドへ移し、終わったら結果を Claude に伝える。`CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` で、バックグラウンドに移さずツール呼び出しの中で待つようにできる
- 追加: `permissions.denyInsteadOfPrompting` 設定（権限の確認待ちになるツール呼び出しを拒否してターンを続ける。ターミナルのセッション・サブエージェント・チームメイトで有効）
- 追加: `/claude-api latency-optimize`（Claude API のコードで待ち時間が生じている箇所を探し、より速い設定を eval で試す）、feature flag の取得だけを止める `CLAUDE_CODE_DISABLE_FEATURE_FLAGS`（テレメトリは止めない。各 flag は組み込みの既定値になる）
- 追加: Claude apps gateway に `admin.pooled_conflict_rule` / `admin.pooled_priority_order`（複数グループに属する開発者でどのグループ共有予算から先に払うか）、`login_notice`（ブラウザの確認ページと Claude Code のサインイン画面に運用者のメッセージ）、`CLAUDE_GATEWAY_LOG_FORMAT=json`、`availableModels` やポリシーまわりの起動時の警告。上限の無い開発者の `/usage` に今日・今週・今月の支出を表示（gateway がこのバージョン以降のとき）
- 追加: claude.ai のログインが切れて `ant auth login` のサインインで続行するときの警告（利用料は Claude Console の組織に請求される）と、起動時に請求先の Claude Console の組織名を示す行
- 追加: `/tasks` に「Earlier in this session」の行（終了したサブエージェントを一覧し、一覧から消えた後や再起動後でも開き直してメッセージを送れる）など（本文は途中で切れている）
