`<style>` の `v-bind()`（CSS 変数）が Teleport・KeepAlive・ループ・フラグメントの中でも SSR・クライアントの両方で正しく付くようにする修正がまとまって入った。

## 新機能

なし

## 変更・修正

### SSR: オブジェクトから継承したプロパティ名の属性を正しく描画する（[#16225](https://github.com/vuejs/core/pull/16225)）

> [!quote] Before
> JavaScript のオブジェクトによくあるプロパティと同じ名前の属性が、SSR で正しく描画されなかった（`.attr` 修飾子を使った場合も）（#16224）。

> [!success] After
> プロパティ名から属性名への対応表で、継承したプロパティを使わないようにした（`domAttrConfig.ts`）。

⏳ 未リリース · トピック: [[repos/vuejs-core/topics/SSR-ハイドレーション|SSR・ハイドレーション]]、[[repos/vuejs-core/topics/属性とスタイル|属性とスタイル]]

### runtime-dom: Teleport を patch せずに中身が入れ替わっても CSS 変数を適用する（[#16239](https://github.com/vuejs/core/pull/16239)）

> [!quote] Before
> Teleport で描画した内容が入れ替わる・移動する・トランジション・スロット・Suspense・KeepAlive の影響を受けると、CSS 変数が更新されないことがあった（#7312 など）。

> [!success] After
> こうした場合も CSS 変数を更新する。カスタム要素の shadow root の中の内容や、複数のルートが同時に変わる場合の更新も改善し、アンマウントしたコンポーネントの更新を保持せず、不要になった observer を切断する（`useCssVars.ts`・`Teleport.ts`）。

⏳ 未リリース · トピック: [[repos/vuejs-core/topics/組み込みコンポーネント|組み込みコンポーネント]]、[[repos/vuejs-core/topics/属性とスタイル|属性とスタイル]]

### SSR: ルートのループ・フラグメントにも CSS 変数を注入する（[#16244](https://github.com/vuejs/core/pull/16244)）

> [!quote] Before
> SSR で、ループや条件付きのテンプレートの中で描画された要素に CSS 変数のスタイルが付かなかった（#16242）。

> [!success] After
> こうした要素にも CSS 変数を付ける。ハイドレーションでは、入れ子のテンプレート・フラグメント・コンポーネントのルートで CSS 変数のスタイルを保ち、誤ったスタイルの不一致の警告を出さない（`ssrInjectCssVars.ts`・`hydration.ts`）。

⏳ 未リリース · トピック: [[repos/vuejs-core/topics/SSR-ハイドレーション|SSR・ハイドレーション]]

### compiler-ssr: KeepAlive・Teleport の中身に CSS 変数を注入する（[#16245](https://github.com/vuejs/core/pull/16245)）

> [!quote] Before
> `<style>` で `v-bind()` を使い、ルートが `<Teleport>`（`body` に描画するモーダルなど）や `<KeepAlive>` のコンポーネントは、サーバーの HTML に CSS 変数が付かなかった。両者は SSR で自分の要素を持たないため、束縛した `_cssVars` が出力に届かず、ハイドレーション後の DOM とずれていた。

> [!success] After
> `<Suspense>` と同じく、組み込みコンポーネント自体ではなくその子に注入する（`KeepAlive` / `Teleport` の両方の書き方で）。

⏳ 未リリース · トピック: [[repos/vuejs-core/topics/SSR-ハイドレーション|SSR・ハイドレーション]]、[[repos/vuejs-core/topics/組み込みコンポーネント|組み込みコンポーネント]]

### shared: プロトタイプの無いオブジェクトを `looseEqual` で扱う（[#16251](https://github.com/vuejs/core/pull/16251)）

> [!quote] Before
> プロトタイプが null の新しい素のオブジェクトをコンポーネントの `style` に渡すと、更新の判定で throw することがあった。`looseEqual` が比較するオブジェクトに `hasOwnProperty` があり、最後の `String()` での比較もできる前提だったため（#16250）。

> [!success] After
> キーの確認には既存の `hasOwn` を使い、変換メソッドの無い null プロトタイプのオブジェクトだけ `toTypeString` で比較する。それ以外のオブジェクトはこれまでどおり `String()` で比較し、オブジェクトを値に持つ `<select>` の選択肢が最初の選択肢に誤ってマッチしないようにしている。

⏳ 未リリース · トピック: [[repos/vuejs-core/topics/属性とスタイル|属性とスタイル]]

### compiler-sfc: ユーザーの `onWarn` を尊重し、インラインテンプレートの警告を返す（[#16152](https://github.com/vuejs/core/pull/16152)）

> [!quote] Before
> `compilerOptions` を展開した後に `onWarn` を上書きしていたため、ユーザーが渡した警告ハンドラーが捨てられ、ユーザーの `nodeTransform` や compat の非推奨の警告が本番ビルドの `<script setup>` で消えていた。`inlineTemplate` では、テンプレートのヒントを `warnOnce`（ビルド時は何もしない）に渡すだけで返していなかった。

> [!success] After
> 渡された `onWarn` / `onError` を内部の収集処理の後に呼ぶ。テンプレートのコンパイル中のメッセージはコールバックに渡され、コンパイル結果にも残る（`compileTemplate.ts`）。

⏳ 未リリース · トピック: [[repos/vuejs-core/topics/コンパイラ|コンパイラ]]
