## 概要

`oxc_lexer` の内部実装（`carve` / `disambiguate` パイプラインと SIMD 実装）の改善が続いている。SIMD 実装には `popcnt` CPU 機能が必須。JSX の字句解析では、HTML 風コメントやコメント・Unicode 空白を含む JSX タグの誤動作を修正済み。`disambiguate` の文脈解析（context walk）では、正規表現と除算や `>>` の判別を tsc と同じ読み方に揃える修正が続いており（for-of の先頭、import 属性、途中から始めた解析の継続、型リテラル内の演算子による型引数の否定など）、並行して重複・不要な状態の削除や、分類用 LUT のコンパイル時計算・`Tables` の削除といった大規模な整理・高速化も進んでいる。非 8 進数リテラルの修正で、Babel コンフォーマンスは 100% に達した。文脈解析では、行頭の `!=`・`as`・`satisfies` や行末で終わる型の扱いも tsc に揃え（トークンが変わる有効な入力はすべて tsc と一致）、密な問い合わせは全体の解析で答える形に整理した（tsx の型引数内のテンプレートの誤った字句解析も修正）。aarch64 向けには NEON による `classify` の実装が始まり、スカラー実装より速くなった（oxlint_v1.88.0）。CPU 機能の検出はコンパイル時から実行時へ移行中で、`DynCpu::detect()` でしか作れない `DynCpu` と、そこからしか得られない `Avx2`・`Neon`・`Generic` を使い、対応していない CPU で特定の機能セットの関数を呼べないことを型で保証する。`cpu_select!`・`cpu_versions!` マクロで実装を振り分け、パイプラインの各段階と `lex_raw` 全体が機能セットごとに別の経路になった（未リリース）。2026-10-30 の回では、`cpu_select!` / `cpu_versions!` が const 関数に対応し、`Lanes` を公開 API から外して `pipeline` へ移す、コメント関連のコードを `carve/comments.rs` に集約するなど公開 API の整理が進んだ（いずれも未リリース）。2026-11-02 の回では、`carve`・コメントの字句解析・`Lanes` のメソッドと cooking・数値の解析・スカラーのスキャナ・`disambiguate` の多くの関数（`Tokens`・`Closers`・`DisambiguateState` のメソッドなど）に `cpu_versions!` を付け、CPU 機能セットごとにコンパイルするようにした（一度しかコンパイルしない Level 3 などは `BASELINE` を使う）。`cpu_versions` マクロはライフタイム・ジェネリック引数と `#[inline(always)]` の関数に対応し、`cpu_version` マクロも追加された。`token` モジュールの非公開化、`cpu` モジュールの `pipeline` 外への移動なども行われた（いずれも未リリース）。2026-11-04 の回では、`Vec256` / `Vec128` の SIMD ベクター型（AVX2 の操作には `Avx2` トークンが必要）とアラインされた `VecData128` / `VecData256` が導入され、`cpu_version` / `cpu_versions` マクロは新しいクレート `oxc_lexer_macros` の proc macro になり（`cpu_versions` は `cpu_multiversion` に改名、`cpu_select!` は削除）、パイプラインの全関数に `#[cpu_version]` か `#[cpu_multiversion]` が付いた。`cpu`・`simd` 以外の `#[cfg(target_arch = ...)]` は取り除かれ、AVX2・Neon・汎用のすべてのコードがどのプラットフォームでもコンパイル・型チェックされる（無い機能セットの型は uninhabited）。`a?.<T>(b)` を型引数として読むなど、オプショナルチェーンのドットの後の字句解析も tsc に揃えた。このうち `Vec256` / `Vec128` とマクロの proc macro 化、型引数の修正は oxlint_v1.91.0 に収録された（`VecData` と全プラットフォームでのコンパイルは未リリース）。
