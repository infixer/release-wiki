## 概要

Oxfmt（フォーマッタ本体 `oxc_formatter`）の Prettier 互換性の向上が続いている。同梱の Prettier は 3.9.9 まで更新済み（oxfmt_v0.71.0 で公開）。コメントの扱いを重点的に直しており、JSDoc（`/***` も JSDoc として扱う）の行末ダブルスペース（ハードブレーク）の保持、通常のブロックコメントの行末スペースの保持、隣接ブロックコメントの揃え、代入演算子 `=` まわりのコメントを元の側・行に保つ方針、引数にコメントがあるテスト呼び出しのレイアウトなどを修正している。意図的な Prettier との差異は `DIVERGENCES.md` に記録される。呼び出し先と開きかっこの間のコメントも呼び出し先側に留めるようになった。埋め込みテンプレート（`` css`...` `` など）のレイアウトはソースの形ではなく AST から決めるようになり、`quoteProps: consistent` は分割代入パターンにも適用される。ignore は、親ディレクトリが除外されていれば否定パターンで再び含めない（Git・Prettier と同じ）挙動に明示パス・stdin・LSP でも揃った。CLI の Stdin モードではグローバルな ignore の先行確認とソース付き診断の表示、LSP では `.prettierignore` の変更の再読み込みに対応した。CSS フォーマッタ（`oxc_formatter_css`）・JSON フォーマッタ（`oxc_formatter_json`）でも Prettier・JS フォーマッタとの互換の修正が続き、埋め込み CSS をセレクターの無いブロックの中身として解析できるようになった（css-in-md 向け）。また、同じ Node.js プロセスで `runCli()` を繰り返し呼べるようになった（Vite+ からの直接呼び出し向け）。oxfmt_v0.72.0 で、Markdown ファイルの整形が Prettier から `oxc_formatter_markdown` に置き換わった（破壊的変更）。TOML の整形も他のフォーマッタと同じ形の `oxc_formatter_toml`（`oxc-toml` のラッパー）経由になり、frontmatter や Markdown 内の TOML も整形され、TOML 1.1 に対応した（oxfmt_v0.73.0 で公開）。`embeddedLanguageFormatting: off` では frontmatter をそのまま残す。CLI では stderr もブロッキングモードにし、出力が 64KB で途切れる問題を直した（oxlint も同様）。`prettier-plugin-astro@1.x` 経由で `.astro` ファイルと埋め込みの `astro` を整形できるようになった（`astro: true` でオプトイン、`@astrojs/compiler-rs` が必要。frontmatter と `<script>` は `oxc_formatter` が整形）。`--migrate prettier` と LSP も Astro に対応した。設定探索はシンボリックリンクの設定ファイルをたどるようになり、oxlint と挙動が揃った。JSDoc の複数段落の `@description` タグの段落も保つようになった（いずれも oxfmt_v0.73.0 で公開）。設定に `associations`（dprint 由来）が加わり、ファイルパスごとに言語（Shiki の ID）を指定してフォーマッタを選べるようになった（配列で後勝ち）。`--migrate prettier` は、カレントディレクトリだけを Prettier と同じ順序で探し（見つからなければエラー）、`resolveConfig()` を使わずに読み込み、`overrides` も移行し（`parser` は `associations[].language` に変換）、Prettier 互換でないオプションは警告するようになった（破壊的変更。YAML・JSON5・TOML の設定は未対応。いずれも oxfmt_v0.73.0 で公開）。css-in-js では、補間を含むコメントでのクラッシュを直し、プレースホルダーを `@media`・`@import`・プロパティ名・条件の中でも扱えるようになった。`(make<T>)!()` のかっこを保ち、`export default` の後の `class` / `function` のかっこは文の先頭と同じ扱いになった（いずれも oxfmt_v0.73.0）。コメントだけの JSX 式コンテナをグループで囲み、右辺がすべてインラインになる論理式の連鎖を余分にインデントしないようになった（未リリース）。穴のある配列のコメントの位置を保ち（for の先頭の空きのコメントも同じ仕組みで扱う）、`TSInstantiationExpression` や型キャストのかっこを保ち、JSX テキストなどで単独の CR を扱うようになった。JSON フォーマッタは不正な JSON を落とさずに拒否し、TOML フォーマッタは BOM を他の言語と同じに扱う。BOM・CRLF のソースでの解析エラーの位置も元のソースに揃え、BOM 付きの設定 JSON の読み込み、`.editorconfig` の検証、`--list-different` の末尾の改行も直った（いずれも未リリース）。ここまで未リリースだった修正は oxfmt_v0.74.0（2026-10-19）で公開された。同じリリースで、空文だけの静的ブロックでの panic、インデントされた区切りで始まる front matter・文書マーカーで始まる YAML のルートのスカラーをそのまま保つ修正、JSDoc の引用符の後のコードスパンの解析も入った。その後（未リリース）、行幅ちょうどのアローのシグネチャを本体にかかわらず保つ（Prettier の不具合と判断して #24440 を取り消し）、`fits` で平坦な `line` の空白を後ろにテキストがあるときだけ数える、という修正が入った。さらに（未リリース）、インスタンス化式の結合の弱いオペランド（`(c ? a : b)<T>` など）とプライベートの `in` 式のかっこを保ち、短いキーの判定や幅のヒューリスティックを表示幅で測るようになった（全角文字のキーでの非冪等な出力を解消）。内部では `AstNode` をスタックに置き、`FormatElement` を 16 バイトに縮める性能改善も入った。ここまで未リリースだった修正は oxfmt_v0.75.0（2026-10-27）で公開された。同じリリースで、閉じの HTML コメントを行頭に保つ（`let --> comment` で構文が変わるのを防ぐ）、`in` / `instanceof` という名前のクラスメンバーの前の `;` を保つ、結合の強い親を通した末尾のインスタンス化式のかっこを保つ、JSX のスプレッドの子の `}` の前のコメントを保つ、配列の fill レイアウトとコメント判定を直す（位置ベースの判定に）、という修正も入った。その後（未リリース）、`(a ?? b)?.#x` のかっこを保ち、`x.b` と `x.#b`・`this.b`・`super.b` を `foo.b` と同じに扱い、`(a + b)[c]` を `(a + b).c` と同じに改行し、型アサーションの中のジェネリックな関数型にかっこを付ける（Prettier の出力は `<<` で解析できなくなる）ようになった。`OXC_LOG=debug` ではファイル読み込みの時間も `oxfmt::read` のスパンとして出る。
