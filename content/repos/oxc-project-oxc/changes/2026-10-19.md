## 新機能

### レキサー: CPU 機能の検出をコンパイル時から実行時へ移行（[#27712](https://github.com/oxc-project/oxc/pull/27712)、[#27713](https://github.com/oxc-project/oxc/pull/27713)、[#27714](https://github.com/oxc-project/oxc/pull/27714)、[#27835](https://github.com/oxc-project/oxc/pull/27835)、[#27850](https://github.com/oxc-project/oxc/pull/27850)、[#27851](https://github.com/oxc-project/oxc/pull/27851)、[#27907](https://github.com/oxc-project/oxc/pull/27907)、[#27909](https://github.com/oxc-project/oxc/pull/27909)）

> [!tip] 何ができるようになったか
> `oxc_lexer` で、CPU 機能（AVX2・NEON など）をコンパイル時ではなく実行時に検出して実装を切り替えるための仕組みが入り、パイプラインの各段階がこれを使うようになった。
>
> - **基本の型**（[#27712](https://github.com/oxc-project/oxc/pull/27712)）: 現在のプラットフォームで使える CPU 機能セットのどれかを表す `DynCpu`、1 つの機能セットを表すゼロサイズ型 `Avx2`・`Neon`・`Generic`、これらが実装するトレイト `Cpu`、`impl Cpu` に応じて実装を振り分けるマクロ `cpu_select!`、機能セットごとに関数を複数生成して振り分ける入口を作るマクロ `cpu_versions!`
> - **安全性**: `DynCpu` は `DynCpu::detect()` でしか作れず、`Avx2` などは `DynCpu` からしか得られない。そのため CPU が AVX2 に対応していないのに `Avx2` を受け取る関数を呼ぶことは静的に不可能で、特定の CPU 機能に依存するだけの理由で unsafe だった関数を safe にできる
> - **各段階への適用**: `classify`（[#27713](https://github.com/oxc-project/oxc/pull/27713)）、`compress`（[#27714](https://github.com/oxc-project/oxc/pull/27714)）、`misc_pre`（[#27835](https://github.com/oxc-project/oxc/pull/27835)）、`misc_post`（[#27850](https://github.com/oxc-project/oxc/pull/27850)）、`coalesce`（[#27851](https://github.com/oxc-project/oxc/pull/27851)）
> - **マクロの拡張**: `cpu_versions` を自由関数だけでなくメソッドにも付けられるようにした（[#27907](https://github.com/oxc-project/oxc/pull/27907)）
> - **`lex_raw` 全体を機能セットごとにコンパイル**（[#27909](https://github.com/oxc-project/oxc/pull/27909)）: 一部が 1 回だけコンパイルされていたのをやめ、パイプライン全体が機能セットごとに別の経路になった。バイナリサイズを減らすための共有は、性能への影響を測ってから後で見直す方針

### Minifier: 配列の `join` 呼び出しを畳み込む（[#27905](https://github.com/oxc-project/oxc/pull/27905)）

> [!tip] 何ができるようになったか
> 配列の要素がすべて副作用の無い値のとき、`join` の呼び出しを畳み込むようになった（不足していた畳み込みの追加）。
>
> - **制限**: 単純な値だけを対象とし、`join` を `+` に置き換えたり、副作用のある `void` 式を移動したりはしない

## 変更・修正

### Oxfmt: 穴のある配列でのコメントの位置を保つ（[#27730](https://github.com/oxc-project/oxc/pull/27730)、[#27729](https://github.com/oxc-project/oxc/pull/27729)、[#27737](https://github.com/oxc-project/oxc/pull/27737)）

> [!quote] Before
> 穴のある配列（`[, , ...]`）でコメントの位置が変わっていた（#22799、#26376）。`[\n, ,// c\n]` は `[, ,// c]` と 1 行にまとめられていた。

> [!success] After
> 穴のある配列でコメントの位置を保つ（[#27730](https://github.com/oxc-project/oxc/pull/27730)）。空き要素の後の行コメントの後で改行し、`[` / `,` / `,// c` / `]` のように複数行で出力する（[#27729](https://github.com/oxc-project/oxc/pull/27729)）。同じ仕組みを `for (/*c*/;;)` のような for の先頭の空きにも使い、コメントを開きかっこ側に付ける（[#27737](https://github.com/oxc-project/oxc/pull/27737)）。根本的にはパターンの AST 側の修正が必要とされている。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### Oxfmt: `TSInstantiationExpression` や型キャストのかっこを保つ（[#27811](https://github.com/oxc-project/oxc/pull/27811)、[#27812](https://github.com/oxc-project/oxc/pull/27812)）

> [!quote] Before
> `(make<T>)<U>();` のような `TSInstantiationExpression` のかっこや、同じ演算子の二項式・アローの連鎖の中の型キャストのかっこが外れることがあった。

> [!success] After
> `(make<T>)<U>();` のかっこを保つ（[#27811](https://github.com/oxc-project/oxc/pull/27811)）。`x = a && /** @type {T} */ (b && c);` や `f = (a) => /** @type {T} */ ((b) => c);` の型キャストのかっこも保つ（[#27812](https://github.com/oxc-project/oxc/pull/27812)）。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### JSON フォーマッタ: 不正な JSON を拒否し、穴のある配列とコメントを扱う（[#27727](https://github.com/oxc-project/oxc/pull/27727)、[#27728](https://github.com/oxc-project/oxc/pull/27728)、[#27785](https://github.com/oxc-project/oxc/pull/27785)）

> [!quote] Before
> `[, /* holey only array with comment */ ]` で panic していた。`{ "foo": -true }` のような不正な JSON を受け付けたり、不正な部分を落として整形したりしていた。

> [!success] After

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### フォーマッタ共通: BOM・CRLF のソースで解析エラーの位置を正しく表示（[#27776](https://github.com/oxc-project/oxc/pull/27776)、[#27777](https://github.com/oxc-project/oxc/pull/27777)）
