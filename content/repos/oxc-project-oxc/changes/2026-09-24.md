### Vite+ モードでは入れ子設定を探索しないように（[#26763](https://github.com/oxc-project/oxc/pull/26763)）

> [!tip] 何ができるようになったか
> Vite+ サポート追加当初は入れ子設定（nested config）を扱うかどうか未定だったが、v1 ではサポートしない方針が確定した。Vite+ は `-c` や `--disable-nested-config` で無効化できるが、これは CLI のみに適用される。LSP は任意のディレクトリがワークスペースになりうるため、SSoT（信頼できる唯一の情報源）として Oxapps（`oxc_config`）側で入れ子設定探索を無効化するようにした。これにより各 IDE 拡張が個別に同じ強制無効化を実装する必要がなくなり、ポリシー変更時の巻き戻しも容易になる。副次効果として、意図しない入れ子設定を探索することによる性能問題も防止できる。

### enum の逆マッピング判定を tsc と同じ構文的な判定に修正（[#26724](https://github.com/oxc-project/oxc/pull/26724)）

> [!quote] Before
> 値が文字列であるメンバーは逆マッピングを持たないはずだが、enum の変換処理はこれを `is_string_literal()` で判定していたため、定数評価器が畳み込めない文字列初期化子は数値であるかのように変換されてしまっていた。内側の代入は文字列を生成するのに外側の書き込みが偽のキーを追加し、本物のメンバーを上書きすることがあった（`const foo = "x"` があるとき、`"xa" = 1` と `A = foo + "a"` を含む enum で `E["xa"]` が本来の `1` ではなく `"A"` になってしまっていた）。

> [!success] After
> tsc の `isSyntacticallyString` と同様に構文的に判定するよう変更した。文字列リテラル・テンプレートリテラル・どちらかの辺が文字列である加算は「文字列」とみなし、括弧の中も見る。`as`・`satisfies`・非 null・山括弧アサーションで囲まれた文字列は構文的には文字列とみなさないため `("x" as string)` は逆マッピングを保持する。`typeof x` や `1 + foo` を含むそれ以外は引き続き逆マッピングを保持し、tsc の出力と完全に一致させる。#26242 の enum 変換調査中に発見された不具合で、通常のコードにも影響するため main に直接反映された。
