## 新機能

### Oxfmt に `associations` 設定を追加し、ファイルパスごとに言語を指定可能に（[#27437](https://github.com/oxc-project/oxc/pull/27437)）

> [!tip] 何ができるようになったか
> dprint にならった `associations` 設定で、ファイル名から自動で決まる言語（フォーマッタ）を上書きできるようになった。CLI では、ファイル名に基づくフォーマッタの選択を飛ばし、指定した言語に決まったものとして扱う。
>
> - **使い方**: `"associations": [{ "files": ["**/*.wxml"], "language": "html" }, { "files": ["**/*.html"], "excludeFiles": ["index.html"], "language": "angular-html" }]`。`language` には Shiki の ID を使う
> - **優先順位**: オブジェクトではなく配列で、`overrides` と同じく後に書いたものが勝つ
> - **嬉しい場面**: `.conf` を JSON として、`.wxml` を HTML として整形したいとき（#17852、#26257 を解決）

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### `--migrate prettier` が `overrides[].parser` を `associations[].language` に移行（[#27475](https://github.com/oxc-project/oxc/pull/27475)）

> [!tip] 何ができるようになったか
> Prettier の設定の `overrides` にある `parser` の指定を、`oxfmt --migrate prettier` が Oxfmt の `associations[].language` に変換するようになった。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### `oxfmt --migrate prettier` を改善（破壊的変更）（[#27444](https://github.com/oxc-project/oxc/pull/27444)）

> [!tip] 何ができるようになったか
> Prettier の設定の探し方・読み込み方・移行する内容を見直した（#18215 を解決）。
>
> - **探索**: Prettier と同じ順序で、カレントディレクトリだけを探す。見つからなければ空の `.oxfmtrc.json` を作らずにエラーで終了する。入れ子の設定は各ディレクトリで実行して移行する
> - **読み込み**: `prettier.resolveConfig()` を使わずに読む（JS/TS の設定は `import()`、`.json`・`package.json` は `{ type: "json" }` 付きの `import()`、`.prettierrc` は `JSON.parse()`、共有設定は `createRequire()`）
> - **移行内容**: `overrides` も移行する（`parser`・`plugins` など未対応のオプションは警告して飛ばす）。Prettier 互換のオプションだけを移行し、それ以外（`importOrder` など）は警告する（以前はそのままコピーしていた）。JS/TS の設定のロジックは保たれないことも警告する
> - 既存の設定として `oxfmt.config.ts`・`oxfmt.config.mts` も確認し、移行後は生成ファイルが整形されていない可能性があるため `oxfmt` の実行を勧める

> [!warning] 移行が必要
> YAML・JSON5・TOML の Prettier 設定は未対応で、エラーで終了する。カレントディレクトリ以外にある設定や入れ子の設定は、それぞれのディレクトリで実行する必要がある。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### パーサーが解析中にノード ID を割り当てる（破壊的変更）（[#27411](https://github.com/oxc-project/oxc/pull/27411)）

> [!tip] 何ができるようになったか
> パーサーが AST ノードを組み立てる時点で一意のノード ID を割り当てるようになった（`Program` は 0）。ID は組み立て順で、捨てられたノードや再解析のために欠番が出ることがある。semantic 解析は引き続き、自分のノードストア用に詰めた ID で置き換える。

> [!warning] 移行が必要
> パース直後のノード ID が未設定であることを前提にしたコードは見直しが必要。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/パーサー|パーサー]]

### コメントの付属先（attachment）を保持する仕組みを追加（破壊的変更）（[#27393](https://github.com/oxc-project/oxc/pull/27393)、[#27512](https://github.com/oxc-project/oxc/pull/27512)）

> [!tip] 何ができるようになったか
> `Comment` に、所有するノードと `Leading` / `Trailing` / `Dangling` の位置を表す任意の `attachment` を持てるようになった。所有ノードは semantic 解析が付け替えられるよう `Cell<NodeId>` で持つ。AST の複製では、semantic の ID を保つ場合は独立したセルとして引き継ぎ、そうでなければ消す。付属先の情報は ESTree への変換と内容の比較からは除かれる。
>
> - `Comment` のサイズは 16 から 24 バイトに増え、パーサーのデシリアライザと oxlint のプラグインのバッファ読み取りも合わせて更新された
> - 単独のレキサーのコメント・手で作ったコメント・ノード ID なしの複製では付属先は無し
> - [#27512](https://github.com/oxc-project/oxc/pull/27512) でこの保持方法がリファクタされた（本文なし。`comment.rs` や `trivia_builder.rs`、生成コードの変更）

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/パーサー|パーサー]]

### Minifier: `delete` 式を `true` / `false` に畳み込む（[#27522](https://github.com/oxc-project/oxc/pull/27522)）

> [!tip] 何ができるようになったか
> 可能な場合に `delete` 式を `true` / `false` に畳み込むようになった。`delete` の対象が数値の NaN・Infinity なら `true`、グローバルの変更できない変数なら `false` になる。
>
> - **背景**: `delete Math.sqrt(-1)`・`delete Number('a')` などが誤った構文に畳み込まれていたため、元の段階で畳み込む方針にした（[#27466](https://github.com/oxc-project/oxc/pull/27466) の続き）

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

> [!quote] Before

### `export` の後の `/*@__NO_SIDE_EFFECTS__*/` を反映（[#27504](https://github.com/oxc-project/oxc/pull/27504)）

> [!quote] Before
> 文の解析は `export` より前の注釈しか拾わないため、`export /*@__NO_SIDE_EFFECTS__*/ function f() {}` で関数の `pure` フラグが立たなかった。

> [!success] After
> `export` の直後の注釈も拾い、既存の関数の純粋性の処理を適用する。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/パーサー|パーサー]]、[[repos/oxc-project-oxc/topics/Minifier|Minifier]]

### `unicorn/prefer-bigint-literals`: 冗長な呼び出しを外し、精度が落ちる自動修正をしない（[#25690](https://github.com/oxc-project/oxc/pull/25690)）

> [!quote] Before
> `BigInt(1000000000000000100)` のように実行時の値（`1000000000000000128n`）と異なる BigInt リテラルに書き換える、安全でない自動修正があり得た。`BigInt(123n)` の簡約も無かった。

> [!success] After
> グローバルの `BigInt(123n)` を `123n` に簡約し、実行時の BigInt の値が変わる数値の自動修正は行わない（診断は「Integer literal loses precision」の注記付きで出す）。2・8・16 進数は `u64` に狭めずに有効桁を比べる（`BigInt(0xffffffffffffffff)` は修正しない）。ローカルに束縛された `BigInt` は対象外で、`BigInt(1n)in {...}` → `1n in {...}` のようにトークンの境界も保つ。精度の判定は `utils/number.rs` に共通化され、2・8・16 進数の修正は `no-loss-of-precision` にも適用される。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Linterルール個別修正|Linterルール個別修正]]

### enum の初期化子で文字列への単項演算を評価しない（[#27447](https://github.com/oxc-project/oxc/pull/27447)）

> [!quote] Before
> `oxc_semantic` の `eval_unary_expression` が文字列への単項 `+`・`-`・`~` を Babel の意味で畳み込んでおり（`+"s"` → `"s"`、`-"s"` → `NaN`、`~"s"` → `-1`）、トランスフォーマーが `enum E { A = +"2" }` を文字列 `"2"` として出力する、`-"3"` が `NaN` になるなど誤った enum を生成していた。誤った値は後続のメンバーにも伝わっていた。

> [!success] After
> 文字列への単項 `+`・`-`・`~`・`void`・`!` は評価せず、計算されたメンバーとしてそのまま出力する（tsc と同じ）。oxc-node#795 の修正中に見つかった。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/TypeScriptトランスフォーマー|TypeScriptトランスフォーマー]]

### `ReplaceGlobalDefines` が非 null アサーション越しのオプショナルチェーンを保つ（[#27526](https://github.com/oxc-project/oxc/pull/27526)）

> [!quote] Before
> TypeScript の非 null アサーションがオプショナルなメンバーを隠していると、オプショナルチェーンを早く外してしまい、Rolldown の define → transform の流れで `c?.a!.b` が ES2017 ターゲットでも `c?.a.b` のまま残っていた。

> [!success] After
> オプショナルの印を探すときに非 null アサーションをたどるようになり、チェーンが下位変換で処理される。rolldown/rolldown#11172 の上流の原因の修正。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/TypeScriptトランスフォーマー|TypeScriptトランスフォーマー]]

### トランスフォーマーの高速化（式の exit 処理を必要なノードだけに）（[#27489](https://github.com/oxc-project/oxc/pull/27489)、[#27491](https://github.com/oxc-project/oxc/pull/27491)、[#27492](https://github.com/oxc-project/oxc/pull/27492)）

> [!quote] Before
> 共通・JSX・クラス・async generator・async の各プラグインの式の exit 処理が、すべての式で実行されていた。ES2022 の変換も、クラス以外の式や通常の文でクラス変換の状態を読んでいた。
