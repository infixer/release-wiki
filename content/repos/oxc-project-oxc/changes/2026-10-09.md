## 新機能

### Oxfmt が `prettier-plugin-astro@1.x` 経由で Astro に対応（[#27386](https://github.com/oxc-project/oxc/pull/27386)）

> [!tip] 何ができるようになったか
> `.astro` ファイルと、埋め込みの `astro` を `prettier-plugin-astro@1.x` を使って整形できるようになった。前提条件は Svelte 対応と同じ。
>
> - **使い方**: `@astrojs/compiler-rs` をインストールして Node.js プロセスから実行できる状態にし（Astro のプロジェクトなら通常は入っている）、設定で `astro: true` か `astro: { ... }` を指定する（オプトイン）
> - **元のプラグインとの違い**: frontmatter と `<script>` ブロックは `oxc_formatter` が整形する。`<style>` ブロックは Prettier が整形するので、`oxc_formatter_css` の出力と異なることがある。`<style lang="sass">` ブロックは整形しない（元のプラグインは整形する）。`allowShortHand` は既定で未設定、`true|false` だけを受け付け、`overrides` で元に戻す方法はない（Prettier と同じ）

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### `--migrate prettier` が Astro プラグインに対応（[#27387](https://github.com/oxc-project/oxc/pull/27387)）

> [!tip] 何ができるようになったか
> Prettier の設定から Oxfmt の設定へ移行する `--migrate prettier` が、Astro プラグインの設定も扱うようになった（`migrate-prettier.ts` とスナップショットの更新）。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### `oxfmt --lsp` が Astro の言語に対応（[#27388](https://github.com/oxc-project/oxc/pull/27388)）

> [!tip] 何ができるようになったか
> Oxfmt の LSP サーバーが `astro` の言語 ID を扱えるようになった。VS Code・Zed・IntelliJ・coc の各拡張側の対応も行われており、LSP と拡張の両方が揃って初めて有効になる。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/LSP|LSP]]、[[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### oxlint の LSP が設定のエラーをクライアントに表示（[#25486](https://github.com/oxc-project/oxc/pull/25486)）

> [!tip] 何ができるようになったか
> ワークスペースの初期化時に Oxlint の設定の読み込みに失敗すると、`window/showMessage` の通知として LSP クライアントに表示するようになった。ルートの設定・入れ子の設定・カスタムの設定パスの読み込み・構築の失敗が対象で、失敗時のフォールバックの lint の挙動は変わらない。
>
> - **嬉しい場面**: 設定ファイルの誤りでルールが効かないとき、エディタ上で原因が分かる
> - VS Code は短時間に最大 5 件までしかメッセージを表示しないが、[#25962](https://github.com/oxc-project/oxc/pull/25962) で通知はもともと最大 5 件に抑えている

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/LSP|LSP]]

### oxfmt の LSP がルート設定のエラーをクライアントに表示（[#26014](https://github.com/oxc-project/oxc/pull/26014)）

> [!tip] 何ができるようになったか
> これまで `.oxfmtrc.json` の誤りなどルート設定の解決エラーはサーバー側で `warn!` に記録するだけで、エディタからは見えなかった。エラーを `ClientMessage` として初期化の流れに渡し、LSP クライアントへの通知として表示するようになった。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/LSP|LSP]]

### oxfmt の設定探索がシンボリックリンクの設定ファイルをたどるように（[#27389](https://github.com/oxc-project/oxc/pull/27389)）

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### 型の import を変換する自動修正どうしの衝突を防止（[#27409](https://github.com/oxc-project/oxc/pull/27409)）

> [!quote] Before
> 同じ修正パスで `typescript/no-import-type-side-effects` が import を `import type` に変え、`import/no-duplicates` がインラインの型指定子を追加すると、`import type { CoreSetup, Logger, type LoggerFactory }` のような不正な構文になった。Kibana のエコシステム CI がこれでパニックしていた。

> [!success] After
> `typescript/no-import-type-side-effects` 側を修正し、衝突する修正を出さないようにした。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Linterルール個別修正|Linterルール個別修正]]

### 型認識の診断でソースをファイルごとに 1 つ共有し、メモリ使用量を大幅に削減（[#27462](https://github.com/oxc-project/oxc/pull/27462)）

> [!quote] Before
> 型認識の診断を送るたびに、ファイルのソース全文をコピーしていた。コピーは診断と同じだけ生き残るため、oxlint のプロセスは「診断数 × ファイルサイズ」で大きくなった。

> [!success] After
> ファイルごとに `Arc<NamedSource>` を 1 つ作り（新しい `DiagnosticService::named_source`）、そのファイルの診断で共有する。出力は変わらない。VS Code の `src`（10,201 ファイル、診断 316k 件）での計測では、oxlint プロセスのピーク RSS が約 31 GiB から 0.7 GiB に、oxlint + tsgolint では約 40 GiB から 10 GiB に減った。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/型認識Lint|型認識Lint]]

### `delete a?.b` などをメンバーへの書き込みとして扱うように（[#27430](https://github.com/oxc-project/oxc/pull/27430)）

> [!quote] Before
> `delete a.b` では `a` が `Read | MemberWriteTarget` になるが、`delete a?.b` と `delete (a.b)` ではならなかった（#27419）。オプショナルチェーンは `ChainExpression`、かっこはメンバー式を包むため、判定から漏れていた。

> [!success] After
> かっこ・型アサーションを外し、要素がメンバー（呼び出しでない）のチェーンも `delete` の対象として扱う。`delete x` は変わらない。Rolldown がメンバーチェーン経由の書き込みの検出に `MemberWriteTarget` を使っている。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/パーサー|パーサー]]

### クラスの静的ブロックの変換で合成のプライベートフィールドを使わないように（[#27300](https://github.com/oxc-project/oxc/pull/27300)）

> [!quote] Before
> 静的ブロックを 1 つずつ合成のプライベート静的フィールドに変換していたため、それより前の静的初期化でクラスが拡張不可になった後にフィールドが追加されることがあった。非拡張性をプライベートフィールドにも適用する提案のもとでは、観測可能な TypeError になる（#27244）。

> [!success] After
> 静的ブロックを後続の静的フィールドの初期化子に畳み込み、末尾のブロックはクラス内で安全に初期化されるクロージャで遅延実行する。静的初期化の順序、クラス式の結果、クラス宣言の TDZ、推論される関数名・クラス名（計算・プライベート・シンボルのキーを含む）を保つ。CommonJS・ESM の `setFunctionName` ヘルパーも、`Symbol("")` と `Symbol()` を区別するよう修正（`"[]"` と `""`）。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/ES2022クラス変換|ES2022クラス変換]]

### 定数の引数で呼ばれる未使用の IIFE を除去（[#27434](https://github.com/oxc-project/oxc/pull/27434)）

> [!quote] Before
> `const f = x => x + 1; f(1);` のような未使用の呼び出しが `(x => x + 1)(1)` として残っていた。

> [!success] After
> アロー関数の IIFE と strict な通常関数の IIFE について定数の引数を追跡し、既存の定数畳み込みと副作用解析で呼び出しを除去する。引数の評価、パラメーターへの書き込み、再宣言、直接の `eval` は尊重し、既定値・分割代入・レストパラメーター・スプレッド引数があるときは変換しない。自身の名前を参照する関数や非 strict な関数も対象外。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

### 空の `do…while` の本体の前に余分なインデントを出さないように（[#27407](https://github.com/oxc-project/oxc/pull/27407)）

> [!quote] Before
> インデントされた空の `do…while` の本体で、`do` と `;` の間に余分な空白が出力されていた。

> [!success] After
> JavaScript と Rust の両方の codegen で空文のインデントを省き、`do` の直後に `;` を出す。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]
