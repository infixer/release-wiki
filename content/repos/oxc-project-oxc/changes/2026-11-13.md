期間: 2026-11-11 〜 2026-11-13 · PR 54 件（新機能 8 / 変更・修正 22 / その他 24）· Release 0 件

この期間は、linter で通常の lint 実行中（`--fix` なしでも）に panic していた多数のルールの修正がまとまって入った（Unicode の空白・マルチバイト文字の位置の扱い、かっこで囲んだオプショナルチェーンの呼び出し先、循環する別名など）。minifier は 1 回だけ使われるメンバーの読み取りを呼び出しの引数・`new` 式・呼び出し先（間接呼び出し `(0, o.m)()`）に埋め込み、同じ本体の隣り合う `switch` の `case` をまとめるようになった。ほかに `oxc_lexer` と SIMD のクレートの crates.io への公開、Playground のヘルパーのモジュール名の指定、`typescript/no-misused-promises` の `flagUnions` オプション、`vue/no-shared-component-data` の自動修正が入った。

PR 数が `maxPrs`（30）を超えたため、`brief: true` の 24 件は「その他」にタイトルから領域ごとにまとめて書いてある。

## 新機能

### Minifier: 1 回だけ使うメンバーの読み取りを呼び出しの引数に埋め込む（[#29303](https://github.com/oxc-project/oxc/pull/29303)）

> [!tip] 何ができるようになったか
> 呼び出し先が識別子の呼び出しは丸ごと埋め込みの対象外だったが、置き換える変数が呼び出し先そのもの（埋め込むと `this` が変わる）の場合だけを除外するようにした。
>
> - 例: `var cubemap = cubemaps.get(texture).texture; return mapTextureMapping(cubemap, texture.mapping);` → `return mapTextureMapping(cubemaps.get(texture).texture, texture.mapping);`
> - `typescript.js` が 1,827 B（gzip で 459 B）小さくなった

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

### Minifier: メンバーの読み取りを `new` 式に埋め込む（[#29304](https://github.com/oxc-project/oxc/pull/29304)）

> [!tip] 何ができるようになったか
> `new` はメンバー参照から `this` を受け取らないため、`new` 式の `this` のガードを外した。1 回だけ使うメンバーの読み取りを、コンストラクターにも引数にも埋め込める。
>
> - 例: `var Ctor = o.Ctor; return new Ctor(o.options);` → `return new o.Ctor(o.options);`

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

### Minifier: メンバーの読み取りを間接呼び出しとして呼び出し先に埋め込む（[#29305](https://github.com/oxc-project/oxc/pull/29305)）

> [!tip] 何ができるようになったか
> 1 回だけ使うメンバーの読み取りを `(0, o.m)()` の形で呼び出し先に埋め込む（`m` は `this` が `o` に束縛されないまま実行される）。terser・uglify-js・swc と同じ挙動で、esbuild は変数を残す。
>
> - 例: `var method = o.method; return method(o.value);` → `return (0, o.method)(o.value);`
> - オプショナルなメンバー（`o?.method`）も `(0, o?.method)()` にする
> - タグ付きテンプレートの経路と `passes_this_when_called` を共有

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

### Minifier: 同じ本体の隣り合う `switch` の `case` をまとめる（[#29316](https://github.com/oxc-project/oxc/pull/29316)）

> [!tip] 何ができるようになったか
> 隣り合う 2 つの `case` の本体が同じで、その本体が必ず `switch` を抜ける（`return`・`throw`・`break`・`continue`）とき、前の本体を空にして後ろへフォールスルーさせる。
>
> - 例: `case 165: return x; case 347: return x;` → `case 165: case 347: return x;`
> - 後ろの本体が `switch` の最後なら、末尾のラベルなしの `break` は両側で無視する。`try_fold_switch` の前に実行されるため、すべての `case` が `default` と同じになれば `switch` ごと畳み込まれる（例: `return -2147483648;` だけになる）

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

## 変更・修正

### linter: `import/no-duplicates` でモジュール文字列の中の波かっこを無視（[#29270](https://github.com/oxc-project/oxc/pull/29270)）

> [!quote] Before
> `import '}{'; import '}{';` のような重複した import で、統合の修正がモジュール文字列の中の波かっこを指定子の区切りとして扱い、修正を無効にしていても通常の lint 中に panic していた。

> [!success] After
> 区切り文字の検索をモジュール文字列より前のテキストに限り、外側の波かっこの組を選び、位置の順序を確かめてから切り出す。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Linterルール個別修正|Linterルール個別修正]]

### linter: `eslint/no-empty` の `finally` のサジェスチョンでバイト位置を使う（[#29271](https://github.com/oxc-project/oxc/pull/29271)）

> [!quote] Before
> 空の `finally` のサジェスチョンで、キーワードの検索がバイト位置と文字の位置を混同しており、前にマルチバイト文字があると panic することがあった。

> [!success] After
> `char_indices()` で後ろ向きに走査して実際のバイト位置で削除範囲を決める。一致した文字列がコメントの中にある場合や、`finally` を消すと `try` にハンドラーが無くなる場合はサジェスチョンを出さない。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Linterルール個別修正|Linterルール個別修正]]

### linter: Unicode の空白・マルチバイト文字で panic していたルールの修正（[#29272](https://github.com/oxc-project/oxc/pull/29272)、[#29276](https://github.com/oxc-project/oxc/pull/29276)、[#29278](https://github.com/oxc-project/oxc/pull/29278)、[#29289](https://github.com/oxc-project/oxc/pull/29289)、[#29292](https://github.com/oxc-project/oxc/pull/29292)、[#29298](https://github.com/oxc-project/oxc/pull/29298)）

> [!quote] Before
> UTF-8 の文字の途中で文字列を切り出してしまい、自動修正を無効にしていても lint 中に panic していた。jest・vitest の `no-large-snapshots`（スナップショットの引数の後の U+00A0 など）、`unicorn/prefer-set-has`（`new` と `Array` の間の Unicode の空白）、`unicorn/no-useless-spread`（`[...( 0, [])]` のように U+00A0 を含む場合）、`vitest/prefer-called-once`（エスケープした Unicode の行継続を含むマッチャー名）、jest・vitest の `prefer-to-be`（計算プロパティのマッチャーや `not` の前の Unicode の空白）、`unicorn/consistent-template-literal-escape`（パーサーがテンプレートの raw 値の CRLF を正規化するため、位置がずれる）が該当。

> [!success] After
> 終端を含まない範囲や AST のスパン、デコードした名前、コメントを考慮したトークンの検索、各 quasi の元のソースの走査などで位置を求めるようにした。`unicorn/prefer-set-has` は初期化子全体を `new Set(...)` で囲み、空白・コメント・エスケープした識別子を保つ。`prefer-to-be` の自動修正はオプショナルのメンバー・呼び出しの演算子を保つ。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Linterルール個別修正|Linterルール個別修正]]

### linter: かっこで囲んだ呼び出し先・オプショナルチェーンで panic していたルールの修正（[#29277](https://github.com/oxc-project/oxc/pull/29277)、[#29279](https://github.com/oxc-project/oxc/pull/29279)、[#29285](https://github.com/oxc-project/oxc/pull/29285)、[#29286](https://github.com/oxc-project/oxc/pull/29286)、[#29293](https://github.com/oxc-project/oxc/pull/29293)）

> [!quote] Before
> `(a.slice)(0, a.length)`、`(parentNode?.removeChild)(child)`、`(x.reduce)(0, 0)`、`(obj?.indexOf)('x') !== -1`、`(arr?.reduce)((acc, x) => [...acc, x], [])` のような正しいコードで、`unicorn/no-length-as-slice-end`・`unicorn/prefer-dom-node-remove`・`unicorn/prefer-object-from-entries`・`unicorn/prefer-includes`・`oxc/no-accumulating-spread` が panic していた。

> [!success] After
> 正規化したメンバー式を使うか、扱えない呼び出し先では早めに抜ける。`unicorn/no-length-as-slice-end` は通常どおり報告して `(a.slice)(0)` に修正し、`unicorn/prefer-dom-node-remove` は ESLint・Unicorn と同じく報告しない。`oxc/no-accumulating-spread` は `get_member_expr()` でメソッドのスパンを取り出す。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Linterルール個別修正|Linterルール個別修正]]

### linter: そのほかの panic・無限再帰の修正（[#29273](https://github.com/oxc-project/oxc/pull/29273)、[#29274](https://github.com/oxc-project/oxc/pull/29274)、[#29275](https://github.com/oxc-project/oxc/pull/29275)、[#29299](https://github.com/oxc-project/oxc/pull/29299)）

> [!quote] Before
> `unicorn/prefer-array-flat` は `array.reduce((a, ...b) => a.concat(b), [])` のような rest 引数で、`typescript/consistent-type-imports` は `}` を含むクォートした import 名（`import type { "}" as A } from 'm';`）で、`vitest/require-test-timeout` は `vi.setConfig({ testTimeout: ... })` を 3 回続けるとオーバーフローの検査ありのビルドで panic していた。`unicorn/no-document-cookie` は `var a = a; a.cookie = 0;` のような循環する別名で無限に再帰していた。

> [!success] After
> `prefer-array-flat` は rest 引数のコールバックを飛ばし、通常の引数がちょうど 2 つのときだけ調べる。`consistent-type-imports` は最後の名前付き指定子の後かつモジュールの前で閉じ波かっこを探し（修正結果は typescript-eslint と一致）、`require-test-timeout` は `Reverse(span.end)` で並べ替え、`no-document-cookie` は訪問済みのシンボルの集合を使って反復的に別名を解決する。

### Oxfmt: 型エイリアスのユニオンの抱え込みとコメント・条件型の分岐（[#29256](https://github.com/oxc-project/oxc/pull/29256)、[#29261](https://github.com/oxc-project/oxc/pull/29261)）

> [!quote] Before
> 抱え込んだ（hug）型エイリアスのユニオンがはみ出すとき、`=` の後で改行していなかった（#29222）。ユニオンの抱え込みとコメント、条件型の分岐のユニオンの出力が揃っていなかった。

> [!success] After
> はみ出す抱え込みの型エイリアスは `=` の後で改行する。抱え込んだユニオン（`X | null`）の直前の 1 行のブロックコメントは最初のメンバーのものとして扱いユニオンを展開し（`| /* c */ X`）、行末のコメントでは抱え込みを保つ。条件型の分岐のユニオンは最初の `|` を `?` / `:` のすぐ後に出す。方針と残る課題は `AGENTS.md`・`DIVERGENCES.md` に記録した。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### HTML フォーマッタ: 文字参照を含む属性を保つ、Angular のブロック（[#29257](https://github.com/oxc-project/oxc/pull/29257)、[#29258](https://github.com/oxc-project/oxc/pull/29258)）

> [!quote] Before
> `<button onclick="x=a &amp; b">` のような文字参照を含むイベント属性を JS として整形すると、`x = a & amp; b;` のように壊れていた。Angular のブロックのパラメーターも保たれていなかった。

> [!success] After

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/HTMLフォーマッタ|HTMLフォーマッタ]]
