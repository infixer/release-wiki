## 新機能

### 型認識ルール `typescript/no-generated-empty-object-type` を追加（[#26958](https://github.com/oxc-project/oxc/pull/26958)）

> [!tip] 何ができるようになったか
> `Pick<Data, never>` のように、型操作の結果が `{}` になってしまうものを報告する型認識（type-aware）ルールを suspicious カテゴリに追加した。型解析は TSGolint 側で行い、ルールにはオプション・自動修正・サジェスチョンは無い。
>
> - **使い方**: 設定で `typescript/no-generated-empty-object-type` を有効にし、`--type-aware` で実行する
> - **注意**: [tsgolint#1229](https://github.com/oxc-project/tsgolint/pull/1229) を含むバックエンドが必要。この PR では固定しているバックエンドパッケージのバージョンは変えていない

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/型認識Lint|型認識Lint]]

### `oxc-transform-react` に `reportDiagnostics` オプションを追加（[#26624](https://github.com/oxc-project/oxc/pull/26624)）

> [!tip] 何ができるようになったか
> オプトインの `reactCompiler.reportDiagnostics` を追加した。`true` にすると、コンパイルに成功したときに React Compiler が出した回復可能な診断が、コンパイラが付けた重大度（`Suppression` は `Error`、`IncompatibleLibrary` は `Warning` など）のまま `result.errors` に追加される。`fatal` は従来どおり `code` が使えるかどうかを表す。既定値は変わらず、回復可能な診断は含めない（Babel の既定 `logger: null` に合わせたもの）。
>
> - **使い方**: `reactCompiler: { reportDiagnostics: true }`
> - **嬉しい場面**: 関数がなぜコンパイルされずスキップされたかを知りたいとき（コンパイラ導入時の棚卸しや、`eslint-disable` による抑制が実際に効いたかの確認）。`@vitejs/plugin-react` の `logDiagnostics` はこのオプションに転送するだけで動くようになる

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/React-Compiler|React-Compiler]]

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/パーサー|パーサー]]

## 変更・修正

### React Compiler が暗黙の `arguments` オブジェクトでは最適化をやめるように（[#26896](https://github.com/oxc-project/oxc/pull/26896)）

> [!quote] Before
> 暗黙の `arguments` オブジェクトを使うコードもコンパイルしており、連続したレンダーで値が更新されない（`1 → 1`）ことがあった。

> [!success] After
> React 本家の [59aff3e](https://github.com/react/react/commit/59aff3e18cb5b3a336c280bbfa57ec37999511b9) を移植し、`arguments` を使う場合はコンパイルを中止（bail out）する。連続レンダーが `1 → 2` になることを確認済みで、5 つのベンチマークで性能低下は見られなかった。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/React-Compiler|React-Compiler]]
