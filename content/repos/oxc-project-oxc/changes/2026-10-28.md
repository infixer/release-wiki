## 新機能

### oxfmt: ファイル読み込みのデバッグ用スパンを追加（[#28204](https://github.com/oxc-project/oxc/pull/28204)）

> [!tip] 何ができるようになったか
> ファイルの読み込みは `oxfmt::format` のスパンの外で行われるため、`OXC_LOG=debug` で I/O にかかった時間が見えなかった。読み込みに `oxfmt::read{path=...}` のスパンを追加した。
>
> - **使い方**: `OXC_LOG=debug` を付けて oxfmt を実行する（`DEBUG oxfmt::read{path=src/foo.tsx}: ... close time.busy=92.6µs` のように出る）
> - **嬉しい場面**: エンドポイントのセキュリティソフトが `open()` / `close()` のたびにスキャンする環境など、整形以外で時間がかかっている原因を調べたいとき

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

## 変更・修正

### Markdown: ディレクティブの中でも範囲 ignore を有効に（[#28164](https://github.com/oxc-project/oxc/pull/28164)）

> [!quote] Before
> 範囲 ignore はトップレベルでしか効かない。`:::` をコンテナディレクティブとして解析するため、その中身はトップレベルにならず、範囲 ignore が無視されていた（#28154。ディレクティブに対応しない Prettier では中身がトップレベルになり効いていた）。

> [!success] After
> 上に引用・リスト項目・脚注の無い `:::` ディレクティブの中はトップレベルとして扱う。どこでも範囲を使えるようにするのは、そのまま出力する部分のインデントのずれなどの懸念があるため見送り。

### Oxfmt: 閉じの HTML コメントを行頭に保つ（[#28064](https://github.com/oxc-project/oxc/pull/28064)）

> [!quote] Before

> [!success] After

### Oxfmt: 型アサーションの中のジェネリックな関数型のかっこを保つ（[#28173](https://github.com/oxc-project/oxc/pull/28173)）

> [!quote] Before
> `var a = < <T>(x: T) => T>f;` を `<<T>(x: T) => T>f` と出力していた。式の中の `<<` は左シフトとして読まれるため、型アサーションが消えて解析できなくなる（Prettier 3.9.10 も同じ出力）。

> [!success] After
> 型パラメーターを持つ関数型の親が `TSTypeAssertion` なら、`<(<T>(x: T) => T)>f` のようにかっこを付ける。型引数の中（`Array<<T>() => T>` など）は TypeScript が `<<` を 2 つのトークンとして読み直すため変えない。差異として `DIVERGENCES.md` に記録した。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### React Compiler: オプショナルチェーンのキャッシュのガードを保つ（[#28165](https://github.com/oxc-project/oxc/pull/28165)）

> [!quote] Before
> `obj?.a.b(getArg())` で、先に `obj = undefined` で描画して `undefined` をキャッシュすると、次に `obj = {}` で描画したときも依存 `obj?.a` が `undefined` のままなので結果を再利用し、本来起きるべき `.b` の読み取りでの `TypeError` が隠れていた（`babel-plugin-react-compiler@1.0.0` でも再現）。

> [!success] After
> オプショナルな部分より後のオプショナルでない続きを依存として残し、プロパティのパスで表せない計算されたアクセス・呼び出しでは元のガードの依存を保つ。条件付きで評価されるチェーンは、最後のオプショナルなつながりの手前で依存を切る。すべてオプショナルなチェーンは従来どおり。上流の挙動も意図的に直している。

📦 oxlint_v1.90.0 · トピック: [[repos/oxc-project-oxc/topics/React-Compiler|React-Compiler]]

### React Compiler: 依存が守れない手動のメモ化は書いたまま残す（[#28101](https://github.com/oxc-project/oxc/pull/28101)）

> [!quote] Before
> 手動の `useMemo` / `useCallback` の依存リストを、推論した依存で置き換えることがあった。たとえば `useMemo(() => sortBy(items, s ?? props.value), [items])` で、作者があえて外した `s` が変わるたびに並べ替え直していた。余分な依存が落ちることもあった（#27113）。

> [!success] After
> 上流の React Compiler と同じく、メモ化の依存の網羅性の検証を既定で有効にした。依存が足りない・余分なときは、そのコンポーネント・フックをまるごとコンパイルせず、手動のメモ化をそのまま残す。同じファイルの他の関数はコンパイルされる。ESLint・Oxlint の抑制コメントはこれまでどおり効く。`oxc-transform-react` のオプションの型（`index.d.ts`）も更新された。

📦 oxlint_v1.90.0 · トピック: [[repos/oxc-project-oxc/topics/React-Compiler|React-Compiler]]

### React Compiler: JSX のアウトライン化でハイフンを含む props に有効な束縛名を使う（[#28111](https://github.com/oxc-project/oxc/pull/28111)）

> [!quote] Before
> `enableJsxOutlining` で、`data-testid` や `aria-label` のような属性名をそのまま束縛名に使い、`const { "data-testid": data-testid } = t0` という不正な出力になっていた（`result.errors` は空。#26288、上流の facebook/react#36218）。

> [!success] After
> 属性名から有効な識別子を作る（`data-testid` → `dataTestid`。空・数字で始まる・予約語なら `_` を前に付ける）。アウトラインしたコンポーネントの中の JSX の属性は元の名前のままなので、描画される DOM は変わらない。

📦 oxlint_v1.90.0 · トピック: [[repos/oxc-project-oxc/topics/React-Compiler|React-Compiler]]

### Minifier: 短縮形の代入先でデフォルト値を保つ（[#28183](https://github.com/oxc-project/oxc/pull/28183)）

> [!quote] Before
> 代入パターンの `{ a: a }` を `{ a }` に書き換える処理が `a: a = b` にも一致し、初期化子を付けずに短縮形を作っていた。`({ x: x = f() } = o)` が `({ x } = o)` になり、`o.x` が `undefined` でも `f()` が呼ばれなかった。

> [!success] After
> 初期化子を短縮形に移し、`({ x = f() } = o)` と出力する。`runtime.snap` の `obj-prop-elem-init-*` の失敗 21 件のうち 9 件の原因だった。

📦 oxlint_v1.90.0 · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

### Minifier: 負の数・有限でない数のキーの角かっこを保つ（[#27855](https://github.com/oxc-project/oxc/pull/27855)）

> [!quote] Before

### transformer_plugins: 参照が残っていれば素の inject を残す（[#26965](https://github.com/oxc-project/oxc/pull/26965)）

> [!quote] Before
> `Symbol` と `Symbol.iterator` の両方を inject に設定していると、メンバーの形の inject が置き換わった時点で素の `Symbol` の inject を落としていた。そのため `typeof Symbol` や `Symbol("x")` はグローバルを参照したままだった（#26928。esbuild・`@rollup/plugin-inject` は 3 つとも置き換える）。

> [!success] After
> 置き換えたメンバー式の根の識別子の `ReferenceId` を記録し、それ以外の未解決の参照が残っていれば素の inject を残す。`Buffer.isBuffer('foo')` だけなら従来どおり `Buffer` の import を足さない。

### semantic: 巻き上げる `var` とブロック内の型の束縛を分ける（[#27936](https://github.com/oxc-project/oxc/pull/27936)）
