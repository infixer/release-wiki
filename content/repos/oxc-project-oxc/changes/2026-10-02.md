## 新機能

### Minifier が同じモジュールからの import と export をまとめるように（[#25533](https://github.com/oxc-project/oxc/pull/25533)）

> [!tip] 何ができるようになったか
> 同じモジュールから import した名前をそのまま export している場合、`export ... from` の 1 文にまとめる（issue [#13047](https://github.com/oxc-project/oxc/issues/13047)）。namespace と名前付き指定子の組み合わせなど、`import` では書けても `export` では書けない形はまとめない。
>
> - **例**: `import { b, g } from "./res.js"; export { g as load_css, b as start };` → `export { g as load_css, b as start } from "./res.js";`

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

### Minifier が同じモジュールからの import 文をまとめるように（[#25534](https://github.com/oxc-project/oxc/pull/25534)）

> [!tip] 何ができるようになったか
> 同じモジュールからの互換性のある import 宣言を 1 つにまとめる。間に別モジュールの import が挟まっていてもまとめる。
>
> - **例**: `import { b } from "./res.js"; import { g } from "./res.js";` → `import { b, g } from "./res.js";`
> - **まとめない場合**: import attributes・phase・type/value の違い、namespace 指定子があるとき。source phase の import も別のまま残す
> - 複数の default 束縛は名前付きの `default` import としてまとめる

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

### Minifier がビット演算の二項式を簡約するように（[#27107](https://github.com/oxc-project/oxc/pull/27107)）

> [!tip] 何ができるようになったか
> ビット演算の二項式について、足りていなかった最適化を実装した。
>
> - `(a OP b) | 0` → `a OP b`
> - `a & 0xffffffff` → `a | 0`

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

### `unicorn/no-useless-switch-case` にサジェスチョンを実装（[#27245](https://github.com/oxc-project/oxc/pull/27245)）

## 変更・修正

### スクリプトでのモジュール構文をパーサーで拒否するように（[#27220](https://github.com/oxc-project/oxc/pull/27220)）

> [!quote] Before

> [!success] After

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/パーサー|パーサー]]

### TypeScript の型メンバーの区切りを検証するように（[#27222](https://github.com/oxc-project/oxc/pull/27222)）

> [!quote] Before
> `type T = { (): void next: string }` のように、カンマやセミコロンなしで同じ行に並んだ型メンバーを診断なしで受け付けていた。

> [!success] After
> TypeScript の `parseTypeMemberSemicolon` と同じく ASI のチェックを行い、区切りの無いメンバーは改行・`}`・EOF の前で終わっていなければエラーにする。カンマ・セミコロン・改行・閉じかっこで区切る正しいコードは従来どおり受け付ける。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/パーサー|パーサー]]

### 型に依存するタプルの rest の診断（TS1265・TS1266）を削除（[#27234](https://github.com/oxc-project/oxc/pull/27234)）

> [!quote] Before
> パーサーが綴りだけで `Array` を判定していたため、`type X<Array extends unknown[]> = [...Array, ...Array];` のような正しいコードにも TS1265 / TS1266 を報告していた。

> [!success] After
> この 2 つの診断はタプルの rest 要素の解決済みの型に依存し、パーサーでは正しく判定できないため、構文ベースの部分的な報告をやめてチェックごと削除した。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/パーサー|パーサー]]

### `quoteProps: consistent` を分割代入パターンと計算キーにも正しく適用（[#27216](https://github.com/oxc-project/oxc/pull/27216)）

> [!quote] Before
> オブジェクトの分割代入・代入パターンには一貫したクォートが適用されず、計算キー（と TS の enum）も兄弟のキーにクォートが要るかの判断に含めていた（issue [#27213](https://github.com/oxc-project/oxc/issues/27213)、[#27214](https://github.com/oxc-project/oxc/issues/27214)）。

> [!success] After
> 分割代入・代入パターンにも一貫したクォートを適用し、代入パターン内のクォート付きキーも正規化する。計算キーと TS の enum は判断から除外する。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### 埋め込みテンプレートのレイアウトをソースの形ではなく AST から決めるように（[#27218](https://github.com/oxc-project/oxc/pull/27218)）

> [!quote] Before
> 唯一の引数やアロー関数の本体になっている埋め込みテンプレート（`` css`...` `` など）のレイアウトをソースの形で決めていたため、同じ入力でも元の書き方でレイアウトが変わり、冪等でない場合があった（issue [#21908](https://github.com/oxc-project/oxc/issues/21908)）。

> [!success] After
> AST から埋め込み対象を判定する（中身の整形の成否に関係なく）。唯一の引数なら最後の引数の展開（1 行目が収まれば hug、収まらなければ引数を改行）、アロー関数の本体なら hug（空白が意味を持つ HTML を除く）。`embeddedLanguageFormatting: off` は従来どおりそのまま出力し、空白だけの埋め込みテンプレートもそのまま残す（Prettier と同じ）。

> [!warning] 出力が変わることがある
> ecosystem-ci では `(entry) => html`…`` のアロー関数の本体が改行される差分が多く出たが、Prettier 3.9.9 と同じ挙動。差異は `apps/oxfmt/DIVERGENCES.md` にも記録されている。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### 除外したディレクトリの下のファイルを否定パターンで再び含めないように（[#27237](https://github.com/oxc-project/oxc/pull/27237)）

> [!quote] Before
> `.prettierignore` に `vendor/` と `!vendor/keep.ts` があると、`oxfmt .` ではスキップされるのに、`oxfmt vendor/keep.ts`・`--stdin-filepath vendor/keep.ts`・LSP（保存時の整形）では整形されていた。`.oxfmtrc.json` の `ignorePatterns` でも同じだった。

> [!success] After
> 明示的なパス・`--stdin-filepath`・LSP でも、親ディレクトリが除外されていれば否定パターンで再び含めない。ディレクトリの走査・Git・Prettier と同じ挙動になった。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### `unicorn/no-zero-fractions` の自動修正で区切り文字付き・巨大な整数をかっこで囲むように（[#27206](https://github.com/oxc-project/oxc/pull/27206)）

> [!quote] Before
> `1_000.0.toFixed(2)` や 20 桁の整数 `10000000000000000000.0.toFixed(2)` の修正でかっこが付かず、`1_000.toFixed(2)` のような構文エラーのコードになっていた。

> [!success] After
> 修正後のテキストが数字と `_` だけならかっこで囲む（`(1_000).toFixed(2)`）。eslint-plugin-unicorn の判定と同じ。`1e10.toFixed()` のような指数形式は従来どおりかっこを付けない。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Linterルール個別修正|Linterルール個別修正]]

### `unicorn/numeric-separators-style` が区切り位置の誤った BigInt を報告するように（[#27207](https://github.com/oxc-project/oxc/pull/27207)）

> [!quote] Before
> BigInt リテラルは長さだけを比べていたため、`12_34_567n` や `0xA_BCDn` のように区切りの数は同じで位置が違うものを報告しなかった。

> [!success] After
> 数値リテラルと同じく、整形後のテキストを元のテキストと比べる。`12_34_567n` → `1_234_567n`、`0xA_BCDn` → `0xAB_CDn` に修正される。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Linterルール個別修正|Linterルール個別修正]]
