## 変更・修正

### 外側で `arguments` が宣言されていても、通常の関数の暗黙の `arguments` を外側に解決しない（[#26929](https://github.com/oxc-project/oxc/pull/26929)）

> [!quote] Before
> 外側のスコープで `arguments` が宣言されていると、内側の通常の関数の暗黙の `arguments` がその宣言に解決されていた。そのため sloppy モードで `{ let arguments = 1; return function () { return arguments[0]; }; }` のようなコードを Minifier が `return 1[0];` に書き換え、`2` ではなく `undefined` を出力していた。

> [!success] After
> `oxc_semantic` は、通常の関数の暗黙の `arguments` への参照を未解決のままにする（明示的なローカル束縛、アロー関数での引き継ぎ、型だけの解決は従来どおり。関数式自身の名前は飛ばす）。async-to-generator の変換も名前で探さずに未束縛の参照を作る（出力される JavaScript は変わらない）。[#26933](https://github.com/oxc-project/oxc/pull/26933) を取り込んでいる。

📦 oxlint_v1.88.0 · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

### Minifier: mapped arguments を通して見える引数への書き込みを保つ（[#27494](https://github.com/oxc-project/oxc/pull/27494)）

> [!quote] Before
> 単純な引数リストを持つ非 strict の関数では `arguments[i]` が引数 `i` の別名になるが、`var` や関数宣言で引数を再宣言すると通常のローカル変数として扱い、`arguments` から見える書き込みを削除・インライン化していた（`(function (a) { var a; console.log(a = "foo", arguments[0]); })("bar")` が `foo bar` を出力）。`compress: { unused: false }` でも、`try { var x = foo(); throw x } catch {}` が `try { throw foo(); } catch {}` になり、後のスクリプトが読めるグローバルを消していた。

> [!success] After
> こうした関数の引数を観測可能として扱い、未使用コードの除去と 1 回だけ使う変数のインライン化で書き込みを残す（`unused` オプションに関係なく適用）。スクリプトのソースは常にこの状態を持つ。現状は `arguments` を使わない関数も含めて保守的に扱い、[#27525](https://github.com/oxc-project/oxc/pull/27525) で対象を絞る予定。

📦 oxlint_v1.88.0 · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

### `Math.cbrt` の負の数を `NaN` に畳み込まない（[#27621](https://github.com/oxc-project/oxc/pull/27621)）

> [!quote] Before
> 定数評価の `try_fold_roots` が `sqrt` と `cbrt` を一緒に扱い、負の引数ではすべて `NaN` を返していた。`Math.cbrt(-8)`・`Math.cbrt(-2)`・`Math.cbrt(-Infinity)` や、定数経由の `const n = -8; Math.cbrt(n)` も `NaN` になっていた（oxc-minify 0.153.0 の既定オプション）。

> [!success] After
> 早期の `NaN` は `Math.sqrt` だけに適用する。`Math.cbrt(-Infinity)` は `-Infinity`（`-1/0`）に、その他の負の数は整数になる場合だけ畳み込む（`Math.cbrt(-8)` → `-2`）。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/Minifier|Minifier]]

### `sort-keys`: `natural: true` の比較を ESLint に揃える（[#27579](https://github.com/oxc-project/oxc/pull/27579)）

> [!quote] Before
> `natural: true` で、`{ a12, a100 }`・`{ item1Name, item10Name }`・`{ "/user/list", "/user-list" }` のような正しく並んだオブジェクトを報告していた。比較が全順序になっておらず（`a12 > a100 > a20 > a12`）、自動修正の並べ替えで panic することがあった。

> [!success] After
> 比較を ESLint の `natural-compare` の移植に置き換えた（UTF-16 コード単位で比較し、数字の並びは数値で比較）。自動修正は安定ソートになり、20 個を超えるプロパティを持つオブジェクトで重複キーを入れ替えて勝つ値が変わる問題もなくなった。ルールのテストはすべて ESLint 10.1.0 と一致する。残る差異は、大文字小文字を区別しないモードで ASCII だけを小文字化する点と、2^53 を超える数字の並びを正確に比較する点。

📦 oxlint_v1.88.0 · トピック: [[repos/oxc-project-oxc/topics/Linterルール個別修正|Linterルール個別修正]]
