期間: 2026-10-30 〜 2026-11-02 · PR 107 件（新機能 5 / 変更・修正 25 / その他 77）· Release なし

この期間の目玉は、Oxfmt の HTML 整形のネイティブ化（[#28273](https://github.com/oxc-project/oxc/pull/28273)、破壊的変更）。`.html` と html-in-js などの埋め込み HTML を、Prettier ではなく新しいクレート `oxc_formatter_htmlish` で整形するようになった。ほかに `oxc_lexer` で実行時の CPU 機能検出に向けた「CPU 機能セットごとのコンパイル」の作業が大量に入り、パーサー・正規表現・linter ルールの細かな修正も多い。いずれも未リリース。

## 新機能

### Oxfmt: `parser:html` のファイルを `oxc_formatter_htmlish` でネイティブに整形（[#28273](https://github.com/oxc-project/oxc/pull/28273)）

> [!tip] 何ができるようになったか
> これまで `.html` と、JS・Markdown などに埋め込まれた HTML（html-in-js など）は Prettier で整形しており、そのために JS を動かす必要がありオーバーヘッドになっていた。今後はすべて `oxc_formatter_htmlish` がネイティブに整形し、このオーバーヘッドが無くなる（#28263 を解決）。
>
> - **使い方**: 特別な設定は不要（`parser:html` のファイルと埋め込み HTML が自動的に対象）
> - **嬉しい場面**: HTML や html-in-js を含むプロジェクトを速く整形したいとき

> [!warning] 移行が必要
> タイトルに `!`（破壊的変更）が付いている。同時に Prettier のバグや一貫しない挙動も直しているため、Prettier との出力の違いは `DIVERGENCES.md` を参照すること。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/HTMLフォーマッタ|HTMLフォーマッタ]]、[[repos/oxc-project-oxc/topics/Oxfmt|Oxfmt]]

### `oxc_formatter_htmlish`: HTML-ish フォーマッタの `Html` バリアントを実装（[#28272](https://github.com/oxc-project/oxc/pull/28272)）

> [!tip] 何ができるようになったか
> 新しいクレート `crates/oxc_formatter_htmlish` を追加し、HTML-ish フォーマッタの `Html` バリアントを実装した（#28263 の一部）。オプション（`options.rs`）・整形本体（`format.rs`）・実行例（`examples/htmlish_formatter.rs`）を含み、変更ファイルは 123 件。
>
> - **使い方**: Oxfmt から使われる（[#28273](https://github.com/oxc-project/oxc/pull/28273)）
> - **嬉しい場面**: Oxfmt で HTML を整形するとき

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/HTMLフォーマッタ|HTMLフォーマッタ]]

### HTML フォーマッタ: 開始タグを省略した `html`・`head`・`body` の終了タグを整形（[#28388](https://github.com/oxc-project/oxc/pull/28388)）

> [!tip] 何ができるようになったか
> HTML では一部のタグの開始タグを省略して書ける。開始タグを省略した `html`・`head`・`body` の終了タグも整形できるようにした（フィクスチャ `omitted-element-end-tags.html` を追加）。
>
> - **使い方**: 特別な設定は不要
> - **嬉しい場面**: 開始タグを省略した HTML を整形するとき

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/HTMLフォーマッタ|HTMLフォーマッタ]]

### Oxfmt: 動的なタグ名を閉じる html-in-js テンプレートに対応（[#28389](https://github.com/oxc-project/oxc/pull/28389)）

> [!tip] 何ができるようになったか
> HTML フォーマッタは `htm` の特別な閉じタグ `<//>` に対応しているため、`` html`<${For} each=${...}> ... </${For}>` `` のように動的なタグ名を `</${For}>` で閉じる書き方にも対応した。違いは `DIVERGENCES.md` に追記された。
>
> - **使い方**: 特別な設定は不要
> - **嬉しい場面**: `html` タグ付きテンプレートで `${Component}` をタグ名に使うとき

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/HTMLフォーマッタ|HTMLフォーマッタ]]

### linter ルールごとのメモリ割り当ての計測（[#28470](https://github.com/oxc-project/oxc/pull/28470)）

> [!tip] 何ができるようになったか
> `tasks/track_memory_allocations` に、linter のルールごとの割り当て計測を追加した（#27477 の代わり）。各ルールを個別に実行し、前後のヒープサイズの差と、システム・アリーナの割り当て回数を比べる。linter の変更は最小限（`context/host.rs`）。
>
> - **使い方**: ローカル専用のオプトイン機能（CI では自動で確認しない。手順は `tasks/track_memory_allocations/README.md`）
> - **嬉しい場面**: どの lint ルールが多く割り当てているかを調べたいとき

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/カバレッジ・テスト基盤|カバレッジ・テスト基盤]]

## 変更・修正

### レキサー: 実行時の CPU 機能検出に向けて、関数を CPU 機能セットごとにコンパイル（25 件）

[#28613](https://github.com/oxc-project/oxc/pull/28613)、[#28615](https://github.com/oxc-project/oxc/pull/28615)〜[#28623](https://github.com/oxc-project/oxc/pull/28623)、[#28625](https://github.com/oxc-project/oxc/pull/28625)〜[#28635](https://github.com/oxc-project/oxc/pull/28635)、[#28643](https://github.com/oxc-project/oxc/pull/28643)〜[#28646](https://github.com/oxc-project/oxc/pull/28646)

> [!quote] Before
> `lex_raw` 全体は CPU 機能セットごとに別の経路になっていたが、その下で呼ばれる多くの関数は 1 つしかコンパイルされず、CPU の型（`cpu`）も受け取っていなかった。

> [!success] After
> 実行時の CPU 機能検出への移行の一部として、`cpu_versions!` を次の関数に付け、呼び出し元から `cpu` を渡すようにした（多くはまだ `cpu` を SIMD に使っていない）。
>
> - `carve`・`carve_js`・`carve_jsx`、コメントの字句解析（`carve/comments.rs`）、`find_line_terminator`
> - JSX の山かっこの判別（`jsx_over_type_params`・`ts_angle_verdict`・`jsx_over_generic`）と JSX の名前・trivia の補助関数
> - `Lanes` の文字列・テンプレート・atom・数値のメソッドと cooking（`cook` など）、`Lanes::clear`、`write_sentinels`、`Lexer::ensure`
> - 数値の解析（`parse_number` など）、スカラーのスキャナ（`scan_quoted`・`scan_regex` など）、`utf8_seq_check`
> - `disambiguate` の関数（演算子位置の判定、`>` の連続の分割、型引数の判定、前方の括弧スキャン、`Tokens`・`Closers`・`DisambiguateState` のメソッド、後方のトークン走査、`kw_match_at`、`bytes.rs` のバイトスキャン）
>
> 一度しかコンパイルしない Level 3 や cold な関数（`lex_html_open_comment` など）とテストは `BASELINE` を渡す。`cook_short` は 2 つの cfg 版から `cpu_select!` で振り分ける `#[inline(always)]` のディスパッチャーに置き換え、`cook_short_avx2` は `#[target_feature]` 付きで `Avx2` を受け取るため、メモリに触れない intrinsics の周りの `unsafe` が不要になった。インライン化が変わった箇所もあり、x86_64 では AVX2 版の `gt_run_split` が約 950 命令から約 3,000 命令に増え、Level 3 の `Walk::step` は約 1,950 命令から約 1,140 命令に縮んだ。aarch64 では `carve_jsx` の `classify` 呼び出しが 16 回から 12 回になり、約 200 命令短くなった。

⏳ 未リリース · トピック: [[repos/oxc-project-oxc/topics/レキサー基盤|レキサー基盤]]
