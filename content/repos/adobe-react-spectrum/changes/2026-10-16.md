## 変更・修正

### `window.screen` が無い環境で import 時に例外を投げないように（[#10774](https://github.com/adobe/react-spectrum/pull/10774)）

> [!quote] Before
> React Native の Jest 環境（jest-expo）では `window` がグローバルオブジェクトで `screen` を持たないため、3.53.0 で入ったテスト用の orientation の shim が `Reflect.has(window.screen, 'orientation')` を `undefined` に対して呼び、`react-aria` の import 時に `TypeError: Reflect.has called on non-object` を投げていた（#10760）。

> [!success] After
> shim の条件に `window.screen != null` の確認を足した（#10743 の確認の一段上）。`window.screen` を持たない Deno のようなランタイムでも import できる。

⏳ 未リリース · トピック: [[repos/adobe-react-spectrum/topics/キーボード操作|キーボード操作]]

### TokenField でユーザーのキャレット移動を毎回 `onChange` で通知（[#10766](https://github.com/adobe/react-spectrum/pull/10766)）

> [!quote] Before
> `setTokenFieldSelection` が「選択が変わったときだけ設定する」確認より前にプログラムによる変更のフラグを立てていた。ブラウザが既に持つ位置と同じため `setBaseAndExtent` が省かれると、フラグを消費する `selectionchange` が来ず、次の本物の `selectionchange` が捨てられた。そのため `onChange` はキャレット移動 2 回に 1 回しか呼ばれず、`value.selectedRange` が DOM の選択より 1 つ遅れていた（#10764）。

> [!success] After
> `setBaseAndExtent` を実際に呼んだときだけフラグを立てる。issue にある WebKit だけの Shift+ArrowLeft でトークンをまたぐ挙動は別の不具合とみられ、この PR では扱っていない。

⏳ 未リリース · トピック: [[repos/adobe-react-spectrum/topics/TokenField|TokenField]]

### ESM ビルドのスタイルマクロの実行エラーを修正（[#10785](https://github.com/adobe/react-spectrum/pull/10785)）

> [!quote] Before
> スタイルマクロの ESM ビルド（`@react-spectrum/s2@1.8.1` の `style-macro.mjs`）を実行すると `Error evaluating macro: $kLxT8$propertiesmjs1 is not defined` で失敗していた（ビルドに使う Parcel v2 の不具合とみられる）。

> [!success] After
> 回避策として、namespace import の代わりに default import を使う。

⏳ 未リリース · トピック: [[repos/adobe-react-spectrum/topics/スタイルマクロ|スタイルマクロ]]
