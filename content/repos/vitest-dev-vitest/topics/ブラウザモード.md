## 概要

Vitest のブラウザモード（`packages/vitest/src/node/plugins/browserLoader.ts` など）。ブラウザ用のサーバーはテストの実行が始まるまで `listen` しないため、VS Code 拡張のようにテストを収集だけして実行しない使い方でも、optimizer の処理が途中で打ち切られてエラーになることがない。ブラウザのテストはプロジェクトの Vite サーバーで配信され、`consumer: 'client'` を明示したカスタム環境は `client` と同様に設定がそのまま保たれる（`optimizeDeps` を失わない）。モックのパスはルートの境界（`withTrailingSlash(root)`）で判定され、ブラウザモードではモックのインターセプターの警告は出ない。キャンセル中のページのクラッシュは無視され、リトライしたテストの `toMatchScreenshot` も正しい参照画像を使う。Chromium でのモックのルートのインターセプトの競合（モックがランダムに効かない #8339）は、最初の `vi.mock` 登録時にコンテキストごとに 1 回インターセプトを有効にし、プローブで有効化を確認してから登録を完了することで解消された。ブラウザクライアントが使う API トークンはアトミックに公開され、並行プロセスでも同じトークンを使う。`toHaveTextContent` は引数なしで使える。v5.0.3 には上記のうち 2026-09-28〜09-30 に取り込んだ修正が収録された。API から渡したブラウザのオプションは、設定ファイルに browser の設定が無くてもルートの設定に適用される。カスタムコマンドの RPC は forks・threads プールと同じく `undefined` の引数をどの深さでも保持する。トレースのスナップショットはロケーターに一致したすべての要素を記録する（`selectorIds: number[]`。アクションや `expect.element` は従来どおり strict）。ブラウザでの V8 カバレッジは、テストファイル間でガベージコレクションを行いメモリリークを防ぐ。セットアップファイルの `vi.mock` が、テストファイルの通常の `import` に効かなかった Vitest 5 の退行は、ランナーが import 前にモックの準備を待つことで直った。テストを表示する iframe の下の 4px の隙間による余分なスクロールも解消した（いずれも未リリース）。ブラウザのインスタンスは 1 つが 1 ワーカーとして扱われ、同時に開くのは `maxWorkers` 個まで、ページ数も `maxWorkers` を上限に共有される（Node のプールと同じく `maxWorkers` は同時に実行するファイル数を意味する）。ウォームなブラウザはプロジェクト間で再利用され、多数のプロジェクトでのメモリ使用量が大きく減った。CDP セッションはテスターごとに 1 つ開く。`vi.unmock` / `vi.doUnmock` で Playwright のルートが正しく消え、モックしたモジュールを読み込まないファイルの登録待ちのモックも次のファイルに漏れない（いずれも未リリース）。v5.0.5 では、ルート・プロジェクトのサーバーとも Vite の既定の `fs.deny`（`.env`・`*.pem`・`.git`）と API トークンのファイル（`.vitest-secret-token`）を拒否するよう直った。ブラウザ用サーバーは作成時にプラグインの `buildStart` を実行し、`--changed` などで先に変換される CSS モジュールが `vite:css` で失敗しない。テストが発行した（untrusted な）`pagehide` は無視され、閉じたセッションの遅れた接続は捨てられ、ブラウザの終了は 30 秒まで待つ。`browser.instances` を宣言した設定の `globalSetup` は全インスタンスで 1 回だけ実行される。トレースビューと Playwright の `browser.trace` は、ステップの位置を求めるときに最初の使えるフレームだけをソースマップで解決するようになり、タイムラインの収集が速くなった（未リリース）。
