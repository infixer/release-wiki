## 概要

Vitest のブラウザモード（`packages/vitest/src/node/plugins/browserLoader.ts` など）。ブラウザ用のサーバーはテストの実行が始まるまで `listen` しないため、VS Code 拡張のようにテストを収集だけして実行しない使い方でも、optimizer の処理が途中で打ち切られてエラーになることがない。ブラウザのテストはプロジェクトの Vite サーバーで配信され、`consumer: 'client'` を明示したカスタム環境は `client` と同様に設定がそのまま保たれる（`optimizeDeps` を失わない）。モックのパスはルートの境界（`withTrailingSlash(root)`）で判定され、ブラウザモードではモックのインターセプターの警告は出ない。キャンセル中のページのクラッシュは無視され、リトライしたテストの `toMatchScreenshot` も正しい参照画像を使う。Chromium でのモックのルートのインターセプトの競合（モックがランダムに効かない #8339）は、最初の `vi.mock` 登録時にコンテキストごとに 1 回インターセプトを有効にし、プローブで有効化を確認してから登録を完了することで解消された。ブラウザクライアントが使う API トークンはアトミックに公開され、並行プロセスでも同じトークンを使う。`toHaveTextContent` は引数なしで使える。v5.0.3 には上記のうち 2026-09-28〜09-30 に取り込んだ修正が収録された。API から渡したブラウザのオプションは、設定ファイルに browser の設定が無くてもルートの設定に適用される。カスタムコマンドの RPC は forks・threads プールと同じく `undefined` の引数をどの深さでも保持する。トレースのスナップショットはロケーターに一致したすべての要素を記録する（`selectorIds: number[]`。アクションや `expect.element` は従来どおり strict）。ブラウザでの V8 カバレッジは、テストファイル間でガベージコレクションを行いメモリリークを防ぐ。セットアップファイルの `vi.mock` が、テストファイルの通常の `import` に効かなかった Vitest 5 の退行は、ランナーが import 前にモックの準備を待つことで直った。テストを表示する iframe の下の 4px の隙間による余分なスクロールも解消した（いずれも未リリース）。ブラウザのインスタンスは 1 つが 1 ワーカーとして扱われ、同時に開くのは `maxWorkers` 個まで、ページ数も `maxWorkers` を上限に共有される（Node のプールと同じく `maxWorkers` は同時に実行するファイル数を意味する）。ウォームなブラウザはプロジェクト間で再利用され、多数のプロジェクトでのメモリ使用量が大きく減った。CDP セッションはテスターごとに 1 つ開く。`vi.unmock` / `vi.doUnmock` で Playwright のルートが正しく消え、モックしたモジュールを読み込まないファイルの登録待ちのモックも次のファイルに漏れない（いずれも未リリース）。v5.0.5 では、ルート・プロジェクトのサーバーとも Vite の既定の `fs.deny`（`.env`・`*.pem`・`.git`）と API トークンのファイル（`.vitest-secret-token`）を拒否するよう直った。ブラウザ用サーバーは作成時にプラグインの `buildStart` を実行し、`--changed` などで先に変換される CSS モジュールが `vite:css` で失敗しない。テストが発行した（untrusted な）`pagehide` は無視され、閉じたセッションの遅れた接続は捨てられ、ブラウザの終了は 30 秒まで待つ。`browser.instances` を宣言した設定の `globalSetup` は全インスタンスで 1 回だけ実行される。トレースビューと Playwright の `browser.trace` は、ステップの位置を求めるときに最初の使えるフレームだけをソースマップで解決するようになり、タイムラインの収集が速くなった（未リリース）。v5.1.0-beta.1（2026-10-19、プレリリース）では、`vi.mock` を import map のルールで実現するようになり（`browser.importMapMocks` で切り替え、HTTP キャッシュが効いたまま。mock の多いスイートで大幅に速い）、Testing Library の `pointer` API のサブセット（実験的）が加わり、トレースビュー（`browser.traceView`）は実験的扱いを外れて各ステップの aria スナップショットも記録する（`browser.traceView.ariaSnapshot: false` で無効）。操作と `expect.element` の待機中にフェイクタイマーを進めるようになり、既定のポートは Windows の予約範囲を避けて `63315` から `23315` に変わった。その後（未リリース）、テストが失敗したときにトレースのステップのタイムラインがターミナルにも表示されるようになり（HTML レポーター無しのトレースビューの警告も削除）、最適化された共有チャンクの判定（Vite 8 の Rolldown optimizer 対応）と `prepare` の時間の計測も直った。リトライ・繰り返しのあるテストの失敗時のスクリーンショットは試行ごとに `<test>-<repeat>-<retry>.png` で保存され、レポーターの出力ではスクリーンショットとトレースのタイムラインが試行ごとのエラーに対応付けられる。CLI のファイルのフィルターに一致するファイルの無いブラウザのプロジェクトは、ブラウザを事前起動しない（いずれも未リリース）。トレースビューには失敗したテストのトレースだけを残す `'failure-only'` モード（`browser.traceView: 'failure-only'` / `traceView.mode`）が加わり、成功するテストにはコストがかからない（`browser.traceView.enabled` は非推奨）。`page.viewport()` は UI モードで描画されていないページでも止まらず、プロバイダーのエラーではすぐに reject する（いずれも未リリース）。その後、`browser.traceView` の既定値が `'failure-only'` になり、設定しなくても失敗したテストはトレースを記録してターミナルにタイムラインを表示する。試行が終わった後に決着した操作・`expect.element` のトレースのエントリーは捨てられ、内部エラーで落ちない。`api.port: 0` で OS が空きポートを選ぶ（Vite 8.2.1 以降。いずれも未リリース）。

## 主な API・オプション

- `browser.traceView.mode` — トレースビューのモード。既定は `'failure-only'`（[#11766](https://github.com/vitest-dev/vitest/pull/11766)）。`'failure-only'` で失敗したテストのトレースだけを残す（`browser.traceView: 'failure-only'` とも書ける。`browser.traceView.enabled` は非推奨）（[#11612](https://github.com/vitest-dev/vitest/pull/11612)）
- `browser.importMapMocks` — import map によるモックを強制的にオン・オフ（既定は自動判定）
- `browser.traceView.ariaSnapshot` — トレースの各ステップで aria スナップショットを記録（既定で有効）
- `pointer`（`@vitest/browser` の操作 API。実験的）— Testing Library の `pointer` API のサブセット
