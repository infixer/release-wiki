## 概要

Vitest のブラウザモード（`packages/vitest/src/node/plugins/browserLoader.ts` など）。ブラウザ用のサーバーはテストの実行が始まるまで `listen` しないため、VS Code 拡張のようにテストを収集だけして実行しない使い方でも、optimizer の処理が途中で打ち切られてエラーになることがない。ブラウザのテストはプロジェクトの Vite サーバーで配信され、`consumer: 'client'` を明示したカスタム環境は `client` と同様に設定がそのまま保たれる（`optimizeDeps` を失わない）。モックのパスはルートの境界（`withTrailingSlash(root)`）で判定され、ブラウザモードではモックのインターセプターの警告は出ない。キャンセル中のページのクラッシュは無視され、リトライしたテストの `toMatchScreenshot` も正しい参照画像を使う。Chromium でのモックのルートのインターセプトの競合（モックがランダムに効かない #8339）は、最初の `vi.mock` 登録時にコンテキストごとに 1 回インターセプトを有効にし、プローブで有効化を確認してから登録を完了することで解消された。ブラウザクライアントが使う API トークンはアトミックに公開され、並行プロセスでも同じトークンを使う。`toHaveTextContent` は引数なしで使える。v5.0.3 には上記のうち 2026-09-28〜09-30 に取り込んだ修正が収録された。API から渡したブラウザのオプションは、設定ファイルに browser の設定が無くてもルートの設定に適用される。カスタムコマンドの RPC は forks・threads プールと同じく `undefined` の引数をどの深さでも保持する。トレースのスナップショットはロケーターに一致したすべての要素を記録する（`selectorIds: number[]`。アクションや `expect.element` は従来どおり strict）。ブラウザでの V8 カバレッジは、テストファイル間でガベージコレクションを行いメモリリークを防ぐ。セットアップファイルの `vi.mock` が、テストファイルの通常の `import` に効かなかった Vitest 5 の退行は、ランナーが import 前にモックの準備を待つことで直った。テストを表示する iframe の下の 4px の隙間による余分なスクロールも解消した（いずれも未リリース）。
