## 概要

実行するテストを絞り込む仕組み（`--changed` / `--related` によるソース・git の変更での絞り込み、位置指定フィルタ）。`--changed` で実行すると、影響を受けたテストの数と総数が表示されるようになった（experimental）。`--changed` での git のエラーや不正な位置指定フィルタは、黙って無視・成功扱いにせず、エラーを表示して終了コード 1 で終わる。`--changed` の影響範囲には、テストファイルの import グラフに加えて、セットアップファイル・グローバルセットアップ・カスタムランナー／環境・設定ファイルの依存・`@vitest-environment` コメント・`__mocks__` のファイルも含まれ、モックに置き換えられたモジュールは除外される。ソースでの絞り込みも transform service 経由でモジュールを変換するため、`fsModuleCache` を使える。新しい `experimental.recordDependencies` を有効にすると、`--changed` / `related` はモジュールグラフを静的に解析する代わりに、前回実行したファイルの依存関係のキャッシュと比べて実行するテストを決める。実行するテストが無いときは変換フェーズを省けるため、規模によっては大幅に速い（未リリース）。v5.0.5 では、`--changed` が git の `-z` 出力を使い、非 ASCII 文字や `"` を含む（git が引用符を付ける）ファイル名も正しく扱う。ブラウザモードで CSS モジュールの変換が失敗し、CSS を import するテストがすべて選ばれてしまう問題も直った。`--changed` で絞り込んだ後、`isolate: false` のワーカーでセットアップファイルが無効化されず再実行されない問題が直った（モジュールグラフに url ではなくファイルパスが残っていたため。未リリース）。v5.1.0-beta.1（プレリリース）では、前回失敗したテストだけを実行する `--last-failed`（`results.json` の `failedTests` を使い、名前で選ぶので追加・移動に強い）と、`git` 無しで前回からの依存の変更を見てテストを選ぶ `--since-last-run`（キャッシュした依存ツリーと新しい `mtime` VCS プロバイダーを使用）が加わった。その後（未リリース）、削除されたファイルを静的に import するテストも実行対象になった（SSR のモジュールグラフで削除されたファイルへのつながりが落ちていたため）。

## 主な API・オプション

- `--changed` — git の変更に関係するテストだけを実行（影響を受けたテスト数と総数を表示）
- `--related` — 指定したソースに関係するテストだけを実行
- `--last-failed` — 前回失敗したテストだけを実行（CLI 専用）
- `--since-last-run` — 前回の実行以降に依存が変わったテストを実行（`git` 不要）
- `TestSpecification.testNames` — テスト名で絞り込むフィルター
