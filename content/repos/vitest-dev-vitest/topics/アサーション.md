## 概要

`expect` の matcher 実装。Jest 互換の非対称マッチャー（`expect.arrayContaining` など）やカスタムテスターまわりの、細かな比較ロジックの不具合修正が中心。ブラウザモードの `toMatchScreenshot` は、リトライしたテストでも正しい参照画像を使う。v5.0.3 では、`expect.extend` で作った非対称マッチャー（`expect.toBeOneOf` など）にも外側の matcher の等価性テスターが渡されるようになった。`toContainEqual`・`toHaveProperty`・`toBeOneOf`・`toHave(Last|Nth)?(Returned|Resolved)With`・`toThrow(非対称マッチャー)` も `toEqual` と同じテスター（`iterableEquality` とカスタムテスター）で比較し、`Map`・`Set` の中身を見る。`pretty-format` は boxed symbol（`Object(Symbol())`）も表示できる。ブラウザモードの `toHaveTextContent` は引数を省略でき、テキストがあること（`.not` なら空であること）を検証する。chai 形式の `expect(spy).to.have.returned(value)` は、`toHaveReturnedWith(value)` と同じく値を確認する。スナップショットでは改行コードの違いを扱うよう修正された（#7305。未リリース）。`Chai` 名前空間を使う d.ts のチャンクには `/// <reference types="chai" />` が付くようになった（未リリース）。型付き配列の等価比較は添字ごとの 1 つのループになり、2 MiB の `toEqual` が約 1.5 秒から約 125 ms になった例がある。`toMatchScreenshot` は、スクリーンショットが終わった後に安定待ちのタイマーを残してプロセスを引き留めないよう直った（いずれも未リリース）。`expect.poll` の `message` は、matcher の失敗だけでなく、コールバックの throw やタイムアウトを含むすべてのエラーに付く（未リリース）。
`expect.soft(...).resolves` / `.rejects` の失敗でも、エラーの位置とコードが表示される（未リリース）。
v5.1.0 で、失敗したスナップショットを対話的にレビューできるようになった（UX は Insta の `review` コマンドが参考）。レビューの更新は `SnapshotState` が `--update` で書き込む内容をそのまま使うため、`--update` と結果が食い違わない。
`objectContaining` / `arrayContaining` の diff は、確認しないキーを変更なしの行として、足りない要素を削除行として表示し、失敗時はラベル無し（`{`）で表示する。`isolate: false` でコンテキストの `expect` がファイルとフィクスチャを保持し続けるリークも直った（いずれも未リリース）。

## 主な API・オプション

- `expect.extend` の非対称マッチャー — 外側の matcher の等価性テスターを受け取る
- `toHaveTextContent(text?)` — browser。引数なしでテキストの有無を検証
- `to.have.returned(value)` — chai 形式。`toHaveReturnedWith(value)` と同じ
