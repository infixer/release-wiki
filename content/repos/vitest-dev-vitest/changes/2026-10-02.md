## 新機能

### `--changed` の実行時に、影響を受けたテストの数と総数を表示（experimental）（[#11424](https://github.com/vitest-dev/vitest/pull/11424)）

> [!tip] 何ができるようになったか
> `--changed` で実行したときに、変更の影響を受けたテストが何件あり、全体が何件かをレポーターが表示するようになった（experimental）。
>
> - **使い方**: `vitest --changed`
> - **嬉しい場面**: 変更に関係するテストだけを流したとき、全体のうちどれだけを実行したかを確認したいとき

⏳ 未リリース · トピック: [[repos/vitest-dev-vitest/topics/テストの絞り込み|テストの絞り込み]]

### browser: `toHaveTextContent` を引数なしで使えるように（[#11425](https://github.com/vitest-dev/vitest/pull/11425)）

> [!tip] 何ができるようになったか
> ブラウザモードの `toHaveTextContent` の `text` 引数が省略可能になった（#8997）。
>
> - **使い方**: `expect(el).toHaveTextContent()` は要素に何らかのテキストがあることを、`expect(el).not.toHaveTextContent()` は空であることを検証する
> - **変更点**: 型定義（`jest-dom.d.ts`）とドキュメントも更新された

### vm: Vite の環境をまたいでスクリプトを再利用しないように（[#11395](https://github.com/vitest-dev/vitest/pull/11395)）

> [!quote] Before
> vm プールは、インライン化したモジュールのコンパイル済みスクリプトをモジュール ID だけをキーにワーカーごとにキャッシュしていた（#10744）。1 つのワーカーが `jsdom`（`client` 環境）と `node`（`ssr` 環境）のファイルを両方実行すると、同じ ID でも変換結果が違う（optimized deps が `deps/` と `deps_ssr/` に解決されるなど）のに、もう一方の環境のコードが評価されていた。その結果、`vi.mock` が効かない、モジュールが二重になり `instanceof` が失敗する、といった問題が、ファイルがどのワーカーに割り当てられるかに応じて起きていた（#11289）。

> [!success] After
> キャッシュにコードも保存し、コードが一致するときだけスクリプトを再利用する（外部化されたモジュール用の `CodeCache` と同じ方式）。PR の検証では、5.0.2 で 1 回あたり 13〜31 件失敗していた実際のスイートが 3 回中 3 回成功した。

📦 v5.0.3 · トピック: [[repos/vitest-dev-vitest/topics/プール|プール]]

### expect: `expect.extend` の非対称マッチャーにも現在の等価性テスターを渡す（[#11401](https://github.com/vitest-dev/vitest/pull/11401)）

> [!quote] Before
> #6825 で外側の matcher の等価性テスターが組み込みの非対称マッチャーには渡されるようになったが、`expect.extend` で作ったもの（`expect.toBeOneOf` など）には渡されていなかった。`expect(new Set()).toEqual(expect.toBeOneOf([new Set(['x'])]))` が通っていた。

> [!success] After
> `expect.extend` の非対称マッチャーにも渡すため、上の例は失敗するようになる。非対称でない `expect(new Set()).toBeOneOf([new Set(['x'])])` はまだ通る（#11296 で対応予定）。ドキュメント（カスタム matcher の拡張）にも追記された。

### browser: モックのルートのインターセプトの競合を解消（[#11083](https://github.com/vitest-dev/vitest/pull/11083)）

> [!quote] Before
> ブラウザモード（Chromium）で、`vi.mocked(...).mockX is not a function` や `[Function x] is not a spy` がランダムに出ていた（#8339）。モックのルートはテストファイルごとに追加・解除されるため、ファイルの切り替わりでルート数が 0 になり Playwright が CDP のリクエストインターセプトを切り替える。Chromium は `Fetch.enable` をインターセプトが有効になる前に応答するため、その隙間に読み込まれたモジュールは本物のまま残っていた。

> [!success] After
> 最初の `vi.mock` 登録時に、コンテキストごとに 1 回だけインターセプトを有効にする。常設のプローブ用ルートでルート数を 0 にせず、プローブ URL の `fetch()` がルートのヘッダー付きで返ってから登録を完了するので、モックした import の前にインターセプトが確実に有効になる。5 秒以内に確認できなければ、黙ってモックが効かないのではなく issue 名を含むエラーで登録を失敗させる。モックを使わないスイートや Firefox・WebKit は変わらない。

⏳ 未リリース · トピック: [[repos/vitest-dev-vitest/topics/ブラウザモード|ブラウザモード]]、[[repos/vitest-dev-vitest/topics/モック|モック]]

### api: API トークンをアトミックに公開（[#11323](https://github.com/vitest-dev/vitest/pull/11323)）

> [!quote] Before
> `resolveTokenFromPath` は `existsSync` で確認してから読み込み、`writeFileSync` で書き込んでいた。並行するプロセスが書き込み前の空ファイルを読むと空のトークンがブラウザクライアントに `"0"` として渡り、websocket のハンドシェイクが拒否されて、テストを実行しないまま 60 秒の接続タイムアウトまで待っていた（#11315）。

> [!success] After
> 読み込みは直接 `readFileSync` し、空の内容は「トークンなし」として再生成する。書き込みは同じディレクトリの一時ファイルに書いて `linkSync` で公開し、先に別のプロセスが公開していれば（`EEXIST`）そのトークンを採用するため、すべてのプロセスが同じトークンを使う。

⏳ 未リリース · トピック: [[repos/vitest-dev-vitest/topics/ブラウザモード|ブラウザモード]]
