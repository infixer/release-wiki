## 新機能

### ブラウザモード: import map でモジュールをモックする（[#11534](https://github.com/vitest-dev/vitest/pull/11534)）

> [!tip] 何ができるようになったか
> `vi.mock` が、テスターのドキュメントにモジュールの URL をモック版（automock、`__mocks__` のファイル、または元のモジュールから export 名を解析したファクトリーのシム）に向ける import map のルールを登録するようになった。プロバイダーがリクエストを横取りしないので HTTP キャッシュも効いたまま。
>
> - **設定**: ブラウザが（モジュールの読み込み後に）import map を受け付けるかを自動で調べる。`browser.importMapMocks` で強制的にオン・オフできる。Firefox は `dom.multiple_import_maps.enabled` が必要で、Playwright プロバイダーが設定する
> - **効果の例**（Chromium、500 ファイル）: mock のスイートが 56.4 s（5.0.3）→ 27.2 s、mixed が 44.0 s → 27.1 s
> - **制限**: `vi.unmock`・`vi.doUnmock` ではルールを消せない（従来通り）、ファクトリーは元のモジュールに無い export を足せない、`vi.mock` より前に import されたモジュールは明示的なエラーになる。モックの登録が拒否されると、黙って無視せず import が失敗する

### `--last-failed` で前回失敗したテストだけを実行（[#11558](https://github.com/vitest-dev/vitest/pull/11558)）

> [!tip] 何ができるようになったか
> CLI 専用の `--last-failed` フラグで、前回の実行で失敗したテストだけを実行できる。
>
> - **仕組み**: `results.json` がファイルごとに失敗したテストのフルネーム（`failedTests`）を保存する。テストの外（フック・収集）での失敗はファイル全体を再実行する
> - **API**: `TestSpecification.testNames` のフィルターを追加。ID ではなく名前なので、ファイル内でテストを追加・移動しても選択が保たれる
> - **組み合わせ**: `vitest list` や他のフィルターと併用できる。ウォッチモードでは最初の実行だけを絞り込む

### `--since-last-run` で前回から依存が変わったテストを実行（[#11516](https://github.com/vitest-dev/vitest/pull/11516)）

> [!tip] 何ができるようになったか
> 前回の実行以降に依存ファイルが変わったテストを実行する `--since-last-run` フラグを追加した。`--changed` と違い `git` が不要で、毎回すべてのファイルを解析せずキャッシュした依存ツリーを再利用する。
>
> - **カスタム VCS プロバイダー**: すべての依存を返せる `resolver` オブジェクトが渡されるようになり、これを使う新しい `mtime` プロバイダーが `--since-last-run` の内部で使われる

### トレースビュー: 実験的扱いを外し、aria スナップショットを記録（[#11518](https://github.com/vitest-dev/vitest/pull/11518)、[#11492](https://github.com/vitest-dev/vitest/pull/11492)）

### ブラウザモード: 失敗時にターミナルへトレースのステップのタイムラインを表示（[#11594](https://github.com/vitest-dev/vitest/pull/11594)、[#11665](https://github.com/vitest-dev/vitest/pull/11665)）

> [!tip] 何ができるようになったか
> ブラウザモードのテストが失敗したとき、既定のレポーターのエラー出力の下に、トレースのステップがテキストの表として出るようになった（レポーターが既に受け取っているトレースのデータから描画し、収集の仕組みは変わらない）。
>
> - **使い方**: `--browser.traceView` を付けて実行する
> - **嬉しい場面**: 不安定な非同期テストで、失敗に至るまでの手順を CI のログやコーディングエージェントからも見たいとき
> - **関連**: HTML レポーター無しで `--browser.traceView` を使ったときの警告を削除した（[#11665](https://github.com/vitest-dev/vitest/pull/11665)）

### `vi.setSystemTime()` で `Temporal.Instant`・`Temporal.ZonedDateTime` を受け付ける（[#11321](https://github.com/vitest-dev/vitest/pull/11321)）

> [!tip] 何ができるようになったか
> `vi.setSystemTime()` が `Temporal.Instant` と `Temporal.ZonedDateTime` を受け付けるようになった（以前は Temporal の `valueOf` が例外を投げて失敗していた）。Sinon と同じ構造的な型（`{ epochMilliseconds: number }`）で受け取るので、組み込みの Temporal の型は必須ではない。
>
> - **補足**: `vi.useFakeTimers({ now })` は既に Sinon 経由で対応しており、テストとドキュメントを追加した。`ZonedDateTime` で設定されるのは時刻（instant）で、システムのタイムゾーンは変わらない

### `node:timers`・`node:timers/promises` のフェイクタイマー（[#10899](https://github.com/vitest-dev/vitest/pull/10899)）

> [!tip] 何ができるようになったか

## 変更・修正

### ブラウザモードの既定のポートを 23315 に変更（[#11640](https://github.com/vitest-dev/vitest/pull/11640)）

> [!quote] Before
> 既定のポート `63315` が、Hyper-V・WSL2・Docker Desktop が動いている Windows で予約されていることがあり、`EACCES` で起動に失敗していた（Vite は `EADDRINUSE` のときしか次のポートに移らない）。

> [!success] After
> 既定のポートを `23315` にした。このポートと、追加のブラウザプロジェクトが使う後続のポートは、Windows の動的ポート範囲や Linux の既定のエフェメラル範囲を避けている。

> [!warning] 移行が必要
> ブラウザモードのポート `63315` を前提にした設定（ファイアウォールやプロキシなど）があれば `23315` に合わせる。

### ブラウザモード: 操作と `expect.element` の待機中にフェイクタイマーを進める（[#11242](https://github.com/vitest-dev/vitest/pull/11242)）

> [!quote] Before
> フェイクタイマーが有効なとき、`setTimeout` などの後に現れる要素への `await locator.click()` などの操作がタイムアウトしていた。Vitest 5 からは `expect.element` も実時間で待つリトライループになったため同じ問題があった。

> [!success] After
> `expect.poll`・`vi.waitFor`・`vi.waitUntil` と同じように、操作や要素の検索の待機中にフェイクタイマーを進める。ロケーターの操作は、実行中 50ms ごとにフェイクタイマーを 50ms 進める。

### 後から生じるモックファクトリーの循環を検出（[#11642](https://github.com/vitest-dev/vitest/pull/11642)）

> [!quote] Before
> ファクトリーが、同じファクトリーを待つモジュールを import すると部分的な export を受け取る仕組み（#11623）は、import の開始時にしか調べていなかった。既に評価中のモジュールが後からファクトリーを待ち始めると、互いに待ち合ってテストがタイムアウトしていた。

> [!success] After
> ファクトリーがモジュールを待っている間にモジュールがファクトリーを待ち始めた場合も、ファクトリーに部分的な export を渡す。

### 削除されたファイルを import するテストを実行対象にする（[#11669](https://github.com/vitest-dev/vitest/pull/11669)）

> [!quote] Before
> SSR では、解決できない import がモジュールグラフに生の指定子を ID として残るため、影響を受けたモジュールをたどる処理で削除されたファイルへのつながりが落ちていた（#11566）。

> [!success] After
> そうした静的な import があれば、client 環境と同じく import 元を失敗扱いにして実行する。動的 import（catch できる）と bare 指定子（Node が読み込める）は対象外。
