## 変更・修正

### API のコールバック式ファイルシステムを改善し、`createVirtualFileSystem` を削除（[#64447](https://github.com/microsoft/TypeScript/pull/64447)）

> [!quote] Before
> `new API({ fs: createVirtualFileSystem({...}) })` のように、`readFile`・`fileExists`・`getAccessibleEntries` などのコールバックを登録できた。自前のコールバックを渡すときに一部を省略すると、その関数だけ黙って OS のファイルシステムが使われ、`readFile` は渡したのに `fileExists` を忘れる、といった食い違いが起きやすかった。

> [!success] After
> `createVirtualFileSystem` はテスト用ユーティリティに移され、公開 API からは無くなった。コールバック式のファイルシステムでは、すべての関数について実装の指定が必須になった。すべてをコールバックで書く必要はなく、サーバー側の実装を表すシンボルを指定できる（例: `readFile` だけを上書きし、他は OS のファイルシステムを使う）。

> [!warning] 移行が必要
> `createVirtualFileSystem` を使っていた場合は置き換えが必要。PR では、インメモリのファイルシステム全体を渡す用途には、サーバーとの往復が FS 呼び出しごとに発生しない #64115 の仕組みを使うよう案内している。自前のコールバックを渡している場合は、省略していた関数にもサーバー側の実装を表すシンボルなどを指定する。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]

### バインダーが作った Symbol をクライアント側でも SourceFile の持ち物に（[#64518](https://github.com/microsoft/TypeScript/pull/64518)）

> [!quote] Before
> API が返す Symbol は、バインダーが作ったもの（SourceFile に属するもの）でもスナップショットごとに別のオブジェクトだった。

> [!success] After
> バインダーが作った Symbol はクライアント側の `SourceFileCache` に保存され、異なるスナップショット間でも参照が同一になる（サーバーや 6.0 と同じ）。キャッシュの再利用が進む。リクエスト・レスポンスの Symbol ID は、ファイルに対して引ける（バインダー由来）か、プロジェクト・スナップショットに対して引ける（transient）かを示すようになった。#64434 の最初の follow-up。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]

### type-only の import 句で `getTypeAtLocation` がクラッシュする不具合を修正（[#64468](https://github.com/microsoft/TypeScript/pull/64468)）

> [!quote] Before
> デフォルトの束縛が無い type-only import（`import type { U } from "./types"`、`import type * as types from "./types"`）の `ImportClause` に対して `getTypeAtLocation` を呼ぶと、nil ポインタ参照で API サーバーが panic していた（#64467）。

> [!success] After
> シンボルを持たない import 句を型宣言として扱わないようにし、クラッシュしなくなった。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]

### Program のオプションを寿命ごとに分割し、古い状態を保持しないように（[#64519](https://github.com/microsoft/TypeScript/pull/64519)）

> [!quote] Before
> `ProgramOptions` にデータ・ホスト・ファクトリが混在していたため、プログラムを作り直すときに古い状態を持ち越しやすかった。診断もプログラム間で保持され、古いデータを参照することがあった（#64465）。

> [!success] After
> `ProgramOptions` を `ProgramConfig`（引き継げるデータ）・`ProgramHosts`（プログラムごとのホスト）・`ProgramFactories`（構築時だけ使う関数）に分け、必要なものだけを引き継ぐ。プログラム間で保持されていた診断も直し、モジュールリゾルバーも引き継げるデータを分けて持つようにした。#64466 を置き換える PR。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### テンプレートリテラル型のサイズに上限を設け、無限に膨らむのを防止（[#64194](https://github.com/microsoft/TypeScript/pull/64194)）

> [!quote] Before
> 再帰的な条件型でチェック型が `any` になると、文字列が倍々に伸びながら末尾再帰が続き、再帰の上限 1000 回に届く前にメモリが尽きていた（#63271）。JS 版の tsc は `RangeError: Invalid string length` を投げ、Go 版は文字列長の制限が無いため止まらなかった（45 秒で 9.8 GB）。

> [!success] After
> `getTemplateLiteralType` が作る型の大きさを制限し、上限を超えると TS2589（`Type instantiation is excessively deep and possibly infinite`）を報告して `errorType` を返す。上限はテキストの長さ（5,000 万文字）とプレースホルダー数（10 万）の 2 つ。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### `resolveObjectTypeMembers` の冪等性を回復し、無限循環するインスタンス化のエラーを改善（[#64372](https://github.com/microsoft/TypeScript/pull/64372)）

> [!quote] Before
