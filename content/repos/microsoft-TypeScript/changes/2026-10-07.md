## 新機能

### DOM の型定義を更新（Web Serial・Document Picture-in-Picture・`CloseWatcher`・`Element.setHTML()` など）（[#64604](https://github.com/microsoft/TypeScript/pull/64604)）

> [!tip] 何ができるようになったか
> 同梱の `lib.dom.d.ts`（+1193 -277）と `lib.webworker.d.ts`（+418 -26）を更新し、新しい Web API の型が使えるようになった。
>
> - **新しい API**: Web Serial（`navigator.serial`、worker 対応を含む）、Document Picture-in-Picture（`documentPictureInPicture`）、`CloseWatcher`、`Origin`
> - **HTML サニタイズ**: `Element.setHTML()`、`setHTMLUnsafe()` と `Document.parseHTMLUnsafe()` の sanitizer オプション、processing instruction の設定
> - **WebGPU**: `"webgpu"` の canvas コンテキストのオーバーロード、グローバルな usage / flag 定数、デバイスの limit の追加、pipeline layout の `immediateSize`、頂点フォーマット `"snorm10-10-10-2"`
> - **WebTransport**: 接続・ストリームの統計、受信 / 送信ストリーム専用のインターフェース、信頼性・プロトコルのプロパティ
> - **CSS・アニメーション**: `CSSFontFaceDescriptors`、ハイライトのヒットテスト、コンテナ条件の情報、キーフレームでの `CSSStyleValue`、アニメーション / トランジションイベントからのアニメーション参照
> - **その他**: Brotli 圧縮、`HTMLMediaElement.captureStream()`、`VisualViewport` の scroll-end イベント、フルスクリーンのキーボードロックのオプション、resource timing の content / delivery の型

> [!warning] 互換性に影響する可能性のある変更
> - `WritableStreamDefaultWriter.write()` と `TransformStreamDefaultController.enqueue()` は chunk 引数が必須になった
> - いくつかの SVG のジオメトリ API が `DOM*` 型ではなく `SVGPoint`・`SVGRect`・`SVGMatrix` を使うようになった
> - `SVGFilterElement` が `SVGURIReference` を継承しなくなった
> - `HTMLImageElement.crossOrigin` が `"anonymous" | "use-credentials" | null` に狭められた

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

## 変更・修正

### アイドル時のキャッシュ掃除タイマーが Session に保存されていなかった問題を修正（[#64624](https://github.com/microsoft/TypeScript/pull/64624)）

> [!quote] Before
> `scheduleIdleCacheClean` が `time.AfterFunc` でタイマーを作っていたが `s.idleCacheCleanTimer` に代入していなかった。そのため `Close` から呼ばれる `cancelIdleCacheClean` がタイマーを止められず、掃除が保留されていなくても `Close` が 30 秒のアイドル遅延が過ぎるまで待たされていた。

> [!success] After
> タイマーを Session に保存し、`Close` で止められるようにした（`tsc/internal/project/session.go`、テスト追加）。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/言語サービス|言語サービス]]

### 後から低い `node_modules` の深さで到達したファイルの import を処理し直す（[#64632](https://github.com/microsoft/TypeScript/pull/64632)）

> [!quote] Before
> ファイルに 2 回目に低い深さで到達したとき、`lowestDepth` は下げても、1 回目で import の処理を始めていたためやり直されなかった。monorepo で、あるパッケージに相対 import と `node_modules` のリンクの両方から到達すると、どのファイルを外部ライブラリとみなすかが実行ごとに変わり、同じビルドで出力されるファイルが変わる（#64498）、API 上の解析結果が実行ごとに変わる、といった問題が起きていた。

> [!success] After
> 深さが下がったときは、すでに始めていても import の処理をやり直す。やり直すたびに `lowestDepth` が厳密に下がるので、追加の処理には上限がある（テスト `symlinkedPackageReachedRelativelyIsNotExternalLibrary` を追加）。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### JS のコンストラクタで定義したプロパティの診断が不安定だった問題を修正（[#64646](https://github.com/microsoft/TypeScript/pull/64646)）

> [!quote] Before
> コンストラクタで宣言されたプロパティに `getTypeOfSymbol` を呼ぶのが一部のチェッカーの入口だけだったため、auto 型の widening による implicit any のエラーが、そのチェッカーで先に emit したかどうかによって出たり出なかったりした（サーバーのログで報告）。

> [!success] After
> こうしたプロパティを常にチェックし、診断が安定して出るようにした。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### 非同期 API で dispose の Promise を捨てないように（[#64584](https://github.com/microsoft/TypeScript/pull/64584)）

> [!quote] Before
> 非同期 API のいくつかのオブジェクトが `[Symbol.asyncDispose]()` ではなく `[Symbol.dispose]()` を使っており、破棄の Promise が捨てられていた。

> [!success] After
> `[Symbol.asyncDispose]()` を使うように直し、待つかどうかを利用者が選べるようにした。あわせて、AsyncDisposable に `using` を使ったときの診断メッセージで `await using` を使うよう提案するようにした。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]

### `typeof import()` の型修飾子について emit が付け加える不安定な診断を修正（[#64636](https://github.com/microsoft/TypeScript/pull/64636)）

> [!quote] Before
> `typeof import()` の型修飾子について、emit によって不安定な診断が付け加えられることがあった（#64623 のコメントで報告）。

> [!success] After
> チェッカーを修正した（テスト `noFlakyDiagnosticsTypeofImportTypeQualifier1` / `2`、`importElisionTypeofImportTypeQualifier` を追加）。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### デコレータ付きのオブジェクトリテラルのメンバーで decorator metadata の出力がクラッシュする問題を修正（[#64633](https://github.com/microsoft/TypeScript/pull/64633)）

> [!quote] Before
> デコレータが付いたオブジェクトリテラルのメンバー（メソッド）があると、decorator metadata の出力でクラッシュしていた（#64613 のコメントで報告）。

> [!success] After
> `tstransforms/metadata.go` を修正し、クラッシュしないようにした（テスト `decoratorMetadataObjectLiteralMethodNoCrash` を追加）。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### 設定ファイルの無いプログラムでプロジェクト参照の診断を報告できるように（[#64637](https://github.com/microsoft/TypeScript/pull/64637)）

> [!quote] Before
> `createPrograms` で作ったプログラムには設定ファイルが無く（`ParsedCommandLine.ConfigFile` が nil）、プロジェクト参照の診断が出ると `CreateDiagnosticAtReferenceSyntax` の nil 参照で API サーバーがクラッシュしていた。composite でないプロジェクトを参照する monorepo では、API サーバーのプロセスごと落ちて開いていたスナップショットがすべて失われ、ツールには EOF しか見えなかった（#64629）。

> [!success] After
> `ConfigFile` が nil のときは `CreateDiagnosticAtReferenceSyntax` が nil を返し、呼び出し元の `verifyProjectReferences` がコンパイラ診断にフォールバックする。`tsc -p` と同じく TS6306 が報告される。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]

### カスタマイズしたモジュール解決では、ディスク上の配置に依存する import の診断を出さない（[#64638](https://github.com/microsoft/TypeScript/pull/64638)）

> [!quote] Before
> 静的な `moduleResolutions` のエントリや `resolveModuleName` コールバックで解決した結果には `ResolvedUsingTsExtension` が設定されないため、`rewriteRelativeImportExtensions` の下で相対の `./x.ts` の値 import に、`tsc` では出ない TS2876 が誤って出ていた。

> [!success] After
> `ResolvedModule` に内部用の `IsCustomResolution` を追加し、これが立っているときはチェッカーが `resolveExternalModule` の `ResolvedUsingTsExtension` のブロック（TS2846・TS5097・TS2876・TS2877・TS2878）を飛ばす。`StaticModuleResolution` は変わらない。なお emit は引き続き指定子のテキストから `./b.ts` を `./b.js` に書き換え、カスタマイズした解決先に対応する出力パスがあるかはチェックしなくなる。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]
