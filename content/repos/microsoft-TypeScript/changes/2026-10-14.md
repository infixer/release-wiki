## 新機能

### コンテンツマッパーに出力拡張子の指定（`outputExtensions`）を追加（[#64581](https://github.com/microsoft/TypeScript/pull/64581)）

> [!tip] 何ができるようになったか
> コンテンツマッピングした（`.gts` などの）ファイルを別のツールがディスクに出力する構成に対応した。これまでの仕組みは、バンドラーを使うかソースをそのまま実行することを前提にしていた。
>
> - **使い方**: コンテンツマッパーの `package.json` の `typescript.contentMapper.outputExtensions` に、元の拡張子から出力の拡張子への対応（例: `{ ".gts": ".js" }`）を書く。`tsconfig.json` の `contentMappers[]` の各項目でも `outputExtensions` で上書きできる（対応全体を置き換え、キーはマージしない）
> - **効果**: `Component.gts` の宣言ファイルの出力が `Component.d.gts.ts` ではなく `Component.d.ts` になる（別のツールが `Component.js` を作る前提）
> - **嬉しい場面**: Ember の `.gts` のように、別のツールが JS を出力するファイルを TypeScript のプログラムに含めたいとき

> [!warning] 移行が必要
> このコンテンツマッパーを使うプログラムでは `rewriteRelativeImportExtensions: true` を設定する必要がある（`import Page from "./Page.gts"` のような import を、出力の拡張子に書き換えて出力するため）。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/コンテンツマッパー|コンテンツマッパー]]

> [!tip] 何ができるようになったか

## 変更・修正

### 同じファイルで宣言した ambient module の中の import を解決しないように（Strada と同じ動作）（[#64491](https://github.com/microsoft/TypeScript/pull/64491)）

> [!quote] Before
> `declare module 'lodash/isEmpty' { import _isEmpty from 'lodash/isEmpty'; ... }` のような内側の import を、Corsa（tsgo）は `@types/lodash/isEmpty.d.ts` に解決し、`@types/lodash` 全体をプログラムに取り込んでいた。その結果、`DeepPartial` に `IntersectionObserver` を渡すようなコードで Lodash の API 全体をたどり、大量のインスタンス化が起きていた（#64486）。

> [!success] After
> Strada（旧 TypeScript）と同じく、内側の import は同じファイルで宣言した ambient module を指すものとして扱い、解決しない。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### 名前型（`as` 節）付きのジェネリックな mapped type の `keyof` の簡約を移植（[#64772](https://github.com/microsoft/TypeScript/pull/64772)）

> [!quote] Before
> microsoft/typescript-go#2750 の移植に誤りがあり、名前型付きのジェネリックな mapped type に対する `keyof` の簡約が抜けていた（#64768）。

### API: 循環する `extends` で `createSnapshot` が止まる問題を修正（[#64755](https://github.com/microsoft/TypeScript/pull/64755)）

> [!quote] Before
> 開いた設定ファイルの `extends` の連鎖が自分に戻ると、`parseConfig` がその設定ファイル自身を `ExtendedSourceFiles` に入れ、プロジェクトのレジストリがロックを待ち続けて `createSnapshot` がエラーも出さずに返らなくなった（`tsc -p` は TS18000 を報告してすぐ終了する）。

> [!success] After
> `ExtendedSourceFiles` から設定ファイル自身のパスを除く。連鎖のほかの設定ファイルはそのまま残るので、監視とキャッシュの無効化は変わらず、TS18000 もこれまでどおり報告される。
