## 新機能

### コンテンツマッパーの登録を `include` の glob で絞り込めるように（[#65047](https://github.com/microsoft/TypeScript/pull/65047)）

> [!tip] 何ができるようになったか
> コンテンツマッパーの登録に `include` の glob を書き、そのマッパーが扱うファイルを絞り込めるようになった（#64362）。既定の `extension` はマッパーのマニフェストから引き継ぐ。tsconfig・jsconfig の JSON スキーマと、VS Code 拡張のコンテンツマッパーの登録処理も対応した。
>
> - **制限**: `outputExtensions` を使うマッパーは通常 `rewriteRelativeImportExtensions` に完全に参加する（例: `"outputExtensions": { ".gts": ".js" }` なら `import Component from "./Component.gts"` が `./Component.js` に書き換わり、`Component.gts` の宣言ファイルは `Component.d.ts` になる）。`include` の絞り込みと組み合わせると、単一ファイルの emit で、import が解決したファイルが書き換えの対象となる登録に含まれるかを判断しにくくなるため、`rootDirs`・`moduleSuffixes` の影響を受ける import には制限がある（PR 本文は途中で切れている）
> - **嬉しい場面**: 同じ拡張子のファイルのうち、一部だけをコンテンツマッパーで扱いたいとき

## 変更・修正

### 遅延した indexed access 型のキャッシュのキーを永続的な access flags にする（[#65450](https://github.com/microsoft/TypeScript/pull/65450)）

> [!quote] Before
> Go 版のチェッカー（`getIndexedAccessKey`）は、遅延した indexed access 型をキャッシュするキーに、型の作成に使う永続的な flags（`accessFlags & AccessFlagsPersistent`）ではなく `accessFlags` 全体を使っていた。従来の TypeScript（Strada）の `getIndexedAccessTypeOrUndefined` とは異なる移植のバグ。

> [!success] After
> キーに `persistentAccessFlags` を使い、Strada と同じ動作に戻した。テスト `indexedAccessUnionKeyIdentity` を追加。
