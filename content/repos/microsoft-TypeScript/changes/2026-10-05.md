### 他の VS Code 拡張が言語機能のレスポンスに LSP ミドルウェアを入れられるように（[#64583](https://github.com/microsoft/TypeScript/pull/64583)）

> [!tip] 何ができるようになったか
> TypeScript の VS Code 拡張（`TypeScriptTeam.native-preview`）が公開する拡張 API に `registerLspMiddleware` が加わり、ほかの拡張が `textDocument/hover` などのレスポンスを書き換えられるようになった（#63800）。拡張 API の型は `typescript` パッケージへ移り、ミドルウェア登録で公開されるため LSP のプロトコル定義の大部分も生成して同梱する。
>
> - **使い方**: `import type { ExtensionAPI } from "typescript/unstable/vscode"` で型を取り、`vscode.extensions.getExtension<ExtensionAPI>("TypeScriptTeam.native-preview")` を `activate()` して `extensionAPI.registerLspMiddleware("textDocument/hover", (hover, context) => ...)` を登録する
> - **嬉しい場面**: `.vue` ファイルなど特定のファイルについて、ホバーなどの結果を独自に加工したいとき

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/言語サービス|言語サービス]]

## 変更・修正

### ファイルパスを強く型付け（[#64159](https://github.com/microsoft/TypeScript/pull/64159)）

> [!quote] Before
> パスは「何の保証もない `string`」と、map のキーに使う OS 依存の `Path`（大文字小文字を区別しないシステムでは小文字化）の 2 種類だけだった。そのため `normalizeSlashes`・`normalizePath` などをあちこちで（Linux や macOS では不要な場合も）呼んでいた。

> [!success] After
> パスの性質を表す名前付き（branded）の型を導入した。`RootedPath`（絶対パス・スラッシュ正規化済み・末尾 `/` なし）と、その派生の `RootedFilePath`・`RootedDirectoryPath`、旧 `Path` を改名した `PathKey`。パスは設定ファイルなどの境界で変換する。変更は API（`api/path.ts`・`api/fs.ts`・クライアントなど）を含む 483 ファイルに及ぶ。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]

### 誤って移植されていたフォーマッタの `TokensAreOnSameLine` を修正（[#64597](https://github.com/microsoft/TypeScript/pull/64597)）

> [!quote] Before
> フォーマッタ（`tsc/internal/format/context.go`）の `TokensAreOnSameLine` が、旧実装から誤って移植されていた。

> [!success] After

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/言語サービス|言語サービス]]
