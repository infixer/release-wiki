## 新機能

### `esnext` に `Promise.allKeyed` と `Promise.allSettledKeyed` を追加（[#64093](https://github.com/microsoft/TypeScript/pull/64093)）

> [!tip] 何ができるようになったか
> `esnext` の lib に `Promise.allKeyed` と `Promise.allSettledKeyed` の型定義が追加された（#63701）。
>
> - **使い方**: `"lib": ["esnext"]`（新しい `lib.esnext.promise.d.ts` が `lib.esnext.d.ts` から読み込まれる）
> - **変更点**: tsconfig / jsconfig の JSON スキーマとオプション定義にも `esnext.promise` が追加されている

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### API に `getSymbol(decl)` を追加（[#64571](https://github.com/microsoft/TypeScript/pull/64571)）

> [!tip] 何ができるようになったか
> TS 6 の `declaration.symbol` プロパティに相当する、Declaration ノードから（マージ前の）バインダーが作った Symbol を取り出す API が追加された。これまでは `checker.getSymbolAtLocation` くらいしか手段がなく、直感的でない挙動があった。型チェッカーなしで Symbol を取れるため、`api.createSourceFile` で作ったファイルの Symbol も取得できる。#64518 の follow-up。
>
> - **使い方**: `api.getSymbol(sourceFile)`。`api` を受け渡さずに使えるトップレベルの `getSymbol`（`import { getSymbol } from "typescript/async"`）もある
> - **`decl.getSymbol()` にしなかった理由**: 同期版と非同期版の `Symbol` 型があり、AST の型に直接結びつけると AST 定義を 3 系統生成する必要があるため

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]

### コンパイラオプションの定義をコード生成し、パッケージに JSON スキーマを同梱（[#64457](https://github.com/microsoft/TypeScript/pull/64457)）

> [!tip] 何ができるようになったか
> `CompilerOptions` をメタデータとして定義し、Go のコード・TS のコード・JSON スキーマをすべてコード生成するようにした。生成した `tsconfig.schema.json` / `jsconfig.schema.json` はパッケージに同梱され、`node_modules/typescript/schemas/tsconfig.schema.json` が使えるようになった（#54192）。
>
> - **背景**: 新しい Web サイトの playground で `CompilerOptions` の仕様が必要になった。Strada では実行時に内部の定義を解析して UI や JSON スキーマを作っており、schemastore への反映なども手作業だった
> - **おまけ**: `CompilerOptions.Clone`・`parseCompilerOptions`・transpile 用のオプション消去処理なども生成できるようになった

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/開発ツールとCI|開発ツールとCI]]

## 変更・修正

### 宣言出力で循環構造と打ち切りをエラーとして報告（[#64461](https://github.com/microsoft/TypeScript/pull/64461)）

> [!quote] Before
> 型の出力中に循環（`visitedTypes.Has`）を検出すると、何も報告せずに `/* elided */ any` を出力していた。

> [!success] After
> 循環や打ち切りが起きたことをエラーとして報告する。リポジトリ内にあった elided な `any` は（ツールチップで表示する場合を除き）すべて無くなった。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

> [!quote] Before
> reverse mapped type を宣言ファイルに出力するときに、黙って elided な `any` になっていた。

> [!success] After

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

> [!success] After

### 型引数からの推論をキャッシュし、キャッシュキーの不足を修正（[#64553](https://github.com/microsoft/TypeScript/pull/64553)）

> [!quote] Before
> 既存のキャッシュは、キーに `priority`・`contravariant`・`bivariant` の状態を含めていなかったため、誤って一致して推論が失われることがあった（#64378）。

> [!success] After
> 同じエイリアスやクラス・インターフェースへの参照の型引数からの推論を、既存の `invokeOnce` の仕組みでキャッシュする（#64388 を置き換え）。キャッシュキーの不足も修正した。

> [!warning] 移行が必要
> 失われた推論に依存していたコードは結果が変わりうる。テストの `correlatedUnions.ts` は、宣言順によってエラーになるケースだったため `NoInfer<T>` を使うよう書き換えられた。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### モジュール宣言の import 属性の型で置換なしテンプレートリテラルを禁止（[#64243](https://github.com/microsoft/TypeScript/pull/64243)）

> [!quote] Before

### `verbatimModuleSyntax` でデフォルト import の横の空の named import を削除（[#64578](https://github.com/microsoft/TypeScript/pull/64578)）

> [!quote] Before
> `verbatimModuleSyntax` が有効で、named import がすべて type-only のとき、`import A, { type T } from "./a"` が `import A, {} from "./a"` と出力されていた（#62239）。6.0 も同じ出力。

> [!success] After
> `import A from "./a"` と出力する。デフォルトの束縛が無い import は従来どおり `import {} from "./a"` と出力し、ソースに書いた `{}` は残す。

### API が返す補完の Symbol を常に現在のスナップショットのものに（[#64554](https://github.com/microsoft/TypeScript/pull/64554)）

> [!quote] Before
> 補完で一時的に作られたスナップショットの Symbol が、親スナップショットの記録に登録されていた。呼び出し側は返された Symbol を現在のスナップショットのものとみなしてそのチェッカーで扱うため、transient な Symbol では誤った結果やクラッシュの原因になりえた（#64518 のレビューで指摘）。

> [!success] After
> API に返す補完の Symbol は常に現在のスナップショットから取るようにした。変更ファイルには、ユーザー設定（preferences）の定義を生成する `tools/gen-preferences` と、生成された `userPreferences.generated.ts` が含まれている。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]
