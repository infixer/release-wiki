## 新機能

### Checker の API に不足していたメソッドを追加（[#65037](https://github.com/microsoft/TypeScript/pull/65037)）

> [!tip] 何ができるようになったか
> tsgo の API（`typescript/async` / sync）の Checker に、足りていなかったメソッドのおよそ半分が加わった。
>
> - **追加**: `isImplementationOfOverload(node)`・`getAmbientModules()`・`getPropertySymbolOfDestructuringAssignment(location)`・`getNullableType(type, flags)`・`getStringLiteralType(value)`・`getNumberLiteralType(value)`・`getBigIntLiteralType(value)`・`getFalseType()`・`getTrueType()`・`getJsxIntrinsicTagNamesAt(location)`・`getPrivateIdentifierPropertyOfType(type, name, location)`（非同期版は `Promise` を返す）
> - **削除**: `getAugmentedPropertiesOfType(type)`（代わりに `Type.getApparentProperties()` を使う）

> [!warning] 移行が必要
> `getAugmentedPropertiesOfType` を使っているコードは `Type.getApparentProperties()` に置き換える。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]

### API に `parseConfigFileTextToJson` を追加（[#65328](https://github.com/microsoft/TypeScript/pull/65328)）

> [!tip] 何ができるようになったか
> tsgo の API（非同期・同期の両方）から `parseConfigFileTextToJson` を呼べるようになった（#64634 の対応）。
>
> - **使い方**: `parseConfigFileTextToJson`（`packages/typescript/src/api/async/api.ts`・`sync/api.ts`）

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]

## 変更・修正

### 離れた abstract メソッドの宣言に TS2516 を報告する（[#65099](https://github.com/microsoft/TypeScript/pull/65099)）

> [!quote] Before
> 同じ abstract メソッドの 2 つの宣言の間に本体のあるメソッドがあると、間のメソッドが実装の名前の間違いとみなされ、正しいコードなのに TS2389（`Function implementation name must be 'func1'.`）が出ていた（#61783）。

> [!success] After
> abstract メソッドでは名前の間違いのチェックを飛ばし、TS2516（`All declarations of an abstract method must be consecutive`）を `func1` に報告する。間にプロパティがある場合と同じ挙動。abstract でないクラスはこれまでどおり TS2389。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### 引数の数が不正な動的 `import()` の TS1450 をエラーにする（[#65317](https://github.com/microsoft/TypeScript/pull/65317)）

> [!quote] Before
> 動的 `import()` の引数の数が不正なときの TS1450 が、エラーではなく情報メッセージになっていた（#65309）。

> [!success] After
> TS1450 をエラーとして報告する（`diagnosticMessages.json`）。関係するベースライン 8 件を更新。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### ASCII の識別子のバイトをルックアップテーブルで判定する（[#64989](https://github.com/microsoft/TypeScript/pull/64989)）

> [!quote] Before
> スキャナーは識別子の ASCII バイトを都度判定していた。

> [!success] After
> ルックアップテーブルで判定する（`scanner/scanner.go`）。Apple M1 Pro の `BenchmarkParse` で 1〜3% 速くなり、識別子の長い `checker.ts` のほうが `dom.generated.d.ts` より効果が大きい。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### `CommonSourceDirectory()` の計算で `ParsedCommandLine` のエラーを書き換えない（[#64193](https://github.com/microsoft/TypeScript/pull/64193)）

> [!quote] Before
> プロジェクト参照の解決チェックなどで `ParsedCommandLine.CommonSourceDirectory()` を評価すると、`ParsedCommandLine.Errors` に設定の診断が追加され、`tsc -b` やソリューションのビルドが `tsconfig.json` にソースの位置を持たない診断を報告していた（#62436）。

> [!success] After
> `checkSourceFilesBelongToPath` に `nil` を渡し、TypeScript の元の実装（`getCommonSourceDirectoryOfConfig`）と同じにする。`Errors` が変わらないことを確かめるテストを追加。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/ビルドとファイル監視|ビルドとファイル監視]]

### VS Code 拡張のワークスペースの TypeScript バージョンの検出を修正（[#65344](https://github.com/microsoft/TypeScript/pull/65344)）

> [!quote] Before
> ワークスペースの TypeScript を探すとき、ブログ記事で案内していた `@typescript/native` などは探していたが、`typescript` パッケージは探していなかった（#64565）。

> [!success] After
> `@typescript/native` に加えて `typescript` も探す。選択リストに tsdk を表示し、ユーザーレベルの tsdk 設定も表示する（`packages/vscode-typescript`）。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/言語サービス|言語サービス]]

### LSP のパフォーマンス最適化（[#64877](https://github.com/microsoft/TypeScript/pull/64877)）

> [!quote] Before
> vscode リポジトリでの計測で、初回読み込みの保持メモリの約 95% はパースキャッシュの AST・シンボルで、プロジェクト側の負担は主に一時的な割り当てと変更ごとの待ち時間だった。

> [!success] After
> ファイルの読み込み・モジュール解決・package.json のキャッシュ・オートインポートなどを最適化（一部はバッチコンパイルにも効く）。vscode リポジトリで `CreateDeleteFile` が 43%・`TsconfigChange` が 40% 速くなり、`EditImports` の割り当ては 41.8% 減、`WatchChange` の割り当ては 90.4% 減、`AutoImportInitial` の保持メモリは 19.8 → 16.7 MB。
