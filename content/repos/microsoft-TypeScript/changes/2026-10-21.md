## 変更・修正

### LSP サーバーが読み込むコンテンツマッパーを、ワークスペースフォルダ内の node_modules のものに限定（[#64837](https://github.com/microsoft/TypeScript/pull/64837)）

> [!quote] Before
> 信頼済みの VS Code ウィンドウに信頼されていないディレクトリのファイルを開くと（VS Code の警告は永続的に抑止できる）、言語サーバーがその tsconfig を見つけ、信頼されていないディレクトリの node_modules から解決したコンテンツマッパーを読み込むことがあった。

> [!success] After
> LSP サーバーは、開いているワークスペースフォルダに含まれる node_modules に解決されたコンテンツマッパーだけを読み込む（診断メッセージも追加）。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/コンテンツマッパー|コンテンツマッパー]]

### API: クライアントの性能を改善（[#64823](https://github.com/microsoft/TypeScript/pull/64823)）

> [!quote] Before
> API クライアント（同期・非同期）で、多くのアロケーションが発生していた。

> [!success] After
> 6 つの独立した変更で、typescript-eslint の performance リポジトリの推奨ルールセット（1024 ファイル）の実行時間が 5.8% 短くなり、クライアントのアロケーションが 57% 減った（保持ヒープは 2.4% 減）。バッチの `getSymbolAtLocation` ベンチマークは非同期クライアントで 28%、同期クライアントで 22% 速くなった。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]

### API: package.json の `"imports"` を削除し、enum を `enums` ディレクトリに生成（[#64879](https://github.com/microsoft/TypeScript/pull/64879)）

> [!quote] Before
> API パッケージは package.json の `"imports"` を使っており、CDN から直接読み込めなかった。

> [!success] After
> `"imports"` を削除し、ビルドした enum をトップレベルの `enums` ディレクトリ（`vendor` と同様にパッケージに含まれる）に生成する。CDN から API を直接読み込むための前提作業（#63858 に先立つもの）。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]
