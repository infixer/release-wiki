## 新機能

### API の `Program` にメソッドを追加し、`Program`・`Project` の重複メソッドを削除（[#64988](https://github.com/microsoft/TypeScript/pull/64988)）

> [!tip] 何ができるようになったか
> tsgo の API の `Program` に、足りていなかったメソッドが加わった。重複していたメソッドは整理された。
>
> - **追加**: `getProjectReferences()`（プログラムが直接宣言したプロジェクト参照。無ければ undefined）・`getRootFileNames()`（プログラムの作成時に渡した、または設定から得たルートのファイル名。import された依存は含まない）・`getStatistics()`（シンボル・識別子・インスタンス化・ノード・型の数と relation キャッシュのサイズ）
> - **見送り**: `getSourceFiles()`・`getResolvedProjectReferences()`
> - **`Program` から削除**: `getTypeChecker()`（所有モデルに合わないため）・`getOptionsDiagnostics()`・`getTypeCount` / `getSymbolCount` / `getRelationCacheSizes` / `getIdentifierCount` / `getInstantiationCount` / `getNodeCount`（`getStatistics()` に統合）
> - **`Project` から削除**: `containsFile`・`getFileNames`・`getRootFiles`・`hasRoots`・`isRoot`・`hasConfigFile`・`getSourceFile`

> [!warning] 移行が必要
> 個別の数を返すメソッド（`getTypeCount` など）を使っているコードは `getStatistics()` に置き換える。`Program.getTypeChecker()`・`getOptionsDiagnostics()` と、上記の `Project` のメソッドは使えなくなる。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]

## 変更・修正

### accessor の decorator metadata で getter の型注釈を保つ（[#65343](https://github.com/microsoft/TypeScript/pull/65343)）

> [!quote] Before
> デコレータ付きのクラスの accessor について出力する decorator metadata で、getter の型注釈が保たれていなかった（#65337）。

> [!success] After
> 型のシリアライズ（`tstransforms/typeserializer.go`）を直し、getter の型注釈を metadata に使う。テスト `decoratorOnClassAccessor8` を追加。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### エスケープしたキーワードのクラスメンバーの前の ASI を修正（[#64885](https://github.com/microsoft/TypeScript/pull/64885)）

> [!quote] Before
> Unicode エスケープを含むキーワードで書かれたクラスメンバーの前で、自動セミコロン挿入（ASI）が正しく扱われていなかった（#64883）。

> [!success] After
> パーサー（`parser/parser.go`）を修正し、テスト `scannerUnicodeEscapeInKeyword2` を追加。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/型チェッカー・コンパイラ|型チェッカー・コンパイラ]]

### fanotify がマウントを `EXDEV` で拒否したときは inotify にフォールバック（[#65325](https://github.com/microsoft/TypeScript/pull/65325)）

> [!quote] Before
> Linux のファイル監視で、fanotify がマウントを `EXDEV` で拒否する環境に対応していなかった（#65290）。

> [!success] After
> `EXDEV` のときは inotify にフォールバックする（`fswatch/fanotify_linux.go`）。

⏳ 未リリース · トピック: [[repos/microsoft-TypeScript/topics/ビルドとファイル監視|ビルドとファイル監視]]
