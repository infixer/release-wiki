## 概要

`tsc -b`（プロジェクト参照のビルド）とファイル監視（watch）まわりの改善。大規模なモノレポ（19,430 個の composite project、依存の深さ 124 段）では、`tsc -b` のビルドスケジューリングが参照の深さ優先順のままだと多くのビルダーがアイドルになってしまう問題があり、依存の深さ順にプロジェクトを割り当てるよう変更された。macOS の `fsevents` では、監視登録時のパスとコールバックで返るパスの形式が食い違うことでファイル変更イベントを取りこぼす問題があり、パスの正規化・比較方法を修正した。プロジェクト参照のビルドは、プログラム的 API の `createBuildOrchestrator`（TS 6 より前の `SolutionBuilder` に相当）からも実行・clean できるようになった。`/app` や `/home/user/project` のようにファイルシステムのルートに近い場所のプロジェクトで `tsc --watch` / `tsc -b --watch` が再ビルドしないリグレッション（7.0.2 にも該当）は修正され、`TS_WATCH_DEBUG=1` で監視の判断を確認できる。インクリメンタルビルドでは、広く import されるモジュールを編集した後の最初の再ビルドが、依存ファイルの宣言出力（シグネチャ計算）で外部モジュールの export を総当たりしていたため遅かった。チェッカーが索引を作るようになり、9,066 ファイルの再現では 45.7 秒から 3.5 秒になった（未リリース）。

## 主な API・オプション

- `tsc -b` の `--verbose` / `--dry` — 出力そのものは変更なし（内部のスケジューリング順序のみ変更）
- `api.createBuildOrchestrator(rootFiles, options)` — API からのビルド・clean（詳しくは [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]）
- 環境変数 `TS_WATCH_DEBUG=1` — watch が監視しない理由などを表示
