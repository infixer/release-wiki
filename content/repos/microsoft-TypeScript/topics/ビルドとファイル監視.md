## 概要

`tsc -b`（プロジェクト参照のビルド）とファイル監視（watch）まわりの改善。大規模なモノレポ（19,430 個の composite project、依存の深さ 124 段）では、`tsc -b` のビルドスケジューリングが参照の深さ優先順のままだと多くのビルダーがアイドルになってしまう問題があり、依存の深さ順にプロジェクトを割り当てるよう変更された（`createBuildOrchestrator` の追加で一度戻ったが、2026-10-13 に復活）。macOS の `fsevents` では、監視登録時のパスとコールバックで返るパスの形式が食い違うことでファイル変更イベントを取りこぼす問題があり、パスの正規化・比較方法を修正した。プロジェクト参照のビルドは、プログラム的 API の `createBuildOrchestrator`（TS 6 より前の `SolutionBuilder` に相当）からも実行・clean できるようになった。`/app` や `/home/user/project` のようにファイルシステムのルートに近い場所のプロジェクトで `tsc --watch` / `tsc -b --watch` が再ビルドしないリグレッション（7.0.2 にも該当）は修正され、`TS_WATCH_DEBUG=1` で監視の判断を確認できる。インクリメンタルビルドでは、広く import されるモジュールを編集した後の最初の再ビルドが、依存ファイルの宣言出力（シグネチャ計算）で外部モジュールの export を総当たりしていたため遅かった。チェッカーが索引を作るようになり、9,066 ファイルの再現では 45.7 秒から 3.5 秒になった（未リリース）。資格情報が自動送信されるおそれがあるため、ファイルの読み込みと監視でネットワークパスを全面的に禁止した（未リリース）。インクリメンタルのスナップショット構築が最初に削除されたファイルで止まり、`lib`・`target` の変更で複数のファイルが消えると古い診断が残ることがあった問題も直った（未リリース）。アトミックな保存で監視から `Created` イベントが来たときもキャッシュを読み直すようになり、変更のない `tsc -b` はルートファイルを繰り返し走査しなくなった（ルート 4,000 ファイルで 1,243 ms → 76 ms）（いずれも未リリース）。
Windows の監視では、`ReadDirectoryChangesW` のバッファがあふれたときに変更を黙って失わず、`ErrOverflow` で再スキャンを促す（未リリース）。
インクリメンタルビルドではコンパイラオプションの無効化と `tsbuildinfo` の保存内容が全面的に見直され（そのリグレッションも修正済み）、再ビルド時の依存ファイルのシグネチャ計算が並列化された。`extends` が循環したときの TS18000 には循環する設定ファイルが表示される（いずれも未リリース）。

## 主な API・オプション

- `tsc -b` の `--verbose` / `--dry` — 出力そのものは変更なし（内部のスケジューリング順序のみ変更）
- `api.createBuildOrchestrator(rootFiles, options)` — API からのビルド・clean（詳しくは [[repos/microsoft-TypeScript/topics/プログラム的API|プログラム的API]]）
- 環境変数 `TS_WATCH_DEBUG=1` — watch が監視しない理由などを表示
